**Feature Branch**: `feat/SCRUM-100-gh-41-github-repo-source`

**Created**: 2026-10-20

**Status**: Draft

**Input**: 로드맵 4절 명세 백로그 QK-ING-002 "GitHub 저장소 파일 수집(트리 비교, 포함·제외 패턴)". 선행은 QK-SEC-001이다.
첫 대상은 공개 저장소 `dnd-side-project/dnd-15th-2-backend`(기본 브랜치 `main`)의 Markdown 문서다(2026-10-20 사용자 결정).
백로그 행의 요구사항 ID(FR-ING-02, FR-SYN-02(파일))는 원문이 없어(Assumptions 참조) 백로그 제목, constitution C-07~C-10·C-14,

## User Scenarios & Testing *(mandatory)*

이 명세의 사용자는 수집 결과를 쓰는 구현자(QK-SYN-001 동기화, QK-CHK-002 청커), 자료원 설정을 바꾸는 운영 담당자,
수집 범위의 개인 정보를 확인하는 사람 리뷰어, PR 리뷰어다.

이 명세는 QK-ING-001 어댑터 계약을 구현하는 첫 실제 수집기다. 계약, 설정 검증, 한도·재시도 공통 동작은 QK-ING-001이,
경로 제외·접근 범위·비밀값 판정은 QK-SEC-001이 이미 맡는다. 이 명세는 그 사이에서 GitHub 저장소 고유의 부분만 정한다.

### User Story 1 - 대상 저장소의 문서 목록을 한 시점 기준으로 빠짐없이 받는다 (Priority: P1)

동기화 구현자가 수집을 실행하면, 자료원 설정의 저장소·브랜치를 그 실행 동안 고정된 한 커밋으로 확정하고, 그 커밋의 파일 중
포함 패턴에 맞고 제외 패턴에 걸리지 않는 파일만 목록으로 받는다. 파일마다 저장소 안 경로, 파일 내용 식별값(blob SHA), 확정한 커밋,
크기가 나온다. 목록을 끝까지 받지 못했으면 그 사실이 표시된다.

**Why this priority**: Phase 1 색인 트랙의 첫 실제 자료다(로드맵 3절 진행 순서 2). QK-SYN-001은 이 목록으로 바뀐 파일과 지운 파일을 판단하므로,
목록이 빠지거나 시점이 섞이면 지우지 않은 문서를 지우거나 바뀐 문서를 놓친다(C-07, C-08).

**Independent Test**: 저장해 둔 GitHub 응답(브랜치, 파일 트리)으로 재생 전송을 만들어 수집을 돌린다. 기대한 파일 목록과 정확히 같은지,
같은 응답으로 두 번 돌렸을 때 결과가 같은지, 트리가 잘렸다는 응답에서 "불완전"이 표시되는지 본다.

**Acceptance Scenarios**:

1. **Given** 포함 패턴 `docs/adr/**/*.md`와 제외 패턴이 있는 자료원 설정, **When** 목록을 조회한다, **Then** 확정한 커밋의 파일 중
   포함 패턴에 맞고 제외 패턴에 걸리지 않는 일반 파일만 나오고, 각 항목에 저장소 안 경로, 내용 식별값, 확정한 커밋, 크기가 있다.
2. **Given** 한 실행 도중 브랜치에 새 커밋이 올라온 상황, **When** 목록과 본문을 조회한다, **Then** 모든 항목과 본문은 실행 시작 때 확정한 한 커밋 기준이다.
3. **Given** 원본이 파일 트리가 너무 커서 잘렸다고 알린 응답, **When** 목록을 조회한다, **Then** 목록은 "불완전"으로 표시되고, 받은 항목만 돌려준다.
4. **Given** 하위 모듈, 심볼릭 링크, 디렉터리 항목이 섞인 트리, **When** 목록을 조회한다, **Then** 일반 파일만 목록에 나온다.
5. **Given** 원본이 바뀌지 않은 상태, **When** 목록을 두 번 조회한다, **Then** 두 결과의 항목과 내용 식별값이 같다.

### User Story 2 - 본문은 목록과 같은 내용이고, 공개 범위 정보와 함께 보안 필터로 간다 (Priority: P1)

동기화 구현자가 목록의 항목으로 본문을 조회하면, 목록에 적힌 내용 식별값과 정확히 같은 내용의 본문을 받는다. 모든 항목에는 저장소의
공개 범위가 QK-SEC-001이 정한 형식의 원본 권한 정보로 붙어 있어, 공개 저장소의 파일만 팀 공용으로 판정되고 나머지는 본문을 추가로 받지 않는다.
원본 링크는 사람이 브라우저로 열 수 있는 확정 커밋 기준 주소다.

**Why this priority**: 목록과 본문이 다르면 변경 판별과 청크 위치가 어긋난다(C-07). 공개 범위를 QK-SEC-001 형식으로 넘기지 않으면
모든 자료가 "미확인"으로 빠지거나, 반대로 형식이 느슨하면 비공개 자료가 팀 공용으로 올라간다(C-14, QK-SEC-001 FR-017).

**Independent Test**: 재생 전송에 공개·비공개·내부·정보 없음 네 가지 저장소 응답을 넣고 수집과 보안 필터를 함께 돌린다. 공개만 통과하고,
나머지는 추가 본문 조회가 0건인지 본다. 본문 응답을 일부러 다른 내용으로 바꾼 사례가 응답 형식 오류로 기록되는지 본다.

**Acceptance Scenarios**:

1. **Given** 목록 항목 하나, **When** 본문을 조회한다, **Then** 본문, 내용 형식(Markdown 등), 확정한 커밋, 저장소 안 경로가 나오고,
   본문 내용은 목록의 내용 식별값과 일치한다.
2. **Given** 본문 응답 내용이 목록의 내용 식별값과 맞지 않는 경우, **When** 본문을 조회한다, **Then** 그 자료는 "응답 형식 오류"(영구 실패)로 기록되고
   다른 자료는 계속 처리된다.
3. **Given** 공개 범위가 "공개"인 저장소, **When** 목록을 조회하고 보안 필터를 지난다, **Then** 항목의 원본 권한 정보는 공개 범위 한 값만 담고
   접근 범위는 "팀 공용"이다.
4. **Given** 공개 범위가 "비공개"·"내부"이거나 원본이 공개 범위를 주지 않은 저장소, **When** 같은 흐름을 지난다, **Then** 접근 범위는 "팀 공용"이 아니고
   본문 추가 조회가 0건이다.
5. **Given** 목록 항목, **When** 원본 식별자와 원본 링크를 본다, **Then** 원본 식별자는 저장소 안 경로이고, 원본 링크는 공개 원본 링크 호스트(`github.com`)의
   확정 커밋·경로 주소다.
6. **Given** UTF-8로 읽을 수 없는 파일, **When** 본문을 조회한다, **Then** 그 자료만 "응답 형식 오류"로 기록된다.

### User Story 3 - GitHub의 한도 응답과 권한 거부를 구분한다 (Priority: P2)

GitHub는 호출 한도를 넘었을 때도 "접근 거부"와 같은 상태 코드를 줄 수 있다. 수집기는 한도 초과를 일시적 실패로 분류해 원본이 알려 준 시각까지
기다리거나 멈추고, 진짜 권한 거부는 재시도하지 않는다. 원본이 응답마다 알려 주는 남은 호출 수와 초기화 시각을 QK-ING-001 한도 동작에 넘긴다.

**Why this priority**: 한도 초과를 영구 실패로 보면 그 실행의 남은 자료가 모두 실패로 기록되고, 반대로 권한 거부를 재시도하면 같은 토큰의 한도를
헛되이 쓴다(QK-ING-001 research 재시도 분류 표). Phase 1 대상 규모(문서 약 81개)에서는 한도에 닿을 가능성이 낮아 P2로 둔다.

**Independent Test**: 재생 전송에 "남은 호출 0"을 담은 거부 응답, "잠시 뒤 다시 시도"를 담은 거부 응답, 한도 정보 없는 권한 거부 응답을 넣는다.
앞의 두 경우는 재시도되거나 한도 멈춤으로 보고되고, 마지막 경우는 재시도 0회인지 본다.

**Acceptance Scenarios**:

1. **Given** 남은 호출 수가 0이라고 알리는 거부 응답, **When** 수집 중이다, **Then** 일시적 실패(호출 한도 초과)로 분류되고 QK-ING-001 한도 동작
   (기다림 또는 멈춤 보고)을 따른다.
2. **Given** 다시 시도할 시각이나 대기 초를 알리는 거부 응답, **When** 수집 중이다, **Then** 같은 방식으로 일시적 실패로 분류된다.
3. **Given** 한도 정보가 없는 거부 응답, **When** 수집 중이다, **Then** 영구 실패(접근 거부)로 재시도 0회다.
4. **Given** 정상 응답에 남은 호출 수와 초기화 시각이 있다, **When** 수집 중이다, **Then** 그 값이 다음 요청의 한도 판단에 쓰인다.
5. **Given** 인증 실패 응답, **When** 수집 중이다, **Then** QK-ING-001 동작대로 그 자료원 수집을 즉시 멈춘다.

### User Story 4 - 첫 자료원을 등록하고, 범위는 사람이 확인한 기록과 함께 넓힌다 (Priority: P2)

운영 담당자가 첫 실제 자료원(백엔드 저장소 문서)을 자료원 설정에 등록한다. 포함 패턴의 확장자가 보안 필터가 아는 파일 확장자인지 검증에서 확인하고,
수집 범위를 더하거나 넓힐 때는 사람이 그 범위에 개인 정보가 없음을 확인한 기록을 함께 남긴다. 등록 뒤 사람이 실제 저장소를 한 번 수집해
요청 수, 소요 시간, 파일 수와 크기, 보안 필터 판정 건수를 기록하고, QK-ING-001 기본 한도값을 이 측정으로 조정한다.

**Why this priority**: QK-SEC-001 FR-024는 개인 정보 확인 절차와 기록 위치를 이 명세에 넘겼고, 첫 실제 색인 전에 끝내야 한다.
포함 패턴의 확장자가 보안 필터 목록에 없으면 경로형 원본 식별자가 주소로 오인되어 자료가 막힌다(QK-SEC-001 research R-07).
QK-ING-001 기본값(분당 60회, 실행당 2,000회, 본문 1 MB)은 추론값이라 측정이 필요하다(C-13). 다만 구현 순서상 US1~US3 뒤라 P2로 둔다.

**Independent Test**: 확장자 목록에 없는 확장자를 포함 패턴에 넣은 설정, 확인 기록 없이 범위를 넓힌 설정을 검증한다. 둘 다 원본 호출 없이 실패해야 한다.
실제 수집은 사람이 외부 호출 시험으로 실행하고 결과를 측정 기록과 대조한다.

**Acceptance Scenarios**:

1. **Given** 포함 패턴 `**/*.adoc`처럼 보안 필터의 파일 확장자 목록에 없는 확장자를 쓴 자료원 설정, **When** 검증한다, **Then** 실패하고
   그 패턴과 이유를 보고하며 원본을 호출하지 않는다.
2. **Given** 개인 정보 확인 기록이 없거나 기록된 범위와 현재 수집 범위가 다른 활성 자료원, **When** 검증한다, **Then** 실패하고 원본을 호출하지 않는다.
3. **Given** 확인에서 개인 정보가 나온 경로, **When** 기록을 남긴다, **Then** 그 경로는 자료원 설정의 제외 패턴으로 빠지고 기록에 이유가 남는다.
4. **Given** 등록을 마친 자료원, **When** 사람이 실제 저장소를 한 번 수집한다, **Then** 요청 수, 소요 시간, 파일 수, 총 바이트, 보안 필터 판정 결과별 건수가
   측정 조건(대상 커밋, 포함·제외 패턴, 실행 환경)과 함께 기록된다.
5. **Given** 측정 기록, **When** 기본 한도값을 검토한다, **Then** 유지하거나 바꾼 값과 근거가 남는다.

### Edge Cases

- 설정한 브랜치가 없거나 저장소가 없을 때: 목록 조회가 영구 실패(자료 없음)로 끝나고 목록은 "불완전"이다. 빈 목록을 "모든 파일 삭제"로 넘기지 않는다.
- 저장소에 파일이 하나도 없거나 포함 패턴에 맞는 파일이 0개일 때: 목록은 "완전"이고 항목은 0개다. 이 값을 근거로 삭제할지는 QK-SYN-001이 정한다.
- 파일 트리가 잘렸을 때: "불완전" 표시(US1 시나리오 3). 잘린 트리를 나눠 받는 방법은 Phase 1 대상 규모(파일 1,569개)에서 필요 없어 다루지 않는다.
- 하위 모듈, 심볼릭 링크: 목록에 넣지 않는다. 심볼릭 링크는 저장소 밖이나 제외 경로를 가리킬 수 있기 때문이다.
- Git LFS 포인터 파일: 원본이 주는 내용(포인터 텍스트)을 그대로 본문으로 본다. LFS 실제 내용은 받지 않는다. Phase 1 대상에는 LFS 파일이 없다는 것을 측정에서 확인한다.
- 파일 크기가 자료원 설정의 최대 본문 크기를 넘을 때: 목록의 크기로 판단해 본문 요청 없이 "영구 실패"(실패 유형 크기 초과)로 기록한다
  (QK-ING-001 research R-08). "건너뜀"은 실행이 멈춰 시도하지 않은 자료에만 쓴다.
- 경로에 공백, 한글, `#`·`?` 같은 문자가 있을 때: 원본 식별자는 경로 그대로, 원본 링크는 경로를 주소용으로 바꿔 쓴다. 두 값이 서로 다른 파일을 가리키지 않는다.
- 대소문자만 다른 두 경로: 서로 다른 파일로 본다. 포함·제외 패턴은 대소문자를 구분한다(QK-ING-001 `scope`).
- 파일 이름을 바꾸거나 옮겼을 때: 목록에는 새 경로만 나온다. 옛 경로 삭제와 새 경로 추가로 처리하는 일은 QK-SYN-001이 한다.
- 디렉터리 이름에 점이 든 경로(예: `v1.2/`): QK-SEC-001 식별자 주소 규칙에 걸려 막힐 수 있다. 수집기는 원본 식별자를 바꾸지 않고, 막힌 건수를 측정 기록에 남긴다.
- 저장소가 공개에서 비공개로 바뀌었을 때: 다음 실행부터 원본 권한 정보가 비공개가 되어 "팀 공용"이 아니게 된다. 이미 저장된 청크를 내리는 일은 QK-SYN-001이 한다.
- 저장소 이름이 바뀌거나 옮겨져 원본이 다른 주소로 안내할 때: 같은 요청 허용 호스트 안이면 따라가고, 다른 호스트면 따라가지 않는다(QK-ING-001 FR-022).
  설정의 저장소 이름은 사람이 고친다.
- 원본이 공개 범위 값을 새 이름으로 바꿨을 때: 원본 권한 정보에 원값을 그대로 담고, QK-SEC-001 규칙이 모르는 값이므로 "미확인"으로 판정된다.

## Requirements *(mandatory)*

### Functional Requirements

**목록 조회 (US1)**

- **FR-001**: GitHub 저장소 파일 수집기는 QK-ING-001 어댑터 계약을 구현하고, 등록된 자료원 종류 `github_repo_files`로 동작한다.
  원본에 쓰는 요청은 보내지 않는다(C-09).
- **FR-002**: 실행마다 자료원 설정의 저장소와 브랜치(또는 태그·커밋)를 한 커밋으로 한 번 확정한다. 그 실행의 목록과 본문은 모두 그 커밋 기준이다.
- **FR-003**: 목록은 확정한 커밋의 파일 트리 전체에서 일반 파일만 대상으로 하고, 자료원 설정의 포함·제외 패턴을 저장소 안 경로에 적용한다(QK-ING-001 FR-012).
  하위 모듈, 심볼릭 링크, 디렉터리는 넣지 않는다.
- **FR-004**: 목록 항목마다 다음 값을 채운다. 원본 식별자와 위치는 저장소 안 경로, 변경 판별값은 파일 내용 식별값(blob SHA, 원본 버전 종류),
  원본 버전은 확정한 커밋, 크기는 원본이 준 파일 크기, 원본 링크는 공개 원본 링크 호스트의 확정 커밋·경로 주소다. 제목은 비운다(본문에서 정하는 일은 청커 몫이다).
- **FR-005**: 원본이 파일 트리가 잘렸다고 알리거나, 트리를 끝까지 받지 못했으면 목록을 "불완전"으로 표시한다(QK-ING-001 FR-005).
  불완전한 목록에서 빠진 파일은 지운 파일로 보지 않게 하는 것이 목적이다.
- **FR-006**: 같은 원본, 같은 커밋, 같은 설정이면 목록 결과(항목, 순서, 변경 판별값)가 같다(C-07).

**본문 조회 (US2)**

- **FR-007**: 본문은 목록 항목의 내용 식별값으로 확정한 커밋의 그 파일 내용을 받는다. 받은 내용이 내용 식별값과 맞지 않으면 그 자료는
  "응답 형식 오류"(영구 실패)다.
- **FR-008**: 본문은 UTF-8 텍스트로 읽고, 읽을 수 없으면 "응답 형식 오류"다. 내용 형식은 경로 확장자로 정한다(Markdown 확장자는 Markdown, 그 밖은 QK-ING-001 형식 목록 기준).
- **FR-009**: 본문 결과의 내용 해시는 QK-ING-001 가짜 어댑터와 같은 계산으로 채운다. 두 어댑터가 같은 본문에 다른 해시를 내지 않게 계산을 한 곳에 둔다
  (QK-ING-001 T053 후속 메모 1).

**원본 권한 정보 (US2, QK-SEC-001 인계)**

- **FR-010**: 실행마다 저장소의 공개 범위를 원본에서 한 번 받아, 그 실행의 모든 항목 원본 권한 정보에 공개 범위 한 값만 원값 그대로 담는다
  (QK-SEC-001 research R-05의 `visibility` 키). 공개 범위를 받지 못하면 권한 정보는 "미확인"이다. 수집기는 접근 범위를 판정하지 않는다.
- **FR-011**: 원본 식별자에는 저장소 안 경로만 쓰고, 저장소 이름·주소·토큰을 넣지 않는다. 원본 링크의 호스트는 QK-SEC-001에 등록된 공개 원본 링크 호스트다
  (QK-SEC-001 FR-023, plan 인계 항목).

**한도와 실패 분류 (US3, QK-ING-001 인계)**

- **FR-012**: 거부 응답 중 남은 호출 수가 0이라고 알리거나 다시 시도할 시각·대기 초를 알리는 응답은 일시적 실패(호출 한도 초과)로 분류한다.
  그 밖의 거부 응답은 영구 실패(접근 거부)다(QK-ING-001 research 재시도 분류 표의 GitHub 예외).
- **FR-013**: 응답이 알려 주는 남은 호출 수와 초기화 시각, 다시 시도할 시각을 QK-ING-001 한도 동작에 넘긴다. 설정 한도와 원본 한도 중 더 엄격한 쪽을 지킨다(QK-ING-001 FR-015).
- **FR-014**: 저장소·브랜치가 없다는 응답은 목록 조회의 영구 실패(자료 없음)이고, 목록은 "불완전"이다. 인증 실패는 QK-ING-001 FR-020을 따른다.

**전송 (US1~US3)**

- **FR-015**: 실제 원본 요청은 HTTPS로 자료원 설정의 요청 허용 호스트에만 보낸다. 인증은 QK-FND-001 설정 항목 이름(`GITHUB_API_TOKEN`)으로 가리킨 값을 쓰고,
  토큰·요청 헤더·응답 본문을 결과와 로그에 남기지 않는다(QK-ING-001 FR-021, AGENTS.md 6절).
- **FR-016**: 실제 전송과 재생 전송은 같은 전송 경계로 바꿔 끼울 수 있다. 기본 검증의 시험은 재생 전송만 쓰고 실제 원본을 호출하지 않는다.
  실제 원본을 부르는 시험은 외부 호출 시험으로 따로 두고 사람이 실행한다(AGENTS.md 7절).
- **FR-017**: GitHub 어댑터는 QK-ING-001 공통 계약 테스트를 통과한다. 공통 계약 테스트가 가짜 어댑터 고유 값을 가정하는 부분은 어댑터별 기대값을 받게 바꾼다
  (QK-ING-001 T053 후속 메모 2). 계약 테스트가 확인하는 동작 자체는 줄이지 않는다.

**자료원 등록과 사람 확인 (US4, QK-SEC-001 FR-024 인계)**

- **FR-018**: 첫 실제 자료원으로 `dnd-side-project/dnd-15th-2-backend`의 `main` 브랜치를 자료원 설정에 등록한다. 포함 패턴은 0.2 인벤토리 1.2절에서
  "포함"으로 표시한 Phase 1 문서 범주(루트 문서, ADR, 제품 설계·데이터 모델, API 규약, 하네스, 계획·명세, 인프라 문서, 기타 문서)로 시작하고,
  "결정 필요"·"제외" 범주는 넣지 않는다(C-04).
- **FR-019**: 포함 패턴에 확장자가 있으면 그 확장자가 QK-SEC-001 파일 확장자 목록에 있어야 한다. 없으면 설정 검증이 실패하고 원본을 호출하지 않는다
  (QK-SEC-001 research R-07).
- **FR-020**: 자료원을 추가하거나 수집 범위(저장소, 브랜치, 포함 패턴)를 넓히는 변경은 사람이 그 범위에 개인 정보(이름, 연락처, 계정 정보)가 없음을
  확인한 기록과 함께 한다. 기록에는 자료원 이름, 확인한 수집 범위, 확인 날짜, 확인한 사람의 역할, 확인 방법(살펴본 경로·표본 수), 결과,
  제외 패턴으로 옮긴 경로와 이유를 담는다. 기록에 사람 이름이나 연락처는 쓰지 않는다.
  기록은 자료원마다 한 파일로 저장소의 설정 디렉터리(`config/`) 아래에 두고 PR로 검토한다. 수집 전 검증은 활성 자료원마다 확인 기록이 있는지,
  기록된 수집 범위(저장소, 브랜치, 포함·제외 패턴)가 현재 자료원 설정과 같은지 확인하고, 없거나 다르면 원본 호출 없이 실패한다(2026-10-20 사용자 결정).
  제외 패턴만 더하는 변경은 범위를 좁히므로 새 확인이 필요 없지만, 기록된 범위는 현재 설정에 맞게 고친다. 파일 이름과 형식은 plan에서 정한다.
- **FR-021**: 확인에서 개인 정보가 나온 경로는 자료원 설정의 제외 패턴으로 뺀다. 보안 필터는 그 제외를 기본 제외와 같이 지킨다(QK-SEC-001 FR-007).
- **FR-022**: 첫 실제 색인 전에 사람이 실제 대상 저장소를 외부 호출 시험으로 한 번 수집하고, 요청 수, 소요 시간, 파일 수, 총 바이트, 가장 큰 파일 크기,
  보안 필터 판정 결과별·규칙별 건수를 측정 조건(대상 커밋, 포함·제외 패턴, 실행 환경, 날짜)과 함께 기록한다(C-13). 식별자 주소 규칙으로 막힌 자료가 있으면
  경로와 이유를 기록한다. 기록에는 비공개 원문과 토큰을 넣지 않는다.
- **FR-023**: QK-ING-001 기본 한도값(분당 요청 수, 실행당 요청 수, 최대 본문 크기, 최대 소요 시간)을 FR-022 측정으로 다시 보고, 유지하거나 바꾼 값과 근거를 남긴다.

**경계 (트리 비교)**

- **FR-024**: 이 명세의 "트리 비교"는 한 커밋 기준의 완전한 파일 목록과 파일별 내용 식별값을 만드는 데까지다. 이전 실행 결과와 비교해 바뀐 파일·지운 파일을
  판정하고 반영하는 일은 QK-SYN-001이 한다(QK-ING-001 명세 범위). 수집기는 이전 실행 상태를 저장하거나 읽지 않는다.
  QK-SYN-001이 "커밋이 같으면 비교를 건너뛴다" 같은 판단을 할 수 있도록 항목마다 확정한 커밋을 남긴다(FR-004).

### Key Entities

- **GitHub 자료원 설정**: QK-ING-001 자료원 설정 중 종류가 `github_repo_files`인 것. 수집 범위에 저장소(`소유자/이름`), 브랜치·태그·커밋, 포함·제외 패턴이 있다.
- **확정 커밋**: 한 실행이 목록과 본문을 받는 기준 커밋. 모든 항목의 원본 버전이다.
- **파일 항목**: QK-ING-001 자료 목록 항목. 원본 식별자·위치는 저장소 안 경로, 변경 판별값은 내용 식별값(blob SHA), 원본 권한 정보는 저장소 공개 범위.
- **개인 정보 확인 기록**: 자료원마다 한 파일. 자료원 이름, 확인한 수집 범위, 날짜, 확인한 사람의 역할, 확인 방법, 결과, 제외로 옮긴 경로와 이유.
  수집 전 검증이 기록된 범위와 현재 자료원 설정을 대조한다.
- **수집 측정 기록**: 대상 커밋, 포함·제외 패턴, 실행 환경, 날짜, 요청 수, 소요 시간, 파일 수, 총 바이트, 가장 큰 파일 크기, 보안 판정 건수, 막힌 자료와 이유.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 재생 응답 시험에서 목록이 기대한 파일 목록과 정확히 같다. 누락·중복·제외 경로·하위 모듈·심볼릭 링크 항목이 0건이다.
- **SC-002**: 한 실행 안의 모든 항목과 본문이 같은 확정 커밋을 가리키고, 같은 응답으로 두 번 돌린 목록 결과가 같다.
- **SC-003**: 트리가 잘렸거나 브랜치가 없는 응답 시험에서 "완전"으로 표시된 목록이 0건이다.
- **SC-004**: 본문 내용이 내용 식별값과 다른 사례, UTF-8이 아닌 사례가 모두 해당 자료만 "응답 형식 오류"로 기록되고, 나머지 자료는 100% 처리된다.
- **SC-005**: 공개·비공개·내부·정보 없음 네 가지 저장소 사례에서 보안 필터 판정이 QK-SEC-001 FR-017과 100% 일치하고, "팀 공용"이 아닌 사례의 본문 추가 조회가 0건이다.
- **SC-006**: 한도 초과를 알리는 거부 응답은 100% 일시적 실패로, 한도 정보가 없는 거부 응답은 100% 영구 실패로 분류되고 그 재시도는 0회다.
- **SC-007**: GitHub 어댑터가 QK-ING-001 공통 계약 테스트를 전부 통과하고, 기본 검증 전체에서 실제 원본 호출과 원본 쓰기 요청이 0건이다.
- **SC-008**: 확장자 목록 밖 포함 패턴, 확인 기록 없는 범위 확장 사례가 모두 원본 호출 0건으로 검증에서 실패한다.
- **SC-009**: 첫 실제 수집 측정 기록이 FR-022 항목을 모두 갖고, 그 실행의 요청 수가 자료원 설정의 실행당 한도 이하다. 식별자 주소 규칙으로 막힌 자료는 모두 이유가 적혀 있다.
- **SC-010**: 수집 결과, 로그, 측정 기록, 확인 기록에서 토큰이나 비밀값 패턴이 발견된 사례가 0건이다(`scripts/preflight.py` 규칙 기준).
