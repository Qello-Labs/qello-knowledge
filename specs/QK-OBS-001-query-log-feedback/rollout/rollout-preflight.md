## 0008 미적용 상태의 최신 main 예약 동기화 영향

**코드 판독에 따른 추론: 0008 미적용 자체가 `qk-sync`의 동기화를 막는 의존성은 발견하지 못했다. 실제 성공 여부는 미확인이다.**

- 운영 문서의 예약 스크립트는 최신 `origin/main` 갱신·잠금 설치 뒤 `qk-index run` 및 실행 이력 정리를 호출한다. `qk-migrate`를 자동 호출하지 않는다(`docs/ops/oci-production-store.md:56`, `:57`, `:58`, `:61`). 실제 설치된 스크립트와 실행 상태는 별도 확인 대상이다.
- CLI는 `queries`일 때만 질의 로그 관리 경로로 분기하고, `run`은 `run_command`로 간다(`src/qello_knowledge/indexer/cli.py:55`, `:84`). 동기화 조립은 기존 본문·동기화·사용량 저장소를 쓴다(`indexer/sync_cli.py:186`, `:199`).
- 실행은 index 설정을 검사한다(`indexer/sync_cli.py:299`). 기록 기능의 보존 날짜 필수·시간 비교 검사는 query 진입점에만 적용된다(`config/check.py:229`). index가 보존 날짜를 명시한다면 형식 검사나 만료 경고는 별개로 있을 수 있다.
- 동기화 DB 접근은 기존 `index_version`, `artifact`, `sync_source`, `sync_run`·`sync_run_source` 등을 쓴다(`src/qello_knowledge/adapters/postgres/sync_store.py:58`, `:73`, `:85`, `:92`). 0008은 별도 질의 기록 표와 함수만 추가하며 기존 동기화 스키마를 바꾸지 않는다(`adapters/postgres/migrations/0008_query_log.sql:1`, `:29`, `:35`, `:41`, `:48`, `:162`). 동기화 경로에는 0008 적용 여부를 요구하는 검사나 기록 함수 호출이 없다.
- 단, 이 비교 구간의 **다른 변화**는 영향을 줄 수 있다. 켜진 Confluence 자료원의 인증 누락은 실행을 막고(`indexer/sync_cli.py:306`), 등록 이력을 포함한 Confluence 인덱스 버전이 대응표에 없으면 원본 호출 전에 멈춘다(`:339`). 메타데이터 버전은 Confluence 켜짐에 따라 달라지고(`sync/keys.py:33`), 활성 버전과 설정 버전 불일치는 처리 보류를 만든다(`sync/run.py:93`). 이런 조건을 0008 누락 문제와 혼동하면 안 된다. 실제 운영 자료원·등록 이력은 조회하지 않았다.

반면 새 query 릴리스의 `/sources`는 기록 기능 꺼짐과 관계없이 앞 기록 경로를 통해 `sources_summary()`를 호출한다(`src/qello_knowledge/query/app.py:157`, `adapters/postgres/query_log.py:122`). 그 함수는 0008에 있다(`migrations/0008_query_log.sql:162`). **꺼짐 배포만으로 `/sources`의 DB 의존성을 피할 수 없으므로 0008 적용·권한 확인을 먼저 한다.** 기록 기능을 먼저 켜면 기록 함수도 없어 실패할 수 있다.

## 문서 차이·미결 사항: 원문은 수정하지 않음

1. OBS-QS 3절 2번은 0008을 “코드 병합 전” 적용하도록 하나 #89는 이미 병합됐고 DB 최신은 7이다(ISSUE-96). 과거 순서를 충족했다고 기록할 수 없다. 위 순서는 남은 운영 배포 전에 적용·확인하는 준비안이며, 0008 지연 적용 순서는 2026-11-04 사용자가 수용했다. 예약 동기화 상태 확인과 H02 운영 명령별 승인은 남아 있다.
2. ADR-016 Decision 첫 문단의 “질문과 답변 원문”·메타데이터 “항상”은 뒤의 2026-10-29 갱신(질문만) 및 OBS-SPEC FR-003·024(켜짐에서만 기록)과 문구가 다르다. 공지 초안은 갱신·명세를 기준으로 썼다. ADR-016은 2026-11-04 사용자가 승인했다. ADR-016 파일 반영은 오케스트레이터 담당이며 이 실행 에이전트는 수정하지 않는다.
3. 동의 전 메모리 대기를 C-10의 저장으로 보지 않는 해석은 2026-11-04 사용자가 수용했다. OBS-QS가 요구하는 운영 메모리 보호 확인과 H02 명령별 승인은 남아 있다.

준비 문서의 preflight와 diff 검사는 실행 에이전트 세션에서 차단됐고 오케스트레이터 재실행으로 통과했다. 운영 검증·평가·Worker 배포·명령 등록은 미실행이다. 독립 재검토와 운영 명령별 승인은 남아 있다.

독립 재검토는 남아 있으며 별도 검토자가 실제 네 파일과 검증 출력을 확인한다. 완료된 사람 결정(2026-11-04 사용자): 계약·주간 계획 합의, ADR-016 승인과 메모리 대기의 C-10 해석 수용, 0008 지연 적용 순서 수용, 운영 배포일·시작일 2026-11-04와 보존 상한 2026-12-04(UTC). 남은 항목: Confluence·Discord 게시 링크·날짜 기록, 서버 관리 권한 전체 명단, H02 운영 명령별 승인, H03 비용 승인. 서버 소유자 tkv00 확인은 전체 권한 명단 확인을 뜻하지 않는다. 향후 백업 도입 시 문서 수정·재공지 방침도 기존 사람 확인 항목으로 유지한다. 게시본의 운영 담당자 멘션은 placeholder로 유지하고 배포 커밋은 H02 명령 승인 시 확인한다. 운영 명령 승인이 끝난 것은 아니며 이 문서로 #96·Jira 완료나 H01~H03 통과를 선언하지 않는다.
