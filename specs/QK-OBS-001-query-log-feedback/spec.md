## Clarifications

### Session 2026-10-29

- Q: 원문 저장 동의를 어떻게 받나? → A: 질문자가 자기 답변에 👎를 누를 때 "질문을 개선용으로 저장할까요?"를 묻고 동의한 질의만 저장한다. 👍 사례와 다른 사람이 누른 👎에는 묻지 않는다(US3, FR-011).
- Q: `/sources`가 무엇을 보여 주나? → A: 지금 검색할 수 있는 자료원 목록(이름·종류, 마지막 수집 시각, 문서 수)과 활성 인덱스 버전이다. 직전 답변의 출처 상세는 보여 주지 않는다(US5, FR-016).
- Q: 저장한 원문의 보존 기간은? → A: Phase 2 완료 리뷰(2.G)까지 보존하고, 그때 사람이 연장·삭제를 정한다(FR-013).
- Q: (독립 검토 H2) 답변 본문에는 비공개 팀 문서(Confluence 등) 내용이 인용된다. AGENTS.md 6절은 비공개 문서 원문을 질의 로그·평가 세트에 남기지 못하게 한다. 무엇을 저장하나? → A: 원문 기록에는
  질문만 저장한다. 답변은 근거 청크 식별자와 인덱스 버전으로 따라가고, 답변 본문은 저장하지 않는다(FR-011).
- Q: (독립 검토 M3) 동의 전 질문을 메모리에 얼마나 두나? → A: 1시간이다. 답변 본문은 두지 않는다(FR-011).
- Q: (plan 검토 M1) `/sources` 목록이 메시지 한도를 넘으면? → A: 나누지 않고 줄 단위로 자르고 남은 자료원 수를 보인다. 지금 자료원 수로는 일어나지 않는다(FR-017, 2026-10-29 spec 변경 승인).
- Q: (plan 검토 H1) 커밋 직후 반환만 늦으면 "상한 초과 시 저장 0건"(SC-004)을 보장할 수 없다. → A: SC-004를 "부분 저장 없음, 결과를 확정하지 못하면 '저장 여부를 확인하지 못했습니다. 다시 눌러 주세요.', 다시 눌러도 평가·원문은 하나"로 바꾼다
  (FR-008, US2-7, SC-004, 2026-10-29 spec 변경 승인).
- Q: (독립 검토 M5) "2.G까지"는 날짜가 없어 늘어질 수 있다. 상한을 어떻게 두나? → A: 날짜 상한을 함께 둔다. 동의 문구에 "2.G까지, 늦어도 <날짜>"를 적고, 날짜가 지나면 동의 묻기를 멈추고
  운영 담당자에게 삭제를 알린다(FR-013).

## User Scenarios & Testing *(mandatory)*

이 명세의 사용자는 Discord에서 질문하고 답을 평가하는 팀원(질문자·평가자), 질의 기록을 읽어 파일럿 보고서와 골든셋 후보를 만드는 운영 담당자, 자기 기록 삭제를 요청하는 팀원,
PR 리뷰어다.

용어:

- **질의 기록**: `/ask` 하나에 남는 메타데이터 한 건. 질문 원문과 답변 본문은 담지 않는다. 운영 로그(QK-BOT-001 FR-021, 실행 환경 로그의 한 줄 JSON)와 다른, 저장소에 쌓이는 기록이다.
- **원문 기록**: 질의 기록에 딸린 질문 원문. 질문자가 동의한 질의만 있다. 답변 본문은 저장하지 않는다.
- **피드백**: 답변 메시지에 붙은 👍/👎 버튼을 누른 결과. 한 평가자가 한 질의에 하나를 가진다.
- **저장 동의**: 질문자가 자기 답변에 👎를 누른 뒤 [저장 동의]를 고른 표시. 질의마다 따로다.
- **원문 대기**: 동의를 받을 수 있게 질의 서비스가 질문 원문을 메모리에만 잠시(초기값 1시간) 들고 있는 것. 저장소·파일·로그에 쓰지 않는다(FR-011).
- **보존 상한 날짜**: 원문 기록 보존의 날짜 상한. 운영 설정이며 동의 문구에 함께 보인다(FR-013).
- **기록 기능 켜짐**: 질의 기록·피드백·원문 저장을 켠 설정. 기본은 꺼짐이다(FR-024).
- **집계 보고**: 운영 담당자가 기간을 정해 뽑는 원문 없는 수치 요약(건수, 상태 분포, 지연 p50·p95, 👍/👎 수).

### User Story 1 - 모든 `/ask`가 원문 없는 질의 기록으로 남는다 (Priority: P1)

팀원이 `/ask`를 실행하면 결과가 답변이든 안내든 실패든 질의 기록이 한 건 남는다. 기록에는 언제, 어떤 결과 상태로, 얼마나 걸렸고, 어떤 청크(인덱스 버전)를 근거로 썼고, 토큰·Neurons를
얼마나 썼는지가 있다. 질문 원문과 답변 본문은 없다.

**Why this priority**: 로드맵 2.G 완료 조건 "파일럿 기간 질의 로그와 피드백이 쌓였다"와 "답변 지연 p95가 측정됐다(NFR-02)"의 입력이다. ADR-016 결정 "질의 메타데이터는 항상 저장한다"이다.
QK-BOT-001 FR-021이 질의 로그 저장을 이 명세로 넘겼다.

**Independent Test**: 가짜 검색·생성 제공자와 로컬 데이터베이스로 FR-002 표의 상태를 하나씩 만들고, 저장된 질의 기록과 기록이 생기지 않아야 하는 경우를 본다.

**Acceptance Scenarios**:

1. **Given** 허용 범위 안의 `/ask`가 답변으로 끝남, **When** 처리가 끝난다, **Then** 질의 기록 한 건에 FR-001의 항목이 있다.
2. **Given** 같은 질의, **When** 질의 기록을 본다, **Then** 질문 원문, 답변 본문, 청크 본문, 출처 제목·링크, 사용자 이름, 채널·서버 식별자가 기록에 없다.
3. **Given** 검색 실패·생성 실패·질의 마감 초과·시작 확인 없음·전달 실패로 끝난 `/ask`, **When** 처리가 끝난다, **Then** 해당 상태가 있는 질의 기록이 한 건 남는다.
4. **Given** 비밀값 규칙에 걸려 처리 중 응답 전에 막힌 `/ask`, **When** 막힌다, **Then** 결과 상태 "비밀값 차단"인 질의 기록이 남고, 원문 기록과 원문 대기는 없다.
5. **Given** 허용 범위 밖 요청, 서명이 틀린 요청, 같은 상호작용의 재전송, **When** 처리한다, **Then** 질의 기록을 남기지 않는다.
6. **Given** 질의 기록 저장이 실패하거나 시간 상한(FR-004)을 넘음, **When** 답변을 보낸다, **Then** 답변은 그대로 사용자에게 가고 버튼도 붙는다. 운영 로그에 기록 실패 종류만 남는다.

### User Story 2 - 답변에 👍/👎를 눌러 평가한다 (Priority: P1)

답변 메시지 끝에 👍과 👎 버튼이 있다. 팀원이 누르면 누른 사람에게만 "평가를 남겼습니다"가 보이고, 그 평가가 질의 기록에 연결된다. 다시 누르면 마지막 선택으로 바뀐다.

**Why this priority**: 2.6 파일럿의 "👎 사례와 실패 유형 분류" 입력이다. 피드백이 없으면 파일럿에서 품질을 잴 방법이 사람이 따로 묻는 것뿐이다.

**Independent Test**: 가짜 버튼 상호작용(서명 포함)을 질의 경로에 넣고 응답 꼴과 저장된 피드백을 본다.

**Acceptance Scenarios**:

1. **Given** 결과 상태가 "답변" 또는 "확인 불가"인 답변 메시지, **When** 표시한다, **Then** 마지막 메시지에만 👍·👎 버튼이 있다. 실패 안내·허용 범위 안내·비밀값 안내·시간 초과 안내에는 버튼이 없다.
2. **Given** 허용 범위 안의 팀원이 👎를 누름, **When** 받는다, **Then** 첫 응답 시간 상한(FR-008) 안에 누른 사람만 보는 확인 응답을 보내고, 질의 기록에 (평가자 식별자, 👎, 시각)이 연결된다.
   채널에 공개되는 새 메시지는 없다. 누른 사람이 질문자이고 원문 대기가 있으면 확인 응답에 저장 동의 질문이 붙는다(US3).
3. **Given** 같은 팀원이 같은 답변에 👍를 다시 누름, **When** 받는다, **Then** 그 팀원의 평가는 👍 하나로 바뀌고 두 건이 되지 않는다.
4. **Given** 질문자가 아닌 팀원이 공개 답변에 버튼을 누름, **When** 받는다, **Then** 평가가 그 팀원의 식별자로 따로 남는다(한 답변에 여러 평가자).
5. **Given** 질의 기록이 없거나(저장 실패, 삭제됨) 알 수 없는 버튼 값, **When** 받는다, **Then** 누른 사람만 보는 "평가를 남기지 못했습니다" 안내를 보내고 아무것도 저장하지 않는다.
6. **Given** 허용 범위 밖(허용 채널 밖, 역할 없음)에서 온 버튼 상호작용, **When** 받는다, **Then** 누른 사람만 보는 허용 범위 안내로 답하고 저장하지 않는다.
7. **Given** 저장소가 느려 첫 응답 시간 상한을 넘음, **When** 받는다, **Then** "저장 여부를 확인하지 못했습니다. 다시 눌러 주세요." 안내로 답하고 부분 저장은 없다. 다시 누르면 결과에 맞는 안내가 나오고 평가는 평가자·질의마다
   하나다(2026-10-29 SC-004 변경).

### User Story 3 - 👎 사례 중 질문자가 동의한 질문만 남는다 (Priority: P1)

질문자가 자기 답변에 👎를 누르면, 평가 확인과 함께 "질문을 개선용으로 저장할까요?"와 [저장 동의]·[저장 안 함] 버튼이 질문자에게만 보인다. 저장 동의를 고른 질의만 질문 원문이 남는다.
고르지 않았거나, 대기 시간이 지났거나, 비밀값 규칙에 걸린 질문은 남지 않는다. 답변 본문은 어떤 경우에도 저장하지 않는다.

**Why this priority**: constitution C-10 "질의 원문은 팀이 동의한 범위와 기간에만 저장한다"와 ADR-016 결정이다. 파일럿에서 👎 사례의 원인을 재현하고 골든셋 후보를 모으려면 질문이 필요하다.
동의 없이 저장하면 C-10을, 답변 본문(비공개 문서 인용)을 저장하면 AGENTS.md 6절을 어긴다.

**Independent Test**: 동의·거절·응답 없음·대기 만료·질의 서비스 재시작·다른 사람의 👎·비밀값·보존 상한 날짜 경과 사례를 가짜 상호작용으로 만들고 원문 기록과 동의 질문 유무를 본다.

**Acceptance Scenarios**:

1. **Given** 👎가 없거나 👍만 있는 질의, **When** 처리가 끝난다, **Then** 질의 기록만 있고 원문 기록은 0건이다. 동의를 묻는 메시지도 없다.
2. **Given** 질문자가 원문 대기가 있는 자기 답변에 👎를 누름, **When** 받는다, **Then** 질문자만 보는 확인 응답에 동의 문구(FR-011)와 [저장 동의]·[저장 안 함] 버튼이 있다.
3. **Given** 2의 응답에서 [저장 동의]를 고름, **When** 받는다, **Then** 원문 기록에 질문 원문, 동의 시각, 동의 방식 "👎 동의"가 있고 질의 기록의 저장 동의가 참이다. 답변 본문은 없다.
4. **Given** 2의 응답에서 [저장 동의] 시도 없이 [저장 안 함]을 고르거나 아무것도 고르지 않음, **When** 대기 시간이 지난다, **Then** 원문 기록은 0건이고 원문 대기의 질문도 사라진다.
5. **Given** 질문자가 아닌 팀원이 공개 답변에 👎를 누름, **When** 받는다, **Then** 평가만 남고 동의를 묻지 않는다.
6. **Given** 대기 시간이 지났거나 질의 서비스가 다시 시작된 뒤 질문자가 👎를 누름, **When** 받는다, **Then** 평가만 남고 동의를 묻지 않는다.
7. **Given** 동의 질문을 받은 뒤 [저장 동의] 시도 없이 대기가 사라진 상태에서 [저장 동의]를 고름, **When** 받는다, **Then** "질문이 남아 있지 않아 저장하지 못했습니다. 평가는 남았습니다."를 질문자에게만 보이고 원문 기록은 0건이다.
8. **Given** 결과가 확정된 선택(저장됨, 저장 안 함, 비밀값 생략) 뒤 동의 질문의 버튼을 다시 누름, **When** 받는다, **Then** 원문 기록이 있으면 "이미 저장된 질문입니다. 지우려면 운영 담당자에게 삭제를 요청해 주세요.", 없으면 "이미 선택했습니다."를 보이고
   원문 기록 수는 바뀌지 않는다(FR-011). 원문 유무 확인 자체가 불명이면 FR-008대로 "저장 여부를 확인하지 못했습니다. 다시 눌러 주세요."다.
9. **Given** 보존 상한 날짜가 지남, **When** 질문자가 👎를 누른다, **Then** 평가만 남고 동의를 묻지 않는다.
10. **Given** [저장 동의]의 결과가 불명("저장 여부를 확인하지 못했습니다. 다시 눌러 주세요."), **When** 대기 시간 안에 [저장 동의]를 다시 누른다, **Then** 저장을 다시 시도하고 결과에 맞는 안내가 나오며 원문 기록은 최대 하나다.
11. **Given** [저장 동의]의 결과가 불명인 뒤, **When** [저장 안 함]을 누르거나 대기가 사라진 뒤(만료, 재시작) 어느 버튼이든 누른다, **Then** 질문자 본인 질의의 원문 기록 유무를 확인해 있으면
    "이미 저장된 질문입니다. 지우려면 운영 담당자에게 삭제를 요청해 주세요.", 없으면 [저장 안 함]은 "저장하지 않았습니다.", [저장 동의]는 "질문이 남아 있지 않아 저장하지 못했습니다. 평가는 남았습니다."를 보인다. 확인도 불명이면 "저장 여부를 확인하지 못했습니다. 다시 눌러 주세요."다.

### User Story 4 - 팀원이 자기 기록을 지울 수 있다 (Priority: P2)

팀원이 자기 질의 원문을 지워 달라고 하면, 운영 담당자가 데이터베이스에 직접 질의하지 않고 명령 하나로 그 팀원의 원문 기록을 모두 지운다. 질의 기록과 피드백은 그 팀원의 식별자를 지운 채 남는다.

**Why this priority**: ADR-016 "삭제 요청 처리"가 이 명세의 수용 기준으로 넘겼다. 파일럿 전에 필요하지만 첫 기록을 쌓는 데는 필요 없어 P2다.

**Independent Test**: 로컬 데이터베이스에 두 팀원의 질의·원문·피드백 기록을 만들고 한 팀원 삭제 명령을 실행한 뒤 남은 기록을 본다.

**Acceptance Scenarios**:

1. **Given** 팀원 A와 B의 원문 기록, **When** A 삭제 명령을 실행한다, **Then** A의 원문 기록은 0건이고 B의 기록은 그대로다.
2. **Given** 같은 명령, **When** 실행이 끝난다, **Then** A의 질의 기록은 남지만 질문자 식별자가 비어 있고, A가 남긴 피드백의 평가자 식별자도 비어 있다. 평가 값(👍/👎)과 수치는 남는다.
3. **Given** 같은 명령을 다시 실행, **When** 끝난다, **Then** 결과가 같고 오류가 없다(멱등).
4. **Given** 삭제 명령, **When** 실행 전, **Then** 지울 건수를 보여 주고 확인 인자 없이는 지우지 않는다. 출력에 원문이나 식별자 값이 없다.
5. **Given** 질의 서비스에 A의 원문 대기가 남아 있음, **When** 삭제를 요청한다, **Then** 운영 절차는 대기 시간(1시간)이 지난 뒤 명령을 실행하거나 질의 서비스를 다시 시작하라고 안내한다(FR-014).

### User Story 5 - `/sources`로 봇이 아는 자료와 그 기준 시각을 본다 (Priority: P2)

팀원이 `/sources`를 실행하면 지금 검색할 수 있는 자료원 목록이 보인다. 자료원마다 이름, 종류(저장소 문서, 코드, Confluence 페이지 등), 마지막 수집 시각(한국 시간), 검색할 수 있는 문서 수가 있고,
맨 위에 활성 인덱스 버전과 활성화 시각이 있다. 답이 오래된 자료에 근거했는지, 찾는 자료가 아직 색인되지 않았는지를 팀원이 스스로 확인한다.

**Why this priority**: 백로그 제목 요소다. C-02(색인을 근거로 쓸 때는 수집 시각을 함께 보여 준다)와 연결된다. 질의 기록이 없어도 쓸 수 있어 P2다.

**Independent Test**: 로컬 데이터베이스에 활성·비활성 인덱스 버전, 여러 자료원의 보이는·숨긴 문서를 넣고 가짜 상호작용으로 `/sources` 응답을 본다.

**Acceptance Scenarios**:

1. **Given** 허용 범위 안의 `/sources`, **When** 받는다, **Then** 첫 응답 시간 상한 안에 질문자만 보는 응답으로 자료원 목록이 보인다.
2. **Given** 활성 인덱스 버전에 보이는 문서가 있는 자료원 둘, **When** 목록을 만든다, **Then** 두 자료원이 이름순으로 나오고 각 문서 수는 검색에서 보이는 문서(C-14 통과)만 센 값이다.
3. **Given** 보이는 문서가 0건인 자료원(비활성, 권한 미확인만, 활성 인덱스에 없음), **When** 목록을 만든다, **Then** 그 자료원은 나오지 않는다. 숨긴 문서의 제목·경로도 나오지 않는다.
4. **Given** 활성 인덱스 버전이 없음, **When** `/sources`를 받는다, **Then** QK-BOT-001 FR-011의 `no_active_index` 안내와 같은 구분의 안내가 질문자에게만 보인다.
5. **Given** 허용 범위 밖의 `/sources`, **When** 받는다, **Then** 질문자만 보는 허용 범위 안내로 답하고 질의 기록은 남기지 않는다.

### User Story 6 - 운영 담당자가 파일럿 수치와 👎 사례를 뽑는다 (Priority: P3)

운영 담당자는 기간을 정해 원문 없는 집계 보고(건수, 결과 상태 분포, 지연 p50·p95, 👍/👎 수, 소비 Neurons)를 뽑는다. 원문 기록이 있는 👎 사례는 질문자·평가자 식별자를 뺀 꼴로 내보내
실패 유형 분류와 골든셋 후보 수집에 쓴다.

**Why this priority**: 로드맵 2.6·2.G(지연 p95, 실패 유형별 개선 목록)의 입력이다. 대시보드는 QK-OBS-002라 여기서는 명령 출력까지만 한다. 기록이 쌓인 뒤에 필요해 P3다.

**Independent Test**: 로컬 데이터베이스에 고정 기록을 넣고 집계·내보내기 출력을 기대값과 비교한다.

**Acceptance Scenarios**:

1. **Given** 기간 안의 질의 기록 N건, **When** 집계 보고를 실행한다, **Then** FR-018 항목이 기간·표본 수·측정 경계와 함께 나온다(C-13).
2. **Given** 같은 보고, **When** 출력을 본다, **Then** 질문 원문·답변 본문·사용자 식별자가 없다.
3. **Given** 원문 기록이 있는 👎 사례, **When** 내보내기를 실행한다, **Then** 질문, 근거 청크 식별자, 인덱스 버전, 평가 값 집계가 나오고 질문자·평가자 식별자와 답변 본문은 없다.
4. **Given** 보존 상한 날짜가 지났고 원문 기록이 남아 있음, **When** 집계 보고나 설정 검사를 실행한다, **Then** 원문 기록 삭제가 필요하다는 경고가 나온다.

### Edge Cases

- 같은 버튼 상호작용이 두 번 들어올 때(Discord 재전송): 평가는 평가자·질의마다 하나라 결과가 같다. 확인 응답도 다시 보내도 된다.
- 답변을 받자마자 버튼을 누를 때: 질의 기록은 답변을 보내기 전에 넣으므로(FR-004) 보통 기록이 있다. 기록 넣기가 실패·초과했으면 US2-5대로 답한다.
- 질의 기록을 지운 뒤(삭제 요청, 보존 정리) 예전 답변의 버튼을 누를 때: 질의 기록이 지워지지는 않으므로(FR-014는 식별자만 비움) 평가는 남는다. 질의 기록 자체가 없으면 US2-5다.
- 삭제 요청 뒤 같은 사람이 예전 답변의 버튼을 다시 누를 때: 새 평가가 그 사람 식별자로 생긴다. 같은 질의에 식별자 없는 옛 평가와 새 평가가 함께 있을 수 있고, 집계 보고는 식별자 없는 평가 수를 따로 보인다.
- 질의 서비스가 다시 시작된 뒤 예전 답변의 버튼을 누를 때: 버튼 값과 저장소만으로 평가를 남긴다. 원문 대기는 사라졌으므로 동의는 묻지 않는다(US3-6).
- "나만 보기" 답변의 버튼: 질문자만 볼 수 있어 질문자만 누른다. 평가·동의 흐름은 공개 답변과 같다.
- 답변이 여러 메시지로 나뉠 때(QK-BOT-001 FR-012): 버튼은 마지막 메시지에만 단다. 버튼 줄이 메시지 수 상한이나 글자 수 한도를 바꾸지 않는다.
- 저장 동의 뒤 마음이 바뀔 때: 삭제 요청(US4)으로 지운다. 동의 뒤 평가를 👍로 바꿔도 원문 기록은 그대로다(동의와 평가는 따로다).
- 질문자가 👎를 여러 번 누를 때: 동의 선택 전이면 동의 질문을 다시 보여도 된다. 이미 골랐으면 US3-8이다.
- 원문 대기가 가득 찰 때(대기 수 상한): 가장 오래된 대기부터 버린다.
- 활성 인덱스 버전이 바뀐 뒤 예전 질의 기록의 근거 청크 식별자: 기록에 인덱스 버전을 같이 남겨 어느 버전의 청크인지 알 수 있다. 청크가 지워져도 기록은 고치지 않는다.
- 근거 청크의 문서가 나중에 보안 숨김(QK-SYN-001 내림)될 때: 질의 기록에는 식별자만 있어 제목·본문이 남지 않는다. 내보내기는 식별자만 내보낸다(FR-019).
- 피드백 버튼을 누른 사람의 표시 이름·별명: 저장하지 않는다. 식별자만 남긴다(ADR-016).

## Requirements *(mandatory)*

### Functional Requirements

**질의 기록 (US1)**

- **FR-001**: 질의 기록의 항목은 아래가 전부다.
  - 질의 실행 식별자(QK-BOT-001 FR-011과 같은 값), 받은 시각(UTC), 질문자 Discord 사용자 식별자(ADR-016), "나만 보기" 여부, 저장 동의 여부, 원문 저장 생략 표시(FR-011)
  - 결과 상태와 실패 종류(FR-002 표), 단계별 시간(처리 중 응답, 검색, 생성, 전달), 단계별 외부 호출 수, 답변 전송 다시 시도 횟수와 전달 실패 종류

  - 생성에 넣은 Context 청크 식별자 목록(넣은 순서대로)과 답변이 인용한 출처 번호 목록, 활성 인덱스 버전, 생성 모델 이름, 프롬프트 버전
  - 질문 유형은 질문 분류(QK-TRK-001) 전에는 없다.
- **FR-002**: 질의 서비스가 받은 `/ask`의 결과마다 기록 여부는 아래와 같다. 질의 기록에는 질문 원문, 답변 본문, 청크 본문, 출처 제목·링크, 사용자 이름·별명, 채널·서버 식별자, 상호작용 토큰,
  서명·자격 정보를 넣지 않는다.

  | 결과 | 질의 기록 |
  | --- | --- |
  | 답변, 확인 불가, 검색 실패·생성 실패 종류, 질의 마감 초과, 시작 확인 없음, 전달 실패, 그 밖의 예상하지 못한 실패 | 남긴다(그 상태로) |
  | 비밀값 차단(QK-BOT-001 FR-006) | 남긴다(상태 "비밀값 차단") |
  | 대기열 가득으로 받아들이지 못함 | 남긴다(상태 "대기열 가득") |
  | 서명 오류, 허용 범위 밖, 지원하지 않는 요청, 같은 상호작용 재전송 | 남기지 않는다 |
  | Worker가 질의 서비스에 닿지 못해 대체 응답한 요청 | 질의 서비스가 받지 못해 남지 않는다. 중계 Worker 운영 로그의 건수로 따로 센다(FR-018) |

- **FR-003**: 질의 기록 저장은 기록 기능 켜짐(FR-024)에서만 한다. 꺼져 있으면 `/ask`의 동작과 운영 로그는 QK-BOT-001과 같다.
- **FR-004**: 답변·안내가 정해지면 보내기 전에 질의 기록을 넣는다. 넣기에는 시간 상한(초기값 1초)을 두고, 실패하거나 넘으면 기다리지 않고 보낸다(이때 버튼은 그대로 붙고 US2-5로 끝난다).
  전달 결과 항목(전달 시간, 다시 시도 횟수, 전달 실패 종류)은 전달 뒤 같은 기록에 갱신한다. 저장 실패는 운영 로그에 실패 종류만 남기고 질의를 다시 돌리지 않는다.
- **FR-005**: 질의 경로 자격(QK-BOT-001 FR-019)에 더하는 저장소 권한은 아래가 전부다. QK-BOT-001 FR-019를 이 범위만큼 넓힌다.
  - 질의 기록 넣기와 정해진 항목(전달 결과, 저장 동의, 원문 저장 생략) 갱신
  - 피드백 넣기와 같은 평가자·질의의 값 갱신
  - 원문 기록 넣기
  - 조회는 좁은 함수로만 한다: 질의 기록이 있는지(참·거짓), 질문자 본인 질의의 원문 기록이 있는지(질문자 식별자가 맞을 때만 참·거짓), `/sources` 목록(FR-016). 질의 기록 표 전체 읽기, 피드백·원문 기록 읽기, 질의 기록·피드백·원문 기록 지우기 권한은 없다.
  - 문서·청크·인덱스 버전·동기화 기록 표의 권한은 바뀌지 않는다.

**피드백 (US2)**

- **FR-006**: 결과 상태가 "답변"(표시 포함)과 "확인 불가"인 답변의 마지막 메시지에 👍·👎 버튼을 단다. 실패 안내, 허용 범위 안내, 비밀값 안내, 시간 초과 안내에는 달지 않는다.
  버튼은 QK-BOT-001 FR-012의 메시지 수 상한과 글자 수 한도 계산을 바꾸지 않는다. 기록 기능이 꺼져 있으면 버튼을 달지 않는다.
- **FR-007**: 버튼 상호작용은 `/ask`와 같은 서명 검사(QK-BOT-001 FR-001)와 허용 범위 판정(QK-BOT-001 FR-004)을 거친다. 통과하면 누른 사람만 보는 확인 응답을 보내고, (질의 실행 식별자, 평가자 식별자,
  값, 처음·마지막 시각)을 저장한다. 같은 평가자의 같은 질의 평가는 하나이며 마지막 값으로 바뀐다. 버튼 상호작용은 검색·생성·Workers AI를 부르지 않는다.
- **FR-008**: 버튼과 `/sources`는 첫 응답 안에서 저장소를 부른다. QK-BOT-001 FR-007의 "처리 중 응답 전에는 저장소 호출을 기다리지 않는다"는 `/ask`에만 적용되고, 이 둘은 예외다.
  저장소 호출에는 첫 응답 시간 상한(초기값 1.5초, 중계 Worker의 첫 응답 제한 시간 2.5초보다 짧게)을 두고, 넘거나 결과를 확정하지 못하면 부분 저장 없이 끝내고 버튼은 "저장 여부를 확인하지 못했습니다. 다시 눌러 주세요.",
  `/sources`는 실패 안내로 답한다. 평가·동의 저장은 다시 눌러도 결과가 같다(평가는 평가자·질의마다 하나, 원문 기록은 질의마다 하나). 설정 검사는 이 상한이 중계 제한 시간보다 짧은지 확인한다.
- **FR-009**: 버튼 값에는 질의 실행 식별자와 동작(👍, 👎, 저장 동의, 저장 안 함)만 넣는다. 값으로 질의 기록을 찾지 못하거나 동작이 틀리면 누른 사람만 보는 "평가를 남기지 못했습니다" 안내로 답하고
  저장하지 않는다. 평가자·질문자 판정은 버튼 값이 아니라 Discord가 상호작용에 실어 보낸 누른 사람 식별자로 한다.
- **FR-010**: QK-BOT-001 FR-003의 "버튼 등 다른 종류의 상호작용은 지원하지 않는 요청"은 이 명세의 버튼과 `/sources`를 뺀 나머지에 그대로 적용된다.
  - 중계 Worker는 이미 PING이 아닌 요청을 모두 질의 서비스로 넘긴다. 바꾸는 것은 Worker가 돌려주는 응답 종류 허용 목록(메시지 고치기 응답이 필요하면 추가)과 대체 응답 문구다.
  - 대체 응답 문구는 상호작용 종류별로 둔다. `/ask`는 지금 문구 그대로, 버튼과 `/sources`는 "지금은 처리할 수 없습니다. 잠시 후 다시 시도해 주세요."다.
  - Worker의 서명 검사·크기 제한·호출 수 상한(QK-BOT-001 FR-016)은 바꾸지 않는다.
  - 허용 범위 안내는 상호작용 종류별 문구를 둔다(`/ask`의 "이 채널에서는 `/ask`를 쓸 수 없습니다."를 버튼과 `/sources`에 그대로 쓰지 않는다).

**원문 저장 동의 (US3)**

- **FR-011**: 원문 기록은 질문자가 동의한 질의의 질문 원문만 저장한다. 답변 본문, 출처 목록, 청크 본문은 저장하지 않는다(2026-10-29 사용자 결정, AGENTS.md 6절).
  - **원문 대기**: 결과 상태가 "답변"·"확인 불가"인 질의는 질문 원문과 질문자 식별자를 질의 서비스 메모리에 둔다. 저장소·파일·운영 로그에 쓰지 않는다. 대기 시간(초기값 1시간)과 대기 수 상한
    (초기값 500)을 넘으면 오래된 것부터 버린다. 질의 서비스가 다시 시작되면 사라진다. 보존 상한 날짜가 지났거나 기록 기능이 꺼져 있으면 대기에 넣지 않는다.
  - **묻기**: 👎를 누른 사람이 그 질의의 원문 대기 질문자와 같고 아직 고르지 않았을 때만 확인 응답에 동의 문구와 [저장 동의]·[저장 안 함] 버튼을 붙인다. 👍, 질문자가 아닌 평가자의 👎,
    대기가 없는 질의에는 묻지 않는다.
  - **동의 문구**: 저장하는 것(이 질문 하나, 답변은 저장하지 않음), 보존 기간("Phase 2 파일럿 검토까지, 늦어도 <보존 상한 날짜>"), 보는 사람(운영 담당자, 파일럿 분석), 평가 세트로 옮기는 사본은
    개인 정보를 지운 별도 사본이라는 점, 삭제 요청 방법을 알린다. 기본값은 "저장 안 함"이다.
  - **선택**: [저장 동의]면 원문 기록(질문 원문, 동의 시각, 동의 방식 "👎 동의")을 넣고 질의 기록의 저장 동의를 참으로 바꾼다. [저장 안 함]이면 저장하지 않는다. 같은 질의의 원문 기록은 하나다.
    동의 버튼은 질문자가 누른 것만 받는다.
  - **결과 확정**: 결과가 확정되면(저장됨, 이미 있음, 저장 안 함, 비밀값 생략, 질의 없음) 대기의 질문을 바로 지우고 확정 사실만 대기 시간 끝까지 남긴다(US3-8).
  - **결과 불명**(FR-008): [저장 동의]의 결과가 불명이면 질문을 지우지 않고 대기 시간 안에 다시 누를 수 있게 둔다(US3-10). 그 뒤 [저장 안 함]을 누르거나 대기가 사라진 뒤 누르면, 질문자 본인 질의의
    원문 기록 유무를 확인해 그대로 안내한다(US3-11). 저장되지 않았다고 단정하지 않는다.
  - 선택 뒤 동의 버튼을 메시지에서 없앨 수 있으면 없앤다(플랫폼 확인은 계획 단계).
- **FR-012**: 저장 직전에 질문을 QK-SEC-001 전송 직전 검사에 다시 넣고, 걸리면 원문 기록을 넣지 않으며 질의 기록에 원문 저장 생략 표시만 남기고, 질문자에게 "비밀값으로 보이는 내용이 있어
  저장하지 않았습니다."를 보인다.
- **FR-013**: 원문 기록은 Phase 2 완료 리뷰(2.G)까지, 늦어도 보존 상한 날짜까지 보존한다(2026-10-29 사용자 결정).
  - 보존 상한 날짜는 운영 설정이며 비워 둘 수 없다. 기록 기능을 켤 때 사람이 정한다.
  - 날짜가 지나면 동의를 묻지 않고(US3-9), 원문 기록이 남아 있으면 집계 보고와 설정 검사가 삭제가 필요하다고 경고한다.
  - 2.G에서 사람이 연장 또는 삭제를 정하고 ADR-016에 기록한다. 연장하면 새 날짜를 팀에 알리고 설정을 바꾼다. 삭제는 원문 기록 전체를 지우는 운영 명령(FR-014와 같은 확인·멱등 규칙,
    질의 기록·피드백은 남김)으로 한다. 날짜로 자동 삭제하지 않는다.

**삭제 요청 (US4)**

- **FR-014**: 운영 명령으로 Discord 사용자 식별자 하나의 원문 기록을 모두 지우고, 그 사용자의 질의 기록 질문자 식별자와 피드백 평가자 식별자를 비운다. 수치·상태·평가 값은 남긴다.
  실행 전 지울 건수만 보여 주고, 확인 인자가 있어야 지운다. 다시 실행해도 결과가 같다. 출력과 운영 로그에 원문과 식별자 값을 남기지 않는다(건수만).
  원문 대기는 메모리에만 있어 이 명령이 지우지 못한다. 운영 절차는 대기 시간이 지난 뒤 실행하거나 질의 서비스를 다시 시작하도록 적는다.
- **FR-015**: 삭제 명령(FR-013 전체 삭제 포함)은 관리 연결로 실행하고, 질의 경로 자격으로는 실행할 수 없다(FR-005). 삭제 실행 사실(시각, 종류, 지운 건수)은 남기되 대상 식별자는 남기지 않는다.

**`/sources` (US5)**

- **FR-016**: `/sources`는 활성 인덱스 버전(식별자, 활성화 시각)과, 그 버전에서 검색에 보이는 문서(C-14 판정 통과)가 1건 이상인 자료원 목록을 이름순으로 보여 준다(2026-10-29 사용자 결정).
  - 자료원마다 이름, 종류, 마지막 수집 시각(한국 시간, C-02), 보이는 문서 수를 보인다. 마지막 수집 시각을 보이는 문서의 가장 최근 수집 시각으로 할지 마지막 성공 동기화 시각으로 할지는 계획
    단계에서 정하고, 동기화 기록을 읽어야 하면 FR-005의 좁은 함수에 넣는다.
  - 문서 제목·경로·링크는 보이지 않는다. 저장소를 읽기만 하고 검색·생성·Workers AI를 부르지 않는다. 활성 인덱스 버전이 없으면 US5-4 안내로 답한다.
- **FR-017**: `/sources`는 `/ask`와 같은 서명 검사·허용 범위 판정을 거치고, 응답은 질문자만 보는 메시지 하나다. 첫 응답 시간 상한(FR-008)을 따른다. 목록이 메시지 하나의 한도를 넘으면 줄 단위로
  앞에서부터 자르고 남은 자료원 수를 "(자료원 N개 더 있음)"으로 보인다. 설정 검사는 등록 자료원 수가 한 메시지를 넘을 수 있으면 경고한다(2026-10-29 사용자 결정, plan 검토 M1). 명령 등록은 QK-BOT-001 FR-022의 등록 명령에 더하고, 다시 실행해도 결과가 같다. `/sources`는 질의 기록을 남기지 않으며 기록 기능 켜짐과 관계없이 쓸 수 있다.

**집계·내보내기 (US6)**

- **FR-018**: 운영 명령으로 기간을 받아 집계 보고를 낸다.
  - 항목: 건수, 결과 상태·실패 종류별 건수, 처리 중 응답 시간과 전달까지 시간의 p50·p95, "나만 보기" 비율, 👍/👎 수, 평가된 질의 비율, 식별자 없는 평가 수, 저장 동의 수, Neurons 합계(측정·추정 구분),
    질의응답 하루 사용량(QK-GEN-001이 넘긴 항목. 운영 화면 표시는 QK-OBS-002).
  - 조건: 기간, 표본 수, 인덱스 버전 분포, 생성 모델·프롬프트 버전 분포, 측정 경계("질의 서비스가 요청을 받은 때부터. Worker 서명 검사·중계 구간 제외")를 함께 낸다(C-13).
    Worker 대체 응답 건수는 질의 기록에 없으므로 중계 Worker 운영 로그에서 따로 센다는 안내를 붙인다.
  - 보존 상한 날짜 경과 경고(FR-013). 원문과 식별자는 없다.
- **FR-019**: 운영 명령으로 원문 기록이 있는 질의를 내보낸다(👎만, 또는 전체).
  - 항목: 질의 실행 식별자, 받은 날짜, 질문, 근거 청크 식별자, 인덱스 버전, 평가 값 집계. 질문자·평가자 식별자, 답변 본문, 출처 제목·링크는 넣지 않는다.
  - 출력은 저장소 밖 파일로만 쓰고 운영 로그에 원문을 남기지 않는다. 출력에 "저장소에 커밋하지 않는다, 평가 세트로 옮길 때 개인 정보와 비공개 문서 원문을 지운다(AGENTS.md 3.4·6절),
    원문 기록을 지울 때(FR-013·FR-014) 이 파일도 지운다"는 안내를 붙인다.

**공통 (전체)**

- **FR-020**: 질의 기록·피드백·원문 기록은 색인 데이터(문서·청크·임베딩·인덱스 버전)와 분리해 둔다. 이 명세의 저장 구조 변경은 인덱스 버전을 바꾸지 않는다(AGENTS.md 3.3).
- **FR-021**: 저장 구조 변경은 다시 실행해도 안전한 마이그레이션으로 하고, 기존 마이그레이션은 고치지 않는다. 운영 반영은 사람이 한다.
- **FR-022**: 기본 검증은 가짜 Discord 수신부, 가짜 검색·생성 제공자, 시험용 서명 키, 로컬 데이터베이스로 외부 호출 0건, 0 Neurons로 돈다(C-12).
- **FR-023**: 이 명세가 더하는 설정(기록 기능 켜짐, 보존 상한 날짜, 원문 대기 시간·대기 수 상한, 질의 기록 넣기 시간 상한, 첫 응답 시간 상한, 동의·확인 문구)은 설정 검사가 형식과 범위를 확인한다.
  기록 기능이 켜져 있는데 보존 상한 날짜가 비었으면 설정 오류다.
- **FR-024**: 기록 기능 켜짐의 기본값은 꺼짐이다. 꺼진 설정에서 `/ask`의 동작과 시험 기대값은 QK-BOT-001과 같다. 운영에서 켜는 일은 팀 공지와 Confluence 동의 문서의 링크·날짜가 ADR-016에
  기록된 뒤 사람이 한다(ADR-016, C-10).

### Key Entities

- **질의 기록(Query Record)**: FR-001 항목. 질의 실행 식별자가 키다. 원문 없음.
- **피드백(Feedback)**: 질의 실행 식별자, 평가자 식별자(삭제 요청 뒤 비어 있을 수 있음), 값(👍/👎), 처음·마지막 시각. 평가자·질의마다 하나.
- **원문 기록(Query Text)**: 질의 실행 식별자, 질문 원문, 동의 시각, 동의 방식("👎 동의"). 질의마다 하나. 답변 본문 없음.
- **원문 대기(Pending Question)**: 질의 실행 식별자, 질문자 식별자, 질문 원문(선택 전까지), 선택 여부, 만료 시각. 질의 서비스 메모리에만 있다(FR-011).
- **자료원 요약(Source Summary)**: `/sources` 한 줄. 자료원 이름, 종류, 마지막 수집 시각, 보이는 문서 수.
- **삭제 실행 기록(Erasure Run)**: 시각, 종류(사용자별, 전체), 지운 원문 수, 비운 질의·피드백 수. 대상 식별자 없음.
- **집계 보고(Usage Report)**: FR-018 항목과 조건.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: FR-002 표의 상태별 `/ask` 시험 전부에서 "남긴다" 행은 질의 기록이 한 건, "남기지 않는다" 행은 0건이다. 예외는 기록 넣기 실패 주입 시험(0건, SC-005)과 질의 서비스 재시작 뒤 같은
  상호작용 재처리 시험(QK-BOT-001 FR-010 예외, 처리된 횟수만큼)이다.
- **SC-002**: 질의 기록·운영 로그·집계 보고·내보내기 시험 전부(실패 주입 포함)에서 FR-002가 금지한 항목(질문 원문은 내보내기 제외, 답변 본문, 청크 본문, 출처 제목·링크, 사용자 이름·별명,
  채널·서버 식별자, 상호작용 토큰, 자격 정보)이 든 사례가 0건이다.
- **SC-003**: 저장 시도가 없었던 동의 시험(👍만, 질문자 👎 뒤 저장 안 함·응답 없음·대기 만료·재시작, 다른 평가자의 👎, 저장 직전 비밀값 검사에 걸림, 보존 상한 날짜 경과) 전부에서 원문 기록이 0건이고, 질문자 👎 뒤
  저장 동의 시험에서는 원문 기록이 정확히 한 건이며 질문 원문과 같다. 결과 불명 시험(커밋 뒤 반환 지연, 문장 취소) 각각에 대해 이어서 [저장 동의] 재시도, [저장 안 함], 만료 뒤 누름, 재시작 뒤 누름을
  했을 때 안내가 실제 원문 기록 유무와 맞고(US3-10·11), 원문 기록은 최대 하나다. 어떤 시험에서도 원문 기록에 답변 본문이 없고, 원문 대기 내용이 저장소·파일·운영 로그에 나온 사례가 0건이다.
- **SC-004**: 버튼 시험(첫 평가, 값 바꾸기, 여러 평가자, 재전송, 없는 질의, 틀린 값, 다른 사람의 동의 버튼, 두 번째 동의 선택, 허용 범위 밖, 첫 응답 시간 상한 초과) 전부에서 평가가 평가자·질의마다
  하나이고, 확인 응답이 누른 사람만 보며, 상한 초과 시험에서 부분 저장이 없고 "저장 여부를 확인하지 못했습니다. 다시 눌러 주세요." 안내가 나오며, 그 뒤 다시 누른 시험에서 결과에 맞는 안내가 나오고
  평가·원문 기록이 각각 하나이며, 채널에 공개되는 새 메시지와 검색·생성 호출이 0건이다(2026-10-29 사용자 결정으로 "상한 초과 시 저장 0건"에서 바꿈. DB 커밋 직후 반환만 늦은 경우 저장 0건을 보장할 수 없다).
- **SC-005**: 질의 기록 넣기 실패·시간 상한 초과 주입 시험에서 사용자가 받는 답변과 버튼이 저장 성공 시험과 같다.
- **SC-006**: 사용자 삭제 시험에서 대상 사용자의 원문 기록이 0건, 질문자·평가자 식별자가 0건이고 다른 사용자 기록과 수치·평가 값은 그대로다. 두 번 실행해도 결과가 같다. 확인 인자 없는 실행은
  지운 건수 0이다. 삭제 실행 기록에 대상 식별자가 없다.
- **SC-007**: 질의 경로 자격으로 질의 기록 표 전체 읽기(질문자 식별자 목록 포함), 피드백·원문 기록 읽기, 세 표의 지우기, 삭제 명령 실행, 색인 표 쓰기를 시도한 시험이 모두 거부되고, FR-005의 넣기·갱신과
  좁은 함수 조회는 성공한다.
- **SC-008**: 전체 삭제 시험(FR-013)에서 원문 기록이 0건이 되고 질의 기록·피드백 건수는 그대로다. 보존 상한 날짜가 지난 설정에서 설정 검사와 집계 보고가 경고를 내고, 동의 질문이 나오지 않는다.
- **SC-009**: 집계 보고 시험에서 고정 기록의 건수·p50·p95·👍/👎 수·식별자 없는 평가 수가 손으로 계산한 기대값과 같고, 측정 경계 문구가 있다.
- **SC-010**: `/sources` 시험(보이는 문서가 있는 자료원, 보이는 문서 0건 자료원, 활성 인덱스 없음, 허용 범위 밖, 첫 응답 시간 상한 초과)에서 목록의 자료원과 문서 수가 기대값과 같고, 숨긴 문서의
  제목·경로와 보이는 문서 0건 자료원의 이름이 응답에 나온 사례가 0건이며, 검색·생성 호출이 0건이다. 등록 명령을 두 번 실행한 시험에서 등록 결과(`/ask`, `/sources`)가 같다.
- **SC-011**: 설정 검사 시험에서 기록 기능 켜짐 + 빈 보존 상한 날짜, 중계 제한 시간 이상인 첫 응답 시간 상한, 범위 밖 대기 시간·대기 수 상한이 모두 거부된다. 기록 기능이 꺼진 설정에서 QK-BOT-001
  시험 기대값이 바뀌지 않고, 버튼이 붙지 않으며, 인덱스 버전이 그대로다.
- **SC-012**: 사람 단계: 팀 공지와 Confluence 동의 문서의 링크·날짜가 ADR-016에 기록되고 보존 상한 날짜를 정한 뒤 기록 기능을 켠다. 운영 반영 뒤 허용 채널에서 `/ask` 3건 이상(질문자 👎 뒤 저장 동의
  1건 이상, "나만 보기" 1건 이상)과 👍·👎, `/sources`를 실행해 질의 기록·피드백·원문 기록이 기대대로 남는지 집계 보고로 확인하고, 날짜·질문 수·인덱스 버전을 함께 기록한다. 소비 Neurons는
  질의 수 × 약 51 이하로 예상량을 먼저 보고한다(AGENTS.md 3.5).

**QK-BOT-001과의 관계** (QK-BOT-001 명세 문서는 고치지 않는다. 이 명세가 아래 범위만큼 바꾼다)

- FR-003(지원하지 않는 상호작용) → 이 명세의 버튼과 `/sources`는 지원한다(FR-010).
- FR-007(처리 중 응답 전 저장소 호출 없음) → 버튼과 `/sources`는 예외다(FR-008).
- FR-019(질의 경로 저장소 권한) → FR-005 범위만큼 넓힌다.
- FR-022(명령 등록) → `/sources`를 더한다(FR-017).
- FR-021(운영 로그)은 바꾸지 않는다. 질의 기록은 운영 로그가 아니다.

**ADR-016과의 관계**

- ADR-016(Proposed)의 결정(메타데이터 항상, 원문은 동의한 건만, Discord 원본 ID, 삭제 경로)을 따르고, 2026-10-29 사용자 결정(👎 때 질문자에게 묻기, 질문만 저장, 2.G까지·날짜 상한, 대기 1시간)을
  ADR-016에 반영한다. 보존 기간을 정해 ADR-016의 C-10 기간 충돌이 풀린다.
- 팀 동의는 Discord 공지와 Confluence 문서로 받는다(ClickUp에서 위치만 정정). 동의 문서가 기록되기 전에는 기록 기능을 켜지 않는다(FR-024).
- 질의 기록에 질문자 식별자를 남기는 것(FR-001)은 ADR-016 결정이고, 질의별 동의가 아니라 팀 동의(공지·문서)를 근거로 한다. 이를 바꾸려면 ADR-016을 다시 정한다.
- 원문 대기(FR-011)는 동의 전 질문을 메모리에만 최대 1시간 두는 것이다. 이를 C-10의 "저장"으로 보지 않는다는 해석은 작성 세션 판단이다(사람 확인 대상). 질의 서비스는 공유 인스턴스(ADR-008)에서
  돌므로, 프로세스 메모리가 파일로 나가지 않게 하는 운영 설정(코어 덤프 끄기 등)은 계획 단계에서 정한다.

**Discord 플랫폼 동작** (계획 단계 research에서 공식 문서로 확인)

- 버튼을 누르면 새 상호작용이 오고, 이것도 3초 안에 첫 응답을 보내야 한다. 버튼이 달린 메시지는 원래 `/ask` 상호작용 토큰(15분)이 끝난 뒤에도 누를 수 있다고 본다 `(일반 설명, 계획 단계에서 확인)`.
- 질문자만 보는 메시지에도 버튼을 달 수 있고, 버튼을 누른 사람의 식별자가 상호작용에 실려 온다고 본다 `(일반 설명, 계획 단계에서 확인)`.
- 버튼 상호작용에 응답하면서 그 메시지의 버튼을 없앨 수 있는지(메시지 고치기 응답)는 계획 단계에서 확인한다(FR-011 마지막 항목).

**비용**

- 질의 기록·피드백·`/sources`·집계·삭제는 Workers AI를 부르지 않는다. 기본 검증과 이 명세 기능의 추가 Neurons는 0이다. 운영 확인(SC-012)의 `/ask`만 기존 질의 비용(약 38~51 Neurons/건)이 든다.
- 저장량: 질문만 저장하고 질의 기록은 원문이 없어 ADR-016 추정(건당 약 2 KB)보다 작다. 운영 저장소 용량에 문제가 없다고 본다.

**범위**

- Grafana 대시보드·알림(QK-OBS-002), 스레드 대화(QK-BOT-002), 사용자별 호출 제한(QK-BOT-001 FR-005의 재판단은 이 명세의 집계 보고를 근거로 사람이 한다), 검색·생성 동작 변경, 골든셋 형식·평가 실행기(QK-EVL-001),
  👎 사례의 실패 유형 분류(2.6 파일럿, 사람), 질문 분류(QK-TRK-001)는 이 명세 밖이다.
- 운영 저장소 마이그레이션 적용, 질의 서비스·중계 Worker 배포, 명령 등록, 동의 공지·문서 작성, 기록 기능 켜기는 이 명세의 산출물로 절차를 쓰고 실제 실행은 사람이 한다.
