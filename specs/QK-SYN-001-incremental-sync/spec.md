# Feature Specification: QK-SYN-001 증분 동기화·문서 단위 원자적 교체·실행 기록·스케줄러·CLI

**Feature Branch**: `feat/SCRUM-102-gh-48-incremental-sync`

**Created**: 2026-10-21

**Status**: Draft

**Input**: 로드맵 4절 명세 백로그 QK-SYN-001 "증분 동기화, 문서 단위 원자적 교체, 실행 기록, 스케줄러, CLI". 선행은 QK-ING-002·QK-CHK-002·QK-EMB-001이다.
백로그 행의 요구사항 ID(FR-SYN-01, 03, 04, 05(CLI), 06)는 원문이 없어(Assumptions 참조) 백로그 제목, constitution C-05·C-07·C-08·C-09·C-10·C-14,
AGENTS.md 3.1·3.3·3.5·4절, ADR-008·ADR-019, 로드맵 1.G 완료 조건, 그리고 이 명세로 일을 넘긴 QK-ING-001·QK-ING-002·QK-SEC-001·QK-CHK-002·QK-EMB-001·QK-STO-001 명세,
첫 실제 수집 측정(`docs/sdd/research/github-source-measurement.md`)을 근거로 썼다.

## User Scenarios & Testing *(mandatory)*

이 명세의 사용자는 색인을 돌리고 결과를 확인하는 운영 담당자, 색인 결과를 검색하는 구현자(QK-RET-001, QK-EVL-001), 이 동기화 위에 자료원을 더할
구현자(QK-ING-003~009), 실패 문서 재시도를 붙일 구현자(QK-SYN-002), PR 리뷰어다. 최종 수혜자는 Discord에서 최신 자료에 근거한 답을 받는 팀원이다.

동기화 실행 하나는 활성 자료원마다 수집(QK-ING-002) → 보안 필터(QK-SEC-001) → 청킹(QK-CHK-002) → 임베딩(QK-EMB-001) → 저장(QK-STO-001)을
잇고, 이전 실행에서 저장한 상태와 비교해 바뀐 문서만 다시 처리한다. 문서마다 새 청크 묶음을 한 번에 바꾸거나 이전 묶음을 그대로 두며,
검색에 나오면 안 되게 된 문서는 내린다. 실행이 끝나면 무엇을 했는지 실행 기록으로 남긴다.

이 명세에서 쓰는 말:

- **처리**: 자료 하나를 보안 필터부터 저장까지 거쳐 새 청크 묶음으로 바꾸는 일.
- **바뀐 문서**: 이전에 저장한 처리 결과와 비교해 다시 처리해야 하는 문서(FR-008).
- **내림**: 저장된 문서를 모든 검색과 문맥 확장 조회에서 빠지게 하는 일(FR-015). 보안 사유(비밀값, 접근 범위, 개인 정보 경로)로 내릴 때는
  그 문서의 청크 본문도 지운다(보안 내림, FR-016).

### User Story 1 - 바뀐 문서만 다시 처리하고, 변경이 없으면 임베딩을 부르지 않는다 (Priority: P1)

운영 담당자가 색인을 돌리면 처음에는 모든 대상 문서가 처리된다. 같은 원본으로 다시 돌리면 아무 문서도 다시 청킹·임베딩되지 않는다.
문서 하나를 고친 뒤 돌리면 그 문서의 청크만 바뀌고 나머지 문서의 청크는 그대로다.

**Why this priority**: 로드맵 1.G 완료 조건 "변경이 없는 재동기화에서 임베딩 호출이 0건", "문서 1개를 고치면 다음 동기화에서 그 문서의 청크만 교체"를
직접 구현한다. 임베딩 무료 한도(C-05, ADR-008)를 매 실행 전체 재임베딩으로 쓰지 않게 하는 근거이기도 하다.

**Independent Test**: 가짜 자료원(QK-ING-001)과 가짜 임베딩 제공자(QK-EMB-001)로 문서 묶음을 한 번 동기화하고, 같은 원본으로 다시 동기화해
외부 임베딩 호출 수와 청크 교체 수를 센다. 문서 하나의 본문 한 줄을 고치고 다시 동기화해 어떤 문서의 청크가 바뀌었는지 본다.

**Acceptance Scenarios**:

1. **Given** 저장된 청크가 없는 상태와 Markdown 문서 5개가 든 가짜 자료원, **When** 동기화한다, **Then** 5개 모두 처리돼 검색할 수 있는 청크가 생기고,
   실행 기록에 처리 5건이 남는다.
2. **Given** 1번 직후, 원본이 그대로인 상태, **When** 다시 동기화한다, **Then** 외부 임베딩 호출 0건, 청크가 바뀐 문서 0개이고 실행 기록에 "변경 없음" 5건이 남는다.
3. **Given** 1번 직후, 문서 B의 본문 한 줄만 고친 원본, **When** 동기화한다, **Then** 청크가 바뀐 문서는 B 하나이고, 나머지 4개 문서의 청크 식별자와 본문은 그대로다.
4. **Given** 원본의 버전 표시(예: 저장소 커밋)는 바뀌었지만 문서 C의 본문은 그대로인 원본, **When** 동기화한다, **Then** C는 "변경 없음"이고 C의 청크는 바뀌지 않는다.
5. **Given** 1번 직후, 새 문서 F가 더해진 원본, **When** 동기화한다, **Then** F만 처리되고 다른 문서는 "변경 없음"이다.
6. **Given** 같은 원본, **When** 동기화를 두 번 연달아 실행한다, **Then** 문서마다 청크 묶음은 하나뿐이고 중복된 청크가 없다(C-08).

### User Story 2 - 문서 하나씩 통째로 바꾸고, 실패한 문서는 이전 청크를 지킨다 (Priority: P1)

문서 하나의 새 청크 묶음은 한 번에 반영되거나 전혀 반영되지 않는다. 청킹·임베딩·저장 중 어디서든 실패한 문서는 이전 청크가 그대로 검색되고,
다른 문서의 처리는 계속된다. 실패한 문서는 다음 실행에서 다시 처리된다.

**Why this priority**: C-08("문서 하나가 실패해도 전체 동기화가 멈추지 않으며, 실패한 문서는 이전 버전을 유지")의 동기화 단계 구현이다.
QK-STO-001이 문서 단위 교체 연산(그 명세 FR-012·013)을, QK-EMB-001이 실패 종류(그 명세 FR-004)를 주지만, 언제 무엇을 교체하고 실패를 어떻게 다룰지는
이 명세가 정한다(QK-STO-001 Assumptions).

**Independent Test**: 가짜 자료원과 가짜 임베딩 제공자로 문서 묶음을 한 번 동기화한 뒤, 일부 문서를 고치고 그 문서에 청킹 실패, 임베딩 실패(입력 한도 초과,
일시 실패, 색인 예산 소진, 전송 직전 비밀값 차단), 저장 실패를 주입해 다시 동기화한다. 실패한 문서의 검색 결과와 다른 문서의 처리 결과를 본다.

**Acceptance Scenarios**:

1. **Given** 처리된 문서 A·B·C에서 A·B를 고치고 B의 청크 하나에 임베딩 "입력 한도 초과"를 주입한 원본, **When** 동기화한다, **Then** A는 새 청크로 바뀌고,
   B는 이전 청크가 그대로 검색되며, C는 "변경 없음"이고, 실행 기록에 B의 실패(단계: 임베딩, 유형: 입력 한도 초과)가 남는다.
2. **Given** 고친 문서 B의 새 청크 중 일부만 임베딩에 성공한 상황, **When** 동기화가 끝난다, **Then** B의 청크는 이전 묶음 그대로이고, 새 묶음의 일부만
   검색에 보이는 순간이 없다. 성공한 벡터는 캐시에 남아 다음 실행에서 외부 호출 없이 쓰인다(QK-EMB-001 FR-011).
3. **Given** 1번 직후 B의 실패 원인을 없앤 상태, **When** 다시 동기화한다, **Then** B만 처리돼 새 청크로 바뀌고 A·C는 "변경 없음"이다.
4. **Given** 고친 문서 B가 청킹 실패(줄 길이 초과)로 돌아오는 원본, **When** 동기화한다, **Then** B는 이전 청크를 유지하고 실패로 기록된다.
5. **Given** 문서 B의 새 청크 묶음을 저장하는 도중 저장소 오류가 나는 상황, **When** 동기화한다, **Then** B는 이전 청크가 그대로 검색되고, 실패로 기록되며,
   다른 문서의 처리는 계속된다.
6. **Given** 한 실행 안에서 색인 예산이 소진되는 상황, **When** 동기화한다, **Then** 예산 소진 뒤 임베딩이 필요한 문서는 처리하지 않고 이전 청크를 유지하며,
   "색인 예산 소진"으로 기록된다. 임베딩이 필요 없는 일(내림, 캐시만으로 끝나는 처리)은 계속된다.

### User Story 3 - 검색에 나오면 안 되게 된 문서는 내린다 (Priority: P1)

원본에서 지운 문서, 원본 권한이 팀 공용이 아니게 된 문서, 비밀값이 새로 걸린 문서, 수집 범위에서 빠진 문서는 다음 동기화에서 검색에서 빠진다.
비밀값·접근 범위·개인 정보 경로 때문에 내린 문서는 청크 본문도 저장소에 남지 않는다. 보안 사유의 검색 제외는 다른 안전장치나 중단 조건에 막히지 않는다.
다만 원본 목록을 끝까지 받지 못한 실행에서는 목록에 없다는 이유로 문서를 내리지 않는다.

**Why this priority**: 로드맵 1.G 완료 조건 "지운 문서는 검색되지 않는다", "접근 범위를 확인할 수 없는 샘플 문서가 검색되지 않는다"와 C-14를 직접 구현한다.
QK-SEC-001(그 명세 Edge Cases·FR-022)과 QK-ING-002(그 명세 Edge Cases), ADR-019(Data and cost)가 "이미 저장된 청크를 내리는 일"을 이 명세로 넘겼다.

**Independent Test**: 가짜 자료원으로 문서 묶음을 동기화한 뒤 원본에서 문서를 지우거나, 원본 권한을 미확인으로 바꾸거나, 비밀값을 심거나,
자료원 설정의 제외 패턴을 더하고 다시 동기화해 로컬 데이터베이스에서 검색한다. 목록을 불완전하게 만든 실행도 같은 방식으로 본다.

**Acceptance Scenarios**:

1. **Given** 처리된 문서 D, **When** 원본에서 D를 지우고 목록이 완전한 동기화를 한다, **Then** 벡터·키워드 검색과 앞뒤 청크 조회에서 D가 나오지 않고,
   실행 기록에 D의 내림(사유: 원본에서 사라짐)이 남는다. D의 청크 정리는 QK-SYN-003이 한다.
2. **Given** 처리된 문서 E, **When** E의 원본 권한 정보가 미확인으로 바뀐 원본으로 동기화한다, **Then** E는 검색에 나오지 않고, 내림 비율 안이거나 확인 옵션을 준 실행이면
   저장소에 E의 청크 본문이 없다(비율을 넘으면 "본문 삭제 대기", FR-017).
3. **Given** 처리된 문서 G, **When** G에 비밀값을 심은 원본으로 동기화한다, **Then** G는 검색에 나오지 않고, 내림 비율 안이거나 확인 옵션을 준 실행이면 저장소에 G의 청크 본문이 없으며,
   실행 기록에는 규칙 이름과 줄 번호만 있고 비밀값은 없다.
4. **Given** 처리된 문서 H, **When** 자료원 설정에 H를 빼는 제외 패턴을 더하고(개인 정보 경로 제외) 동기화한다, **Then** H는 검색에 나오지 않고
   내림 비율 안이거나 확인 옵션을 준 실행이면 저장소에 H의 청크 본문이 없다. 목록이 불완전한 실행에서도 같다.
5. **Given** 보안 내림 근거(설정 제외 패턴 등)가 없는 처리된 문서 D, **When** 목록 조회가 중간에 실패해 목록이 "불완전"인 실행에서 D가 목록에 없다, **Then** D는 내려지지 않고
   이전 청크가 그대로 검색되며,
   실행 기록에 "목록 불완전으로 삭제 판단 안 함"이 남는다.
6. **Given** 내려진 문서 E, **When** E의 원본 권한이 다시 팀 공용이 된 원본으로 동기화한다, **Then** E는 처음부터 다시 처리돼 검색에 나온다(QK-SEC-001 FR-018).
7. **Given** 저장된 문서가 100개인 자료원, **When** 목록에 없다는 이유의 내림 대상이 정해진 비율(FR-017)을 넘는 동기화를 한다(예: 포함 패턴 실수로 목록이 0개),
   **Then** 그 이유의 내림을 하나도 하지 않고, 사람이 확인 옵션을 줘야만 내린다.
8. **Given** 저장된 문서가 모두 검색되는 자료원, **When** 저장소가 비공개로 바뀌어 모든 문서가 접근 범위 보류인 원본으로 확인 옵션 없이 동기화한다, **Then** 모든 문서가
   즉시 검색에서 빠진다. 청크 본문 삭제는 비율 안전장치에 걸려 사람이 확인 옵션을 준 실행에서 한다.
9. **Given** 비밀값을 심은 문서 G, **When** 인덱스 버전 불일치나 예산 초과로 바뀐 문서 처리를 멈추는 실행을 한다, **Then** G는 그 실행에서 검색에서 빠진다.

### User Story 4 - 실행 전에 비용을 보고, 실행 뒤에 무엇을 했는지 안다 (Priority: P2)

운영 담당자는 실제로 임베딩을 부르기 전에 이번 실행이 몇 개 문서를 처리하고 몇 Neurons를 쓸지 미리 본다. 실행이 끝나면 단계별 요약과
실패 목록을 실행 기록으로 확인한다. 실행 기록에는 문서 원문과 비밀값이 없다.

**Why this priority**: AGENTS.md 3.5("무료 한도를 넘길 수 있는 색인은 실행 전에 예상 사용량을 적는다")와 QK-EMB-001 FR-022~024(미리 보기, 예산 초과 시 기본 미실행)를
색인 실행에 잇는다. 첫 실제 색인은 미리 보기 결과를 사람이 보고 승인한 뒤에만 한다. 실행 기록은 C-13(수치에 조건 붙이기)과
QK-SYN-002(실패 문서 재시도), 2.G "정해진 주기로 동기화" 증빙의 바탕이다. 저장 동작 자체는 US1~3이 먼저라 P2로 둔다.

**Independent Test**: 가짜 자료원과 가짜 임베딩 제공자로 미리 보기를 실행해 외부 임베딩 호출과 저장소 쓰기가 0건인지 보고, 같은 상태에서 실제 실행한 결과와
미리 보기 수치를 비교한다. 실패를 주입한 실행의 실행 기록을 자료별 결과와 대조하고, 기록 전체에서 원문·비밀값을 찾는다.

**Acceptance Scenarios**:

1. **Given** 처리된 문서 5개 중 2개를 고치고 1개를 지운 원본, **When** 미리 보기를 실행한다, **Then** 새로 처리할 문서 2, 변경 없음 2, 내릴 문서 1, 임베딩할 청크 수,
   캐시 적중 수, 예상 Neurons와 계산 근거, 오늘 남은 색인 예산, 실행 가능 여부가 나오고, 외부 임베딩 호출과 저장소 쓰기는 0건이다.
2. **Given** 1번과 같은 상태, **When** 미리 보기 직후 원본·저장 상태·설정을 바꾸지 않고 실제로 동기화한다, **Then** 처리 대상·변경 없음·내림 대상 문서 집합이
   미리 보기와 같다. 실패를 주입하지 않았으면 처리 성공 수도 같다(FR-023).
3. **Given** 예상 Neurons가 남은 색인 예산을 넘는 상태, **When** 옵션 없이 동기화한다, **Then** 임베딩과 청크 교체를 하지 않고 "예산 초과로 처리 안 함"을 보고한다.
   보안 내림의 검색 제외와 "변경 없음" 문서의 확인 시각 갱신은 한다(FR-024).
   사람이 예산 안 부분 실행을 명시적으로 고른 경우에만 예산 안에서 처리한다(QK-EMB-001 FR-024).
4. **Given** 실패를 주입한 실행, **When** 실행 기록을 본다, **Then** 실행 식별자, 시작·끝 시각, 시작 방식(수동·예약), 자료원별 원본 버전과 목록 완전 여부,
   수집·필터·청킹·임베딩·저장 단계별 요약, 문서별 결과, 실패 목록(문서, 단계, 실패 유형), 최종 상태가 있고, 요약 수치는 문서별 결과를 센 값과 같다.
5. **Given** 비밀값을 심은 문서와 원문 일부를 오류 메시지로 내는 실패를 주입한 실행, **When** 실행 기록·콘솔 출력·로그 전체를 검사한다, **Then** 문서 원문과 비밀값이 없다.

### User Story 5 - 정해진 주기로 돌고, 명령 하나로 다룬다 (Priority: P2)

색인은 사람이 명령으로 돌릴 수도 있고, 정해진 주기로 자동으로 돌 수도 있다. 자동 실행은 동기화 뒤 사용량 기록 정리(`usage prune`)까지 한다.
같은 자료원에 동기화가 두 개 동시에 돌지 않는다.

**Why this priority**: 백로그 제목의 스케줄러와 CLI다. ADR-008이 색인을 Workers 밖(GitHub Actions 또는 로컬 CLI)에서 돌리기로 했고,
2.G "정해진 주기로 동기화"의 증빙을 그 실행 기록으로 남기기로 했다. 주기 실행은 운영 저장소와 비밀값 설정이 갖춰진 뒤에 켜므로 P2로 둔다.

**Independent Test**: 명령을 로컬 데이터베이스와 가짜 자료원·가짜 임베딩으로 실행해 종료 상태와 출력 형식을 본다. 같은 자료원에 두 실행을 겹쳐 시작한다.
주기 실행 정의는 실제 예약 없이 내용(주기, 실행하는 명령, 비밀값을 쓰는 방식)을 검사한다.

**Acceptance Scenarios**:

1. **Given** 성공한 실행, 일부 문서가 실패한 실행, 실행 전 점검에서 멈춘 실행, **When** 명령의 종료 상태를 본다, **Then** 세 경우가 서로 다른 종료 상태로 구분되고,
   주기 실행은 실패·멈춤을 실패한 실행으로 표시한다.
2. **Given** 같은 자료원에 동기화가 이미 돌고 있는 상태, **When** 두 번째 동기화를 시작한다, **Then** 두 번째 실행은 저장소에 아무것도 쓰지 않고 "이미 실행 중"으로 끝난다.
3. **Given** 로컬이 아닌 저장소를 가리키는 설정, **When** 확인 옵션 없이 동기화를 실행한다, **Then** 원본을 호출하기 전에 멈춘다.
4. **Given** 주기 실행 정의, **When** 내용을 본다, **Then** 정해진 주기와 수동 시작을 모두 지원하고, 동기화 뒤 사용량 기록 정리를 실행하며, 비밀값을 정의 파일에 적지 않고
   실행 환경의 비밀값 저장소에서 읽는다.
5. **Given** 설정 검사·자료원 검사·보안 규칙 검사 중 하나가 실패하는 설정, **When** 동기화를 실행한다, **Then** 원본을 호출하지 않고 멈춘다(QK-ING-001 FR-011).
6. **Given** 활성 인덱스 버전이 없는 저장소에 첫 동기화를 마친 상태, **When** 검색한다, **Then** 결과가 없다(활성 인덱스 없음). 사람이 활성화 명령을 실행한 뒤에는
   그 버전의 청크가 검색된다. 활성 버전이 이미 있거나, 그 버전에 쓴 마지막 실행이 성공이 아니거나, 벡터 없는 청크가 있으면 활성화 명령은 아무것도 바꾸지 않고 거부된다.
7. **Given** 실행 기록이 쌓인 저장소, **When** 실행 기록 조회 명령을 실행한다, **Then** 최근 실행의 최종 상태와 요약, 지정한 실행의 실패 목록을 볼 수 있다.

### Edge Cases

- 첫 실행(저장된 상태가 없음): 모든 대상 문서가 "바뀐 문서"다. 첫 실제 색인은 미리 보기 결과를 사람이 승인한 뒤에만 한다(AGENTS.md 3.5).
  활성 인덱스 버전이 없으면 준비 상태 버전에 쓰고, 사람이 활성화 명령을 실행하기 전까지는 검색되지 않는다(FR-021).
- 원본 버전 표시만 바뀌고 청킹 입력이 같은 문서: "변경 없음"이다. 청크, 처리한 원본 버전, 원본 링크는 그 내용을 처리한 때의 값으로 남고,
  마지막으로 확인한 원본 버전과 시각은 갱신한다(FR-010). 저장소 자체를 옮겨 링크가 다른 저장소를 가리켜야 하는 경우는 자료원 정체성 변경이라 실행 전 점검에서 멈춘다(FR-002).
- 이름을 바꾸거나 옮긴 문서: 옛 위치는 원본에서 사라진 문서로 내리고 새 위치는 새 문서로 처리한다(QK-ING-002 Edge Cases). 본문이 같으면 임베딩 입력이 위치만 다르고,
  검색 헤더에 위치가 들어가므로 다시 임베딩한다(QK-CHK-002 Edge Cases).
- 빈 문서(청크 0개): 실패가 아니다. 이전에 청크가 있었으면 그 청크를 비운다. 그 문서는 검색에 나오지 않는다.
- 청킹 "대상 아님"(Markdown이 아닌 형식): 처리하지 않는다. 이전에 처리된 적이 있으면 내린다(일반 내림). Phase 1 포함 패턴은 Markdown만이라 실제로는 생기지 않는다 `(추론)`.
- 청킹 실패·임베딩 실패·저장 실패: 그 문서는 이전 청크를 유지하고 실패로 기록한다. 다음 실행에서 다시 "바뀐 문서"로 처리된다(FR-012).
- 본문 조회 실패(일시적 실패 재시도 소진, 영구 실패): 그 문서는 이전 청크를 유지한다. 원본이 "자료 없음"이라고 답한 경우도 목록에 있는 한 내리지 않는다.
  조회 실패는 내림의 근거가 아니다. 다만 목록 항목만으로 정해지는 보안 판정(경로 제외, 접근 범위 보류)과 설정 제외 패턴에 따른 보안 내림은 본문 조회와 상관없이 한다(FR-016).
- 한도 때문에 수집이 중간에 멈춘 실행(QK-ING-001 FR-016): 받은 문서까지만 처리하고, 남은 문서는 이전 청크를 유지한다. 목록이 완전했어도 본문을 받지 못한 문서는
  일반 내림을 하지 않는다. 목록 항목만으로 정해지는 보안 내림은 한다(FR-016). 실행 기록에 남은 문서 수와 다시 시도할 수 있는 시각을 남긴다. 다음 실행은 처음부터 다시 돌고, 이미 처리한 문서는 "변경 없음"이 되므로 이어서 하는 것과 같다.
- 인증 실패: 그 자료원의 수집을 멈추고, 그 자료원 문서의 처리와 일반 내림은 하지 않는다. 현재 설정의 제외 패턴만으로 정해지는 보안 내림(FR-016 (2))은 한다.
- 보안 규칙 버전만 바뀐 경우: 모든 대상 문서는 매 실행 현재 규칙으로 다시 판정되므로(FR-005), 새 규칙에 걸린 문서는 내리고 여전히 통과한 문서는 본문이 같으면 "변경 없음"이다.
  보안 규칙 버전 변경은 인덱스 버전 변경이 아니다(QK-SEC-001 FR-022).
- 청킹 규칙 버전이나 임베딩 모델이 바뀌어 현재 설정의 인덱스 버전이 저장된 활성 인덱스 버전과 다른 경우: 문서를 섞어 쓰지 않는다. 바뀐 문서 처리는 하지 않고,
  수집·보안 필터와 보안 내림의 검색 제외만 한다(FR-020).
- 활성 버전이 아직 없는 동안 설정이 바뀐 경우: 새 설정의 준비 상태 버전을 만들고, 저장된 상태의 인덱스 버전이 달라 모든 문서가 "바뀐 문서"로 그 버전에 다시 처리된다(FR-008 (5)).
- 자료원을 비활성화하거나 설정에서 지운 경우: 그 자료원 문서는 모두 일반 내림 대상이고, 내림 비율 안전장치(FR-017)에 걸리므로 사람의 확인 옵션이 있어야 내린다.
- 저장소가 공개에서 비공개로 바뀐 경우: 모든 문서가 "접근 범위 보류"다. 검색 제외는 확인 옵션 없이 즉시 하고, 청크 본문 삭제는 FR-017에 걸려 사람이 확인한 뒤 한다.
- 같은 종류의 자료원을 둘 이상 켜거나, 자료원의 수집 대상(예: 저장소)을 설정에서 바꾼 경우: 저장된 문서를 구분할 수 없으므로 실행 전 점검에서 멈춘다(FR-002).
  자료원을 설정에서 지우거나 끈 경우는 이 검사에 걸리지 않고 일반 내림(FR-016 (5))으로 간다.
- 설정은 그대로인데 원본 저장소가 다른 저장소로 바뀌었거나(같은 이름으로 새로 만듦), 이름을 바꾸거나 옮겨져 수집이 리다이렉트로 따라간 경우: 수집한 뒤 원본이 알려 준
  바뀌지 않는 식별값 또는 이름·위치가 기준값과 다르므로 그 자료원의 처리와 일반 내림을 멈추고 사람이 정한다(FR-002). 보안 내림은 한다. 원본이 정체성을 알려 주지 않을 때도 같다.
- 같은 문서가 목록에 두 번 나온 경우: 수집기가 하나만 남긴다(QK-ING-001 FR-005).
- 실행 도중 프로세스가 끊긴 경우: 끝난 문서는 새 청크와 그 문서의 결과 기록을 함께 가지고, 끝나지 않은 문서는 이전 청크다(FR-013). 실행 기록은 최종 상태 없이 남고,
  다음 실행이 "끝나지 않음"으로 닫는다(FR-027). 다음 실행은 처음부터 다시 돌고 결과는 끊기지 않았을 때와 같다(C-08 멱등).
- 실행 시간이 길어 하루 경계(00:00 UTC)를 넘는 경우: 예산은 호출 시점의 날로 판정한다(QK-EMB-001 FR-018).
- 임베딩 입력이 같은 청크가 여러 문서에 있는 경우: 벡터는 하나를 같이 쓴다(QK-STO-001 FR-003). 한 문서를 내려도 다른 문서의 청크가 쓰는 벡터는 남는다.
- 비밀값: 수집 결과는 항상 보안 필터를 거친다. 필터를 건너뛰는 실행 방식은 없다(QK-SEC-001 FR-001). 임베딩 직전 검사는 QK-EMB-001이 한다.

## Requirements *(mandatory)*

### Functional Requirements

**실행 흐름 (공통)**

- **FR-001**: 동기화 실행 하나는 자료원 설정에서 활성인 자료원마다 수집 → 보안 필터 → 청킹 → 임베딩 → 저장을 순서대로 잇는다. 각 단계는 선행 명세의 동작을 그대로 쓰고,
  단계를 건너뛰거나 단계의 판정을 바꾸는 실행 방식은 두지 않는다.
- **FR-002**: 실행 전 점검으로 설정 검사(QK-FND-001), 자료원 설정 검사와 개인 정보 확인 기록 검사(QK-ING-001 FR-011, QK-ING-002 FR-020), 보안 규칙 검사(QK-SEC-001),
  임베딩 예산 설정 검사(QK-EMB-001 FR-017), 자료원 식별 검사, 원격 저장소 확인(FR-032)과 운영 저장소 정책 확인(FR-033)을 하고, 하나라도 실패하면 원본을 호출하지 않고
  저장소에 쓰지 않고 멈춘다. 자료원 식별 검사는 같은 종류의 자료원이 둘 이상 활성이거나, 활성 자료원과 같은 종류의 문서를 저장한 자료원(이름과 수집 대상, 예: 저장소·브랜치)이
  현재 설정의 그 자료원과 다르면 실패한다. 저장된 문서는 자료원 종류와 원본 식별자로만 구분되기 때문이다(QK-STO-001 FR-001, QK-ING-002 FR-011). 설정에서 지우거나
  끈 자료원은 이 검사 대상이 아니고 일반 내림(FR-016 (5))으로 간다. 수집을 시작한 뒤에도 원본이 알려 준 정체성을 저장된 기준값과 비교한다. 정체성은 원본의 바뀌지 않는
  식별값(원본 자체가 다른 것으로 바뀌었는지 확인)과 현재 이름·위치(출처 링크가 가리키는 곳이 바뀌었는지 확인) 두 가지다. 이를 위해 수집 공통 결과가 자료원 정체성을
  내보내도록 수집 경계(QK-ING-001 공통 형식, QK-ING-002 어댑터)를 넓힌다. 구체 필드는 `plan.md`에서 정한다. 기준값이 없으면 실행 전 점검을 통과하고 원본이 알려 준
  정체성을 받은 뒤, 그 자료원의 첫 저장소 쓰기보다 먼저 또는 그 쓰기와 함께 이번 값을 기준값으로 확정한다. 확정한 기준값은 그 실행이 실패하거나 끊겨도 남는다.
  미리 보기는 기준값을 등록하지 않는다. 둘 중 하나라도 다르거나 원본이 정체성을 알려 주지 않으면 그 자료원의 처리와 일반 내림을 멈추고 보안 내림만 한다. 실패하면 정리 방법을 사람이 정한다. 저장된 자료원 정체성은 실행 기록을 정리해도 남는다.
  자료원별 식별을 저장 스키마에 넣는 일은 이 검사를 풀 때 함께 한다.
- **FR-003**: 동기화는 원본에 쓰지 않는다(C-09). 외부로 보내는 데이터는 수집 요청과 보안 필터·전송 직전 검사를 통과한 임베딩 입력뿐이다.
- **FR-004**: 자료원 하나, 문서 하나의 실패가 같은 실행의 다른 자료원·문서 처리를 멈추지 않는다(C-08). 실행 전체를 멈추는 경우는 실행 전 점검 실패(FR-002),
  동시 실행(FR-029), 저장소 사용 불가뿐이다. 인덱스 버전 불일치(FR-020), 예산 초과(FR-024), 내림 비율 초과(FR-017)는 정해진 처리만 멈추고, 그때도 수집·보안 필터와
  보안 내림의 검색 제외(FR-016)는 한다. 검색에 나오면 안 되는 문서를 내리는 일은 비용·버전·삭제 안전장치보다 앞선다(C-14).

**변경 판단 (US1)**

- **FR-005**: 목록에 있고 경로 제외·접근 범위 판정을 통과한 모든 문서는 매 실행 본문을 받아 현재 보안 규칙으로 판정한다. 그래서 보안 규칙이 바뀌면 다음 실행에서
  모든 문서에 새 규칙이 적용된다. 변경 판단으로 본문 조회를 건너뛰지 않는다(Assumptions 참조).
- **FR-006**: 문서마다 마지막으로 성공한 처리의 결과를 저장된 상태로 둔다. 저장된 상태는 적어도 처리한 원본 버전과 원본 링크, 청킹 입력(본문 내용 해시, 위치,
  원본 제목), 그 처리에 쓴 청킹 규칙 버전과 인덱스 버전, 접근 범위, 처리 결과(청크 있음·빈 문서), 마지막으로 확인한 원본 버전과 시각, 내림 여부와 사유를 담는다.
  원본 식별·위치는 QK-STO-001 원본 자료 항목을 따른다.
- **FR-007**: 저장된 상태는 그 문서의 청크 묶음과 함께 바뀐다. 처리에 실패한 문서는 저장된 상태도 이전 값 그대로다. 그래서 저장된 상태가 가리키는 내용과
  검색되는 청크는 항상 같은 처리의 결과다.
- **FR-008**: 보안 필터를 통과한 문서는 다음 중 하나면 "바뀐 문서"로 처리하고, 아니면 "변경 없음"이다.
  (1) 저장된 상태가 없다(새 문서), (2) 청킹 입력(본문 내용 해시, 위치, 원본 제목) 중 하나가 저장된 값과 다르다(QK-CHK-002 FR-002·FR-017),
  (3) 현재 청킹 규칙 버전이 저장된 값과 다르다, (4) 저장된 문서가 내려진 상태이거나 저장된 접근 범위가 팀 공용이 아니다(FR-015, QK-SEC-001 FR-018 "처음부터 다시 색인"),
  (5) 저장된 상태의 인덱스 버전이 이번 실행이 쓰는 인덱스 버전과 다르다(FR-021).
  원본 버전 표시만 바뀐 것과, 인덱스 버전이 아직 준비 상태라 검색되지 않는 것은 "바뀐 문서"의 조건이 아니다.
- **FR-009**: "변경 없음"인 문서는 청킹·임베딩·청크 교체를 하지 않는다. 그래서 변경 없는 재동기화의 외부 임베딩 호출은 0건이고 청크가 바뀐 문서는 0개다.
- **FR-010**: "변경 없음"인 문서는 청크를 바꾸지 않고, 마지막으로 확인한 원본 버전과 시각만 갱신한다. 처리한 원본 버전과 원본 링크는 청크와 같은 처리의 값으로 남아
  출처 표시(원본 링크·버전·위치)와 청크가 어긋나지 않는다. 마지막 확인 시각은 현재 상태 질문의 근거 시각으로 쓸 수 있다(C-02). 원본 링크가 다른 저장소를
  가리켜야 하는 경우는 자료원 정체성 변경이라 FR-002가 실행 전 점검이나 수집 뒤 비교에서 막는다.
- **FR-011**: "바뀐 문서"는 청킹(QK-CHK-002) → 임베딩(QK-EMB-001, 캐시 우선) → 문서 단위 교체(FR-013) 순서로 처리한다. 청킹 결과가 "빈 문서"면 청크 0개 묶음으로 교체한다.
- **FR-012**: 처리에 실패한 문서는 다음 실행에서 FR-008에 따라 다시 "바뀐 문서"가 된다(저장된 상태가 바뀌지 않았기 때문이다). 이 명세는 실패한 문서만 골라
  다시 돌리는 별도 동작을 두지 않는다. 그것은 QK-SYN-002다.

**문서 단위 원자적 교체 (US2)**

- **FR-013**: 문서 하나의 새 청크 묶음은 그 문서의 모든 청크 임베딩이 준비된 뒤에만 반영한다. 저장된 상태(FR-006), 출처 정보, 청크 묶음(빈 묶음 포함),
  그 문서의 실행 기록 결과(FR-026)는 한 번에 반영되거나 전혀 반영되지 않는다. 반영 도중이나 실패 뒤에 검색에 보이는 것은 이전 묶음뿐이고, 저장된 상태와
  다음 실행의 변경 판단도 이전 그대로다. 현재 저장소 경계는 원본 자료 항목 갱신과 청크 교체를 따로 반영하므로(QK-STO-001 FR-012는 청크 교체만 다룬다),
  이 명세는 저장소 경계에 문서 단위 반영 연산을 더한다. 기존 연산의 동작과 QK-STO-001의 승인된 요구사항은 바꾸지 않는다.
- **FR-014**: 청킹 실패, 임베딩 실패(QK-EMB-001 FR-004의 모든 종류와 전송 직전 비밀값 차단), 저장 실패가 난 문서는 교체하지 않고 이전 청크와 저장된 상태를 유지한다.
  문서 하나의 청크 중 일부만 임베딩에 성공해도 그 문서는 실패다. 이미 만든 벡터는 캐시로 남는다(QK-EMB-001 FR-011).

**내림 (US3)**

- **FR-015**: 내림은 저장된 문서를 모든 검색과 문맥 확장 조회(QK-STO-001 FR-008·FR-011)에서 즉시 빠지게 하는 일이다(검색 제외). 원본 자료 항목은 내린 사유와 함께 남긴다.
  일반 내림은 검색 제외만 하고, 청크·원본 자료 항목의 물리 삭제와 쓰지 않는 벡터 정리는 QK-SYN-003에 맡긴다(QK-STO-001 Edge Cases).
  보안 내림은 검색 제외에 더해 그 문서의 모든 인덱스 버전 청크 본문과 키워드 검색용 텍스트를 저장소에서 지운다. 비밀값이 걸렸거나 팀 공용이 아니게 됐거나 개인 정보
  경로로 뺀 문서의 본문을 저장소에 남기지 않기 위한 예외다(AGENTS.md 3.1, QK-SEC-001 FR-011·FR-018, 2026-10-21 사용자 결정). 보안 내림은 문서 단위로 다음 둘 중
  하나를 한 번에 반영한다. 삭제가 허용되면 검색 제외, 모든 인덱스 버전의 본문 삭제, 결과 기록을 함께 반영한다. 삭제가 보류되면(FR-017) 검색 제외, "본문 삭제 대기" 기록,
  결과 기록을 함께 반영한다. "본문 삭제 대기"는 검색 제외와 따로 두는 기록으로, 그 문서에서 아직 지우지 않은 보안 대상 본문이 남은 인덱스 버전 목록이다. 벡터는 다른 청크가 같이 쓸 수 있으므로 어느 내림에서도 지우지 않는다.
- **FR-016**: 다음 문서는 내린다. 내림 사유를 실행 기록에 남긴다.
  보안 내림: (1) 이번 실행에서 보안 필터가 경로 제외·비밀값 차단·접근 범위 보류로 판정한 문서, (2) 저장된 위치가 현재 자료원 설정의 제외 패턴에 걸리는 문서
  (개인 정보 경로 제외, QK-ING-002 FR-021). 이 둘은 이번 실행의 판정과 현재 설정만으로 정해지므로 목록 완전 여부와 상관없이 적용한다.
  일반 내림: (3) 목록이 완전한 실행에서 목록에 없는 문서(원본에서 사라짐, 포함 패턴에서 빠짐), (4) 청킹 결과가 "대상 아님"인 문서,
  (5) 비활성화되거나 자료원 설정에서 빠진 자료원의 문서.
  목록이 불완전하거나 수집이 중간에 멈춘 실행에서는 (3)을 적용하지 않는다(QK-ING-001 Edge Cases, QK-ING-002 FR-005). 본문 조회 실패와 판정 실패(QK-SEC-001 FR-004)는
  내림 사유가 아니다. 이전 청크를 유지한다.
- **FR-017**: 한 실행에서 한 자료원의 일반 내림 대상 수 또는 본문 삭제 대상 수("본문 삭제 대기" 문서 포함)가 기준 문서 수의 정해진 비율을 넘으면, 그 자료원에서는
  일반 내림과 본문 삭제를 하나도 하지 않고 사람이 확인 옵션을 준 실행에서만 한다. 기준 문서 수는 그 자료원의 저장된 문서 중 일반 내림으로 내려지지 않은 문서 수다
  (보안 검색 제외·삭제 대기 문서 포함). 기준 문서 수가 0이면 대상이 1개 이상일 때 비율을 넘은 것으로 본다. 보안 내림의 검색 제외는 이 안전장치와 상관없이 즉시 한다.
  "본문 삭제 대기"는 다음 목록에 없거나 원본에서 사라져도 남는다. 문서가 다시 보안 필터를 통과해 처음부터 처리되면(FR-018) 그 문서는 현재 인덱스 버전에서 다시 검색되고,
  현재 버전은 새 청크로 바뀌었으므로 대기 목록에서 빠진다. 다른 인덱스 버전에 남은 보안 대상 본문은 대기 목록에 남아 있다가 확인 옵션을 준 실행에서 지울 때만 빠진다.
  그런 본문은 활성이 아닌 버전에만 있어 검색되지 않는다(FR-020·FR-021). 이 "확인 옵션을 준 실행에서만" 규칙은 다시 처리한 뒤 다른 인덱스 버전에 남은 삭제 대기 본문에만
  적용한다. 비율 안에서 하는 첫 보안 삭제(FR-015)와 현재 버전을 다시 처리해 청크를 바꾸는 일은 확인 옵션 없이 한다. 이 안전장치는 포함 패턴 실수, 자료원 설정 오류처럼 사실상 인덱스 전체 삭제가 되는 실행을 막는다(AGENTS.md 4절). 비율의 초기값은 `plan.md`에서 정한다.
- **FR-018**: 내려진 문서가 다시 목록에 나오고 보안 필터를 통과하면 새 문서처럼 처음부터 처리한다(FR-008 (4)).

**인덱스 버전 (US1, US2)**

- **FR-019**: 저장하는 청크는 현재 설정(임베딩 모델 버전, 차원, 청킹 규칙 버전, 메타데이터 스키마 버전)에 해당하는 인덱스 버전 하나에 쓴다. 한 실행 안에서 인덱스 버전이 섞이지 않는다.
- **FR-020**: 활성 인덱스 버전이 있고 현재 설정의 인덱스 버전과 다르면 바뀐 문서 처리(청킹·임베딩·청크 교체)를 하지 않고 "인덱스 버전 불일치"로 보고한다.
  수집·보안 필터와 보안 내림의 검색 제외는 한다(FR-004). 새 인덱스 버전을 만들어 전체를 다시 색인하고
  평가를 거쳐 바꾸는 일은 QK-STO-002다(AGENTS.md 3.3).
- **FR-021**: 활성 인덱스 버전이 하나도 없으면(첫 색인) 동기화는 현재 설정의 인덱스 버전을 준비 상태로 만들고(이미 있으면 그대로 쓴다) 그 버전에 쓴다.
  준비 상태 버전의 청크는 검색되지 않는다(QK-STO-001 FR-008). 동기화는 인덱스 버전을 활성화하지 않는다. 활성화 전에 설정이 바뀌면 새 설정의 준비 상태 버전을 만들고
  FR-008 (5)에 따라 모든 문서를 그 버전에 다시 처리한다. 쓰지 않게 된 준비 상태 버전의 정리는 QK-STO-002다.
  대신 첫 인덱스 버전 활성화 명령을 둔다. 사람이 실행하고, 활성 인덱스 버전이 하나도 없을 때만 지정한 준비 상태 버전을 활성으로 바꾼다. 활성 버전이 이미 있으면
  아무것도 바꾸지 않고 거부한다. 활성 버전을 다른 버전으로 바꾸는 일은 평가 게이트를 거치는 QK-STO-002다. 활성화는 다음을 모두 채울 때만 한다.
  (1) 대상 버전이 현재 설정의 인덱스 버전이다(옛 준비 버전은 출처 정보가 맞지 않을 수 있어 활성화하지 않는다), (2) 그 버전에 쓴 마지막 실행이 "성공"으로 끝났고
  실행 중이거나 끝나지 않은 실행이 없다, (3) 활성화하면 검색될 문서(내려지지 않았고 접근 범위가 팀 공용이며 그 버전의 청크가 있는 문서)가 1개 이상이다,
  (4) 그 버전에 벡터 없는 청크가 0개다. 조건 확인과 활성화 사이에 동기화가 끼어들지 않는다. 조건을 못 채우면 거부하고 이유를 보여 준다. 활성화 전에 그 버전의 문서 수·청크 수·벡터 없는 청크 수와
  마지막 실행 결과를 보여 준다. 첫 버전 활성화는 평가 통과 조건(AGENTS.md 3.3)의 예외로 사용자가 승인했다(2026-10-21 사용자 결정). 첫 검색 평가는
  활성화 뒤 QK-EVL-001이 이 버전으로 한다.

**실행 전 미리 보기와 예산 (US4)**

- **FR-022**: 미리 보기는 실제 실행과 같은 수집·필터·청킹·변경 판단을 하고, 외부 임베딩 호출과 저장소 쓰기를 하지 않는다. 자료원별로 바뀐 문서·변경 없음·보안 내림·일반 내림·
  청킹 단계까지의 실패 문서 수,
  임베딩할 청크 수, QK-EMB-001 미리 보기 결과(새 임베딩·캐시 적중·중복 제거·입력 한도 초과 예상 개수, 예상 Neurons와 계산 근거, 오늘 남은 색인 예산, 실행 가능 여부),
  내림 비율 안전장치 판정을 보여 준다. 원본 수집 요청은 실제 실행과 같은 수만큼 보낸다.
- **FR-023**: 같은 원본·같은 저장 상태·같은 설정에서 미리 보기가 정한 처리 대상·변경 없음·내림 대상 문서 집합은 이어서 실행한 실제 실행이 정한 집합과 같다.
  실제 처리의 성공·실패 수는 임베딩·저장 결과에 달려 있으므로 미리 보기가 보장하지 않는다. 예상 Neurons의 오차 목표는 QK-EMB-001을 따른다.
- **FR-024**: 실제 실행은 임베딩 전에 같은 판단으로 예상 사용량을 계산하고, 남은 색인 예산을 넘으면 임베딩과 청크 교체를 하지 않는다. 보안 내림의 검색 제외와
  "변경 없음" 문서의 확인 시각 갱신은 한다(FR-004). 사람이 명시적으로 고른 경우에만
  예산 안에서 처리할 수 있는 문서까지만 처리하고, 나머지 문서는 이전 청크를 유지한다(QK-EMB-001 FR-024). 예산 판정과 기록은 QK-EMB-001의 규칙을 그대로 쓴다.
- **FR-025**: 실행 중 제공자 할당 소진이나 색인 예산 소진이 나면 그 뒤 임베딩이 필요한 문서는 처리하지 않고 "예산 소진"으로 기록한다. 임베딩이 필요 없는 일(내림,
  모든 청크가 캐시에 있는 문서의 교체, 마지막 확인 시각 갱신)은 계속한다.

**실행 기록 (US4)**

- **FR-026**: 실행마다 실행 기록을 남긴다. 실행 식별자, 시작·끝 시각, 시작 방식(수동·예약), 대상 저장소 구분(로컬·운영), 보안 규칙 버전, 청킹 규칙 버전, 인덱스 버전,
  자료원별 원본 버전·목록 완전 여부·멈춘 이유와 다시 시도할 수 있는 시각, 단계별 요약(QK-ING-001 수집 결과, QK-SEC-001 FR-021, QK-CHK-002 FR-027, QK-EMB-001 FR-015 요약),
  문서별 결과(바뀐 문서 처리 성공·변경 없음·내림과 사유·실패와 단계·유형·건너뜀), 최종 상태(성공, 일부 실패, 멈춤, 끝나지 않음)를 담는다. 요약 수치는 문서별 결과를 센 값과 같다.
- **FR-027**: 실행 기록은 저장소(색인과 같은 데이터베이스)에 남긴다(2026-10-21 사용자 결정). 이를 위해 버전이 붙은 마이그레이션으로 저장 스키마를 더한다
  (QK-STO-001 FR-016~018). 실행 기록 추가는 청크 메타데이터 스키마를 바꾸지 않으므로 인덱스 버전 변경이 아니다. 실행 기록 생성과 이전 기록 정리를 포함한 모든 저장소 쓰기는
  실행 전 점검(FR-002, 원격 저장소 확인과 운영 저장소 정책 확인 포함)과 동시 실행 확인(FR-029)을 통과한 뒤에만 한다. 그 전에 멈춘 실행과 미리 보기는 저장소에 쓰지 않고
  출력만 남긴다. 문서별 결과는 그 문서의 반영과 함께 저장한다(FR-013). 끝날 때 최종 상태로 닫는다. 최종 상태 없이 남은 기록은 같은 자료원의 실행 권한을 얻은 다음 실행이,
  그 기록의 실행이 더 이상 돌고 있지 않음을 확인한 경우에만 "끝나지 않음"으로 닫는다. 다른 자료원의 실행 중인 기록은 건드리지 않는다. 실패 목록은 QK-SYN-002가 실패한 문서를 고르는 데 쓸 수 있게 문서 식별자·단계·유형으로 조회할 수 있다.
  미리 보기는 저장소에 쓰지 않으므로 실행 기록을 남기지 않고 결과만 출력한다(FR-022). 보관 기간과 정리 방법은 `plan.md`에서 정하고, 정리는 재실행해도 안전하다(AGENTS.md 4절).
- **FR-028**: 실행 기록·콘솔 출력·로그에는 문서 원문, 비밀값, 토큰, 접속 주소를 넣지 않는다. 문서 식별자·위치·제목·원본 링크는 QK-SEC-001 기록 출력 규칙(그 명세 FR-023)을 거치고,
  오류는 정해진 유형만 남긴다(AGENTS.md 6절). 실행 기록의 문서 식별은 다시 찾기용 내부 식별값과 출력 규칙을 거친 표시값으로 나눠 둔다. 내부 식별값은 자료원과
  원본 식별자에서 만든 되돌릴 수 없는 값이라, 원본 식별자가 출력 규칙에 걸려 가려진 문서와 아직 저장되지 않은 새 문서도 QK-SYN-002가 다음 목록에서 같은 문서를 찾을 수 있다.

**CLI와 동시 실행 (US5)**

- **FR-029**: 같은 자료원에 대한 동기화(미리 보기 제외)는 동시에 하나만 돌고, 첫 인덱스 버전 활성화(FR-021)는 어떤 동기화와도 동시에 돌지 않는다. 이미 돌고 있으면 새 실행은 저장소에 아무것도 쓰지 않고 "이미 실행 중"으로 끝난다.
  끊긴 실행이 남긴 표시 때문에 다음 실행이 영원히 막히지 않는다.
- **FR-030**: 색인 진입점(`qk-index`)에 동기화 실행, 미리 보기(`qk-index run --preview`), 실행 기록 조회, 첫 인덱스 버전 활성화(FR-021)를 둔다. 기존 하위 명령(`check`, `sources check`, `security check`,
  `usage`, `usage prune`)의 동작은 바꾸지 않는다. 명령과 옵션 이름은 `plan.md`의 계약에서 정한다.
- **FR-031**: 명령은 사람이 읽는 출력과 기계가 읽는 출력(JSON)을 모두 낼 수 있고, 종료 상태로 성공, 일부 실패, 실행 전 점검 실패·멈춤, 저장소 사용 불가를 구분한다.
- **FR-032**: 로컬이 아닌 저장소에 쓰는 실행은 사람이 확인 옵션을 줘야 한다. 없으면 원본을 호출하기 전에 멈춘다(`usage prune --allow-remote`와 같은 방식).
- **FR-033**: 운영 저장소에 실제 팀 자료를 처음 저장하기 전에, 저장소 제공자의 데이터 처리 정책(학습 사용 여부, 보존 기간) 확인 결과가 결정 기록(ADR-008 또는 ADR-019)에
  있어야 한다(ADR-019 2026-10-20 사용자 결정, AGENTS.md 3.1). 확인 전에는 운영 저장소 대상 실행을 하지 않는다. 이 확인과 첫 실제 색인은 사람 단계다.

**스케줄러 (US5)**

- **FR-034**: 정해진 주기로 동기화를 실행하는 주기 실행 정의를 둔다. 실행 위치는 Workers 밖이다(ADR-008). 주기 실행은 동기화 다음에 사용량 기록 정리
  (`qk-index usage prune`, QK-EMB-001 FR-025)를 실행하고, 사람이 수동으로도 시작할 수 있다. 주기의 초기값은 하루 1회이고 `plan.md`에서 시각을 정한다.
- **FR-035**: 주기 실행은 비밀값(원본 토큰, 임베딩 제공자 접속 정보, 저장소 접속 정보)을 정의 파일이나 출력에 적지 않고 실행 환경의 비밀값 저장소에서 읽는다.
  비밀값 이름은 QK-FND-001 설정 항목 이름을 따른다.
- **FR-036**: 주기 실행은 FR-033 확인과 첫 실제 색인 승인이 끝나고, 사람이 비밀값을 등록한 뒤에만 켠다. 그 전에는 정의만 두고 예약 실행이 돌지 않게 한다.
- **FR-037**: 주기 실행이 실패하거나 멈추면 실행 환경의 실행 결과가 실패로 표시된다. 다음 주기 실행은 이전 실행 결과와 관계없이 처음부터 돈다(FR-012).

### Key Entities

- **동기화 실행(Sync Run)**: 실행 하나. 실행 식별자, 시작 방식, 대상 저장소 구분, 시작·끝 시각, 규칙·인덱스 버전, 자료원별 결과, 최종 상태.
- **저장된 문서 상태(Indexed Document State)**: 문서마다 마지막으로 성공한 처리의 원본 버전·원본 링크, 청킹 입력(내용 해시, 위치, 원본 제목), 청킹 규칙 버전,
  인덱스 버전, 접근 범위, 처리 결과, 마지막으로 확인한 원본 버전과 시각, 내림 여부와 사유, 본문 삭제 대기 목록(보안 대상 본문이 남은 인덱스 버전). QK-STO-001 원본 자료 항목을 바탕으로 한다.
- **문서별 결과(Document Outcome)**: 한 실행에서 문서 하나의 결과. 처리 성공(청크 있음·빈 문서), 변경 없음, 내림(사유), 실패(단계, 유형), 건너뜀(수집 중단).
- **내림 사유(Takedown Reason)**: 보안 내림(보안 필터 판정의 경로 제외·비밀값 차단·접근 범위 보류, 설정 제외 패턴)과 일반 내림(원본에서 사라짐·포함 패턴에서 빠짐,
  대상 아님, 자료원 비활성). 보안 내림만 청크 본문을 지운다.
- **실행 기록(Run Record)**: 동기화 실행의 요약과 문서별 결과, 실패 목록. 저장소에 남기고 원문·비밀값은 담지 않는다. 문서는 내부 식별값과 표시값으로 가리킨다.
- **자료원 정체성(Source Identity)**: 자료원 이름, 수집 대상(예: 저장소·브랜치), 원본이 알려 준 바뀌지 않는 식별값과 현재 이름·위치. 기준값은 그 자료원의 첫 저장소 쓰기보다 먼저 또는 함께 확정하고(FR-002), 실행이 실패해도 남는다. 같은 종류의 저장된 문서가 어느 자료원의 것인지 확인하는 데 쓴다(FR-002).
  실행 기록을 정리해도 남는다.
- **인덱스 버전(Index Version)**: QK-STO-001의 인덱스 버전. 이 명세는 현재 설정의 버전을 준비 상태로 만들고, 활성 버전이 없을 때만 사람 명령으로 첫 버전을 활성화한다.
- **미리 보기 결과(Sync Preview)**: 자료원별 바뀐 문서·변경 없음·내림·실패 예상 수, 임베딩 미리 보기, 내림 비율 판정, 실행 가능 여부.
- **주기 실행 정의(Schedule)**: 주기, 수동 시작, 실행하는 명령(동기화, 사용량 기록 정리), 비밀값 이름.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 가짜 자료원과 가짜 임베딩 제공자로 첫 동기화를 한 뒤 원본을 그대로 두고 다시 동기화했을 때, 외부 임베딩 호출 수와 청크가 바뀐 문서 수가 모두 0이다.
  원본 버전 표시만 바꾼 원본으로 동기화해도 둘 다 0이다(로드맵 1.G).
- **SC-002**: 같은 상태에서 문서 1개의 본문만 고쳐 동기화했을 때 청크가 바뀐 문서는 정확히 그 1개이고, 다른 문서의 청크 식별자·본문이 바뀐 건수가 0이다(로드맵 1.G).
- **SC-003**: 원본에서 지운 문서, 원본 권한을 미확인으로 바꾼 문서, 비밀값을 심은 문서, 제외 패턴에 걸리게 한 문서를 넣은 로컬 데이터베이스 시험에서, 동기화 뒤 이 문서들이
  벡터·키워드 검색·문맥 확장 조회에 나온 건수가 0이다(로드맵 1.G, C-14). 내림 비율 안에서, 또는 확인 옵션을 준 실행에서 원본 권한·비밀값·제외 패턴 문서는 저장소에 남은
  청크 본문과 키워드 검색용 텍스트 수가 0이다. 비율을 넘어 보류된 문서는 "본문 삭제 대기"로 남고, 이어서 확인 옵션을 준 실행 뒤 그 수가 0이다(그 사이 원본에서 사라진 문서 포함).
  준비 상태 버전 둘에 본문이 있는 문서를 보안 삭제 보류한 뒤 본문을 고쳐 한 버전에만 다시 처리하는 시험에서, 다른 버전의 예전 본문이 대기 목록에서 빠졌는데 저장소에 남은
  경우가 0이고, 확인 옵션을 준 실행 뒤 남은 수가 0이다.
- **SC-004**: 청킹·임베딩(종류별)·저장 실패를 주입한 시험에서, 실패한 문서의 검색 결과가 이전 청크와 다른 건수가 0이고, 새 묶음의 일부만 검색에 보인 건수가 0이며,

- **SC-006**: 같은 동기화를 연달아 두 번, 그리고 중간에 끊은 뒤 다시 실행했을 때 문서마다 청크 묶음이 하나이고 중복 청크가 0개이며, 최종 저장 상태가 끊기지 않은 실행과 같다(C-08).

  미리 보기와 100% 같다. 실패를 주입하지 않은 통제 시험에서는 처리 성공 수도 같다. 예상 Neurons와 실제 소비량의 차이는 QK-EMB-001 목표(±20%)를 따른다.
- **SC-008**: 예산 초과 상태에서 옵션 없이 실행했을 때 외부 임베딩 호출과 청크 교체가 0건이다(보안 내림은 SC-015).
- **SC-009**: 실패를 주입한 실행의 실행 기록에서 모든 요약 수치가 문서별 결과를 직접 센 값과 같고, 실행 기록·콘솔 출력·로그 전체에서 문서 원문·비밀값·토큰·접속 주소가 나온 건수가 0이다.

- **SC-010**: 같은 자료원에 동기화 두 개를 겹쳐 시작한 시험에서 둘 다 저장소에 쓴 경우가 0이고, 끊긴 실행 뒤 다음 실행이 막힌 경우가 0이다.
- **SC-011**: 설정·자료원·보안 규칙·예산 설정 검사 실패, 같은 종류 자료원 둘 이상, 설정상 자료원 정체성 변경, 로컬이 아닌 저장소에 확인 옵션 없음, 운영 저장소 정책 확인 없음,
  동시 실행의 각 경우에서 원본 요청 수가 0이고(동시 실행 제외) 실행 기록을 포함한 저장소 쓰기가 0이다. 인덱스 버전 불일치 실행과 수집 뒤 정체성 불일치 자료원
  (바뀌지 않는 식별값만 다름, 이름·위치만 다름, 정체성 정보 없음의 세 사례)에서 청크 교체와 일반 내림이 0건이다. 첫 실행에서 문서 일부를 저장한 뒤 끊고 원본 정체성을 바꿔 다시 실행한 시험에서, 바뀐 정체성을 새 기준값으로 받아들인 경우가 0이다.
  미리 보기만 한 뒤에 기준값이 생긴 경우가 0이다. 설정에서 자료원을 지운 실행은 실행 전 점검에서 멈추지 않고 일반 내림 경로로 간다.
- **SC-012**: 첫 실제 색인(사람 단계): Phase 1 대상 자료원 `dnd-backend-docs`의 미리 보기 결과(예상 Neurons)를 사람이 승인한 뒤 실행하고, 이어서 바로 다시 실행한 결과의
  외부 임베딩 호출이 0건이다. 사람이 결과를 확인하고 첫 인덱스 버전을 활성화한 뒤 검색으로 청크가 나오는지 확인한다. 측정 조건(대상 커밋, 보안·청킹 규칙 버전, 인덱스 버전, 실행 환경, 날짜)과 원본 요청 수, 소요 시간, 처리 문서 수, 청크 수, 소비 Neurons를
  기록한다(C-13). 수치 목표: 첫 실행 소비량이 일일 색인 예산(초기값 5,000 Neurons) 안이다.
- **SC-013**: Phase 1 규모(Markdown 79개, 측정 기록 2절)를 가짜 자료원·가짜 임베딩·로컬 데이터베이스로 처음 동기화하는 데 60초, 변경 없이 다시 동기화하는 데 30초가
  넘지 않는다(원본 호출 대기 제외). 고정 입력, 측정 장비, 반복 횟수, 시간 집계 방식은 `plan.md`에서 정한다.
- **SC-014**: 활성 인덱스 버전이 있는 저장소에서 활성화 명령이 활성 버전을 바꾼 경우가 0이고, 동기화가 인덱스 버전을 활성화한 경우가 0이며, FR-021 활성화 조건 중 하나라도
  못 채운 버전(옛 준비 버전, 실행 중·끝나지 않은 실행, 검색될 문서 0개, 벡터 없는 청크)을 활성화한 경우가 0이다. 활성화 전 변경 없는 재실행에서 다시 처리된 문서 수가 0이고,
  활성화 전에 설정을 바꾼 시험에서 새 준비 상태 버전에 처리되지 않은 문서 수가 0이다. 서로 다른 자료원의 실행을 겹친 시험에서 실행 중인 다른 기록을 닫은 경우가 0이다.
  문서 반영 직전·직후와 실행 기록을 닫기 직전에 프로세스를 끊는 시험에서, 반영된 문서와 그 문서의 결과 기록이 어긋난 경우가 0이고 그 실행의 기록이 다음 실행 뒤
  "끝나지 않음"이 아닌 경우가 0이다.
- **SC-015**: 저장소 비공개 전환(전체 접근 범위 보류), 인덱스 버전 불일치, 예산 초과 각각에 비밀값을 심은 문서를 더한 시험에서, 동기화 뒤 보안 사유 문서가 검색에 나온 건수가 0이다.

**범위**

- Discord `/reindex`와 실패 문서만 골라 다시 돌리기는 QK-SYN-002다. 이 명세에서 실패한 문서는 다음 실행에서 자연히 다시 처리된다(FR-012).
- 인덱스 버전 생성·평가 게이트·활성화(전체 재색인으로 새 버전 만들기)는 QK-STO-002다. 이 명세는 현재 설정의 인덱스 버전에만 쓰고, 활성 버전과 다르면 멈춘다(FR-020).
  그래서 Phase 1 동안 청킹 규칙이나 임베딩 모델을 바꾸면 QK-STO-002 전에는 동기화가 멈춘다. 그때 처리 방법은 사람이 정한다.
- 주기적 전체 대조, 원본 자료 항목의 물리 삭제, 쓰지 않는 벡터 정리, 백업·복구·재색인 절차 문서는 QK-SYN-003이다.
- 새 자료원(ClickUp, PR·Issue, OpenAPI 등)은 QK-ING-003 이후다. 이 명세의 흐름은 자료원 종류에 묶이지 않게 공통 형식(QK-ING-001)만 쓴다(C-06).
- 검색·생성은 QK-RET-001·QK-GEN-001이다. 이 명세의 검색 확인은 QK-STO-001 검색 질의로 한다.
- 청크 단위 증분(문서 안에서 바뀐 청크만 다시 임베딩)은 따로 두지 않는다. 바뀐 문서도 바뀌지 않은 청크는 임베딩 입력이 같아 캐시 적중이므로(QK-CHK-002 FR-011,
  QK-EMB-001 FR-008) 외부 호출은 바뀐 청크만큼만 생긴다 `(추론)`.

**사용자 결정 (2026-10-21)**

- 첫 인덱스 버전은 동기화가 준비 상태로 만들고, 활성 버전이 없을 때만 쓸 수 있는 활성화 명령으로 사람이 활성화한다(FR-021). 동기화가 스스로 활성화하는 안은 사람 확인 없이
  검색 대상이 바뀌어 고르지 않았고, QK-STO-002까지 미루는 안은 Phase 1 안에서 1.G 검색 조건을 확인할 수 없어 고르지 않았다. 첫 버전 활성화는 AGENTS.md 3.3의
  평가 통과 조건에 대한 사용자 승인 예외다. 검색 SQL이 활성 버전만 보므로 활성화 전에는 QK-EVL-001 평가를 돌릴 수 없다는 사정을 감안했다.
  이후 버전 교체는 QK-STO-002 평가 게이트를 따른다.
- 실행 기록은 저장소에 테이블로 남긴다(FR-027). 실행 결과 파일·실행 환경 로그만 남기는 안은 스키마를 바꾸지 않지만, QK-SYN-002 실패 재시도와 실행 기록 조회 명령,
  2.G 주기 실행 증빙에 다시 저장을 정해야 해서 고르지 않았다.
- 보안 내림만 청크 본문을 지운다(FR-015·FR-016). 일반 내림은 QK-STO-001대로 검색 제외만 하고 물리 정리는 QK-SYN-003에 맡긴다. 모두 검색 제외만 하는 안은 비밀값이나
  비공개가 된 본문이 Phase 5까지 저장소에 남아 고르지 않았고, 모두 본문을 지우는 안(첫 초안)은 QK-STO-001의 물리 삭제 경계를 이 명세가 바꾸는 셈이라 고르지 않았다
  (Codex 1차 검토 지적 4). 많은 문서의 본문을 한꺼번에 지우는 실행은 내림 비율 안전장치(FR-017)로 사람 확인을 받는다.

**기본값으로 정한 것 (리뷰에서 확인)**

- 본문 조회를 건너뛰지 않는다(FR-005). 대안은 목록 항목의 변경 판별값(GitHub 파일 내용 식별값)과 보안 규칙 버전을 문서마다 저장하고 둘 다 같으면 본문 조회를 건너뛰는 것이다.
  매번 받는 쪽을 고른 이유: (1) 보안 규칙이 바뀌어도 별도 재판정 절차 없이 모든 문서가 새 규칙으로 판정된다. (2) 저장 스키마에 변경 판별값을 더하지 않아도 된다.
  (3) Phase 1 비용이 작다. 실행 1회 원본 요청 83회, 73초로 실행당 한도 2,000회의 4.2%이고(측정 기록 2절), 하루 1회 실행이면 토큰 시간당 한도(5,000회)와 멀다.
  자료원이 커져 요청 수가 문제가 되면(ADR-019 다시 볼 조건: 실행당 한도의 50%) 다시 정한다.
- 원본 버전 표시만 바뀐 문서는 처리하지 않는다(FR-008·FR-010). GitHub 자료원은 저장소에 커밋이 하나 생기면 모든 문서의 원본 버전(커밋)이 바뀌므로, 원본 버전으로 판단하면
  1.G "문서 1개를 고치면 그 문서의 청크만 교체"를 지킬 수 없다. 대신 처리한 원본 버전·링크는 청크와 같은 처리의 값으로 남기고, 마지막으로 확인한 원본 버전·시각을
  따로 둔다. 같은 청킹 입력이라 출처 확인에는 문제가 없다고 본다 `(추론)`. 저장소 이동처럼 링크 자체가 바뀌어야 하는 경우는 FR-002가 막고 사람이 정리 방법을 정한다.
- 보안 사유의 검색 제외는 인덱스 버전 불일치·예산 초과·내림 비율 초과에도 멈추지 않는다(FR-004). 비공개로 바뀐 문서나 비밀값이 걸린 문서가 비용·버전 문제로
  계속 검색되면 C-14를 어기기 때문이다. 검색 제외는 원본 자료 항목의 상태만 바꾸므로 임베딩 비용이 없다 `(추론)`.
- 내림 비율 안전장치(FR-017)는 AGENTS.md 4절("인덱스 전체 삭제는 사람의 확인 없이 실행하지 않는다")을 동기화에 적용한 것이다. 자료원 비활성화와 저장소 비공개 전환도
  이 장치에 걸려 사람의 확인이 필요하다.
- 실행 위치는 ADR-008의 두 선택지(GitHub Actions, 로컬 CLI)를 모두 지원한다. 주기 실행은 GitHub Actions를 기본으로 본다. ADR-008이 2.G 증빙을 GitHub Actions 실행 기록으로
  남긴다고 적었기 때문이다. 이 저장소는 비공개라 실행 시간이 무료 할당에서 빠진다. 하루 1회, 회당 수 분이면 무료 할당 안이라고 보지만 할당량은 `plan.md`에서 확인한다 `(추론)`.
  변경(2026-10-23 ADR-020): 저장소는 공개이고, 주기 실행은 운영 OCI 인스턴스의 systemd 타이머로 한다. GitHub Actions 워크플로는 2026-10-25 지웠다(SCRUM-113).

**환경과 선행 조건**

- 운영 저장소는 아직 정해지지 않았다. ADR-008은 Supabase Free로 정했고, 2026-10-19 Oracle Cloud 인스턴스로 바꾸는 변경 제안이 있다. 어느 쪽이든 첫 실제 저장 전에 데이터 처리
  정책을 확인해야 한다(FR-033, ADR-019). 이 명세의 구현과 자동 시험은 로컬 데이터베이스만 쓰고, 운영 저장소 대상 실행은 사람 단계로 둔다.
- 첫 실제 색인 예상 사용량은 ADR-002 추정으로 약 325 Neurons(일일 무료 10,000의 3.3%)다. 실행 전에 미리 보기로 다시 확인하고 사람이 승인한다(AGENTS.md 3.5).
- 원본 자료 항목에는 자료원 이름이 없고, 원본 식별자는 자료원 종류 안에서만 중복되지 않는다(QK-STO-001 FR-001). GitHub 자료원의 원본 식별자는 저장소 안 경로라
  (QK-ING-002 FR-011) 같은 종류의 자료원이 둘 이상이거나 수집 대상이 바뀌면 문서를 구분하지 못한다. 그래서 이 명세는 그런 설정을 실행 전 점검에서 막는다(FR-002).
  Phase 1 활성 자료원은 하나라 실행에는 지장이 없다. 같은 종류 자료원을 더하는 명세(예: Android 저장소)가 자료원별 식별을 저장 스키마에 넣고 이 검사를 푼다.
  저장된 자료원 정체성을 어디에 둘지(실행 기록 또는 원본 자료 항목)는 `plan.md`에서 정한다.
- 처리 결과 시험은 QK-ING-001 가짜 자료원, QK-EMB-001 가짜 임베딩 제공자, 로컬 데이터베이스(QK-STO-001)로 한다. 실제 원본·실제 임베딩을 부르는 시험은 외부 호출 시험으로
  따로 두고 사람이 실행한다(AGENTS.md 7절, C-12).
- 성능 기준(SC-013)은 Phase 1 규모의 초기값이다. Phase 2에서 자료원이 늘면 다시 정한다.
