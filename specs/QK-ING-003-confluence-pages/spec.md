# Feature Specification: QK-ING-003 Confluence 페이지 수집, 문서 분류, 회의록·용어집 처리

**Feature Branch**: `feat/SCRUM-119-gh-72-confluence-source`

**Created**: 2026-10-27

**Status**: Draft

**Input**: 로드맵 4절 명세 백로그 QK-ING-003 "ClickUp Docs 수집, 문서 분류, 회의록·용어집 처리". 선행은 QK-SYN-001이다.
팀이 2026-10-17에 문서를 Confluence `SCRUM` 스페이스로 옮겨(`docs/github-workflow.md`), 이 작업(SCRUM-119, #72)에서 자료원을 Confluence로 바꿨다.
자료원 결정은 ADR-026(Proposed)에 있다. AGENTS.md 3.1, constitution, QK-ING-001·QK-SEC-001·QK-CHK-002·QK-SYN-001 명세,
0.3 조사(`clickup-migration-check.md`)와 0.4 작성 규칙(`clickup-writing-rules.md`)의 문서 종류·회의록·용어집 규칙을 근거로 썼다.

## User Scenarios & Testing *(mandatory)*

이 명세의 사용자는 Discord에서 회의 결정과 팀 문서를 묻는 팀원, 자료원 설정과 개인 정보 확인을 맡는 운영 담당자,
수집 결과를 쓰는 후속 구현자(QK-SYN-001 동기화, QK-CHK-002 청커, QK-CHK-003 회의·작업 연결), PR 리뷰어다.

### User Story 1 - 팀 스페이스의 현재 페이지 목록을 빠짐없이 받는다 (Priority: P1)

운영 담당자가 자료원 설정에 Confluence 스페이스 키를 적으면, 수집기는 그 스페이스의 현재 페이지를 모두 목록으로 돌려준다.
목록 항목은 원본 식별자, 원본 링크, 제목 경로, 변경 판별값을 갖는다. 초안·보관·휴지통 페이지와 페이지가 아닌 콘텐츠는 목록에 없다.

**Why this priority**: Phase 2 문서 자료원의 첫 자료다. QK-SYN-001은 이 목록으로 바뀐 페이지와 지운 페이지를 판단하므로(QK-SYN-001 범위),
목록이 빠지거나 중복되면 검색에서 문서가 사라지거나 두 번 나온다.

**Independent Test**: 저장해 둔 Confluence 응답(스페이스, 페이지 목록, 페이지 이어 받기)으로 재생 전송을 만들어 수집을 돌린다.
기대한 페이지 목록과 정확히 같은지, 같은 응답으로 두 번 돌린 결과가 같은지 본다.

**Acceptance Scenarios**:

1. **Given** 현재 페이지 30개, 초안 2개, 보관 페이지 1개, 휴지통 페이지 1개가 있는 스페이스, **When** 목록을 조회한다, **Then** 현재 페이지 30개만 나온다.
2. **Given** 목록이 여러 쪽으로 나뉘어 오는 스페이스, **When** 끝까지 조회한다, **Then** 쪽 경계에서 같은 페이지가 두 번 나오지 않는다(QK-ING-001 FR-005).
3. **Given** 다음 쪽을 받다가 영구 실패한 응답, **When** 목록을 조회한다, **Then** 목록은 "불완전"으로 표시된다.
4. **Given** 제목만 바뀐 페이지, **When** 다시 목록을 조회한다, **Then** 변경 판별값이 바뀐다.
5. **Given** 같은 응답, 같은 설정, **When** 두 번 조회한다, **Then** 항목·순서·변경 판별값이 같다(C-07).

### User Story 2 - 원본 권한을 접근 범위로 옮겨, 팀 공용 페이지만 색인된다 (Priority: P1)

수집기는 스페이스 종류, 스페이스 보기 권한, 페이지와 상위 페이지의 보기 제한을 원본 권한 정보로 넘긴다.
보안 필터는 Confluence 규칙으로 팀 공용·제한·미확인을 판정한다. 팀 공용이 아닌 페이지는 청킹·임베딩·저장되지 않는다.

**Why this priority**: GitHub 공개 저장소와 달리 Confluence 페이지는 비공개 팀 자료이고, 개인 스페이스와 보기 제한 페이지가 섞일 수 있다.
AGENTS.md 3.1과 C-14는 권한을 확인한 자료만 보여 주라고 하고, QK-SEC-001 FR-015는 새 자료원 종류의 규칙을 그 종류의 명세에 넘겼다.

**Independent Test**: 재생 전송에 전역 스페이스·개인 스페이스, 팀 그룹 보기 권한 있음·없음, 페이지 자신의 보기 제한, 상위 페이지의 보기 제한,
권한 조회 실패 응답을 넣고 수집과 보안 필터를 함께 돌린다. 판정이 FR-008~FR-012와 같고, 팀 공용이 아닌 페이지의 청크가 0건인지 본다.

**Acceptance Scenarios**:

1. **Given** 전역 스페이스이고 설정한 팀 그룹에 보기 권한이 있으며 보기 제한이 없는 페이지, **When** 판정한다, **Then** 팀 공용이다.
2. **Given** 상위 페이지 하나에 보기 제한이 걸린 페이지, **When** 판정한다, **Then** 제한이고 청크가 만들어지지 않는다.
3. **Given** 보기 제한을 조회하다 실패한 페이지, **When** 판정한다, **Then** 미확인이고 청크가 만들어지지 않는다.
4. **Given** 설정에 개인 스페이스 키가 적혔거나 스페이스 키가 두 개 이상인 자료원, **When** 설정을 검증한다, **Then** 원본 호출 없이 실패한다.
5. **Given** 규칙이 모르는 권한 주체 종류만 보기 권한을 가진 스페이스, **When** 판정한다, **Then** 미확인이다(QK-SEC-001 FR-016).
6. **Given** 지난 실행에서 팀 공용이었는데 이번에 보기 제한이 걸린 페이지, **When** 다시 동기화한다, **Then** 검색에서 내려간다(QK-SEC-001 FR-018, QK-SYN-001).
7. **Given** "사이트 사용자 확인" 판정 방식의 Free 사이트 자료원, **When** 사이트 사용자 확인 기록이 있으면 판정한다, **Then** 전역 스페이스의 제한 없는 페이지는 팀 공용이다.
   기록이 없거나 확인일에서 90일이 지났으면 모두 미확인이다(FR-012).
8. **Given** 지난 실행에 팀 공용으로 색인됐는데, 수집 계정이 보기 제한에서 빠져 이번 목록에 없는 페이지, **When** 동기화한다, **Then** 단건 확인에서 접근 거부가 나오고 보안 내림으로 내려간다. 일반 내림의 비율 검사에 막히지 않는다(FR-030).
9. **Given** 권한 조회가 목록의 10%를 넘는 페이지에서 실패한 실행, **When** 동기화한다, **Then** 목록은 "불완전"이고 미확인 때문에 생기는 내림이 0건이다(FR-031).

### User Story 3 - 본문을 Markdown으로 바꿔 청커에 넘기고, 잃는 내용은 경고로 남긴다 (Priority: P1)

수집기는 페이지 본문을 Markdown으로 바꿔 QK-CHK-002 Markdown 청커에 넘긴다. 제목·문단·목록·표·코드 블록·인용·링크는 Markdown으로 바꾸고,
접는 블록과 강조 패널은 펼친다. Markdown으로 옮길 수 없는 블록은 자리 표시와 변환 경고로 남긴다. 사람을 가리키는 멘션은 표시 이름만 남기고 계정 식별자는 버린다.

**Why this priority**: 청커는 Markdown만 안다(QK-CHK-002 FR-026). 변환이 표나 코드 블록을 깨면 검색 품질이 떨어지고(RISK-01),
멘션의 계정 식별자가 색인되면 AGENTS.md 3.1(계정 정보) 위반이다.

**Independent Test**: 원본 구조 형식으로 저장한 합성 페이지(표, 셀 병합 표, 코드 블록, 접는 블록, 패널, 알 수 없는 매크로, 멘션, 이미지, 첨부 링크)를
변환하고, 사람이 쓴 기대 Markdown과 변환 경고 목록이 같은지 본다.

**Acceptance Scenarios**:

1. **Given** 제목·목록·표·코드 블록이 있는 페이지, **When** 변환한다, **Then** 기대 Markdown과 같고 청커가 표·코드 블록 경계를 지킨다.
2. **Given** 알 수 없는 매크로가 있는 페이지, **When** 변환한다, **Then** 그 자리에 매크로 이름만 담은 자리 표시가 남고 "변환 불가 블록" 경고가 붙는다.
3. **Given** 팀원 멘션이 있는 페이지, **When** 변환한다, **Then** 결과에는 표시 이름만 남고, 결과와 메타데이터에 계정 식별자가 0건이다.
4. **Given** 이미지와 첨부 파일만 있는 문단, **When** 변환한다, **Then** 이미지·첨부 자리 표시만 남고 파일은 받지 않는다.
5. **Given** 같은 원본, **When** 두 번 변환한다, **Then** 결과가 바이트 단위로 같다(C-07).

### User Story 4 - 문서 종류를 정하고 회의록에서 날짜·결정·액션 아이템을 찾게 한다 (Priority: P2)

수집기는 페이지가 스페이스 첫 단계의 어느 페이지 아래에 있는지로 문서 종류(회의록, 용어집, 기능 명세, 설계 문서 등)를 정한다.
회의록이면 본문 위쪽 필드 표에서 회의 날짜·회의 종류·관련 명세 ID를 메타데이터로 붙인다. 그래서 "10월 14일 회의에서 뭘 정했지?" 같은 질문을 날짜와 종류로 좁힐 수 있다.

**Why this priority**: 회의 결정은 팀 질문의 주요 유형이고(로드맵 Phase 2 목표), QK-CHK-003은 회의 액션 아이템을 작업과 잇는다.
다만 목록·권한·변환(US1~US3)이 없으면 쓸 수 없으므로 P2다.

**Independent Test**: 첫 단계 페이지 아래에 놓인 합성 페이지와 필드 표가 있는·없는·날짜 형식이 틀린 회의록으로 수집을 돌리고,
문서 종류와 회의록 메타데이터가 기대값과 같은지 본다.

**Acceptance Scenarios**:

1. **Given** 문서 종류 대응표에 "회의록"으로 적힌 첫 단계 페이지 아래의 페이지, **When** 수집한다, **Then** 문서 종류는 회의록이다.
2. **Given** 대응표에 없는 첫 단계 페이지 아래의 페이지, **When** 수집한다, **Then** 미분류로 색인하지 않고(이미 색인됐으면 보안 내림), 수집 요약에 미분류 수가 나온다.
6. **Given** 대응표에 있는 첫 단계 페이지의 제목만 바뀐 경우, **When** 수집한다, **Then** 하위 페이지의 문서 종류가 그대로다.
3. **Given** 필드 표의 `일시`가 `2026-10-14`인 회의록, **When** 수집한다, **Then** 회의 날짜 메타데이터가 2026-10-14다. 제목의 날짜는 쓰지 않는다.
4. **Given** `일시` 필드가 없거나 날짜 형식이 아닌 회의록 아래 페이지, **When** 수집한다, **Then** 회의 날짜 없이 수집하고 "회의 메타데이터 없음" 경고를 붙인다.
5. **Given** 참석자·담당자 이름이 있는 회의록과 이름 색인을 허용한 확인 기록, **When** 수집한다, **Then** 이름이 본문에 남는다. 기록에 허용이 없으면 설정 검증이 실패한다.

### User Story 5 - 용어집 한 줄이 한 검색 단위가 된다 (Priority: P2)

용어집 페이지의 표는 행마다 따로 검색되게 넘긴다. 질문에 쓴 말("결제 재시도")과 코드 식별자(`retryPayment`)를 검색이 이어 준다.

**Why this priority**: 한국어 활용형·식별자 검색 품질(RISK-05)을 보완하는 장치다. 용어집이 큰 표 하나로 청크되면 행 하나를 찾는 질문에 표 전체가 붙는다.

**Independent Test**: 5행짜리 합성 용어집 페이지를 수집·청킹해 행마다 청크 하나가 나오고, 각 청크에 용어·정의·동의어·식별자가 함께 있는지 본다.

**Acceptance Scenarios**:

1. **Given** 머리글이 `용어 | 정의 | 동의어·약어·영문 | 코드 식별자·API 경로 | 관련 문서`인 표 하나가 있는 용어집 페이지, **When** 수집·청킹한다, **Then** 행마다 그 용어를 제목으로 한 청크가 하나씩 나온다.
2. **Given** 머리글이 다른 표, **When** 수집한다, **Then** 일반 페이지처럼 넘기고 "용어집 형식 아님" 경고를 붙인다.

### User Story 6 - 자료원을 비활성으로 등록하고, 사람 확인과 실측 뒤에 켠다 (Priority: P2)

운영 담당자는 Confluence 자료원을 비활성으로 등록한다. 켜기 전에 수집 범위에 개인 정보가 없음을 확인한 기록을 쓰고,
실제 스페이스를 한 번 수집해 페이지 수·크기·요청 수·소요 시간·예상 Neurons를 잰다. 원본의 한도 응답과 권한 거부는 구분한다.

**Why this priority**: QK-SEC-001 FR-024는 개인 정보 자동 탐지를 하지 않고 사람 확인으로 막는다. 회의록은 공개 저장소 문서보다 개인 정보가 들어 있을 가능성이 높다.
첫 색인 비용도 아직 모른다(ADR-026 Data and cost).

**Independent Test**: 확인 기록 없이 켠 설정, 범위를 넓히고 기록을 고치지 않은 설정을 검증한다. 둘 다 원본 호출 없이 실패해야 한다.
재생 전송에 한도 초과 응답(다시 시도할 시간 포함), 인증 실패, 페이지 접근 거부를 넣어 분류를 본다.

**Acceptance Scenarios**:

1. **Given** 확인 기록이 없는 활성 Confluence 자료원, **When** 수집을 실행한다, **Then** 원본 호출 없이 멈추고 기록이 필요하다고 알린다.
2. **Given** 다시 시도할 시간을 알리는 한도 초과 응답, **When** 수집한다, **Then** 일시적 실패로 그 시간 뒤에 재시도한다(QK-ING-001 FR-018).
3. **Given** 인증 실패 응답, **When** 수집한다, **Then** 그 자료원의 남은 호출 없이 멈춘다(QK-ING-001 FR-020).
4. **Given** 한 페이지만 접근 거부인 응답, **When** 수집한다, **Then** 그 페이지만 영구 실패로 기록하고 나머지를 처리한다.

### Edge Cases

- 페이지가 다른 스페이스로 옮겨졌다: 목록에서 빠지고, 단건 확인(FR-030)에서 다른 스페이스로 나오므로 이 자료원 범위 밖으로 보고 보안 내림으로 내린다.
- 페이지가 개인 스페이스로 옮겨졌거나 수집 계정이 보기 제한에서 빠졌다: 수집 계정이 볼 수 없으므로 목록에서 빠지고, 단건 확인에서 접근 거부·없음이 나와 보안 내림으로 내려간다(FR-030).
  일반 내림의 비율 검사에 걸려 검색에 남지 않는다.
- 상위 페이지를 지우자 하위 페이지의 상속 보기 제한이 풀렸다(Atlassian 버그 보고 CONFCLOUD-26297): 판정은 매 실행의 원본 상태를 따른다. 사람이 원본에서 바로잡는다.
- 상위가 페이지가 아닌 콘텐츠(폴더 등)다: 그 상위의 보기 제한을 읽을 수 없으면 미확인이다.
- 셀 병합이나 표 안 표가 있는 표: Markdown 표로 옮길 수 없으면 셀 내용을 순서대로 펼친 목록으로 바꾸고 "표 구조 손실" 경고를 붙인다.
- 다른 페이지 본문을 끌어오는 매크로(페이지 포함, 발췌 포함): 끌어온 내용을 가져오지 않고 자리 표시만 남긴다. 끌어온 페이지는 그 페이지 자체로 따로 색인된다.
- 본문이 자료원 설정의 최대 본문 크기를 넘는 페이지: QK-ING-001 크기 초과 영구 실패다.
- 본문이 비었거나 자리 표시만 남는 페이지(이미지만 있는 페이지): 청크가 0개일 수 있다. 수집 요약에 "본문 없음"으로 센다.
- 제목이 같은 페이지 두 개: 원본 식별자(페이지 ID)가 다르므로 둘 다 수집한다. 제목 경로가 같아도 문제없다.
- 본문에 비밀값이 들어간 페이지: QK-SEC-001이 그 페이지를 차단한다. 원문은 기록에 남지 않는다.
- 본문에 에이전트 지시문이 있는 페이지: 데이터로만 다룬다(C-03).
- 스페이스가 보관됐다: 스페이스 상태가 현재가 아니므로 그 스페이스의 페이지는 모두 미확인이 되어 보안 내림으로 내려간다(FR-008). 다시 현재 상태가 되면 다음 동기화에서 처음부터 색인한다(QK-SEC-001 FR-018).
- 스페이스를 조회하지 못했거나 지워졌다: 목록은 "불완전"이고, 불완전한 목록으로는 문서를 내리지 않는다(QK-SYN-001). 사람이 원인을 확인한다.
- 토큰 범위가 빠져 권한 조회가 모든 페이지에서 거부됐다: 권한 조회 실패 비율이 기준을 넘으므로 실행을 "불완전"으로 멈추고, 대량 보안 내림을 하지 않는다(FR-031).
- 상위 페이지 제목이 바뀌었다: 하위 페이지의 위치(제목 경로)가 바뀌어 모두 다시 처리되고 임베딩 호출이 생긴다. FR-027 측정과 plan에서 비용을 본다.

## Requirements *(mandatory)*

### Functional Requirements

**목록 조회 (US1)**

- **FR-001**: Confluence 수집기는 QK-ING-001 어댑터 계약을 구현하고 새 자료원 종류로 동작한다. 종류 등록은 ADR-026을 근거로 한다(QK-ING-001 FR-010).
- **FR-002**: Confluence 자료원 하나는 스페이스 하나를 맡는다. 자료원 설정의 수집 범위는 스페이스 키 하나이고, 두 개 이상이면 설정 검증이 실패한다.
  스페이스 종류가 전역 스페이스가 아니면 설정 검증이 실패하고 원본을 호출하지 않는다(2026-10-27 사용자 결정, 검토 H2).
- **FR-002a**: 원본 정체성(QK-SYN-001 원본 식별값)은 스페이스 ID(바뀌지 않는 값)이고 이름은 스페이스 키다. 범위 키도 스페이스 ID로 계산한다.
  스페이스 키가 바뀌어도 같은 스페이스면 같은 자료원이다. 다른 스페이스를 맡기려면 새 자료원을 만든다. 같은 종류 자료원을 둘 이상 켜는 일은 자료원별 식별 명세(백로그 추가 대기) 뒤에 한다.
- **FR-003**: 목록은 설정한 스페이스의 현재 상태 페이지만 담는다. 초안·보관·휴지통 페이지, 블로그 글, 댓글, 첨부 파일, 화이트보드, 데이터베이스, 폴더는 담지 않는다.
- **FR-004**: 목록 항목의 원본 식별자는 페이지 ID다. 원본 링크는 페이지 화면 주소, 위치 정보는 스페이스 키와 첫 단계부터의 제목 경로다.
  변경 판별값은 원본 버전 번호(원본 버전 종류)로 채운다. 제목이 바뀌면 버전이 바뀐다는 것을 plan에서 확인하고, 아니면 제목을 판별값에 더한다.
- **FR-005**: 목록을 끝까지 받지 못했으면 "불완전"이다(QK-ING-001 FR-005). 같은 응답·설정이면 목록 결과가 같다(C-07).

**원본 권한 정보와 접근 판정 (US2, QK-SEC-001 FR-015 인계)**

- **FR-006**: 원본 권한 정보에 다음 원값만 담는다. 판정 방식(팀 그룹·사이트 사용자 확인), 스페이스 종류, 스페이스 상태, 설정한 팀 그룹의 스페이스 보기 권한 여부,
  사이트 사용자 확인 기록의 유효 여부, 보기 제한 위치(없음·자신·상위), 상위 페이지 수. 사용자·그룹 식별자와 이름은 담지 않는다.
- **FR-007**: 팀 그룹은 자료원 설정에 이름으로 적는다. 팀 그룹이 바뀌면 개인 정보 확인 기록(FR-025)을 다시 쓴다.
- **FR-008**: Confluence 접근 판정 규칙을 QK-SEC-001 규칙 등록 방식으로 등록한다. 다음을 모두 만족할 때만 팀 공용이다.
  전역 스페이스, 현재 상태 스페이스, 팀 그룹 보기 권한 있음, 페이지와 모든 상위 페이지에 보기 제한 없음.
- **FR-009**: 페이지나 상위 페이지에 보기 제한이 있으면 제한이다.
- **FR-010**: 스페이스 권한이나 보기 제한을 조회하지 못했으면 미확인이다. 팀 그룹의 보기 권한 여부를 정하는 데 쓰는 값(권한 주체 종류, 작업 종류)이 규칙이 모르는 값이면 미확인이다.
  팀 그룹 보기 권한이 확인된 스페이스에 다른 사용자·역할 할당이 더 있는 것은 판정에 영향을 주지 않는다(QK-SEC-001 FR-016).
- **FR-011**: 팀 공용이 아닌 페이지의 본문은 청킹·임베딩·저장하지 않고, 기록·로그·요약에 본문을 남기지 않는다(QK-SEC-001 FR-018). 목록 응답에 본문이 함께 오더라도 같다.
  그 페이지의 판정 기록에는 제목과 제목 경로를 남기지 않고 페이지 ID만 남긴다.
- **FR-012**: 사이트 요금제가 스페이스 권한을 바꿀 수 없는 경우(Confluence Free)에는 자료원 설정에 "사이트 사용자 확인" 판정 방식을 적는다. 이 방식에서는 팀 그룹 보기 권한(FR-008) 대신
  "사이트 사용자가 모두 팀원임"을 사람이 확인한 기록을 쓴다. 기록이 있고 전역·현재 상태 스페이스이며 페이지와 상위 페이지에 보기 제한이 없으면 팀 공용이다.
  기록이 없거나 확인일에서 90일이 지났으면 미확인이다. 기존 보기 제한은 Free에서도 남으므로 FR-009는 그대로 적용한다. 사이트 사용자 구성이 바뀌면 사람이 기록을 다시 쓴다
  (2026-10-27 사용자 결정 A안, 유효 기간 90일). 판정 방식과 기록 내용 해시는 보안 규칙 버전 재료에 넣어, 기록이 바뀌면 다음 동기화에서 다시 판정한다(QK-SEC-001 FR-022).

**본문 변환 (US3)**

- **FR-013**: 본문은 원본의 구조 형식으로 받아 Markdown으로 바꾼다. 받는 형식은 ADR-026을 따른다. 변환 결과의 내용 형식은 Markdown이고, QK-CHK-002 청커 규칙을 바꾸지 않고 쓴다(QK-CHK-002 FR-026).
- **FR-014**: 제목·문단·목록·표·코드 블록(언어 표시 포함)·인용·구분선·링크 텍스트는 대응하는 Markdown으로 바꾼다. 접는 블록과 강조 패널은 제목 줄과 본문으로 펼친다.
- **FR-015**: Markdown으로 옮길 수 없는 블록(알 수 없는 매크로, 다른 페이지를 끌어오는 매크로, 차트 등)은 매크로 이름만 담은 자리 표시로 바꾸고 "변환 불가 블록" 경고를 붙인다.
  매크로 설정값과 끌어온 내용은 넣지 않는다.
- **FR-016**: 셀 병합·표 안 표처럼 Markdown 표로 옮길 수 없는 표는 셀 내용을 행 순서대로 펼친 목록으로 바꾸고 "표 구조 손실" 경고를 붙인다.
- **FR-017**: 사람 멘션은 원본에 표시된 이름 텍스트만 남기고 계정 식별자는 버린다. 사용자 정보를 보여 주는 매크로와 메일 링크(`mailto:`)는 자리 표시로 바꾼다.
  이름을 남기는 근거와 확인 기록은 FR-021과 같다. 이미지는 `[이미지]`, 첨부는 `[첨부: <파일 이름>]`으로 바꾸고 파일을 받지 않는다. 날짜·상태 표시 같은 인라인 요소는 표시 텍스트만 남긴다.
- **FR-018**: 링크는 링크 텍스트를 남긴다. 주소는 QK-SEC-001에 등록된 원본 링크 호스트이거나 공개 웹 주소일 때만 남기고, 그 밖의 주소는 지운다.
  Confluence 사이트 호스트를 원본 링크 호스트로 등록하는 방식(종류별 고정값 또는 자료원 설정)은 plan에서 정한다.
- **FR-019**: 같은 원본이면 변환 결과가 바이트 단위로 같다(C-07). 변환 규칙에는 버전을 두고, 버전이 바뀌면 다음 동기화에서 영향받는 페이지가 다시 처리되게 한다.
  변경 키에 넣을지 청킹 규칙 버전에 넣을지는 plan에서 정한다(AGENTS.md 3.3).

**문서 분류와 회의록 (US4)**

- **FR-020**: 문서 종류는 자료원 설정의 대응표(첫 단계 페이지 ID → 문서 종류)로 정한다. 첫 단계 페이지는 스페이스 홈 바로 아래 페이지다. 제목이 아니라 페이지 ID로 찾으므로 제목을 바꿔도 종류가 그대로다.
  대응표는 0.4 작성 규칙의 종류(회의록, 용어집, 기능 명세, 설계 문서, API 문서, 디자인 문서, 개발 규칙)로 시작한다.
- **FR-020a**: 대응표에 없는 첫 단계 아래의 페이지("미분류")와 스페이스 홈 페이지 자체, 대응표에서 "색인 안 함"으로 표시한 종류의 페이지는 색인하지 않는다(2026-10-27 사용자 결정, 검토 M2).
  이 페이지들은 설정 제외와 같은 보안 내림으로 내리고, 일반 내림의 비율 검사를 거치지 않는다. 수집 요약에 미분류 수를 보여 사람이 대응표에 넣을지 정하게 한다.
- **FR-021**: 회의록의 참석자와 액션 아이템 담당자 이름은 그대로 색인한다. "누가 맡았어?"에 답하기 위해서다(2026-10-27 사용자 결정 B안).
  개인 정보 확인 기록(FR-025)에 팀원 이름 색인을 허용한다고 적어야 하고, 적지 않으면 설정 검증이 실패한다.
  구조로 알 수 있는 계정 식별자·연락처(FR-017)는 지운다. 본문 글자로 적힌 연락처는 자동으로 찾지 않으므로(QK-SEC-001 FR-024) 사람 확인에서 찾아 그 페이지 트리를 제외한다.
- **FR-022**: 회의록이면 본문 첫 표의 `일시`(YYYY-MM-DD), `회의 종류`, `관련 명세 ID`를 회의록 메타데이터로 붙인다. 날짜는 제목에서 읽지 않는다.
  `일시`가 없거나 형식이 틀리면 메타데이터 없이 수집하고 "회의 메타데이터 없음" 경고를 붙인다. 이런 페이지는 회의로 세지 않는다(0.4 작성 규칙 2.4). `결정 사항`·`액션 아이템` 절은 본문에 그대로 남는다.
  메타데이터로 검색을 좁히는 필터는 QK-TRK-001 범위다. 이 명세는 메타데이터를 남기는 데까지 한다.

**용어집 (US5)**

- **FR-023**: 문서 종류가 용어집인 페이지에서 머리글이 0.4 작성 규칙 3절과 같은 표는 행마다 용어를 제목으로 한 절로 바꿔 넘긴다. 머리글이 다르면 일반 페이지로 넘기고 "용어집 형식 아님" 경고를 붙인다.

**자료원 등록, 사람 확인, 한도 (US6)**

- **FR-024**: Confluence 자료원(`confluence-scrum`, 가칭)을 `SCRUM` 스페이스로 비활성 등록한다. 켜는 일은 이 명세의 범위가 아니고 사람이 한다.
- **FR-025**: 자료원을 켜거나 수집 범위(스페이스, 문서 종류 대응표의 색인 대상, 팀 그룹, 판정 방식)를 넓히는 변경에는 개인 정보 확인 기록이 있어야 한다. 기록이 없거나 범위와 맞지 않으면
  설정 검증이 실패하고 원본을 호출하지 않는다(QK-SEC-001 FR-024, QK-ING-002 FR-020과 같은 방식).
- **FR-025a**: 개인 정보 확인 기록 형식(QK-ING-002 `contracts/source-reviews.md`)을 Confluence용으로 넓힌다. 범위 항목(스페이스 ID·키, 판정 방식, 팀 그룹, 색인하는 문서 종류의 첫 단계 페이지 ID),
  팀원 이름 색인 허용 여부, Free 사이트면 사이트 사용자 확인일과 사용자 수를 담는다. 이름·메일은 적지 않는다. 기존 GitHub 기록의 형식과 검증은 바뀌지 않는다.
- **FR-026**: 다시 시도할 시간을 알리는 거부 응답은 일시적 실패(호출 한도 초과)이고 그 시간을 따른다. 인증 실패는 QK-ING-001 FR-020, 페이지 하나의 접근 거부·없음은 그 페이지만 영구 실패다.
- **FR-027**: 첫 실제 색인 전에 사람이 실제 스페이스를 외부 호출 시험으로 한 번 수집하고, 요청 수, 소요 시간, 페이지 수, 총 바이트, 가장 큰 페이지 크기, 판정별 페이지 수,
  변환 경고 수, 예상 Neurons를 기록한다. 기록에 페이지 제목·본문·사람 이름을 남기지 않는다.
- **FR-028**: 실제 원본 요청은 읽기 요청만 HTTPS로 자료원 설정의 요청 허용 호스트에 보낸다. 인증은 QK-FND-001 설정 항목 이름으로만 가리킨다.
  Atlassian 인증에는 값이 여럿(계정 메일, 토큰, 사이트 식별값) 필요하므로, 자료원 설정의 인증 항목이 이름 여러 개를 가리키게 넓히는 방식은 plan에서 정한다. 기본 검증의 시험은 재생 전송만 쓰고 실제 원본을 호출하지 않는다.
- **FR-029**: Confluence 어댑터는 QK-ING-001 공통 계약 테스트를 통과한다.

**사라진 페이지와 판정 실패 (US2, QK-SYN-001 확장)**

- **FR-030**: 지난 동기화에 있었는데 이번 완전한 목록에 없는 페이지는 단건으로 다시 조회한다(2026-10-27 사용자 결정, 검토 H1).
  접근 거부·없음이면 수집 계정이 볼 수 없게 된 것으로 보고, 다른 스페이스에 있으면 범위 밖으로 보고, 둘 다 보안 내림(접근 범위 보류)으로 내린다. 일반 내림의 비율 검사를 거치지 않는다.
  보관·휴지통 상태면 일반 내림이다. 단건 조회가 일시적 실패면 그 페이지는 이번 실행에서 그대로 둔다. 이 처리를 위해 QK-SYN-001 동기화 계획에 자료원 종류별 "사라진 자료 확인" 단계를 더한다.
- **FR-031**: 한 실행에서 권한 조회가 실패해 미확인이 된 페이지가 목록의 10%를 넘으면 그 실행의 목록을 "불완전"으로 표시하고, 미확인 때문에 생기는 보안 내림을 하지 않는다.
  기준 10%는 초기값이고 FR-027 측정으로 다시 본다. 스페이스 보관처럼 원본이 미확인을 확정해 준 경우는 실패로 세지 않는다.

**공통 형식 확장 (QK-ING-001·QK-SYN-001 인계)**

- **FR-032**: 변환 경고, 문서 종류, 회의록 메타데이터, "본문 없음"을 수집 결과에 담을 자리를 QK-ING-001 공통 형식에 더한다. 다른 자료원 종류는 비워 두고 동작이 바뀌지 않는다.
  문서 종류와 회의록 메타데이터를 저장하는 위치와 메타데이터 스키마 버전 변경 여부, 인덱스 버전 영향은 plan에서 정하고 바뀌면 AGENTS.md 3.3을 따른다.

### Key Entities

- **Confluence 페이지 항목**: 원본 식별자(페이지 ID), 스페이스 키, 제목 경로, 원본 링크, 원본 버전, 문서 종류, 원본 권한 정보. QK-ING-001 목록 항목을 채운다.
- **원본 권한 요약**: 스페이스 종류·상태, 팀 그룹 보기 권한 여부, 보기 제한 위치, 상위 페이지 수. 사람 식별자는 없다.
- **변환 결과**: Markdown 본문, 변환 규칙 버전, 변환 경고 목록(경고 종류, 위치). 경고에 원문을 담지 않는다.
- **문서 종류 대응표**: 첫 단계 페이지 ID → 문서 종류, 색인 여부. 자료원 설정에 있다. 대응표에 없으면 색인하지 않는다.
- **회의록 메타데이터**: 회의 날짜, 회의 종류, 관련 명세 ID.
- **용어집 항목**: 용어, 정의, 동의어·약어, 코드 식별자·API 경로. 청크 하나에 대응한다.
- **개인 정보 확인 기록**: 확인한 범위(스페이스, 색인 대상 종류, 팀 그룹), 팀원 이름 색인 허용 여부, 확인일, 확인한 사람의 역할, 제외한 페이지 트리. 이름·연락처는 적지 않는다.
- **사이트 사용자 확인 기록**: Free 사이트에서 사이트 사용자가 모두 팀원임을 사람이 확인한 기록. 확인일(90일 유효), 사용자 수, 확인한 사람의 역할. 이름·메일은 적지 않는다.
  개인 정보 확인 기록 안에 둔다(FR-012, FR-025a).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 재생 응답 시험에서 목록이 기대한 페이지 목록과 정확히 같다. 초안·보관·휴지통·페이지 아닌 콘텐츠·중복 항목이 0건이고, 같은 응답으로 두 번 돌린 결과가 같다.
- **SC-002**: 권한 시험 사례(스페이스 종류, 팀 그룹 권한, 자신·상위 보기 제한, 조회 실패, 모르는 값, Free 사이트 확인 기록 있음·없음·만료)의 판정이 FR-008~FR-010·FR-012와 100% 일치하고, 팀 공용이 아닌 페이지의 청크·임베딩 입력·저장이 0건이다.
  수집 계정이 볼 수 없게 된 페이지는 100% 보안 내림으로 내려가고, 권한 조회 실패가 기준을 넘는 실행의 내림은 0건이다(FR-030, FR-031).
- **SC-003**: 합성 페이지 변환 결과가 사람이 쓴 기대 Markdown·경고 목록과 100% 같고, 두 번 변환한 결과가 같다.
- **SC-004**: 수집 결과·메타데이터·로그·측정 기록에서 계정 식별자가 0건이고, 로그·측정 기록에는 사람 이름도 0건이다. 이름 색인을 허용하지 않은 확인 기록으로 회의록을 수집하려는 사례는 원본 호출 0건으로 검증에서 실패한다.
- **SC-005**: 회의록 시험에서 회의 날짜·종류·관련 명세 ID가 기대값과 100% 같고, 필드 표가 없는 페이지는 모두 "회의 메타데이터 없음" 경고를 받는다.
- **SC-006**: 용어집 시험에서 행 수와 용어 청크 수가 같다.
- **SC-007**: 확인 기록 없는 활성화, 개인 스페이스 키, 스페이스 두 개 이상, 기록과 맞지 않는 범위 확장 사례가 모두 원본 호출 0건으로 검증에서 실패한다.
  기존 GitHub 자료원의 확인 기록 검증 결과는 바뀌지 않는다.
- **SC-008**: 한도 초과 응답은 100% 일시적 실패, 인증 실패는 100% 자료원 중단, 페이지 접근 거부는 그 페이지만 영구 실패로 분류된다.
- **SC-009**: Confluence 어댑터가 공통 계약 테스트를 통과하고, 기본 검증 전체에서 실제 원본 호출과 원본 쓰기 요청이 0건이다.
- **SC-010**: 첫 실제 수집 측정 기록이 FR-027 항목을 모두 갖고, 예상 Neurons가 하루 색인 예산을 넘으면 켜기 전에 보고된다(AGENTS.md 3.5).

## Assumptions

**요구사항 원문과 자료원 전환**

- 백로그 요구사항 FR-ING-03과 `sources.md` 3.5는 저장소에 원문이 없다. 백로그 제목, AGENTS.md 3.1, ADR-026, 0.4 작성 규칙을 근거로 했다.
- 백로그 제목은 "ClickUp Docs 수집"이지만 2026-10-17 이관에 따라 이 작업의 로드맵 변경(같은 PR)에서 "Confluence 페이지 수집"으로 바뀐다. WBS 번호와 명세 ID는 그대로다.
- ADR-026은 Proposed다. 이 명세가 승인될 때 ADR-026의 결정(수집 계정, 범위 지정 토큰, 받는 본문 형식)도 함께 검토한다.

**범위**

- 대상은 Confluence `SCRUM` 스페이스의 현재 페이지 본문이다. 블로그·댓글·첨부·화이트보드·데이터베이스는 넣지 않는다(ADR-026, C-04).
- Jira 이슈 수집은 QK-ING-004(Phase 3)다. 이 명세의 변환 규칙을 Jira가 다시 쓸 수 있게 두는 것은 plan에서 본다.
- 바뀐 페이지·지운 페이지 판단, 원자적 교체, 재판정 시점은 QK-SYN-001 범위다. 이 명세는 완전한 목록과 판별값을 만든다.
  예외로 사라진 페이지의 단건 확인(FR-030), 권한 조회 실패 기준(FR-031), 미분류의 보안 내림(FR-020a)은 동기화 계획을 바꿔야 하므로 이 명세의 구현 범위에 QK-SYN-001 코드 변경을 넣는다.
  GitHub 자료원의 동작은 바뀌지 않아야 한다.
- 공통 수집 형식(QK-ING-001)과 개인 정보 확인 기록 형식(QK-ING-002)을 넓히는 일(FR-025a, FR-028, FR-032)도 이 명세의 구현 범위다. 기존 자료원의 결과와 시험 기대값은 바뀌지 않는다.
- 동기화는 지금 자료원 종류마다 하나만 켤 수 있다(`sync/identity.py`). 스페이스를 더하는 일은 자료원별 식별 명세(별도 세션 초안 QK-SYN-005, 백로그 추가 대기) 뒤에 한다.
- 청킹 규칙은 QK-CHK-002를 그대로 쓴다. 위치 정보(페이지 ID, 제목 경로)를 위치 값에 더하는 방식만 이 명세가 정한다(QK-CHK-002 FR-026).
- 회의 액션 아이템과 작업을 잇는 일은 QK-CHK-003이다. 이 명세는 `액션 아이템` 절을 본문에 남긴다.
- 웹훅 반영은 QK-SYN-004(Phase 6 후보)다.

**환경과 기본값**

- Confluence 작성 규칙은 아직 없다. ClickUp 작성 규칙(0.4)의 문서 종류·회의록 템플릿·용어집 형식이 이관 뒤에도 유지된다고 가정했다. 실제 페이지 트리와 다르면 plan 측정 뒤 대응표를 고친다.
- 사이트 요금제, 페이지 수·크기, 이관 검증 기록은 확인하지 못했다(Atlassian 읽기 권한 없음). plan 단계에서 토큰 발급 뒤 읽기 전용으로 잰다.
- 호출 한도 기본값은 QK-ING-001 기본값으로 시작하고 FR-027 측정으로 다시 본다.
- 단계 게이트 1.G는 미완료다. QK-CHK-001 선례처럼 명세 단계를 먼저 하고, 구현 시작 시점은 사람이 정한다.

**설계 단계로 넘기는 것**

- 목록 응답에 본문을 함께 받을지, 팀 공용 판정 뒤 본문만 따로 받을지(호출 수와 FR-011의 관계).
- 상위 페이지 판정 결과를 실행 안에서 다시 쓰는 방식(호출 수 감소).
- 변환 규칙 버전을 넣을 곳, 문서 종류·회의록 메타데이터를 넣을 저장 위치와 메타데이터 스키마 버전 영향(AGENTS.md 3.3).
- 범위 지정 토큰의 접두어 확인과 비밀값 규칙 반영(ADR-026).

**다른 문서에 남길 수정 (이 작업에서 고치지 않는다)**

- `docs/sdd/research/tokens.md`: Atlassian 토큰을 발급할 때 범위·만료·`.env` 변수를 더한다.
