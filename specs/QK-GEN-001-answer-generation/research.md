## R-01 생성 제공자 호출 방식

- **Decision**: 이 명세는 Workers AI REST(`POST /client/v4/accounts/{account}/ai/run/{model}`) 생성 제공자를 새 파일 `adapters/workers_ai/generation.py`에 만든다. 요청 본문은
  `{"messages": [{"role": "system", ...}, {"role": "user", ...}], "max_tokens": 800, "temperature": 0.2}`다. Workers 바인딩(`env.AI.run`) 제공자는 같은 경계(`GenerationProvider`) 뒤에
  QK-BOT-001이 더한다.
- **`rest.py`와의 관계**: `rest.py`는 바꾸지 않는다. 공개 상수(`API_BASE`, `INPUT_TOO_LONG_CODE`, `QUOTA_CODE`, `NEURONS_HEADER`)만 가져다 쓴다. `classify()`는 성공 경로에서 임베딩 벡터를 파싱하므로
  (`rest.py:113-127`) 쓰지 않는다. 비공개 함수(`_error_codes`·`_neurons`·`_retry_after`)도 가져오지 않는다. 대신 생성 어댑터 안에 같은 판정 규칙의 오류 판정 함수를 두고, 두 판정이 같은 상태 코드·오류
  코드에 같은 종류를 내는지 표 시험으로 고정한다(독립 검토 M2 (b)).
- **전송**: 생성 전용 전송 `GenerationTransport.post(url, headers, body, timeout)`을 둔다. 시간 제한을 호출마다 받는다. `urllib` 예외 가운데 `TimeoutError`·`socket.timeout`과
  `URLError(reason=TimeoutError|socket.timeout)`는 "시간 초과"로, 그 밖의 연결·읽기 오류는 "일시 실패"로 가른다(spec FR-002). `UrllibTransport`(생성자에서만 시간 제한)는 쓰지 않는다(M2 (c)).
- **응답 해석**: 스파이크는 생성 응답의 `usage`(입력·출력 토큰)와 헤더 `cf-ai-neurons`를 확인했지만(spike W-04, 3.2절) 본문 필드 이름과 종료 사유는 기록하지 않았다. 그래서 두 꼴을 받는다:
  (a) `result.response`(문자열) + `result.usage`, (b) OpenAI 호환 `result.choices[0].message.content` + `choices[0].finish_reason` + `result.usage`. 둘 다 아니면 "잘못된 응답"이다.
  종료 사유가 없으면 출력 토큰 = 출력 상한일 때 잘림으로 본다(spec FR-023).
- **응답 꼴 기록**: 어댑터는 본문 글 없이 응답의 꼴만 `ResponseShape`(최상위 키 이름, `result` 키 이름, `usage` 유무, Neurons 헤더 유무, 종료 사유 유무, 쓴 해석 (a)/(b))로 남긴다. 성공이면 `ProviderReply`에,
  "잘못된 응답"이면 실패 예외에 싣는다. 키 이름만 담고 값은 담지 않는다. H01은 이 값으로 R-01 판단을 확인한다(독립 검토 M9).
- **Alternatives**: `rest.py`에 공개 오류 판정 함수 추가 — QK-EMB-001 파일 변경이라 Scope 승인이 필요하고 임베딩 시험 범위가 넓어진다. OpenAI 호환 엔드포인트 — 스파이크가 이 경로의 생성 Neurons 헤더를
  확인하지 않았다. AI Gateway — 새 서비스(C-05·ADR 필요).

## R-02 프롬프트 버전과 저장 위치

- **Decision**: 프롬프트는 코드 상수다(`generation/prompts.py`). 프롬프트 하나는 (시스템 프롬프트, 사용자 메시지 템플릿, 렌더링 규칙 이름)의 묶음이고, 식별자는 `<이름>-<sha256 앞 12자>`다.
  해시 재료는 `json.dumps({"system": …, "template": …, "render_rule": …}, ensure_ascii=False, sort_keys=True)`의 UTF-8 바이트다(독립 검토 L11).
  - `gen-p1`: 시스템 프롬프트 후보 1과 사용자 메시지 템플릿을 `TASK.md` "승인된 입력"에서 글자 그대로 옮긴다. 템플릿은 `{question} /no_think`로 끝나므로 렌더러는 ` /no_think`를 따로 붙이지 않는다(M3).
    렌더링 규칙 `render-v1`(R-03).
  - `gen-base`: 스파이크 부록 B 시스템 프롬프트 글자 그대로와, 스파이크가 설명한 사용자 메시지 꼴을 옮긴 템플릿·렌더링 규칙 `render-base`(R-03). 스파이크는 템플릿 원문을 남기지 않았으므로 아래 글을
    이 계획에서 정했고 2026-10-23 사용자가 승인했다(L12).

    ```text
    [자료]
    {context}

    [질문]
    {question} /no_think
    ```

- **렌더링 규칙 고정**: 렌더링 규칙 이름은 사람이 붙인 번호라, 같은 이름으로 출력이 바뀌는 것을 막으려고 고정 Context 3종의 렌더링 결과를 글자 그대로 비교하는 골든 시험을 둔다. 출력이 바뀌면
  시험이 깨지고 규칙 이름을 올려야 한다(SC-010).
- **Rationale**: spec FR-005와 SC-010을 시험으로 확인한다. 청킹 규칙 버전(`chunking/version.py`)과 같은 방식이다. 파일로 두면 Workers 번들에 데이터 파일을 넣는 문제가 생긴다.
- **Alternatives**: 환경값에 프롬프트 원문 — 길고 줄바꿈이 많다. DB 저장 — 사람 승인 기록과 코드 리뷰가 떨어진다.

## R-03 생성 입력 렌더링과 구분자 무력화

- **`render-v1`(gen-p1)**: 자료 블록은 묶음마다 아래 줄들이다. 묶음 사이는 빈 줄 하나.

  ```text
  [S1] 제목 경로 A > B | 수정 2026-10-10
  (발췌문 청크 1)
  …(중간 생략)…
  (절: A > C)
  (발췌문 청크 5)
  ```

  - 제목: 묶음 첫 청크의 `heading_path`를 ` > `로 잇는다. 비면 `locator["path"]`, 그것도 없으면 `제목 없음`(spec FR-004).
  - 수정일: `source_modified_at`을 UTC+9로 바꾼 날짜. 없으면 `수정 미상`.
  - 생략 줄: 묶음의 `gaps`마다 한 줄. `ContextBlock.text`(생략 표시 `(…)`)는 쓰지 않는다.
  - `(절: …)` 줄: 같은 묶음 안에서 앞 청크와 `heading_path`가 다를 때.
- **`render-base`(gen-base)**: 묶음마다 `[S1] 제목: <제목>` 줄 다음에 청크 본문을 줄바꿈으로 잇는다(스파이크 부록 A.1 꼴). 수정일·생략·절 줄은 없다. 제목 규칙과 무력화는 같다.
- **무력화(spec FR-011)**: 청크 본문·제목·위치·질문에 아래를 적용하고 바꾼 개수를 센다.
  - 대괄호 쌍 `[`…`]` 안에 `S` + 숫자가 있는 모든 글(줄바꿈 포함, 가장 짧게 맞춤: `\[[^\[\]]*?S\d[^\[\]]*?\]`, DOTALL)의 `[`·`]`를 전각 `［`·`］`로 바꾼다.
    줄바꿈이 든 `[S1,\nS2]`, `[\nS7\n]`도 잡는다(독립 검토 H1).
  - `[자료 시작]`, `[자료 끝]`, `[자료]`, `[질문]`도 같은 방식으로 바꾼다.
  - 제목·위치의 ` | `는 ` ¦ `로 바꾼다.
  - 원본 값(무력화 전 제목, 원본 `ContextBlock`)은 따로 들고 있다가 출처 목록에 쓴다(M4).
- **인식 쪽과의 관계**: 후처리의 인용 인식(R-04)은 대괄호 안 공백을 `[ \t]`로만 받는다(줄바꿈을 받지 않는다). 무력화 범위(줄바꿈 포함)가 인식 범위보다 넓으므로, 사용자 메시지 안에서 인식될 수 있는 꼴은
  렌더러가 만든 머리줄의 `[S번호]`뿐이다(SC-004).
- **SC-004 검사 범위**: SC-004는 사용자 메시지(템플릿 + 자료 블록 + 질문)에 적용한다. 시스템 프롬프트에는 승인 원문의 인용 예시(`[S1]`, `[S1][S3]`)가 있고, 이는 무력화 대상이 아니다(재검토 N8).
- **Rationale**: 전각 괄호는 사람이 읽을 때 뜻이 같고 후처리는 반각만 본다. 자료 내용을 지우지 않는다(C-03).

## R-04 후처리 알고리즘

spec FR-014의 순서를 따르되, 문장 경계가 필요한 단계보다 문장 나누기를 앞에 두고(독립 검토 L2) 코드 가림을 끝까지 유지한다(M5). 모든 단계는 결정적 순수 함수다.

1. **추론 블록**: `<think>…</think>`(여러 개 가능)를 지운다. 닫히지 않은 `<think>`는 끝까지 지운다. 짝 없는 `</think>`는 그 앞까지를 추론으로 보고 지운다. 지운 블록 안에 공백 아닌 글이 있으면 "추론 출력 감지".
   코드 표기(백틱 span·코드 블록) 안의 `<think>`·`</think>`는 추론 표시로 보지 않는다(구현 독립 검토 M2). 응답 안의 NUL 문자는 코드 자리 표시와 겹치지 않게 먼저 지운다(L1).
2. **코드 가림**: 세 개 백틱 코드 블록(닫히지 않으면 끝까지)과 한 개 백틱 코드 span을 자리 표시(`\x00C0\x00` 꼴, 문장 부호·대괄호 없음)로 바꾼다. 10단계까지 유지한다.
3. **출처 목록 줄**: `^[ \t]*(출처|참고|Sources?|References)[ \t]*[:：]`인 줄과 바로 아래 이어지는 목록 줄(`^[ \t]*([-*]|\d+\.)[ \t]`)을 지운다.
4. **URL**: 후보는 `https?://` 뒤로 공백·`<>"`·`)`·반각·전각 대괄호(`[` `]` `［` `］`)·전각 괄호가 나오기 전까지 가장 길게 잡는다(한글 등 비ASCII 포함). `[`를 빼서 URL 바로 뒤의 인용(`…/deploy[S1]`)을 URL로 잡지 않는다(구현 독립 검토 M1). 발췌문(무력화 전 청크 본문)에서도 같은 규칙으로 후보를 뽑고, 끝의 `.,;:!?'`를 떼어
   URL 집합을 만든다. 답변의 후보는 (1) 끝 문장부호를 뗀 값이 집합에 정확히 있으면 남기고, (2) 집합의 어떤 URL `u`로 시작하고 나머지가 정해진 조사(에서·에게·으로·부터·까지·에·은·는·을·를·이·가·의·로·와·과·도·만) 하나면 `u`와 나머지를 남기며
   (2026-10-23 사용자 결정으로 한글 1~2자 전부에서 조사 목록으로 좁혔다. `…/배포안`처럼 한글 경로의 변형은 남지 않는다, 구현 독립 검토 L4),
   (3) 그 밖이면 후보 전체를 지운다(뒤의 공백·문장부호는 남는다). `…/deploy에 있다`는 (2)로 남는다(H2). 발췌문이 `…/docs/설계.md`일 때 답변의 `…/docs/가짜.md`는 (3)으로 지워진다(재검토 N1).
   괄호가 든 경로(`…/Foo_(bar)`)는 발췌문과 답변이 같은 자리에서 끊기므로 같은 규칙으로 비교된다.
5. **문장 나누기**: 마침표·물음표·느낌표 뒤(바로 뒤에 인용 꼴이 붙어 있으면 그 인용까지 포함) 공백·줄 끝이 오는 자리와 줄바꿈에서 나눈다. 점 뒤에 공백 없이 글자가 오는 `5.5`, `a.py`는 나뉘지 않는다.
   `…잡는다.[S3] 다음` 은 `…잡는다.[S3]` | `다음`으로 나뉜다(L5). 나눈 뒤, 조각 머리에 인용 꼴(인식한 꼴과 6단계의 인식 못 한 꼴)이 공백을 사이에 두고 이어져 있고 앞 조각이 문장부호로 끝나면,
   그 인용들을 앞 조각 끝으로 옮긴다. `A다. [S1] B다. [S2]`는 `A다. [S1]` | `B다. [S2]`가 된다(재검토 N3). 인용 꼴만 남은 조각은 앞 조각에 붙이고, 빈 조각은 버린다.
6. **인용**: 문장마다
   - 인식: `\[[ \t]*S([1-9]\d*)([ \t]*[,，][ \t]*S([1-9]\d*)|[ \t]+S([1-9]\d*))*[ \t]*\]`. 인식한 인용은 `[S1][S2]` 꼴로 바꾸고 같은 문장 안 같은 ID는 하나로 줄인다.
   - 인식하지 못한 꼴: 위에 맞지 않으면서, 대괄호 안이 `S`+숫자와 구분 기호(공백·`,，;；/-~–`·`및`)만으로 된 글, 그리고 `(S숫자)`·`【S숫자】`·`[s숫자]`. `[S9,]`, `[S1；S2]`, `[S1/S2]`, `[S1 및 S2]`,
     `[S1, S3-S5]`, `[S0]`, `[S01]`이 모두 여기에 든다(M7). `[AWS S3 버킷]` 같은 일반 글은 세지 않는다(재검토 N6. 무력화 범위 R-03은 그대로 넓다). 지우지 않고 센다. 이 꼴은 반각 대괄호가 남아도
     인용이 아니므로 출처 목록에 들지 않는다.
   - 생성 입력에 없는 ID의 인식된 인용은 지우고 센다. `[S1, S9]`는 정규화 뒤 S9만 지운다.
7. **빈 결과**: 1~6을 거친 뒤 공백 아닌 조각이 0개면 "잘못된 응답"이다. 확인 불가로 바꾸지 않는다(M6).
8. **확인 불가 판정(spec FR-009)**: 문장마다 인식한 인용·인식하지 못한 꼴·따옴표(`"'“”‘’「」`)·앞뒤 공백을 걷어 낸다(L3). `CANNOT = "제공된 자료만으로 확인할 수 없습니다"`, `ORIGIN = "현재 상태는 원본에서 확인해야 합니다"`.
   (가) 모든 문장이 `CANNOT`(끝 마침표 무시)과 같으면 확인 불가·본문 = `CANNOT + "."`. (나) 모든 문장이 `CANNOT`으로 끝나거나 `ORIGIN`과 같으면 확인 불가·본문은 인용을 지운 문장들. (다) 그 밖은 답변.
   코드 자리 표시만 있는 조각은 사실 문장으로 본다.
9. **세기**: 답변이면 유효 인용 수와 인용 없는 문장 수(코드 자리 표시만 있는 조각·(나)에 해당하는 문장 제외)를 센다. 유효 인용 0이면 "출처 확인 안 됨"(spec FR-015).
10. **코드 되돌림**: 자리 표시를 원래 코드로 되돌린다. 코드 안 글은 1~9에서 건드리지 않았다.
11. **출처 목록**: 본문(코드 밖)에 남은 인식된 인용의 ID를 번호 순서로, 원본 `ContextBlock`의 출처 정보와 무력화 전 제목으로 만든다.

- **남는 위험**: (1) 마침표 없이 쉼표·접속어로 이어지는 한국어 문장은 한 문장으로 센다(인용 없는 문장 수가 적게 나온다). (2) spec FR-009 (나)는 "재시도는 3회이며 나머지는 제공된 자료만으로 확인할 수 없습니다 [S1]."처럼
  유효 인용이 있는 사실 문장도 확인 불가로 만들고 출처를 비운다(독립 검토 L4, spec에서 온 위험). 2026-10-23 사용자 결정으로 spec은 그대로 두고 이 동작을 시험 사례로 고정한다.
  SC-008 실측에서 이 경우가 나오면 횟수를 기록한다.

## R-06 생성 사용량 저장

- **Decision**: 새 마이그레이션 `0006_generation_usage.sql`로 테이블 `qk.generation_usage`(시도마다 한 행)와 `qk.generation_usage_daily`(90일 지난 날의 합계), 함수
  `qk.generation_record(...)`, `qk.generation_usage_today(query_reserve int)`, `qk.generation_usage_prune(retention_days int)`를 더한다. 기존 `qk.embedding_*` 테이블·함수는 바꾸지 않는다.
- **열**: `purpose`(`'generate'` 하나만 허용, spec FR-020의 용도, M8 (d)), `occurred_at`, `usage_day`(UTC 생성 열), `run_id`, `model_id`, `prompt_version`, `attempt`(1·2),
  `input_tokens`·`output_tokens`(모르면 NULL), `estimated_input_tokens`, `neurons numeric(14,6)`, `measured boolean`, `outcome`, `truncated boolean`. 질문·답변·프롬프트 원문 열은 없다.
- **질의응답 합계**: `qk.generation_usage_today`는 그날 생성 합계, `qk.embedding_used(day, 'query')`, 둘의 합(질의응답 합계), 예비분 초과 여부를 돌려준다. 생성 쪽 예비분 경고는 이 합으로 판정한다.
- **남는 차이(M8 (a))**: 기존 `qk.embedding_record`와 `qk-index usage`는 `query_used`를 질의 임베딩만으로 계산한다. 그래서 (1) 질의 임베딩 쪽 예비분 초과 경고는 생성 사용량을 모르고, (2) `qk-index usage`의
  `query_used`와 생성 쪽 질의응답 합계가 다르다. spec Assumptions("기존 기록 행과 하루 합계 값은 바뀌지 않아야 한다")를 지키려고 이 차이를 받아들인다. 대신 `qk-index ask` 출력과 `--json` 요약에
  임베딩·생성·질의응답 합계·하루 전체(색인 포함)를 함께 보여 준다. 운영 화면 통합은 QK-OBS-001로 넘긴다.
- **보관(M8 (b))**: `qk-index usage prune`이 임베딩 정리 뒤 `qk.generation_usage_prune`도 부르게 한다(`indexer/usage.py` 변경, Scope 승인 대상). 출력에 생성 쪽 `days_rolled_up`·`rows_deleted`를 더한다.
  임베딩 정리가 끝난 뒤 생성 정리가 실패하면 앞 정리는 그대로 남고 종료 코드 2로 끝난다. 두 정리 모두 다시 실행해도 안전하므로 재실행으로 마친다(구현 독립 검토 L8, 받아들인 위험).
- **실패 시도의 Neurons(M8 (c))**: QK-EMB-001 코드는 실패 시도를 0 Neurons·추정으로 기록한다(`embedding/service.py:280-281`). spec FR-020은 "결과를 받지 못한 시도도 과금됐을 수 있으므로 추정값으로" 기록하라고
  한다. 이 계획은 과금 가능성으로 나눈다(2026-10-23 사용자 승인). 아래 표가 R-01 오류 판정과 사용량 기록이 함께 쓰는 하나의 표이고, 같은 표 시험으로 고정한다(재검토 N2).

  | 응답·예외 | 결과 종류 | 과금 | 기록 Neurons |
  | --- | --- | --- | --- |
  | 200, 본문 해석 성공 | `ok`(후처리가 빈 결과면 `bad_response`) | 예 | 헤더 값 → `usage` 토큰 × 단가 → 추정 |
  | 200, 본문 해석 실패 | `bad_response` | 예 | 헤더 값 → 추정 |
  | 429 + 오류 코드 3036 | `provider_quota` | 아니오 | 0 |
  | 429(그 밖), 5xx | `transient` | 예 | 추정 |
  | 시간 초과 | `timeout` | 예 | 추정 |
  | 연결·읽기 오류 | `transient` | 예(구분 불가라 보수적으로) | 추정 |
  | 401, 403 | `auth_config` | 아니오 | 0 |
  | 400 + 오류 코드 3030 | `input_too_long` | 아니오 | 0 |
  | 그 밖의 4xx(400, 404, 413, 422 등) | `bad_response` | 아니오 | 0 |

  - 추정 = 예상 입력 토큰 × 입력 단가 + 출력 상한 × 출력 단가, `measured=false`. 헤더 값은 `measured=true`, 토큰 × 단가는 `measured=false`.
  - 성공 응답 시도의 기록은 후처리(R-04) 뒤에 쓴다. 그래서 후처리가 빈 결과로 판정한 시도는 `outcome='bad_response'`로 남는다. 실패 시도는 실패를 받은 즉시 쓴다.
  - 이 구분은 spec FR-020 문구 안의 해석이고 QK-EMB-001의 실패 기록 규칙과 다르다. spec "QK-EMB-001과 같은 규칙"은 측정·추정 표시 규칙을 가리키는 것으로 읽는다.
- **Alternatives**: 기존 표에 `purpose='generate'` 추가 — 제약 변경(ALTER)과 토큰 열 부재, QK-EMB-001 합계 변화. 기존 `query_used`를 생성 포함으로 바꿈 — 승인된 QK-EMB-001 동작 변경.

## R-07 재시도와 시간 제한

- **Decision**: 호출 시간 제한 20초(설정), 일시 실패·시간 초과 재시도 1회. 대기 시간은 생성 경계가 `RetryDelay`로 주입받는다. 확인 명령은 `indexer/search_cli.py:41`의 `query_retry_delay`(제공자 값, 없으면 0.5초,
  최대 2초)를 넘긴다. Workers 경로의 대기 함수는 QK-BOT-001이 넘긴다(L13).
- **마감 시각**: 생성 경계는 `deadline_seconds`를 받는다. 기본값은 `2 × 시간 제한 + 5`(시간 제한 20이면 45)이고, 직접 주면 설정 검사가 `2 × 시간 제한 + 5 ≤ 마감`을 확인해
  (하한이 `+ 2`면 시도가 시간 제한을 조금만 넘겨도 재시도가 사라져 `+ 5`로 올렸다, 구현 독립 검토 L5)
  어기면 거부한다. 그래서 설정만으로 재시도가 조용히 꺼지지 않는다(재검토 N4). 다시 시도하기 전에 (지난 시간 + 대기 + 시간 제한)이 마감을 넘으면 다시 시도하지 않고 마지막 실패로 끝낸다. 소켓 시간 제한은 소켓 작업마다
  걸리므로 한 시도가 시간 제한보다 길어질 수는 있다. 그래서 42초는 기본값 기준 추정이고, 보장은 "재시도를 마감 안에서만 시작한다"까지다(L8). 사용량 기록 DB 시간은 포함하지 않는다.
- **외부 호출 수**: 생성 호출 + 시도마다 기록 1 → 최대 4(spec FR-024). 검색 요약 `external_calls`(최대 7)에 더한 값을 질의 전체 호출 수로 낸다.

## R-08 입력 토큰 추정과 한도 검사

- **Decision**: `estimate(text) = ceil(len(text.encode()) / bytes_per_token)`(QK-RET-001 `RetrievalSettings.bytes_per_token` 3.5와 같은 값)에 `underestimate_factor`(2.0)를 곱한다.
  설정 검사(spec FR-019 (1)): `factor × (estimate(system) + estimate(template 고정 문구) + ceil(question_max_chars × 4 / bpt) + context_budget) + max_tokens ≤ 32,768`.
  호출 직전 검사(2): `factor × estimate(system + user) + max_tokens ≤ 32,768`.
- **계산**: 후보 1 시스템 프롬프트 2,184바이트 ÷ 3.5 = 624, 템플릿 고정 문구 50바이트 ÷ 3.5 = 15(L6). 기본값으로 (1) = 2.0 × (624 + 15 + 2,286 + 2,000) + 800 = 10,650으로 통과.
  덮어쓰기 최대(질문 8,000자, 예산 8,000)면 2.0 × (639 + 9,143 + 8,000) + 800 = 36,364로 (2)에서 막힌다.
- **Rationale**: 실제 토크나이저를 Workers에 넣지 않는다(새 의존성·번들 크기). QK-RET-001 R-08의 실측 최대 1.875배를 덮는 배율이다.
