# Feature Specification: QK-ING-001 자료원 어댑터 계약·자료원 설정·호출 한도·재시도

**Feature Branch**: `docs/SCRUM-92-gh-24-phase1-first-specs`

**Created**: 2026-10-18

**Status**: Draft

**Input**: 로드맵 4절 명세 백로그 QK-ING-001 "자료원 어댑터 계약·자료원 설정·호출 한도·재시도". 선행은 QK-FND-001이다.
백로그 행의 요구사항 ID(FR-ING-01, 10, 11)는 원문이 없어(Assumptions 참조) 2026-10-18 사용자 결정에 따라 백로그 제목,
constitution, AGENTS.md 3.1, `tokens.md`, Confluence `설계` 페이지(Step06 변경 반영 방식)를 근거로 설계했다.

## User Scenarios & Testing *(mandatory)*

이 명세의 사용자는 자료원별 수집기를 만드는 후속 명세 구현자(Phase 1 QK-ING-002 GitHub 저장소 파일, Phase 2~4 QK-ING-003~009),
수집기 결과를 쓰는 구현자(QK-SEC-001 보안 필터, QK-CHK-002 청커, QK-SYN-001 동기화), 자료원 설정을 바꾸는 운영 담당자, PR 리뷰어다.

### User Story 1 - 새 자료원은 정해진 계약만 구현하면 파이프라인에 붙는다 (Priority: P1)

수집기 구현자가 새 자료원을 붙일 때, 공통 어댑터 계약(자료 목록 조회, 자료 본문 조회)만 구현하면 동기화·보안 필터·청커 코드를 고치지 않고도
그 자료원의 자료가 파이프라인을 지나간다. 어댑터는 원본 시스템 고유 형식이 아니라 공통 자료 형식으로 결과를 돌려준다.

**Why this priority**: 로드맵은 자료원을 단계마다 하나씩 붙인다(C-04). 계약이 없으면 자료원마다 동기화·보안 코드가 갈라지고,
Confluence `설계` Step06이 정한 "Adapter 형태로 확장" 방향을 지킬 수 없다. QK-SEC-001, QK-ING-002, QK-CHK-002가 모두 이 계약을 기다린다.

**Independent Test**: 저장해 둔 응답으로 동작하는 가짜 자료원 어댑터를 계약대로 만들고, 공통 계약 테스트 세트를 돌린다. 가짜 어댑터를
하나 더 추가할 때 계약 밖 코드의 변경이 없어야 한다.

**Acceptance Scenarios**:

1. **Given** 계약을 구현한 어댑터, **When** 자료 목록을 조회한다, **Then** 자료마다 원본 식별자, 원본 링크, 원본 버전 또는 수정 시각,
   자료 종류, 원본이 준 권한 정보(없으면 "미확인")가 공통 형식으로 나온다.
2. **Given** 목록에서 받은 원본 식별자, **When** 본문을 조회한다, **Then** 본문, 내용 형식(Markdown·코드·JSON 등), 원본 버전이 나온다.
3. **Given** 원본이 수정 시각을 주지 않는 자료원, **When** 목록을 조회한다, **Then** 어댑터가 변경 판별용 값을 내용 해시로 대신 채운다.
4. **Given** 원본이 페이지를 나눠 목록을 주는 자료원, **When** 목록을 끝까지 조회한다, **Then** 페이지 경계에서 같은 자료가 두 번 나오지 않는다.
5. **Given** 어떤 어댑터든, **When** 계약 테스트 세트를 돌린다, **Then** 원본 시스템에 쓰는 요청(생성·수정·삭제)이 0건이다(C-09, AGENTS.md 3.1).

### User Story 2 - 자료원 설정을 선언하고, 잘못되면 수집 전에 멈춘다 (Priority: P1)

운영 담당자가 자료원마다 활성 여부, 수집 범위(대상 저장소·브랜치·경로 포함·제외 패턴 등 자료원별 항목), 호출 한도, 인증 설정 이름을
저장소의 자료원 설정에 선언한다. 수집 실행 전에 설정을 검증하고, 틀리면 원본에 한 번도 요청하지 않고 멈춘다.
토큰 값은 자료원 설정에 쓰지 않고 QK-FND-001 설정 항목 이름으로만 가리킨다.

**Why this priority**: 수집 범위가 곧 색인 범위다. 범위가 틀리면 색인하면 안 되는 자료(AGENTS.md 3.1: 개인 페이지, Notion 문서 등)가
외부 임베딩 API로 나갈 수 있다. 토큰 값이 설정 파일에 들어가면 AGENTS.md 6절 위반이다.

**Independent Test**: 형식이 틀린 설정, 등록되지 않은 자료원 종류, 토큰 값을 직접 넣은 설정을 각각 검증한다. 모두 실행 전에 실패하고
원본 호출이 0건이어야 한다.

**Acceptance Scenarios**:

1. **Given** 필수 항목이 빠진 자료원 설정, **When** 수집을 실행한다, **Then** 빠진 항목을 자료원 이름과 함께 보고하고 원본을 호출하지 않는다.
2. **Given** 등록되지 않은 자료원 종류(예: Notion)가 적힌 설정, **When** 검증한다, **Then** 실패하고, 자료원 추가에는 결정 기록이
   필요하다는 안내가 나온다(AGENTS.md 3.1).
3. **Given** 인증 항목에 설정 이름 대신 토큰 형식의 값이 들어간 설정, **When** 검증한다, **Then** 실패하고 값은 출력하지 않는다.
4. **Given** 비활성으로 표시한 자료원, **When** 수집을 실행한다, **Then** 그 자료원은 호출하지 않고 "비활성"으로 보고한다.
5. **Given** 올바른 설정, **When** 검증만 실행한다, **Then** 자료원별 통과 여부와 적용될 수집 범위 요약이 나온다.

### User Story 3 - 원본의 호출 한도를 넘지 않는다 (Priority: P2)

수집기는 자료원 설정의 호출 한도(초당·분당 최대 요청 수, 실행 1회당 최대 요청 수)와 원본이 응답으로 알려 주는 한도 정보(남은 호출 수,
다시 시도할 시각)를 함께 지킨다. 한도에 닿으면 정해진 만큼 기다리거나, 기다릴 수 없으면 그 실행을 멈추고 어디까지 처리했는지 보고한다.

**Why this priority**: GitHub 토큰 한도(시간당 5,000회, `tokens.md` 2절)와 Workers 밖 색인 실행 시간(ADR-008)을 지켜야 한다.
한도를 넘기면 수집뿐 아니라 같은 토큰을 쓰는 다른 작업도 막힌다. 다만 Phase 1 대상 규모에서는 한도에 닿을 가능성이 낮아 P2로 둔다.

**Independent Test**: 남은 호출 수가 적다고 응답하는 가짜 자료원으로 수집을 돌린다. 실제 요청 수가 설정 한도와 원본이 알린 한도를 넘지 않는지,
멈출 때 처리한 자료와 남은 자료가 보고되는지 본다.

**Acceptance Scenarios**:

1. **Given** 분당 최대 60회로 설정한 자료원, **When** 자료 200개를 수집한다, **Then** 어떤 1분 구간에도 요청이 60회를 넘지 않는다.
2. **Given** 원본이 "남은 호출 0, N초 뒤 초기화"를 알린 상태, **When** N이 최대 대기 시간 이하다, **Then** N초를 기다린 뒤 이어서 수집한다.
3. **Given** 같은 상태에서 N이 최대 대기 시간보다 크다, **When** 수집 중이다, **Then** 기다리지 않고 멈추며, 처리한 자료 수, 남은 자료 수,
   다시 시도할 수 있는 시각을 보고한다.
4. **Given** 실행 1회당 최대 요청 수에 닿은 상태, **When** 수집 중이다, **Then** 멈추고 같은 형식으로 보고한다.

### User Story 4 - 일시적 실패는 재시도하고, 한 자료의 실패가 전체를 멈추지 않는다 (Priority: P2)

수집 중 일시적 실패(호출 한도 초과 응답, 원본 서버 오류, 연결 시간 초과)가 나면 간격을 늘려 가며 정해진 횟수까지 재시도한다.
영구 실패(자료 없음, 접근 거부)는 재시도하지 않고 그 자료만 실패로 기록한 뒤 다음 자료로 넘어간다. 인증 실패는 자료원 전체가 실패할 것이므로
그 자료원 수집을 즉시 멈춘다.

**Why this priority**: C-08(실패 격리)의 수집 단계 구현이다. 실패한 자료는 이전 버전을 유지해야 하므로(QK-SYN-001), 어떤 자료가 왜 실패했는지
구분된 결과가 필요하다.

**Independent Test**: 가짜 자료원에 일시적 실패 2회 뒤 성공하는 자료, 영구 실패하는 자료, 정상 자료를 섞고 수집한다. 결과에서 각 자료의 상태와
재시도 횟수를 본다. 인증 실패를 넣은 경우에는 요청이 첫 실패 뒤 멈추는지 본다.

**Acceptance Scenarios**:

1. **Given** 처음 두 번은 일시적 실패, 세 번째에 성공하는 자료, **When** 재시도 상한이 3회다, **Then** 자료는 성공으로 기록되고 재시도 횟수 2가 남는다.
2. **Given** 재시도 상한을 넘겨 계속 실패하는 자료, **When** 수집한다, **Then** 그 자료만 "일시적 실패, 재시도 소진"으로 기록되고 나머지 자료는 처리된다.
3. **Given** "자료 없음" 응답을 받는 자료, **When** 수집한다, **Then** 재시도 0회로 "영구 실패"로 기록되고 다음 자료로 넘어간다.
4. **Given** 인증 실패 응답, **When** 수집한다, **Then** 그 자료원 수집을 멈추고 "인증 실패"를 보고한다. 같은 토큰으로 남은 자료를 더 호출하지 않는다.
5. **Given** 재시도가 있었던 실행, **When** 결과를 본다, **Then** 자료별 결과(성공·일시적 실패·영구 실패·건너뜀), 재시도 횟수, 실패 유형이 나오고
   응답 본문 속 비밀값이나 토큰은 나오지 않는다.

### Edge Cases

- 원본이 권한 정보를 주지 않는 자료원: 권한 정보를 "미확인"으로 채운다. 판정은 QK-SEC-001이 하고, 미확인 자료는 검색에 노출되지 않는다(QK-STO-001).
- 목록 조회 도중 한 페이지가 재시도 상한을 넘겨 실패: 목록이 불완전하다는 사실을 결과에 표시한다. 불완전한 목록을 근거로 "원본에서 삭제됨"을
  판단하지 않게 한다(삭제 반영은 QK-SYN-001·003).
- 원본이 재시도 시각을 아주 길게(예: 1시간) 알릴 때: 최대 대기 시간을 넘으면 기다리지 않는다(US3 시나리오 3).
- 재시도 간격의 합이 실행 1회의 최대 소요 시간을 넘을 때: 남은 재시도를 하지 않고 멈춘다.
- 같은 자료가 목록에 두 번 나올 때(페이지 경계, 이동한 자료): 원본 식별자로 하나만 남긴다.
- 본문 크기가 자료원 설정의 최대 크기를 넘을 때: 본문을 받지 않고 "크기 초과로 건너뜀"으로 기록한다.
- 원본 응답 형식이 예상과 다를 때(필드 누락, 형식 변경): 그 자료를 "응답 형식 오류"로 기록하고 다음 자료로 넘어간다. 계약 형식을 억지로 채우지 않는다.
- 자료원 설정의 포함·제외 패턴이 서로 겹칠 때: 제외가 이긴다.
- 원본이 리다이렉트로 다른 호스트를 가리킬 때: 자료원 설정에 등록된 호스트가 아니면 따라가지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

**어댑터 계약 (US1)**

- **FR-001**: 모든 자료원 어댑터는 같은 계약을 구현한다. 계약은 자료 목록 조회와 자료 본문 조회 두 동작이며, 원본에 쓰는 동작은 계약에 없다(C-09).
- **FR-002**: 목록 조회는 자료마다 자료원 종류, 원본 식별자, 원본 링크, 변경 판별값(원본 버전 또는 수정 시각, 없으면 내용 해시), 자료 종류,
  원본 권한 정보(없으면 "미확인"), 원본 상태(활성·보관·삭제를 원본이 알려 주는 경우)를 공통 형식으로 돌려준다.
- **FR-003**: 본문 조회는 원본 식별자를 받아 본문, 내용 형식, 원본 버전, 원본 안 위치 정보(경로 등)를 공통 형식으로 돌려준다.
  공통 형식은 QK-STO-001 원본 자료 항목(FR-001)을 채울 수 있어야 한다.
- **FR-004**: 어댑터의 입력과 출력에 원본 시스템 SDK의 타입이 나오지 않는다(C-06).
- **FR-005**: 목록 결과는 원본 식별자 기준으로 중복이 없다. 목록이 끝까지 조회되지 못했으면 "불완전" 표시를 붙인다.
- **FR-006**: 모든 어댑터가 통과해야 하는 공통 계약 테스트 세트를 둔다. 계약 테스트는 저장해 둔 응답 샘플로 돌고 실제 원본을 호출하지 않는다(C-12).
  계약 테스트에는 원본 쓰기 요청이 0건임을 확인하는 항목이 있다.
- **FR-007**: 저장된 응답으로 동작하는 가짜 자료원 어댑터를 제공한다. 후속 명세(QK-SEC-001, QK-CHK-002, QK-SYN-001)는 실제 자료원 없이 이 어댑터로 테스트한다.

**자료원 설정 (US2)**

- **FR-008**: 자료원 설정은 저장소 안의 설정 파일로 선언하고, 자료원마다 이름, 종류, 활성 여부, 수집 범위(자료원 종류별 항목), 호출 한도,
  재시도 정책, 최대 본문 크기, 인증 설정 이름을 가진다.
- **FR-009**: 인증은 QK-FND-001 설정 항목의 이름으로만 가리킨다. 자료원 설정에 토큰 형식의 값이 있으면 검증이 실패한다(AGENTS.md 6절).
- **FR-010**: 자료원 종류는 등록된 목록 안에서만 고를 수 있다. 목록에 없는 종류는 검증이 실패하고, 종류 추가에는 결정 기록이 필요하다고 안내한다
  (AGENTS.md 3.1). Notion은 등록하지 않는다.
- **FR-011**: 수집 실행 전에 모든 활성 자료원의 설정을 검증한다. 하나라도 틀리면 원본 호출 없이 멈추고, 틀린 자료원과 항목 이름을 보고한다.
- **FR-012**: 수집 범위의 포함·제외 패턴이 겹치면 제외가 우선한다.
- **FR-013**: 설정 검증만 하는 실행 방식을 제공하고, 결과로 자료원별 통과 여부와 적용될 수집 범위 요약을 보여 준다.

**호출 한도 (US3)**

- **FR-014**: 자료원마다 단위 시간당 최대 요청 수와 실행 1회당 최대 요청 수를 설정할 수 있고, 수집기는 이를 넘지 않는다.
- **FR-015**: 원본이 응답으로 알려 주는 남은 호출 수와 다시 시도할 시각을 따른다. 설정 한도와 원본 한도 중 더 엄격한 쪽을 지킨다.
- **FR-016**: 한도 때문에 기다려야 할 시간이 최대 대기 시간을 넘거나 실행 1회당 최대 요청 수에 닿으면 실행을 멈추고, 처리한 자료 수, 남은 자료 수,
  다시 시도할 수 있는 시각을 보고한다. 이어서 수집하는 방법은 QK-SYN-001이 정한다.

**재시도와 실패 분류 (US4)**

- **FR-017**: 실패를 일시적 실패(호출 한도 초과, 원본 서버 오류, 연결 시간 초과), 영구 실패(자료 없음, 접근 거부, 응답 형식 오류, 크기 초과),
  인증 실패로 나눈다.
- **FR-018**: 일시적 실패는 간격을 늘려 가며(지수 백오프와 무작위 지연) 재시도 상한까지 재시도한다. 원본이 다시 시도할 시각을 알려 주면 그 시각을 따른다.
  재시도 대기의 합이 실행 1회의 최대 소요 시간을 넘으면 멈춘다.
- **FR-019**: 영구 실패는 재시도하지 않고 그 자료만 실패로 기록한 뒤 다음 자료를 처리한다(C-08).
- **FR-020**: 인증 실패를 받으면 그 자료원의 수집을 즉시 멈추고 남은 자료를 호출하지 않는다.
- **FR-021**: 수집 결과에는 자료별 상태(성공·일시적 실패·영구 실패·건너뜀), 재시도 횟수, 실패 유형을 담는다. 결과와 로그에 토큰·요청 헤더·응답 본문 속
  비밀값을 남기지 않는다(AGENTS.md 6절).
- **FR-022**: 원본이 등록되지 않은 호스트로 리다이렉트하면 따라가지 않고 영구 실패로 기록한다.

### Key Entities

- **자료원 설정(Source Config)**: 이름, 종류, 활성 여부, 수집 범위, 호출 한도, 재시도 정책, 최대 본문 크기, 인증 설정 이름.
- **자료원 종류(Source Type)**: 등록된 자료원 종류 목록. Phase 1은 GitHub 저장소 파일과 가짜 자료원이다.
- **자료 목록 항목(Source Item)**: 자료원 종류, 원본 식별자, 원본 링크, 변경 판별값, 자료 종류, 원본 권한 정보, 원본 상태.
- **자료 본문(Source Content)**: 원본 식별자, 본문, 내용 형식, 원본 버전, 원본 안 위치 정보.
- **수집 결과(Fetch Result)**: 실행 단위 요약(처리·실패·남은 자료 수, 목록 완전 여부, 멈춘 이유, 다시 시도 가능 시각)과 자료별 상태·재시도 횟수·실패 유형.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 가짜 자료원 어댑터가 공통 계약 테스트를 전부 통과하고, 두 번째 가짜 어댑터를 추가하는 변경에서 계약 밖 코드(동기화·보안·청커) 변경이 0줄이다.
- **SC-002**: 계약 테스트와 수집 시험 전체에서 원본 쓰기 요청이 0건이다.
- **SC-003**: 잘못된 자료원 설정 사례(필수 항목 누락, 미등록 종류, 토큰 값 직접 기재) 전부에서 실행 전에 실패하고 원본 호출이 0건이다.
- **SC-004**: 호출 한도 시험에서 설정 한도나 원본 한도를 넘은 요청이 0건이다.
- **SC-005**: 재시도 상한 이내로 일시적 실패를 넣은 자료는 100% 성공하고, 영구 실패 자료의 재시도는 0회다.
- **SC-006**: 자료 하나에 영구 실패를 넣은 시험에서 나머지 자료가 100% 처리된다.
- **SC-007**: 수집 결과와 로그에서 토큰이나 비밀값 패턴이 발견된 사례가 0건이다(`scripts/preflight.py` 규칙 기준).

## Assumptions

**요구사항 원문 부재**

- FR-ING-01, FR-ING-10, FR-ING-11은 저장소(git 이력 포함), Confluence `SCRUM` 스페이스, 로컬 파일 어디에도 원문이 없다(2026-10-18 확인).
  뜻을 추측해 대응시키지 않았다. FR-ING-10은 QK-FND-001 백로그 행에도 있으므로 원문이 나오면 두 명세를 함께 대조한다.
- 백로그 제목 요소와 이 명세의 대응은 아래와 같다.

| 백로그 제목 요소 | 이 명세 | 근거 |
| --- | --- | --- |
| 자료원 어댑터 계약 | FR-001~007, US1 | C-06, C-09, Confluence `설계` Step06(Adapter 형태로 확장) |
| 자료원 설정 | FR-008~013, US2 | AGENTS.md 3.1·6절, `tokens.md` 6절 |
| 호출 한도 | FR-014~016, US3 | `tokens.md` 2절(GitHub 시간당 5,000회), ADR-008 |
| 재시도 | FR-017~022, US4 | C-08 |

**범위**

- 실제 자료원 수집기(GitHub 저장소 파일)는 QK-ING-002 범위다. 이 명세는 계약, 설정, 한도·재시도 공통 동작, 가짜 어댑터까지다.
- 색인 제외 경로, 비밀값 차단, 접근 범위 판정은 QK-SEC-001 범위다. 이 명세는 원본 권한 정보를 그대로 넘기고, 없으면 "미확인"으로 채운다.
- 언제 수집할지(주기), 이어서 수집하기, 변경 비교, 삭제 반영은 QK-SYN-001 범위다.
- 이벤트 수신(웹훅)은 다루지 않는다. Confluence `설계` Step06이 주기적 증분 조회(Polling)를 골랐고, C-04가 웹훅을 필요가 확인된 뒤로 미뤘다.

**환경과 기본값**

- 어댑터는 색인 진입점(QK-FND-001, Workers 밖)에서만 돈다. 질의응답 진입점은 어댑터를 쓰지 않는다(ADR-008). 원본 현재 상태 조회(C-02)는
  QK-TRK-002 등 후속 명세가 따로 정한다.
- 재시도 기본값은 상한 3회, 첫 간격 1초, 최대 간격 60초, 최대 대기 시간 5분이다. 실행 1회 최대 소요 시간은 자료원 설정으로 정하고 기본값은 30분이다.
  모두 초기값이며 QK-ING-002 측정 결과로 조정한다.
- 자료원 설정 파일은 비밀값이 아니므로 저장소에 커밋한다. 설정 파일도 비밀값 검사(QK-FND-001) 대상이다.
- Phase 1 등록 자료원 종류는 GitHub 저장소 파일 하나와 테스트용 가짜 자료원이다. ClickUp 이관 뒤 Jira·Confluence를 자료원으로 쓸지는
  AGENTS.md 3.1 결정 기록이 필요한 별도 작업이다(SCRUM-91 TASK 제외 범위).
