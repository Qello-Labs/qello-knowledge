# Feature Specification: QK-SEC-001 색인 제외 경로·비밀값 차단·접근 범위 판정

**Feature Branch**: `feat/SCRUM-99-gh-37-security-filter`

**Created**: 2026-10-19

**Status**: Draft

**Input**: 로드맵 4절 명세 백로그 QK-SEC-001 "색인 제외 경로·비밀값 차단·접근 범위(`access_scope`)". 선행은 QK-ING-001이다.
백로그 행의 요구사항 ID(FR-SEC-03, FR-SEC-06)와 `sources.md` 8절은 원문이 없어(Assumptions 참조) 백로그 제목, constitution C-10·C-14,
AGENTS.md 3.1·6절, 로드맵 RISK-09와 1.G 완료 조건, 0.2 인벤토리, 0.3 ClickUp 조사(`access_scope` 판별), QK-ING-001·QK-STO-001 명세를 근거로 썼다.

## User Scenarios & Testing *(mandatory)*

이 명세의 사용자는 자료원 수집기 구현자(QK-ING-002 이후), 필터를 통과한 자료를 쓰는 구현자(QK-CHK-002 청커, QK-EMB-001 임베딩,
QK-SYN-001 동기화, QK-GEN-001 답변 생성), 차단 기록을 검토하는 운영 담당자, PR 리뷰어다.

보안 필터는 수집기가 공통 형식(QK-ING-001)으로 넘긴 자료가 청킹·임베딩·저장 단계로 가기 전에 반드시 지나는 관문이다.
자료마다 경로 제외, 접근 범위, 비밀값 세 가지를 판정하고, 그 결과와 이유를 비밀값 원문 없이 남긴다.

### User Story 1 - 비밀값이 든 자료는 외부 API로 나가지 않는다 (Priority: P1)

수집한 자료의 본문이나 제목에 토큰, 비밀번호, 개인 키, 비밀번호가 든 DB 연결 주소 같은 비밀값이 있으면, 그 자료는 임베딩·생성 API로
보내지지 않고 저장되지도 않는다. 운영 담당자는 어느 자료가 어느 규칙 때문에 막혔는지 보지만, 비밀값 자체는 어디에도 남지 않는다.

**Why this priority**: 로드맵은 "첫 실제 색인은 QK-SEC-001이 끝난 뒤에만 돌린다"고 정했다. RISK-09(코드 안의 비밀값이 외부 API로 전송)의
대응이 이 명세다. 0.2 인벤토리에서 비밀값 검사를 꼭 거쳐야 하는 파일(`application*.yml`, `*.tfvars.example`, `.env.example` 등)을 이미 찾았다.

**Independent Test**: 규칙마다 비밀값을 심은 샘플 자료와 placeholder만 든 샘플 자료를 섞어 가짜 자료원(QK-ING-001 FR-007)으로 흘린다.
비밀값 샘플은 모두 막히고, placeholder 샘플은 통과하고, 판정 기록과 로그에 비밀값 원문이 없어야 한다.

**Acceptance Scenarios**:

1. **Given** 본문에 GitHub 토큰 형식의 값이 든 자료, **When** 필터를 지난다, **Then** 그 자료는 "비밀값 차단"으로 판정되고
   청킹·임베딩·저장 단계로 넘어가지 않는다.
2. **Given** 같은 자료, **When** 판정 기록을 본다, **Then** 자료원, 원본 식별자, 위치, 걸린 규칙 이름, 줄 번호가 나오고 비밀값 원문,
   앞뒤 문맥, 일부를 가린 값은 나오지 않는다.
3. **Given** `<github-token>`, `${GITHUB_TOKEN}`, `example` 같은 placeholder만 든 설정 예시 파일, **When** 필터를 지난다, **Then** 차단하지 않는다.
4. **Given** 사람이 검토해 오탐 예외 목록에 (경로, 규칙 이름, 사유)로 올린 자료, **When** 필터를 지난다, **Then** 그 경로의 그 규칙만 건너뛰고
   다른 규칙은 그대로 적용한다.
5. **Given** 필터를 통과한 자료로 만든 청크나 질의 문맥, **When** 임베딩·생성 API로 보내기 직전에 검사한다, **Then** 비밀값 규칙에 걸리면
   그 요청을 보내지 않는다.

### User Story 2 - 팀 공용으로 확인한 자료만 검색 대상이 된다 (Priority: P1)

수집기가 넘긴 원본 권한 정보(QK-ING-001 `AccessInfo`)를 자료원 종류별 규칙으로 판정해 접근 범위 값(팀 공용·제한·미확인)을 붙인다.
원본 정보만으로 팀 공용임을 확인할 수 없으면 "미확인"이다. 팀 공용이 아닌 자료는 본문을 받지 않고 청킹·임베딩·저장도 하지 않으므로, 외부 API로 나가지 않고 답변에도 나오지 않는다.

**Why this priority**: C-14와 AGENTS.md 3.1("권한을 확인할 수 없는 자료는 검색 결과에 노출하지 않는다"), 로드맵 1.G 완료 조건
"접근 범위를 확인할 수 없는 샘플 문서가 검색되지 않는다"의 판정 쪽 절반이다. QK-STO-001은 값 체계와 판정을 이 명세에 넘겼다.

**Independent Test**: 원본 권한 정보가 "공개 저장소", "비공개 저장소", "정보 없음", "모순된 값"인 가짜 자료와 판정 규칙이 등록되지 않은 자료원 종류의
자료를 흘린다. 공개 저장소만 팀 공용으로 통과하고, 나머지는 본문 조회 없이 "접근 범위 보류"로 빠져야 한다.

**Acceptance Scenarios**:

1. **Given** 원본 권한 정보가 "미확인"인 자료, **When** 판정한다, **Then** 접근 범위는 "미확인"이고, "접근 범위 보류"로 빠져 본문을 조회하지 않는다.
2. **Given** 공개 범위가 "공개"인 GitHub 저장소의 파일, **When** 판정한다, **Then** 접근 범위는 "팀 공용"이고, 판정에 쓴 규칙 이름과 원본 권한 원값이 함께 남는다.
3. **Given** 공개 범위가 "비공개" 또는 "내부"인 GitHub 저장소의 파일, **When** 판정한다, **Then** 접근 범위는 "팀 공용"이 아니다.
4. **Given** 접근 판정 규칙이 등록되지 않은 자료원 종류의 자료, **When** 판정한다, **Then** 접근 범위는 "미확인"이다.
5. **Given** 원본 권한 정보에 서로 모순되는 값이나 규칙이 모르는 값이 있는 자료, **When** 판정한다, **Then** 팀 공용으로 올리지 않고 "미확인"으로 둔다.

### User Story 3 - 색인하면 안 되는 경로는 자료원 설정과 상관없이 빠진다 (Priority: P2)

환경 설정 파일, 개인 키, 비밀 디렉터리, 인프라 상태 파일, 의존성·빌드 산출물 같은 경로는 자료원 설정의 포함 패턴이 무엇이든 항상 빠진다.
경로만으로 판정하므로 본문을 받기 전에 걸러서, 원본 호출도 아끼고 본문이 메모리에 올라오지도 않게 한다.

**Why this priority**: 비밀값 패턴 검사는 알려진 형식만 잡는다. 형식을 모르는 비밀값이 든 파일(`.env`, 키 파일)은 경로로 막아야 한다.
다만 자료원 설정의 포함 패턴(QK-ING-001 FR-012)이 Phase 1에서는 `**/*.md` 정도로 좁아서, 이 규칙이 실제로 걸리는 일은 Phase 2 코드 수집부터 늘어난다. 그래서 P2로 둔다.

**Independent Test**: 기본 제외 범주마다 경로 사례를 만들고, 자료원 설정의 포함 패턴이 그 경로를 포함하도록 해서 가짜 자료원으로 흘린다.
모두 빠지고, 그 자료의 본문 조회 요청이 0건이어야 한다.

**Acceptance Scenarios**:

1. **Given** 포함 패턴이 `**`인 자료원에 `.env`, `config/.env.production`, `secrets/db.txt`, `deploy/id_rsa` 경로가 있음, **When** 필터를 지난다,
   **Then** 모두 "경로 제외"로 판정되고 본문을 조회하지 않는다.
2. **Given** `.env.example`, `terraform.tfvars.example` 같은 예시 파일, **When** 필터를 지난다, **Then** 경로로 빼지 않고 비밀값 검사로 넘긴다.
3. **Given** 자료원 설정이 기본 제외 규칙을 해제하려는 항목을 가짐, **When** 설정을 검증한다, **Then** 검증이 실패한다.
4. **Given** `./docs/../.ENV`처럼 표기가 다른 경로, **When** 필터를 지난다, **Then** 경로를 정규화해 같은 규칙으로 뺀다.

---

### User Story 4 - 운영 담당자가 막힌 자료와 이유를 검토한다 (Priority: P2)

실행이 끝나면 통과·경로 제외·비밀값 차단·접근 범위별 자료 수와 규칙별 건수가 요약되고, 자료별 판정 기록이 남는다. 운영 담당자는 이 기록으로
오탐을 찾아 예외 목록에 올리거나, 막혔어야 할 자료가 통과한 사례를 찾는다. 규칙이 바뀌면 판정 기록의 규칙 버전으로 다시 판정할 자료를 알 수 있다.

**Why this priority**: RISK-09 대응에 "차단 기록 검토"가 들어 있다. 기록이 없으면 오탐으로 빠진 문서와 새는 비밀값을 모두 찾을 수 없다.
다만 판정 자체(US1~3)가 먼저 동작해야 의미가 있어 P2로 둔다.

**Independent Test**: US1~3 시험 자료를 한 번에 흘린 뒤 실행 요약과 판정 기록을 본다. 건수가 실제 판정과 맞고, 비밀값 원문이 없어야 한다.

**Acceptance Scenarios**:

1. **Given** 통과 5건, 경로 제외 2건, 비밀값 차단 1건, 접근 범위 미확인 1건인 실행, **When** 요약을 본다, **Then** 결정별·규칙별 건수가 그대로 나온다.
2. **Given** 비밀값 규칙이나 기본 제외 규칙, 오탐 예외 목록, 접근 판정 규칙이 바뀐 뒤, **When** 판정 기록을 본다, **Then** 기록마다 판정 당시의
   보안 규칙 버전이 있어 현재 버전과 다른 자료를 골라낼 수 있다.

---

### Edge Cases

- 필터 자체가 오류를 낸 자료(규칙 실행 실패, 예상하지 못한 입력): 통과시키지 않는다. "판정 실패"로 기록하고 다음 자료를 처리한다(C-08).
- 비밀값이 제목이나 위치(경로)에 든 자료: 본문과 같은 규칙으로 검사한다. 위치는 판정 기록에 남으므로, 위치에서 비밀값이 나오면 기록의 위치도 비밀값 원문 없이 남긴다.
- 여러 줄에 나뉘었거나 인코딩(base64 등)된 비밀값: 패턴 검사로 못 잡을 수 있다. 이 한계는 경로 제외(US3)와 커밋 전 검사(`preflight.py`)로 보완하고, 판정 기록 검토(US4)에서 찾는다.
- 테스트 자료 안의 가짜 토큰: 형식이 맞으면 차단한다. 필요하면 오탐 예외로 올린다. 예외 없이 자동으로 풀어 주는 경로는 두지 않는다.
- 이전 실행에서 통과한 자료가 규칙 변경 뒤 차단 대상이 됨: 다음 실행에서 다시 판정한다. 이미 저장된 청크를 검색에서 내리는 일은 QK-SYN-001이 한다.
- 원본 권한이 공개에서 비공개로 바뀐 자료: 다음 실행에서 팀 공용이 아니게 판정된다. 검색에서 내리는 일은 QK-SYN-001이 한다.
- 자료가 제외 경로로 이동했거나 이름이 바뀐 경우: 새 위치 기준으로 판정한다.
- 오탐 예외 목록에 사유가 없거나, 경로 없이 규칙 전체를 끄는 항목이 있는 경우: 예외 목록 검증이 실패하고 실행 전에 멈춘다.
- 본문이 아주 크거나 줄이 아주 긴 자료: 크기 상한은 QK-ING-001이 먼저 거른다. 필터는 크기 때문에 검사를 건너뛰지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

**공통 (US1~4)**

- **FR-001**: 수집기가 넘긴 모든 자료는 청킹 전에 보안 필터를 지난다. 필터를 끄거나 특정 자료원·자료 종류에서 건너뛰는 설정은 두지 않는다.
  필터는 자료원 종류와 상관없이 QK-ING-001 공통 형식만 입력으로 받는다(C-06).
- **FR-002**: 판정 순서는 경로 제외 → 접근 범위 → 비밀값이다. 경로 제외와 접근 범위는 자료 목록 항목만으로 판정해, 앞 단계에서 빠진 자료는
  본문을 조회하지 않는다.
- **FR-003**: 자료마다 판정 결과는 통과, 경로 제외, 비밀값 차단, 접근 범위 보류, 판정 실패 중 하나다. 통과한 자료에는 접근 범위 값(항상 팀 공용, FR-018)이 붙는다.
- **FR-004**: 필터 오류가 나면 그 자료는 통과시키지 않고 "판정 실패"로 기록한다. 한 자료의 판정 실패가 다른 자료의 판정을 멈추지 않는다(C-08).
- **FR-005**: 필터는 원본에 쓰지 않고, 외부 API를 호출하지 않는다(C-09).

**색인 제외 경로 (US3)**

- **FR-006**: 자료원 설정과 별개로 항상 적용하는 기본 제외 규칙을 둔다. 최소한 다음 범주를 포함한다.
  환경 설정·비밀값 파일(`.env` 계열, 단 example·sample·template 예시 파일은 제외하지 않고 비밀값 검사로 넘긴다),
  개인 키·인증서·키 저장소 파일, 비밀값 디렉터리(`secrets/` 등), 인프라 상태·변수 파일(Terraform state, 실제 값이 든 tfvars),
  의존성·빌드 산출물·도구 캐시 디렉터리, 버전 관리 내부 디렉터리. 범주별 패턴 목록은 `plan.md`에서 확정한다.
- **FR-007**: 자료원 설정은 제외 규칙을 더할 수 있지만 기본 제외 규칙을 해제할 수 없다. 해제하려는 설정은 검증에서 실패한다.
  자료원 설정의 포함 패턴이 기본 제외 경로를 포함해도 제외가 이긴다(QK-ING-001 FR-012와 같은 방향).
- **FR-008**: 경로는 정규화(`./`·`..`·중복 구분자 정리)한 뒤 비교한다. 기본 제외 규칙은 대소문자를 구분하지 않는다.

**비밀값 차단 (US1)**

- **FR-009**: 비밀값 규칙은 저장소 커밋 검사(`scripts/preflight.py`)와 한 벌로 관리해 둘이 갈라지지 않게 한다. 현재 규칙(개인 키, 클라우드·서비스 토큰,
  비밀번호가 든 DB 연결 주소, 비밀값 이름에 할당된 값 등)을 모두 포함한다. Phase 1 토큰 목록(`tokens.md`)에 있는데 규칙이 없는 종류를 더할지는
  `plan.md`에서 오탐률을 보고 정한다.
- **FR-010**: 검사 대상은 본문, 제목, 위치다. 비밀값 규칙의 예외인 placeholder(`<...>`, `${...}`, example·redacted·changeme 같은 표시)는 차단하지 않는다.
- **FR-011**: 비밀값 규칙에 하나라도 걸린 자료는 자료(문서) 전체를 청킹·임베딩·저장하지 않는다. 비밀값이 든 부분만 빼거나 값을 가리고 색인하지 않는다
  (2026-10-19 사용자 결정, 로드맵 1.G "비밀값을 심은 샘플 파일이 색인되지 않는다").
- **FR-012**: 오탐 예외는 저장소 안의 예외 목록에 (경로, 규칙 이름, 사유)로 적고, 사람이 PR로 검토한다. 사유가 없는 항목, 경로 없이 규칙 전체를 끄는 항목은
  검증에서 실패한다. 예외는 그 경로의 그 규칙에만 적용된다.
- **FR-013**: 임베딩·생성 API로 보낼 텍스트를 보내기 직전에 같은 비밀값 규칙과 예외 목록으로 다시 검사하는 동작(전송 직전 검사)을 제공한다.
  걸리면 그 요청을 보내지 않고 기록한다. 전송 직전 검사를 실제 임베딩·생성 호출에 연결하는 일은 QK-EMB-001과 QK-GEN-001이 한다.

**접근 범위 판정 (US2)**

- **FR-014**: 접근 범위 값은 팀 공용, 제한, 미확인 세 가지다. 팀 공용만 검색 대상이다(QK-STO-001 FR-008). 값 이름은 QK-STO-001 저장 스키마와 맞춘다.
- **FR-015**: 접근 판정 규칙은 자료원 종류마다 등록한다. 규칙이 등록되지 않은 종류의 자료는 미확인이다. 새 자료원 종류의 규칙은 그 종류를 추가하는
  명세가 정하고, 규칙을 추가할 때 필터 공통 동작은 바뀌지 않는다.
- **FR-016**: 원본 권한 정보가 미확인이면 접근 범위도 미확인이다. 원본 권한 정보가 규칙의 팀 공용 조건을 모두 만족할 때만 팀 공용으로 판정한다.
  모순되는 값이나 규칙이 모르는 값이 있으면 미확인으로 둔다. 판정은 확인되지 않은 쪽을 팀 공용으로 올리는 방향으로 추측하지 않는다.
- **FR-017**: Phase 1 GitHub 저장소 파일 규칙: 저장소 공개 범위가 "공개"이면 팀 공용, "비공개"·"내부"이면 미확인, 정보가 없으면 미확인이다.
  비공개 저장소를 팀 공용으로 판정하려면 결정 기록(AGENTS.md 3.1)과 이 규칙 변경이 필요하다. 가짜 자료원 규칙은 시험용 원본 권한 값으로 세 값을 모두 만들 수 있게 한다.
- **FR-018**: 접근 범위가 미확인·제한인 자료는 "접근 범위 보류"로 판정하고 본문을 조회하지 않으며 청킹·임베딩·저장하지 않는다. 그래서 필터를 통과한 자료의
  접근 범위는 항상 팀 공용이다. 나중에 팀 공용으로 확인되면 다음 동기화에서 처음부터 색인한다(2026-10-19 사용자 결정). QK-STO-001 FR-008의 검색 필터는
  저장 단계의 방어선으로 그대로 둔다.
- **FR-019**: 판정 결과에 원본 권한 원값과 적용한 규칙 이름을 함께 남긴다(C-14 원본 권한 보존).

**기록과 규칙 버전 (US4)**

- **FR-020**: 자료별 판정 기록에는 자료원, 원본 식별자, 위치, 판정 결과, 판정 단계, 걸린 규칙 이름, 비밀값이면 줄 번호, 보안 규칙 버전을 담는다.
  비밀값 원문, 앞뒤 문맥, 일부를 가린 값은 판정 기록·실행 요약·로그 어디에도 남기지 않는다(AGENTS.md 6절).
- **FR-021**: 실행마다 판정 결과별·규칙별·접근 범위별 건수를 요약한다.
- **FR-022**: 기본 제외 규칙, 비밀값 규칙, 오탐 예외 목록, 접근 판정 규칙 중 하나라도 바뀌면 보안 규칙 버전이 바뀐다. 판정 기록에 버전을 남겨
  다시 판정할 자료를 고를 수 있게 한다. 버전이 바뀐 자료를 언제 다시 판정하고 검색에서 내릴지는 QK-SYN-001이 정한다.
  보안 규칙 버전 변경은 인덱스 버전 변경(AGENTS.md 3.3)이 아니다. 통과한 자료의 청크 경계와 메타데이터 스키마는 바뀌지 않기 때문이다.

### Key Entities

- **보안 판정(Security Verdict)**: 자료 하나의 판정 결과. 자료원, 원본 식별자, 위치, 결과(통과·경로 제외·비밀값 차단·접근 범위 보류·판정 실패),
  판정 단계, 걸린 규칙 이름, 줄 번호, 접근 범위, 원본 권한 원값, 보안 규칙 버전.
- **접근 범위(Access Scope)**: 팀 공용·제한·미확인. QK-STO-001 원본 자료 항목의 "접근 범위" 값이다.
- **접근 판정 규칙(Access Rule)**: 자료원 종류별로 원본 권한 정보를 접근 범위로 바꾸는 규칙. Phase 1은 GitHub 저장소 파일과 가짜 자료원.
- **기본 제외 규칙(Default Exclusion)**: 항상 적용하는 경로 제외 범주와 패턴. 자료원 설정이 해제할 수 없다.
- **비밀값 규칙(Secret Rule)**: 규칙 이름과 탐지 패턴, placeholder 예외. 커밋 검사와 한 벌이다.
- **오탐 예외(Secret Exception)**: (경로, 규칙 이름, 사유). 사람이 검토한다.
- **보안 규칙 버전(Security Rules Version)**: 위 규칙과 예외 목록 전체를 가리키는 버전.
- **실행 요약(Filter Summary)**: 실행 단위의 결과별·규칙별·접근 범위별 건수.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 비밀값 규칙마다 1건 이상 비밀값을 심은 샘플 세트에서 차단율이 100%이고, 차단된 자료가 청킹·임베딩·저장 단계로 넘어간 건수가 0이다.
  같은 세트의 placeholder 샘플은 차단 0건이다.
- **SC-002**: 비밀값을 넣은 텍스트로 전송 직전 검사를 시험할 때 보내진 요청이 0건이다.
- **SC-003**: 기본 제외 범주마다 1건 이상 경로 사례를 만들고 자료원 포함 패턴이 그 경로를 포함하게 한 시험에서 100% 제외되고, 그 자료의 본문 조회 요청이 0건이다.
- **SC-004**: 접근 범위 시험에서 원본 권한 미확인·비공개·모순·규칙 미등록 사례 중 팀 공용으로 판정된 건수가 0이고, 그 자료의 본문 조회 요청과
  청킹·임베딩·저장 단계로 넘어간 건수가 0이다. 공개 저장소 사례는 100% 팀 공용으로 통과한다.
- **SC-005**: 판정 기록, 실행 요약, 로그 전체를 커밋 검사 규칙으로 검사했을 때 비밀값이 발견된 건수가 0이다.
- **SC-006**: 두 번째 가짜 자료원 종류의 접근 판정 규칙을 추가하는 변경에서 필터 공통 동작 코드 변경이 0줄이다.
- **SC-007**: 필터 오류를 주입한 시험에서 오류가 난 자료가 통과한 건수가 0이고, 나머지 자료는 100% 판정된다.
- **SC-008**: Phase 1 대상 규모(Markdown 81개, 약 1.1 MB, 0.2 인벤토리)의 자료를 필터에 통과시키는 데 1분이 넘지 않는다.

**범위**

- 실제 GitHub 수집기는 QK-ING-002 범위다. GitHub 원본 권한 정보(저장소 공개 범위)를 `AccessInfo`에 담는 일은 QK-ING-002가 하고,
  이 명세는 그 값을 읽는 규칙(FR-017)을 정한다.
- 청크 단위 처리와 검색 헤더 생성은 QK-CHK-002, 전송 직전 검사를 실제 호출에 연결하는 일은 QK-EMB-001·QK-GEN-001 범위다.
- 재판정 시점, 이미 저장된 청크를 검색에서 내리는 일, 판정 기록의 영구 저장은 QK-SYN-001과 QK-STO-001 범위다. 이 명세는 판정 기록과 요약을 만들어 넘긴다.
- 질의 원문 안의 비밀값 처리(사용자가 `/ask`에 토큰을 붙여 넣은 경우)와 질의 로그 저장은 QK-BOT-001·QK-OBS-001 범위다. 전송 직전 검사(FR-013)를 그쪽에서도 쓸 수 있다.
- ClickUp Doc 접근 판정 규칙은 ClickUp 수집 명세(QK-ING-003)가 정한다. 0.3 조사는 `public`·`hidden`·`permission_level`·Folder 비공개 여부만으로
  팀 전체 접근을 판정할 수 없다고 했고(F-06, F-13), Doc별 사람 확인 허용 목록을 잠정 제안했다. 이 명세의 규칙 등록 방식(FR-015)은 그 제안을 담을 수 있어야 한다.
- 개인 정보(이름, 연락처) 탐지는 다루지 않는다. Phase 1 대상은 저장소 Markdown 문서이고, 개인 페이지·비공개 대화는 자료원 설정 단계에서 색인 대상이 아니다(AGENTS.md 3.1).

**환경과 기본값**

- Phase 1 GitHub 토큰은 공개 저장소 읽기만 할 수 있다(`tokens.md` 2절). 그래서 Phase 1 대상 저장소의 파일은 FR-017에 따라 팀 공용으로 판정될 것으로 본다.
- 패턴 기반 비밀값 검사는 알려진 형식만 잡는다. 형식을 모르는 비밀값은 경로 제외와 커밋 전 검사가 보완하고, 남는 위험은 판정 기록 검토로 줄인다.
- 오탐 예외 목록은 커밋 검사의 예외 목록(`scripts/preflight_allowlist.txt`)과 같은 형식(경로, 규칙 이름, 사유)을 쓴다. 둘을 한 파일로 합칠지는 `plan.md`에서 정한다.
- 성능 기준(SC-008)은 Phase 1 규모 기준의 초기값이다. Phase 2 코드 수집에서 규모가 커지면 다시 정한다.
