# Feature Specification: QK-EMB-001 임베딩 Provider·캐시·사용량 기록·일일 예산·실행 전 미리 보기

**Feature Branch**: `docs/SCRUM-42-emb-001-spec`

**Created**: 2026-10-20

**Status**: Draft

**Input**: 로드맵 4절 명세 백로그 QK-EMB-001 "임베딩 Provider(Workers AI), 캐시, 사용량 기록, 일일 예산, 실행 전 사용량 미리 보기".
선행은 QK-STO-001(병합됨, #36)이다. 백로그 행의 요구사항 ID(FR-EMB-01~04, 06)는 원문이 없어(Assumptions 참조) 백로그 제목,
constitution C-05·C-06·C-07, ADR-002, ADR-008, `docs/sdd/research/spike-workers-ai.md`(W-02~W-04, 6절), QK-STO-001 US5를 근거로 썼다.

## Clarifications

### Session 2026-10-20

- Q: 하루 무료 할당 10,000 Neurons를 색인과 질의응답에 어떻게 나누나? → A: 색인 예산 5,000, 질의응답 예비분 3,000, 나머지 2,000은 여유분(FR-017).
- Q: 실행 전 미리 보기가 "예산 초과"면 색인 실행의 기본 동작은? → A: 실행하지 않는다. 사람이 명시적으로 고를 때만 예산 안 부분 실행(FR-024).
- Q: Workers에서 도는 질의 임베딩의 사용량도 색인과 같은 저장소에 호출마다 기록하나? → A: 기록한다. 질의 원문은 기록하지 않는다(FR-013, FR-016).
- Q: 호출별 사용량 기록은 얼마나 보관하나? → A: 90일(FR-025).
- Q: 비밀값 검사는 "통과 표시"로 확인하나, 보내기 직전에 다시 검사하나? → A: QK-SEC-001이 구현한 전송 직전 검사(`check_outgoing`)를
  제공자 호출 직전에 부른다. 색인용은 출처(자료원·경로)를 함께 넘겨 그 출처의 예외만 적용하고, 질의용은 출처 없이 검사한다(FR-005, 2026-10-20 QK-SEC-001 병합 반영).

## User Scenarios & Testing *(mandatory)*

이 명세의 사용자는 임베딩을 부르는 후속 명세 구현자(QK-SYN-001 동기화, QK-RET-001 검색), 색인을 실행하는 운영 담당자,
비용을 확인하는 PR 리뷰어다. 최종 사용자(Discord에서 질문하는 팀원)는 이 명세를 직접 보지 않지만, "색인이 하루 할당을 다 써서
질문에 답하지 못하는 상황"을 막는 장치는 여기서 시작한다(C-05).

### User Story 1 - 텍스트 묶음을 정해진 모델의 벡터로 바꾼다 (Priority: P1)

동기화·검색 구현자가 텍스트 묶음과 용도(색인용 문서 또는 검색용 질의)를 넘기면, 임베딩 경계는 활성 인덱스 버전의 임베딩 모델
(ADR-002: `@cf/baai/bge-m3`, 1,024차원)로 만든 벡터를 입력 순서대로 돌려준다. 결과마다 모델 버전과 차원이 함께 온다.
호출하는 쪽은 외부 제공자 고유의 타입이나 오류 코드를 보지 않는다.

**Why this priority**: 색인(QK-SYN-001)과 검색(QK-RET-001)이 모두 이 경계 없이는 시작할 수 없다. C-06(교체할 수 있는 경계)과
C-07(같은 입력·같은 모델이면 같은 벡터, 모델 버전 추적)의 바탕이다.

**Independent Test**: 외부 호출 없이 동작하는 가짜 임베딩 제공자로 텍스트 3개를 넘겨, 벡터 3개가 입력 순서대로 1,024차원으로
나오고 모델 버전이 붙는지 본다. 제공자 고유 타입이 결과에 없는지 본다.

**Acceptance Scenarios**:

1. **Given** 텍스트 3개, **When** 색인용으로 임베딩을 요청한다, **Then** 벡터 3개가 입력 순서대로 나오고 각각 모델 버전과 차원 1,024가 붙는다.
2. **Given** 모델 입력 한도(8,192토큰)를 넘는 텍스트 하나가 섞인 묶음, **When** 임베딩을 요청한다, **Then** 그 텍스트는 잘라서 임베딩하지 않고
   "입력 한도 초과"로 표시돼 돌아오며, 나머지 텍스트는 정상 처리된다.
3. **Given** 제공자가 일시 오류를 낸 상태, **When** 임베딩을 요청한다, **Then** 정해진 횟수 안에서 다시 시도하고, 끝내 실패하면
   "일시 실패"로 구분해 돌려준다.
4. **Given** 제공자가 무료 할당 소진을 알린 상태, **When** 임베딩을 요청한다, **Then** 다시 시도하지 않고 "제공자 할당 소진"으로 구분해 돌려준다.
5. **Given** 빈 문자열이나 공백뿐인 텍스트, **When** 임베딩을 요청한다, **Then** 외부 호출 없이 "빈 입력"으로 거부된다.

### User Story 2 - 변경이 없는 텍스트는 다시 임베딩하지 않는다 (Priority: P1)

동기화 구현자가 같은 텍스트를 같은 모델로 다시 임베딩하려 하면, 임베딩 경계는 저장된 벡터를 돌려주고 외부 호출을 하지 않는다.
캐시는 (임베딩 입력 해시, 모델 버전)으로 찾는다(QK-STO-001 US5·FR-003).

**Why this priority**: 1.G 완료 조건 "변경이 없는 재동기화에서 임베딩 호출이 0건이다"를 직접 만족시키는 기능이다. 비용(C-05)과도 바로 이어진다.

**Independent Test**: 같은 텍스트 10개를 두 번 연속 임베딩한다. 두 번째 실행에서 외부 호출 0건, 소비 사용량 0, 결과 벡터가 첫 번째와 같은지 본다.

**Acceptance Scenarios**:

1. **Given** 텍스트 10개를 한 번 임베딩해 저장한 상태, **When** 같은 10개를 다시 임베딩한다, **Then** 외부 호출이 0건이고 같은 벡터가 나온다.
2. **Given** 같은 상태에서 텍스트 1개만 바뀐 묶음, **When** 임베딩한다, **Then** 바뀐 1개만 외부로 보낸다.
3. **Given** 같은 텍스트, **When** 활성 모델 버전이 다른 상태에서 임베딩한다, **Then** 캐시를 쓰지 않고 새로 임베딩한다.
4. **Given** 한 묶음 안에 같은 텍스트가 두 번 들어 있음, **When** 임베딩한다, **Then** 외부로는 한 번만 보내고 두 자리 모두 같은 벡터를 받는다.
5. **Given** 검색용 질의, **When** 임베딩한다, **Then** 질의 벡터는 캐시에 저장하지 않는다(질의 원문 저장 정책 ADR-016과 분리).

### User Story 3 - 모든 외부 호출의 사용량을 남긴다 (Priority: P1)

운영 담당자와 리뷰어는 하루 동안 임베딩에 쓴 Neurons를 용도(색인·질의), 실행 단위, 모델별로 볼 수 있다. 외부 호출 한 번마다
제공자가 알려 준 실제 사용량을 기록하고, 제공자가 사용량을 알려 주지 않은 호출은 추정값으로 기록하되 추정임을 표시한다.

**Why this priority**: 일일 예산(US4)은 이 기록 없이는 판정할 수 없다. AGENTS.md 3.4·3.5는 비용 수치를 조건과 함께 남기라고 한다.
스파이크 W-04는 응답 헤더의 사용량으로 호출 단위 집계가 가능하다고 확인했다.

**Independent Test**: 가짜 제공자가 호출마다 정해진 사용량을 알려 주게 하고 색인용 3회·질의용 2회를 호출한다. 하루 합계, 용도별 합계,
실행 단위 합계가 가짜 제공자 값의 합과 같은지 본다. 사용량을 알려 주지 않는 호출을 하나 섞어 "추정"으로 표시되는지 본다.

**Acceptance Scenarios**:

1. **Given** 외부 호출 1회, **When** 호출이 끝난다, **Then** 시각, 용도, 실행 식별자, 모델 버전, 입력 개수, 입력 크기, 소비 Neurons, 결과(성공·실패 종류),
   측정·추정 구분이 기록된다.
2. **Given** 캐시로만 처리된 요청, **When** 끝난다, **Then** 소비 Neurons 0과 캐시 적중 개수가 실행 단위 요약에 남는다.
3. **Given** 실패한 외부 호출(입력 한도 초과 등), **When** 끝난다, **Then** 제공자가 사용량을 알려 주지 않아도 실패 기록이 남는다.
4. **Given** 하루 동안의 기록, **When** 운영 담당자가 사용량을 조회한다, **Then** 하루 합계, 용도별 합계, 남은 예산이 나온다. 하루 경계는
   제공자 할당 초기화 시각(00:00 UTC, 한국 시간 09:00)이다.
5. **Given** 사용량 기록, **When** 내용을 본다, **Then** 텍스트 원문은 들어 있지 않다.

### User Story 4 - 색인이 질의응답 몫을 쓰지 않게 일일 예산을 지킨다 (Priority: P1)

운영 담당자가 색인 예산과 질의응답 예비분을 설정하면, 색인용 임베딩은 그날의 색인 예산 안에서만 실행된다. 예산이 모자라면 색인은
새 외부 호출을 멈추고, 이미 끝난 결과는 유지하며, 나머지는 다음 날로 미룬다. 질의용 임베딩은 색인 예산 소진과 관계없이 계속된다.

**Why this priority**: C-05 "예산이 부족하면 색인보다 질의응답을 우선한다"와 스파이크 6절 "할당을 넘으면 다음 날 09:00까지 질의응답이 멈춘다"를
막는 장치다. AGENTS.md 3.5는 한도를 넘을 것으로 보이면 실행하지 않도록 요구한다.

**Independent Test**: 색인 예산을 작게(예: 10 Neurons) 설정하고 그보다 큰 색인을 실행한다. 예산 안에서 멈추는지, 멈춘 이유가 "색인 예산 소진"으로
보고되는지, 같은 날 질의용 임베딩이 계속 되는지 본다.

**Acceptance Scenarios**:

1. **Given** 그날 색인에 쓴 양이 색인 예산에 닿은 상태, **When** 색인용 임베딩을 요청한다, **Then** 외부 호출 없이 "색인 예산 소진"으로 거부된다.
2. **Given** 같은 상태, **When** 질의용 임베딩을 요청한다, **Then** 정상 처리된다.
3. **Given** 남은 색인 예산보다 큰 색인용 묶음, **When** 임베딩을 요청한다, **Then** 예산 안에 드는 앞부분만 처리하고 나머지는 "색인 예산 소진"으로
   돌려준다. 처리된 결과는 저장돼 다음 실행에서 캐시로 쓰인다.
4. **Given** 하루 경계(00:00 UTC)가 지난 뒤, **When** 색인용 임베딩을 요청한다, **Then** 새 하루 예산으로 처리된다.
5. **Given** 질의용 사용량이 질의응답 예비분을 넘은 날, **When** 그 사실이 생긴다, **Then** 질의는 막지 않고 경고를 기록한다.
6. **Given** 색인 예산 + 질의응답 예비분이 하루 무료 할당(10,000 Neurons)을 넘는 설정, **When** 설정을 불러온다, **Then** 설정 검사가 실패한다.

### User Story 5 - 색인을 돌리기 전에 예상 사용량을 본다 (Priority: P2)

운영 담당자가 색인을 실행하기 전에 미리 보기를 요청하면, 외부 호출 없이 이번 실행이 임베딩할 텍스트 개수, 캐시로 처리될 개수,
예상 Neurons, 그날 남은 색인 예산, 실행 가능 여부를 본다. 예상 사용량이 남은 예산을 넘으면 미리 보기가 "예산 초과"로 판정하고,
그 판정은 실제 실행을 막는 데도 쓰인다.

**Why this priority**: AGENTS.md 3.5 "무료 한도를 넘길 수 있는 색인 작업은 실행 전에 예상 사용량을 적는다"를 사람과 자동화 모두가 지킬 수 있게 한다.
US4가 실행 중 가드라면 이 기능은 실행 전 가드다. US4만으로도 할당은 지킬 수 있어 P2로 둔다.

**Independent Test**: 텍스트 묶음(일부는 캐시에 있음)으로 미리 보기를 실행한다. 외부 호출이 0건인지, 캐시 적중 개수가 맞는지,
예상값이 실제 실행 사용량과 정해진 오차 안인지 본다.

**Acceptance Scenarios**:

1. **Given** 텍스트 100개 중 60개가 캐시에 있음, **When** 미리 보기를 요청한다, **Then** 새 임베딩 40개, 캐시 60개, 40개분 예상 Neurons,
   남은 색인 예산, 실행 가능 여부가 나오고 외부 호출은 0건이다.
2. **Given** 예상 사용량이 남은 색인 예산을 넘는 묶음, **When** 미리 보기를 요청한다, **Then** "예산 초과"로 판정되고 필요한 양과 남은 양이 함께 나온다.
3. **Given** 미리 보기가 "예산 초과"인 실행, **When** 운영 담당자가 실행을 요청한다, **Then** 기본 동작은 실행하지 않는 것이다. 사람이 명시적으로
   "예산 안에서 부분 실행"을 고른 경우에만 US4-3처럼 진행한다.
4. **Given** 입력 한도를 넘는 텍스트가 섞인 묶음, **When** 미리 보기를 요청한다, **Then** 그 텍스트가 "입력 한도 초과 예상"으로 따로 표시된다.

### Edge Cases

- 제공자가 사용량을 알려 주지 않는 성공 호출(헤더 누락): 입력 크기로 추정해 기록하고 "추정"으로 표시한다. 예산 판정에는 추정값을 쓴다.
- 사용량 기록 저장이 실패했을 때: 그 호출의 결과는 돌려주되, 색인용이면 다음 외부 호출을 멈춘다. 기록 없는 소비가 쌓이면 예산을 판정할 수 없다.
- 같은 날 색인 실행 두 개가 동시에 돌 때: 둘의 사용량 합으로 예산을 판정한다. 둘이 합쳐 예산을 넘지 않는다(예산 판정과 기록이 엇갈려 초과하는 폭은
  묶음 하나의 예상 사용량 이하로 제한한다).
- 제공자가 "할당 소진"을 알렸는데 우리 기록상 남은 양이 있을 때: 제공자 판정을 따르고 그날 색인을 멈추며, 기록과 제공자 사이 차이를 경고로 남긴다.
- 활성 인덱스 버전이 없을 때: 어느 모델로 임베딩할지 정할 수 없으므로 "활성 인덱스 없음"으로 거부한다.
- 모델 버전이 바뀌었을 때(새 인덱스 버전 준비 중): 색인 실행은 대상 인덱스 버전의 모델을 명시적으로 받는다. 활성 버전 모델만 가정하지 않는다.
  인덱스 버전 활성화 절차는 QK-STO-002 몫이다.
- 묶음 크기가 제공자 한 요청 한도를 넘을 때: 여러 요청으로 나눠 보내고 결과 순서는 입력 순서를 유지한다.
- 돌려받은 벡터 차원이 기대와 다를 때: 저장하지 않고 "제공자 응답 이상"으로 실패 처리한다(QK-STO-001 FR-004와 같은 기준).
- 비밀값 규칙에 걸리는 텍스트: 수집 단계 검사(QK-SEC-001)를 통과했더라도 보내기 직전에 다시 검사해 걸리면 보내지 않는다(AGENTS.md 3.1).
  색인용 입력에 출처(자료원·경로)가 없으면 예외를 적용할 수 없으므로 외부 호출 없이 거부한다.

## Requirements *(mandatory)*

### Functional Requirements

**임베딩 경계 (US1)**

- **FR-001**: 텍스트 묶음과 용도(색인용 문서·검색용 질의), 대상 모델 버전을 받아 입력 순서대로 벡터를 돌려주는 임베딩 경계를 제공한다.
  결과마다 모델 버전과 차원을 붙인다. 경계의 입력·출력·오류에 외부 제공자 고유 타입이나 오류 코드가 나오지 않는다(C-06).
- **FR-002**: 첫 제공자는 Cloudflare Workers AI의 `@cf/baai/bge-m3`(1,024차원)다(ADR-002). 모델 식별자, 차원, 입력 한도(8,192토큰),
  사용량 단가는 설정값으로 두고, 카탈로그가 알려 주는 값을 그대로 쓰지 않는다(스파이크 W-03).
- **FR-003**: 모델 입력 한도를 넘는 텍스트는 자르지 않는다. 제공자의 자르기 옵션을 켜지 않고, 해당 텍스트를 "입력 한도 초과"로 돌려준다.
  한 텍스트의 한도 초과가 같은 묶음의 다른 텍스트 처리를 막지 않는다(스파이크 W-02, C-07).
- **FR-004**: 실패를 다음 종류로 구분해 돌려준다: 빈 입력, 입력 한도 초과, 일시 실패(재시도 뒤), 제공자 할당 소진, 색인 예산 소진,
  인증·설정 오류, 제공자 응답 이상(차원·개수 불일치). 일시 실패만 정해진 횟수 안에서 다시 시도한다. 할당 소진과 예산 소진은 다시 시도하지 않는다.
- **FR-005**: 제공자로 보내기 직전에 보낼 텍스트마다 QK-SEC-001의 전송 직전 검사(QK-SEC-001 FR-013)를 거친다. 색인용 입력은 출처(자료원 이름, 경로)를
  함께 받아 그 출처의 오탐 예외만 적용하고, 질의용 입력은 출처 없이 예외 없이 검사한다. 걸린 텍스트는 보내지 않고 "비밀값 차단"으로 돌려주며,
  보내는 요청에는 검사를 통과한 텍스트만 담는다. 기록에는 항목 번호·규칙 이름·줄 번호만 남긴다. 출처가 없는 색인용 입력은 외부 호출 없이
  "출처 없음"으로 거부한다(AGENTS.md 3.1, C-10).
- **FR-006**: 외부 호출 없이 동작하고 같은 입력에 같은 벡터를 내는 가짜 임베딩 제공자를 제공한다. 후속 명세(QK-SYN-001, QK-RET-001)는 이것으로 테스트한다.
- **FR-007**: 실행 환경에 따라 제공자 접속 방식이 달라도(질의응답의 Workers 바인딩, 색인의 외부 실행 환경, ADR-008) 같은 경계와 같은 결과 규칙을 지킨다.
  접속 정보는 QK-FND-001 설정 로딩의 비밀 항목으로 다루고 문서·코드·로그에 남기지 않는다(AGENTS.md 6절).

**임베딩 캐시 (US2)**

- **FR-008**: 색인용 텍스트는 외부로 보내기 전에 (임베딩 입력 해시, 모델 버전)으로 저장된 벡터를 찾고, 있으면 외부 호출 없이 그 벡터를 쓴다
  (QK-STO-001 FR-003·US5).
- **FR-009**: 임베딩 입력 해시는 실제로 외부에 보낼 텍스트 전체로 계산한다. 같은 텍스트면 같은 해시가 나오고(C-07), 해시 규칙이 바뀌면 인덱스 버전을 올린다.
- **FR-010**: 한 묶음 안의 중복 텍스트는 외부로 한 번만 보낸다.
- **FR-011**: 새로 만든 색인용 벡터는 저장소에 넣어 다음 실행의 캐시로 쓴다. 저장은 벡터 단위로 끝나며, 묶음 중간에 멈춰도 이미 만든 벡터는 남는다(C-08).
- **FR-012**: 검색용 질의 벡터는 캐시에 저장하지 않는다.

**사용량 기록 (US3)**

- **FR-013**: 외부 호출마다 시각, 용도, 실행 식별자, 모델 버전, 입력 개수, 입력 크기, 소비 Neurons, 결과 종류, 측정·추정 구분을 기록한다.
  텍스트 원문과 질의 원문은 기록하지 않는다(C-10, ADR-016).
- **FR-014**: 소비 Neurons는 제공자가 응답에 알려 준 값을 쓴다(스파이크 W-04). 알려 주지 않으면 설정의 단가와 입력 크기로 추정하고 추정임을 표시한다.
- **FR-015**: 실행 단위 요약(요청 개수, 캐시 적중 개수, 외부 호출 개수, 실패 종류별 개수, 소비 Neurons)을 남긴다. 후속 동기화 실행 기록(QK-SYN-001)이 이 요약을 쓴다.
- **FR-016**: 하루(00:00 UTC 기준) 합계, 용도별 합계, 남은 색인 예산을 조회할 수 있다. 색인(Workers 밖)과 질의(Workers 안)의 사용량은
  같은 저장소에 호출마다 기록하고, 하루 합계는 두 경로를 모두 더한 값이다.

**일일 예산 (US4)**

- **FR-017**: 설정은 하루 무료 할당(초기값 10,000 Neurons), 색인 예산, 질의응답 예비분을 가진다. 색인 예산 + 질의응답 예비분이 하루 무료 할당을
  넘으면 설정 검사가 실패한다. 초기값은 색인 예산 5,000, 질의응답 예비분 3,000, 배정하지 않은 여유분 2,000이다(2026-10-20 사용자 결정, Assumptions 참조).
- **FR-018**: 색인용 외부 호출 직전에, 그날 색인 사용량 + 이번 호출 예상량이 색인 예산 안인지 판정하고, 넘으면 호출하지 않고 "색인 예산 소진"으로 돌려준다.
- **FR-019**: 질의용 임베딩은 색인 예산과 관계없이 처리한다. 질의용 사용량이 예비분을 넘으면 경고를 기록한다.
- **FR-020**: 제공자가 할당 소진을 알리면 그날 남은 색인을 멈추고, 기록과 제공자 판정의 차이를 경고로 남긴다.
- **FR-021**: 동시에 도는 색인 실행들은 같은 하루 사용량을 보고 예산을 판정한다. 판정과 기록 사이에 생길 수 있는 초과는 묶음 하나의 예상량 이하다.

**실행 전 미리 보기 (US5)**

- **FR-022**: 텍스트 묶음과 대상 모델 버전을 받아 외부 호출 없이 새 임베딩 개수, 캐시 적중 개수, 중복 제거 개수, 입력 한도 초과 예상 개수,
  예상 Neurons, 그날 남은 색인 예산, 실행 가능 여부를 돌려준다.
- **FR-023**: 예상 Neurons는 설정의 단가와 입력 크기로 계산하며, 같은 묶음을 실제로 실행했을 때의 측정값과 비교할 수 있게 계산 근거(단가, 입력 크기 합)를 함께 낸다.
- **FR-024**: 미리 보기가 "예산 초과"면 색인 실행의 기본 동작은 실행하지 않는 것이다. 사람이 명시적으로 고른 경우에만 예산 안 부분 실행을 한다.

**기록 보관**

- **FR-025**: 호출별 사용량 기록은 90일 보관한 뒤 지운다. 지우기 전에 하루 단위 합계(날짜, 용도, 모델 버전, 소비 Neurons, 호출 수)는 남겨
  단계 간 비용 비교(Phase 2 파일럿, QK-EVL-003 사후 측정)에 쓸 수 있게 한다. 정리 작업은 재실행해도 안전하다(AGENTS.md 4절).

### Key Entities

- **임베딩 요청**: 텍스트 묶음, 용도(색인·질의), 대상 모델 버전, 실행 식별자, (색인용) 항목별 출처(자료원 이름·경로).
- **임베딩 결과**: 입력 위치별 벡터 또는 실패 종류, 모델 버전, 차원, 캐시 적중 여부.
- **임베딩 모델 설정**: 모델 식별자, 차원, 입력 한도, 단가, 제공자 종류. 인덱스 버전의 모델 버전과 연결된다.
- **사용량 기록**: 외부 호출 한 번의 시각, 용도, 실행 식별자, 모델 버전, 입력 개수·크기, 소비 Neurons, 결과 종류, 측정·추정 구분.
- **일일 사용량 합계**: 날짜(UTC), 용도, 모델 버전, 소비 Neurons, 호출 수. 호출별 기록을 90일 뒤 지워도 남는다.
- **실행 요약**: 실행 하나의 요청·캐시 적중·외부 호출·실패 개수와 소비 Neurons.
- **일일 예산 설정**: 하루 무료 할당, 색인 예산, 질의응답 예비분, 하루 경계 기준(UTC).
- **미리 보기 결과**: 새 임베딩·캐시·중복·한도 초과 예상 개수, 예상 Neurons와 계산 근거, 남은 예산, 실행 가능 여부.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 같은 텍스트 묶음을 두 번 연속 임베딩한 시험에서 두 번째 실행의 외부 호출이 0건이고 결과 벡터가 첫 실행과 100% 같다.
- **SC-002**: 색인 예산을 작게 둔 시험에서 그날 색인 사용량이 색인 예산 + 묶음 하나의 예상량을 넘은 사례가 0건이고, 같은 날 질의용 요청 거부가 0건이다.
- **SC-003**: 사용량 기록 합계가 가짜 제공자가 알려 준 사용량 합과 100% 같다. 기록에 텍스트 원문이 들어간 사례가 0건이다.
- **SC-004**: 입력 한도를 넘는 텍스트가 잘린 채 저장된 사례가 0건이다. 한도 초과 텍스트는 모두 "입력 한도 초과"로 보고된다.
- **SC-005**: 미리 보기가 외부 호출을 0건 만든다. 실제 임베딩(사람 승인 뒤 실행하는 실측 시험)에서 미리 보기 예상 Neurons와 측정값의 차이가 ±20% 안이다.
  측정 조건(텍스트 수, 언어 비중, 모델, 실행일)을 함께 기록한다(C-13).
- **SC-006**: 비밀값 규칙에 걸리는 텍스트(색인용·질의용)와 출처가 없는 색인용 입력이 외부 제공자로 나간 사례가 0건이다.
- **SC-007**: 임베딩 경계를 쓰는 코드(후속 명세 포함)에 외부 제공자 고유 타입·오류 코드가 나오지 않는다 — 경계 밖 모듈에서 제공자 모듈을 직접 참조하는 사례 0건.

## Assumptions

**요구사항 원문 부재**

- FR-EMB-01~04, 06은 저장소에 원문이 없다(2026-10-20 확인, QK-STO-001과 같은 상황). 뜻을 추측해 대응시키지 않았다. 원문이 나오면 이 명세와 대조해 고친다.
  백로그 제목 요소와 이 명세의 대응은 아래와 같다. FR-EMB-05는 QK-STO-002 범위다(로드맵 4절).

| 백로그 제목 요소 | 이 명세 | 근거 |
| --- | --- | --- |
| 임베딩 Provider(Workers AI) | FR-001~007, US1 | ADR-002, ADR-008, C-06, 스파이크 W-02·W-03 |
| 캐시 | FR-008~012, US2 | QK-STO-001 US5·FR-003, 로드맵 1.G |
| 사용량 기록 | FR-013~016, US3 | 스파이크 W-04, AGENTS.md 3.4 |
| 일일 예산 | FR-017~021, US4 | C-05, 스파이크 6절, AGENTS.md 3.5 |
| 실행 전 사용량 미리 보기 | FR-022~024, US5 | AGENTS.md 3.5 |

**범위**

- 청크 크기를 입력 한도 안으로 맞추는 일은 QK-CHK-002 몫이다. 이 명세는 한도를 넘는 입력을 잘라 쓰지 않고 알려 주기만 한다.
- 비밀값 규칙, 오탐 예외 목록, 전송 직전 검사 함수는 QK-SEC-001 몫이다. 이 명세는 그 검사를 임베딩 제공자 호출에 잇는다(QK-SEC-001 FR-013).
- 언제 어떤 문서를 임베딩할지(증분 판단), 실행 기록, 스케줄러, CLI 명령 구성은 QK-SYN-001 몫이다. 이 명세는 미리 보기와 실행 요약을 제공한다.
- 생성 모델 사용량(QK-GEN-001)은 이 명세 범위가 아니다. 다만 하루 무료 할당은 임베딩과 생성이 함께 쓰므로, 질의응답 예비분(초기값 3,000)은
  생성 몫(스파이크 4절: 하루 50건 330~800 Neurons)까지 감안한 값이다. 생성 사용량 기록 방식은 QK-GEN-001이 이 명세의 사용량 기록과 맞춘다.
- 인덱스 버전 생성·활성화와 모델 교체 절차는 QK-STO-002 몫이다. Phase 1은 bge-m3 첫 인덱스 버전 하나를 쓴다.
- 사용량 대시보드와 알림은 QK-OBS-002 몫이다.

**수치 초기값**

- 색인 예산 5,000과 질의응답 예비분 3,000은 초기값이다(2026-10-20 사용자 결정). 근거: Phase 1 전체 색인 1회 약 325 Neurons(ADR-002),
  Phase 2 전체 색인(원문 약 10 MB) 약 3,070 Neurons(스파이크 3.2절 1KB당 0.30으로 계산), 질의응답 하루 330~800 Neurons(스파이크 4절).
  나머지 2,000은 단가 추정 오차, 사용량을 알려 주지 않은 호출, 같은 계정의 수동 시험을 흡수하는 여유분이다. 사용량 기록이 쌓이면 조정한다. ADR-002 재검토 조건(일일 사용량이 할당의 80% 초과)과 함께 본다.
- 미리 보기 오차 목표 ±20%는 스파이크 3.2절 단가 측정(한국어 비중이 높은 합성 텍스트)과 실제 문서(영어·코드 혼재)의 차이를 감안한 초기값이다.
- 하루 경계는 제공자 할당 초기화 시각 00:00 UTC다(스파이크 6절).

**환경**

- 색인은 Workers 밖(GitHub Actions 또는 로컬 CLI)에서, 질의 임베딩은 Workers 안에서 실행한다(ADR-008). 두 경로 모두 같은 저장소의 사용량 기록을
  쓴다(FR-016). 질의마다 저장소 쓰기가 한 번 늘어나는 비용은 계획 단계에서 Workers 한도(요청당 CPU 10 ms, subrequest 50개) 안인지 확인한다.
- 실제 Workers AI 호출 시험은 사람 승인 뒤 `uv run pytest -m external`로만 실행하고 기본 검증에 넣지 않는다(AGENTS.md 7절).
