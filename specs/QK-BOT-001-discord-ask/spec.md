  드러나고, 사용 기록을 보고 QK-OBS-001이나 파일럿에서 다시 판단한다(FR-005).
- Q: (독립 검토 H1) Workers의 응답 뒤 계속 처리(`waitUntil`)는 최대 30초인데 생성 경계는 재시도까지 기본 45초가 걸릴 수 있다. 어떻게 하나? → A: 명세는 지킬 조건(실행 방식이
  보장하는 시간 − 안내 여유 = 질의 마감, 마감은 모든 단계에 적용, 45초는 강제 종료가 아님)만 정한다. 30초 안에 맞출지, 더 오래 도는 별도 실행으로 넘길지는 계획 단계에서 생성 시간을
  실측해 정하고, plan 승인 전에 사람 승인을 받는 필수 결정으로 둔다(FR-008).
- Q: (계획 단계) 검색·생성을 어디서 실행하나? 기존 검색·생성 코드는 동기 방식(`urllib`, `psycopg`)이라 Python Workers에서 그대로 돌지 않는다. → A: Cloudflare Worker는 Discord
  요청의 서명 검사와 중계만 하고, 검색·생성은 OCI 인스턴스의 질의 서비스가 기존 코드로 실행한다. Worker와 질의 서비스는 Workers VPC 바인딩(Cloudflare Tunnel, 공인 포트·공개 호스트명
  없음)으로 잇는다. 2026-10-25 사용자 결정이고, ADR-008 일부 개정이라 새 결정 기록(ADR-022, Proposed)의 사람 승인과 팀원(인스턴스 관리자) 동의를 받는다(FR-008·FR-015·FR-018).

## User Scenarios & Testing *(mandatory)*

이 명세의 사용자는 Discord에서 질문하는 팀원(질문자), 명령 등록·배포·실측을 맡는 운영 담당자, 이 창구 위에 기능을 더하는 후속 명세 구현자(QK-OBS-001 질의 로그·피드백,
QK-BOT-002 스레드 대화, QK-SYN-002 `/reindex`), PR 리뷰어다.

용어:

- **상호작용**: 팀원이 `/ask`를 실행할 때 Discord가 이 시스템으로 보내는 요청 하나. 응답할 수 있는 시간이 정해져 있고, 그 뒤에는 같은 상호작용에 딸린 메시지를 고치거나 더할 수 있다.
- **처리 중 응답**: 상호작용을 받은 직후 "답변을 준비하고 있다"고 알리는 첫 응답. Discord가 정한 시간(3초) 안에 보내야 한다.
- **답변 갱신**: 처리 중 응답을 검색·생성 결과로 바꾸는 것. 길면 이어지는 메시지를 더한다.
- **허용 범위**: `/ask`를 쓸 수 있는 서버, 채널, (선택) 역할의 묶음. 설정으로 정한다.
- **질문자만 보는 안내**: 질문자에게만 보이고 채널의 다른 사람에게는 보이지 않는 응답.
- **질의 경로**: 상호작용 수신부터 검색(QK-RET-001), 생성(QK-GEN-001), 답변 갱신까지. Discord 요청을 받는 Cloudflare Worker(서명 검사·중계)와 OCI 인스턴스의 질의 서비스(허용 범위·
  비밀값 검사, 검색·생성, 답변 갱신)로 나뉜다(ADR-022).
- **안내 문구**: 상태·실패 종류마다 사용자에게 보여 줄 정해진 한국어 문장. 오류 원문을 담지 않는다.

### User Story 1 - 허용된 채널에서 `/ask`로 질문하고 출처가 붙은 답을 받는다 (Priority: P1)

팀원이 허용된 채널에서 `/ask`에 질문을 넣어 실행하면 3초 안에 처리 중 응답이 보이고, 잠시 뒤 그 자리가 답변 본문과 출처 목록으로 바뀐다. 출처 목록의 각 항목에서
원본 문서로 바로 갈 수 있고, 본문의 `[S1]` 같은 표기가 목록의 번호와 맞는다.

**Why this priority**: 로드맵 1.G 완료 조건 "허용된 Discord 채널에서 `/ask`가 3초 안에 처리 중 응답을 보내고, 출처 링크가 붙은 답변으로 갱신된다"를 만드는 핵심 경로다.
Phase 1 목표(저장소 문서로 Discord에서 출처가 붙은 답을 받는다)가 이 이야기로 끝난다.

**Independent Test**: 서명한 가짜 상호작용 요청을 질의 경로에 넣고, 가짜 검색·생성 제공자가 미리 정한 결과를 돌려주게 한다. 처리 중 응답의 꼴과 걸린 시간, 그 뒤 Discord로
보낸 갱신 메시지(가짜 Discord 수신부가 받은 내용)를 본다. 실제 Discord 확인은 사람 단계(SC-001)다.

**Acceptance Scenarios**:

1. **Given** 허용 채널에서 온 서명이 맞는 `/ask` 요청이고 질의 서비스가 받아들인 경우(FR-007 예외에 들지 않음), **When** 질의 경로가 받는다, **Then** 처리 중 응답을 보내고, 처리 중 응답을
   보내기 전에는 검색·생성을 기다리지 않는다. 검색·생성은 Worker의 시작 확인 뒤에 시작한다.
2. **Given** 생성 결과 상태가 "답변"이고 출처 S1·S2가 있음, **When** 답변을 갱신한다, **Then** 처리 중 응답 자리에 답변 본문이 오고, 본문 뒤 마지막 메시지(출처가 많으면 마지막
   메시지들, FR-012)에 출처 목록이 있으며, 각 항목에 `[S1]` 번호, 제목, 원본 링크, 원본 버전, 원본 수정일, 수집 시각이 있다.
3. **Given** 같은 상호작용, **When** 갱신이 끝난다, **Then** 처리 중 응답은 한 번만 바뀌고 같은 내용이 두 번 올라가지 않는다. 글을 조금씩 이어 붙이는 방식(스트리밍)은 쓰지 않는다.
4. **Given** 검색·생성 결과나 실패가 질의 마감(FR-008) 안에 정해지고 Discord가 갱신 요청을 받는 상태, **When** 갱신한다, **Then** 처리 중 응답은 결과나 안내 문구로 바뀐다.
   마감에 닿으면 시간 초과 안내로 바뀐다. Discord가 갱신을 받지 않는 경우(재시도까지 실패, 질문자가 응답을 지움, 실행 환경이 강제로 끝냄)는 FR-009대로 다시 시도 횟수와 운영 로그로
   판정하고, 질의를 다시 돌리지 않는다.
5. **Given** 처리 중 응답 전 검사(허용 범위, 비밀값, 지원하지 않는 요청)를 통과하고 질의 서비스가 받아들였으며 "나만 보기"를 켜지 않은 `/ask`, **When** 처리한다, **Then** 처리 중 응답과 답변 메시지가 모두
   채널 전체에 보인다. 검사에 걸린 요청은 인자와 상관없이 질문자만 보는 안내다(FR-007).
6. **Given** "나만 보기"를 켠 `/ask`, **When** 처리한다, **Then** 처리 중 응답, 답변, 이어지는 메시지가 모두 질문자만 보는 응답이고 채널에 공개되는 메시지는 0건이다.

### User Story 2 - 결과가 답이 아닐 때 무슨 일인지 알아볼 수 있게 안내받는다 (Priority: P1)

자료에 근거가 없으면 "제공된 자료만으로 확인할 수 없습니다."가 보이고 출처 목록은 없다. 출처를 확인하지 못한 답이나 길어서 잘린 답에는 그 사실이 함께 보인다. 검색·생성이
실패하면 실패 종류에 맞는 짧은 안내(다시 시도할지, 운영 담당자에게 알릴지)가 보이고, 오류 원문이나 내부 주소는 보이지 않는다.

**Why this priority**: 로드맵 1.G "자료에 없는 질문에 '확인할 수 없습니다'로 답한다"와 constitution C-01이다. QK-GEN-001이 "출처 확인 안 됨"·"출력 잘림" 표시와 상태별 안내
문구를 이 명세에 넘겼다(QK-GEN-001 FR-015·FR-023, plan "다른 명세에 넘기는 것"). 출처 없는 답을 표시 없이 보여 주면 FR-015의 보완 장치가 사라진다(QK-GEN-001 Assumptions).

**Independent Test**: 가짜 생성 제공자로 상태(답변, 확인 불가, 검색 실패 종류별, 외부 전송 차단, 생성 실패 종류별)와 표시(출처 확인 안 됨, 출력 잘림)를 하나씩 만들어 갱신 메시지를 본다.

**Acceptance Scenarios**:

1. **Given** 생성 결과 상태가 "확인 불가", **When** 갱신한다, **Then** 본문은 생성 결과 본문 그대로(확인 불가 문장)이고 출처 목록은 없다.
2. **Given** 상태 "답변"에 "출처 확인 안 됨" 표시, **When** 갱신한다, **Then** 본문 앞에 출처를 확인하지 못한 답이라 원문으로 확인해야 한다는 경고 줄이 있고 출처 목록은 없다.
3. **Given** "출력 잘림" 표시, **When** 갱신한다, **Then** 본문 끝에 답이 길어 일부가 잘렸다는 안내 줄이 있다.
4. **Given** 검색 실패·생성 실패 각 종류, **When** 갱신한다, **Then** FR-011 표의 안내 문구가 나오고, 실패 종류 이름·제공자 오류·예외 메시지·주소·실행 식별자 말고 다른 내부 값이 메시지에 없다.
5. **Given** 그날 생성 할당이 소진돼 "제공자 할당 소진"으로 끝난 질문, **When** 갱신한다, **Then** 오늘 사용 한도에 닿아 답할 수 없다는 안내가 나온다.

### User Story 3 - 허용 범위 밖이나 위험한 요청은 처리하지 않는다 (Priority: P1)

Discord가 보낸 것이 아닌 요청은 거부된다. 허용되지 않은 서버·채널·DM·스레드에서, 또는 허용 역할이 없는 사람이 `/ask`를 쓰면 질문자만 보는 안내를 받고 검색·생성은 일어나지
않는다. 질문에 비밀값으로 보이는 내용이 있으면 질문자만 보는 안내를 받고, 질문은 채널에 공개되지 않으며 외부로 나가지 않는다. 답변이나 출처 제목에 멘션 꼴 글이 있어도 누구에게도
알림이 가지 않는다.

**Why this priority**: AGENTS.md 3.1(외부 전송 전 비밀값 검사)·6절(민감 정보), C-09(쓰기는 답변 게시로 한정), C-10, C-14다. Discord 요청 주소는 인터넷에 열려 있으므로 서명 검사
없이는 누구나 질의 경로와 생성 비용을 쓸 수 있다(C-05). 허용 채널을 정하는 일은 이 명세로 넘어왔다(tokens.md 4.3).

**Independent Test**: 서명이 틀린·없는·오래된 요청, 허용 밖 서버·채널·DM·스레드 요청, 허용 역할이 없는 사용자 요청, 비밀값 규칙에 걸리는 질문, 본문·제목에 `@everyone`·`@here`·
사용자·역할 멘션 꼴을 심은 가짜 결과를 넣고 응답, 외부 호출 수, 갱신 메시지의 알림 설정을 본다.

**Acceptance Scenarios**:

1. **Given** 서명이 틀리거나 없는 요청, **When** 받는다, **Then** 거부 응답을 보내고 검색·생성·Discord 호출은 0회다.
2. **Given** 허용 목록에 없는 채널, DM, 허용 채널 아래 스레드, 허용 역할이 없는 사용자의 `/ask`, **When** 받는다, **Then** 질문자만 보는 허용 범위 안내를 보내고 검색·생성은 0회다.
3. **Given** 허용 채널 목록이 비어 있는 설정, **When** `/ask`를 받는다, **Then** 모든 요청에 2와 같이 답한다(열어 두지 않고 닫는다).
4. **Given** 비밀값 규칙에 걸리는 질문, **When** 받는다, **Then** 질문자만 보는 안내를 보내고, 채널에 공개되는 메시지는 0건이며, 임베딩·생성 호출은 0회다. 안내와 로그에 맞은 문자열이 없다.
5. **Given** 답변 본문이나 출처 제목에 `@everyone`, `@here`, 사용자·역할 멘션 꼴 글, **When** 갱신한다, **Then** 어떤 메시지도 알림을 일으키지 않는다. 출처 제목 안의 Discord 서식 글자는
   링크 꼴을 깨거나 다른 주소로 바꾸지 못하게 바뀐다.

### User Story 4 - 긴 답변과 출처 목록이 잘리지 않고 나뉜다 (Priority: P1)

답변 본문과 출처 목록이 메시지 하나의 글자 수 한도를 넘으면, 문단·문장 경계에서 나뉘어 이어지는 메시지로 올라간다. 코드 블록, 링크, `[S1]` 표기가 중간에서 끊기지 않고,
출처 목록은 빠짐없이 마지막에 온다.

**Why this priority**: 백로그 제목의 "답변 표시·분할"이다. 생성 출력 상한(800토큰, QK-GEN-001 FR-018)과 출처 목록을 합치면 메시지 하나의 한도를 넘을 수 있고, 한도를 넘는 메시지는
Discord가 받지 않아 답변 갱신 자체가 실패한다.

**Independent Test**: 긴 본문, 긴 코드 블록, 한도 경계에 걸친 링크·인용 표기, 출처 10개를 담은 가짜 결과로 분할 결과를 본다.

**Acceptance Scenarios**:

1. **Given** 본문 + 출처 목록이 한도 안, **When** 갱신한다, **Then** 메시지 1개다.
2. **Given** 한도를 넘는 본문, **When** 나눈다, **Then** 모든 메시지가 한도 안이고, 나눈 자리는 문단 경계 → 문장 경계 → 공백 순으로 고르며, 링크·`[S번호]` 표기 중간에서 나누지 않는다.
3. **Given** 한도를 넘는 코드 블록, **When** 나눈다, **Then** 각 조각의 코드 블록이 열리고 닫혀 서식이 깨지지 않는다.
4. **Given** 나눈 메시지 수가 상한(FR-012)을 넘는 본문, **When** 나눈다, **Then** 상한 안에서 본문을 줄이고 일부를 생략했다는 줄을 넣으며, 출처 목록은 줄이지 않는다.

### User Story 5 - 질의 경로가 운영 저장소에 열린 포트 없이 최소 권한으로 붙는다 (Priority: P2)

질의 경로는 인터넷에 데이터베이스 포트를 열지 않고 운영 저장소(OCI 공유 인스턴스의 PostgreSQL, ADR-008)에 붙어 검색하고 질의응답 사용량을 기록한다. 질의 경로가 가진 권한으로는
색인 데이터를 바꾸거나 지울 수 없다. 연결 방식과 그 대안·비용·데이터 처리 정책은 결정 기록으로 남는다.

**Why this priority**: ADR-008이 "Workers 질의 경로의 연결은 QK-BOT-001에서 정한다"고 넘겼다(ADR-008 확정 사항·대가와 위험). 이 연결 없이는 운영 환경에서 US1이 돌지 않는다.
로컬 시험은 연결 없이 가짜 저장소로 할 수 있어 P2로 둔다.

**Independent Test**: 결정 기록 리뷰, 인스턴스 공인 주소의 데이터베이스 포트 외부 접속 시험, 질의 경로 자격으로 색인 표에 쓰기·지우기를 시도하는 시험(로컬 데이터베이스).

**Acceptance Scenarios**:

1. **Given** 구성을 마친 운영 환경, **When** 인스턴스 공인 주소로 데이터베이스 포트에 접속한다, **Then** 접속되지 않는다(보안 목록·호스트 방화벽 변경 없음).
2. **Given** 질의 경로 자격, **When** 검색 함수 호출과 질의응답 사용량 기록을 한다, **Then** 성공한다.
3. **Given** 질의 경로 자격, **When** 문서·청크·인덱스 버전 표에 쓰거나 지우거나 스키마를 바꾸려 한다, **Then** 거부된다.
4. **Given** 저장소에 닿지 않는 상태, **When** `/ask`를 받는다, **Then** 질의 마감 안에 "검색 실패(저장소 사용 불가)" 안내로 갱신된다.

### User Story 6 - 운영 담당자가 명령을 등록하고, 실행 환경의 한도 안인지 잰다 (Priority: P2)

운영 담당자는 명령 하나로 설정된 서버에 `/ask`를 등록하거나 갱신한다. 배포 뒤 소수 질문으로 질의 하나의 단계별 시간, 실행 환경이 센 처리 시간, 외부 호출 수, 소비 Neurons를 재서
기록하고, 한도에 걸리면 정해 둔 대안으로 넘어간다.

**Why this priority**: 질의 전체 시간과 Workers 한도 측정은 QK-RET-001·QK-GEN-001이 이 명세로 넘겼다. Python Worker 기동이 요청당 처리 시간 한도를 얼마나 쓰는지는 QK-FND-001에서
확인하지 않은 위험이다(QK-FND-001 research 남는 위험). 운영 장치라 P2다.

**Independent Test**: 등록 명령을 가짜 Discord 수신부로 두 번 실행해 결과가 같은지 본다. 실측은 사람 확인 뒤 운영 환경에서 한다.

**Acceptance Scenarios**:

1. **Given** 등록되지 않은 서버, **When** 등록 명령을 실행한다, **Then** `/ask`(필수 질문 인자 하나, 서버 안에서만 쓰기)가 등록된다. 다시 실행해도 같은 결과다.
2. **Given** 배포를 마친 운영 환경, **When** 소수 질문 세트로 실측한다, **Then** 질문마다 처리 중 응답 시간, 갱신까지 시간, 단계별 시간(검색·생성·갱신), 실행 환경이 센 처리 시간,
   외부 호출 수, 소비 Neurons가 조건(날짜, 모델, 인덱스 버전, 질문 수)과 함께 기록된다.
3. **Given** 실측에서 한도를 넘는 단계, **When** 기록한다, **Then** 넘은 한도와 넘어갈 대안(Assumptions "실행 환경 한도")이 함께 남는다.

---

### Edge Cases

- 질의 서비스나 인스턴스가 멈췄을 때: Worker가 첫 응답 제한 시간 안에 답을 못 받으면 질문자만 보는 안내로 답한다(FR-011). 처리 중 응답은 보내지 않으므로 갱신되지 않은 채 남는 메시지가 없다.
- 질의 서비스가 처리 중 응답을 정했지만 Worker가 제한 시간 안에 받지 못했을 때: Worker는 질문자만 보는 안내를 보내고 시작 확인을 보내지 않는다. 질의 서비스는 시작 확인이 오지 않은 작업을
  실행하지 않고 버린다. 그래서 Worker 안내와 질의 서비스 답변이 섞이지 않는다(plan research R-03).
- 같은 상호작용이 두 번 들어올 때(Discord 재전송): 처리 중이든 처리가 끝난 뒤든 처리 중 응답을 다시 보내지 않고 질의를 다시 돌리지 않는다. 상호작용 식별자로 가려낸다(FR-010).
- 처리 중 응답 뒤 질의가 질의 마감 안에 끝나지 못할 때: 마감에서 진행 중인 단계를 기다리지 않고 시간 초과 안내로 갱신한다. 안내는 안내 전달 마감(FR-008) 안에 보내므로
  실행 환경이 강제로 끝내기 전에 보낼 수 있다. 그래도 강제 종료로 안내를 못 보낸 경우는 실측(US6)으로 빈도를 잰다.
- 검색이 늦게 끝나 생성에 쓸 남은 시간이 모자랄 때: 생성 경계의 유효한 설정 하한(생성 마감 최소 7초)을 만들 수 없으면 생성을 시작하지 않고 시간 초과 안내로 끝낸다(FR-008).
- 처리 중 응답을 공개로 보낸 뒤 질의 중에 질문이 전송 차단될 때(검색 실패 `outgoing_blocked` 또는 생성 상태 "외부 전송 차단"): 처리 중 응답 전 검사(FR-006)와 같은 규칙이라 보통
  일어나지 않는다. 일어나면 이미 보낸 응답의 공개 범위는 바꿀 수 없으므로 공개 메시지를 FR-006 안내 문장으로 바꾼다. 안내에 질문 원문이나 맞은 문자열은 없다.
- 답변 갱신 호출이 실패할 때: 일시 실패면 1회 다시 시도한다. 그래도 실패하면 운영 로그에 실패 종류만 남긴다. 질문을 다시 검색·생성하지 않는다.
- 질문자가 처리 중에 처리 중 응답을 지웠을 때: 갱신이 실패해도 운영 로그에만 남기고 새 메시지를 만들지 않는다.
- 빈 질문, 공백만 있는 질문: 명령 인자가 필수라 보통 오지 않는다. 오면 검색 실패(빈 질문) 안내로 답한다.
- 질문 길이가 검색 질문 길이 상한(2,000자, QK-RET-001)을 넘을 때: 명령 인자 길이 상한을 같은 값으로 두어 Discord가 막는다. 설정이 달라 넘어오면 검색 실패(질문 길이 초과) 안내로 답한다.
- 검색이 한쪽 검색을 생략하고 결과를 낸 때: 사용자에게 따로 알리지 않는다. 생략 사유는 운영 로그(FR-021)에 남는다.
- Context 묶음 일부가 전송 직전 검사로 빠졌을 때(QK-GEN-001 FR-010): 사용자에게 따로 알리지 않는다. 운영 로그(FR-021)에 뺀 수만 남는다.
- 출처 링크가 없는 출처 항목(원본 링크를 만들 수 없는 자료): 링크 자리에 "링크 없음"이 보이고 나머지 항목(제목, 원본 버전, 수정일, 수집 시각)은 그대로 보인다.
- 활성 인덱스 버전이 질의 중에 바뀔 때: 검색은 QK-RET-001 규칙(인덱스 버전 바뀜 실패)을 따르고, 안내는 FR-011의 "잠시 후 다시 시도"다.
- 같은 사람이 짧은 시간에 여러 번 묻거나 여러 사람이 동시에 물을 때: 질문마다 따로 처리한다. 사용자별 호출 제한은 두지 않는다(FR-005).
- "나만 보기" 인자에 참·거짓이 아닌 값이 오거나 인자가 없을 때: 인자가 없으면 공개로 본다. 형식이 틀린 값은 Discord가 막는다고 보고, 오면 공개가 아니라 질문자만 보기로 처리한다
  (공개 쪽으로 잘못 가지 않게 한다).
- 허용 채널이 지워졌거나 봇이 그 채널에 글을 쓸 수 없을 때: 처리 중 응답과 갱신은 상호작용에 딸린 응답이라 채널 쓰기 권한 없이도 된다고 본다 `(일반 설명, 계획 단계에서 확인)`.

## Requirements *(mandatory)*

### Functional Requirements

**요청 수신과 검증 (US1, US3)**

- **FR-001**: 모든 상호작용 요청의 서명을 Discord 애플리케이션 공개 키로 검사한다. 서명이 없거나 틀리거나, 서명 시각이 허용 차이(초기값 5분)를 벗어나면 거부 응답을 보내고 그 밖의 일
  (검색, 생성, Discord 호출, 기록)을 하지 않는다.
- **FR-002**: Discord의 연결 확인 요청에는 정해진 확인 응답만 보낸다.
- **FR-003**: 명령은 `/ask` 하나다. 필수 문자열 인자 "질문"과 선택 참·거짓 인자 "나만 보기"(기본 거짓)를 받는다. "질문"의 길이 상한은 검색 질문 길이 상한(초기값 2,000자, QK-RET-001)과
  같다. 서버 안에서만 쓸 수 있고 DM에서는 쓸 수 없게 등록한다. 모르는 명령이나 다른 종류의 상호작용(버튼 등)은 질문자만 보는 "지원하지 않는 요청" 안내로 답하고 처리하지 않는다.
- **FR-004**: 허용 범위는 서버 하나와 허용 채널 목록, 선택 항목인 허용 역할 목록이다. 허용 역할 목록이 비면 허용 채널에 있는 모든 구성원이 쓸 수 있다. 허용 채널 아래 스레드는 허용하지
  않는다(스레드 대화는 QK-BOT-002). 허용 범위 밖 요청에는 질문자만 보는 허용 범위 안내를 보내고 검색·생성을 하지 않는다. 허용 채널 목록이 비었거나 서버가 설정되지 않았으면 모든 요청을
  허용 범위 밖으로 본다.
- **FR-005**: Phase 1에서는 사용자별 호출 제한을 두지 않는다. 허용 범위 안의 질문은 모두 같은 경로로 처리한다. 비용 이상은 질의응답 예비분 경고(QK-GEN-001 FR-021)와 할당 소진
  안내(FR-011)로 드러난다. 제한이 필요한지는 질의 로그(QK-OBS-001)와 파일럿 사용 기록을 보고 다시 정한다(2026-10-25 사용자 결정).
- **FR-006**: 처리 중 응답을 보내기 전에 질문을 QK-SEC-001 전송 직전 검사에 넣는다(질문만, 출처 없이). 걸리면 질문자만 보는 안내("질문에 비밀값으로 보이는 내용이 있어 처리하지
  않았습니다. 해당 값을 지우고 다시 질문해 주세요.")로 바로 답하고, 채널에 공개되는 메시지를 만들지 않으며 검색·생성을 하지 않는다. 안내·로그에 맞은 문자열이나 규칙에 걸린 글을 담지 않는다.

**처리 중 응답과 답변 갱신 (US1)**

- **FR-007**: 허용 범위 안의 `/ask`에는 요청을 받은 뒤 3초 안에 처리 중 응답을 보낸다. 공개 범위는 "나만 보기" 인자로 정한다. 끄면(기본) 처리 중 응답과 답변·이어지는 메시지를
  채널 전체에 보이고, 켜면 모두 질문자만 보는 응답으로 보낸다. 한 상호작용 안에서 공개 범위가 섞이지 않는다(2026-10-25 사용자 결정). 허용 범위 안내(FR-004), 비밀값 안내(FR-006),
  지원하지 않는 요청 안내(FR-003)는 인자와 상관없이 늘 질문자만 본다. 질의 서비스가 요청을 받아들이지 못한 경우(Worker가 질의 서비스에 닿지 않음, 첫 응답 제한 시간 초과, 질의 서비스
  대기열 가득, 같은 상호작용 재전송)도 처리 중 응답 대신 질문자만 보는 안내로 답한다(FR-011). 처리 중 응답 전에는 검색·생성·저장소 호출을 기다리지 않는다(FR-006의 검사만 한다).
- **FR-008**: 처리 중 응답 뒤 검색(QK-RET-001)과 생성(QK-GEN-001)을 이어 실행하고, 결과로 처리 중 응답을 한 번 바꾼다. 본문이 나뉘면(FR-012) 이어지는 메시지를 순서대로 더한다.
  - 시간은 요청을 받은 때부터 재고, 두 시점을 구분한다.
    - **질의 마감**: 검색(재시도 대기 포함), 생성, 저장소 호출을 멈추는 시점이다. 마감에 닿으면 진행 중인 단계를 기다리지 않고(결과를 버리고) 시간 초과 안내로 넘어간다.
    - **안내 전달 마감**: 질의 마감 + 안내 전송 여유(초기값 5초)다. 답변이나 안내의 전송과 그 다시 시도(FR-009)는 이 시점까지 끝낸다. 안내 전달 마감은 실행 방식이 처리 중 응답 뒤
      계속 실행을 보장하는 시간을 넘지 않는다.
  - QK-GEN-001의 생성 마감(기본 45초)은 재시도를 시작할지 정하는 기준이지 강제 종료 시간이 아니다(QK-GEN-001 research R-07, 재시도 직전에만 마감을 본다). 그래서 질의 경로는
    (1) 생성 경계에 남은 시간에 맞춘 생성 마감과 호출 시간 제한을 질의별 생성 설정으로 넘기고, (2) 질의 마감에서는 생성이 끝나기를 기다리지 않는다. 생성 마감과 시간 제한은 생성 설정으로
    바꿀 수 있는 값이라(QK-GEN-001 FR-025) 생성 결과 계약과 설정 하한은 바뀌지 않는다. 생성 설정 규칙(시간 제한 ≥ 1초, 2 × 시간 제한 + 5 ≤ 생성 마감)상 생성 마감의 최솟값은 7초이므로,
    검색 뒤 질의 마감까지 남은 시간이 7초보다 짧으면 생성을 시작하지 않고 시간 초과 안내로 끝낸다. 검색 단계의 외부 호출에도 남은 시간 안의 시간 제한을 건다.
  - **실행 방식**: Workers의 응답 뒤 계속 처리는 최대 30초다(Assumptions). 그래서 검색·생성은 Worker가 아니라 OCI 인스턴스의 질의 서비스가 실행하고, 질의 서비스가 답변 갱신도 직접
    보낸다(2026-10-25 사용자 결정, ADR-022). 질의 서비스는 실행 시간 제한이 없으므로 "보장 시간"은 Discord 상호작용 토큰 유효 기간(15분)이고, 질의 마감 초기값은 55초, 안내 전달 마감은
    60초다. 생성 기본값(시간 제한 20초, 생성 마감 45초)은 바꾸지 않는다. Worker는 처리 중 응답을 돌려준 뒤 질의 서비스에 시작 확인을 보내는 일만 하고, 질의 서비스는 시작 확인을 받은
    작업만 실행한다. 시작 확인이 오지 않은 작업은 검색·생성 없이 안내로 첫 메시지를 바꾼다(plan research R-03).
  - 설정 검사는 안내 전달 마감이 고른 실행 방식의 보장 시간 이하인지, 기본 생성 설정(2 × 시간 제한 + 5 ≤ 생성 마감, QK-GEN-001 R-07)이 질의 마감 안에 들어가는지, 안내 전달 마감이
    Discord가 상호작용 메시지를 고칠 수 있는 기간(15분)보다 짧은지 확인한다.
- **FR-009**: 답변 갱신과 이어지는 메시지 전송은 메시지마다 1회까지 다시 시도한다. 다시 시도하는 경우는 일시 실패(제공자 일시 오류, 전송 속도 제한 응답)와, 첫 메시지 갱신의 첫 시도가 "메시지
  없음"으로 실패한 경우(처리 중 응답이 아직 반영되지 않았을 수 있다)다. Discord가 알려 준 대기 시간이 안내 전달 마감(FR-008)까지
  남은 시간보다 길면 다시 시도하지 않는다. 실패는 운영 로그에 실패 종류만 남기고, 질의를 다시 돌리지 않는다.
- **FR-010**: 같은 상호작용 식별자의 요청이 다시 오면, 처리 중이든 끝난 뒤든 처리 중 응답과 질의를 되풀이하지 않는다. 이를 위해 상호작용 식별자를 중복 판정 상태로 상호작용 토큰
  유효 기간(15분)만큼 보존하고 그 뒤 지운다. 이 상태에는 상호작용 식별자와 처리 단계(처리 중, 끝남)만 두고 질문·사용자 정보는 두지 않는다. 중복 판정 상태는 운영 로그가 아니다(FR-021).
  보존 위치는 질의 서비스 메모리다(plan research R-10). 그래서 질의 서비스가 다시 시작되면 그 전 상태는 사라지고, 다시 시작한 뒤 15분 안에 같은 상호작용이 다시 오면 한 번 더 처리될 수 있다.
  이 예외는 받아들인 위험이다(plan 승인 때 사람 확인).

**답변 표시 (US1, US2)**

- **FR-011**: 생성 결과 상태와 표시를 아래처럼 보여 준다. 질의 경로는 상호작용마다 질의 실행 식별자를 만들어 생성 요청의 실행 식별자(`GenerationRequest.run_id`)로 넘기고 운영 로그에도
  같은 값을 쓴다. 실패 안내에는 이 식별자를 짧게 붙여 운영 담당자가 로그를 찾을 수 있게 하고, 실패 종류 이름·제공자 오류·예외 메시지·주소·질문 원문을 넣지 않는다.
  검색 실패 행은 QK-RET-001 실패 종류(`RetrievalFailure`) 9개를 모두 덮는다. 생성 결과의 "검색 실패"는 원래 검색 실패 종류를 싣고 온다(QK-GEN-001 FR-008).

  | 결과 | 사용자에게 보이는 것 |

  | 답변 | 답변 본문 + 출처 목록(FR-013) |
  | 답변 + 출처 확인 안 됨 | 본문 앞 경고 줄 "⚠️ 출처를 확인하지 못한 답변입니다. 원문으로 확인해 주세요." + 본문. 출처 목록 없음 |

  | 생성 실패: 인증·설정 오류, 잘못된 응답, 입력 한도 초과 | "답변을 만드는 중 문제가 생겼습니다. 운영 담당자에게 알려 주세요." |

  문구 글은 계획 단계에서 다듬을 수 있지만 표의 구분(다시 시도 / 운영 담당자에게 알림 / 내일 다시)과 담지 않는 값은 바꾸지 않는다. 확인 불가 문장은 생성 결과 그대로이며 이 명세가
  바꾸지 않는다(C-01).
- **FR-012**: 메시지 하나는 계획 단계에서 고른 표시 꼴(본문 또는 임베드)의 Discord 한도 안이다(본문은 2,000자). 질문 하나의 메시지 수 상한(초기값 4)을 두고, 자리는 출처 목록이
  먼저 받는다.
  - 출처 목록: 항목 사이에서만 나누고 여러 메시지에 걸칠 수 있으며 본문 뒤 마지막 메시지들에 온다. 항목은 줄이거나 빼지 않는다. FR-013의 길이 규칙으로 항목 하나는 메시지 하나를 넘지 않는다.
  - 설정 검사(항목 단위): 출처 항목 최대 길이는 FR-013의 길이 상한에 서식 바꿈(FR-014, 최악의 경우 제목 글자마다 바꿈), 항목 번호·이름표·구분자·줄바꿈을 더한 최종 길이다.
    메시지당 항목 수 = ⌊(메시지 한도 − 목록 머리글 길이) ÷ 항목 최대 길이⌋, 출처에 필요한 메시지 수 = ⌈Context 묶음 최대 수 ÷ 메시지당 항목 수⌉이다(묶음 최대 수는 QK-RET-001 확장 대상
    상위 개수, 문서당 묶음 하나). 이 값이 (메시지 수 상한 − 1) 이하여야 하며, 넘는 설정은 거부한다. 그래서 본문 자리가 적어도 메시지 하나 남는다. 기본 설정(확장 대상 8, 본문 꼴 2,000자,
    FR-013 기본 상한)은 이 검사를 통과해야 한다 `(추론: 2026-10-25 독립 검토 계산으로 본문 꼴 항목 최대 551자(제목·비해시 버전 전부 서식 바꿈), 목록 머리글 14자 → 메시지당 3항목 → 출처 3개 메시지 ≤ 4 − 1. 렌더러가 없어 구현으로 확인한 값은 아니다)`. 계획 단계에서 표시 꼴을 고른 뒤 실제 렌더링 길이로 다시 계산한다.
  - 본문: 출처 목록이 쓰고 남은 메시지에 넣는다. 나눌 자리는 문단 경계 → 문장 경계 → 공백 순으로 고르고, 링크·`[S번호]` 표기·FR-014로 바꾼 글 중간에서는 나누지 않는다. 공백 없는
    긴 문자열은 한도에서 자른다. 링크 하나가 한도를 넘으면 그 링크를 "(긴 링크 생략)"으로 바꾼다. 코드 블록이 나뉘면 조각마다 닫고 다음 조각에서 같은 언어 표시로 다시 연다. 남은 자리를
    넘으면 본문 끝을 줄이고 "(답변이 길어 일부를 생략했습니다.)" 줄을 넣는다.
  - 같은 입력이면 같은 분할 결과가 나온다.
- **FR-013**: 출처 목록은 생성 결과의 출처 목록(QK-GEN-001 FR-016)에서만 만들고 답변 본문에서 가져오지 않는다. 항목의 순서와 개수는 그대로 지키고, 화면에는 생성 결과의 모든
  필드를 보인다: `[S번호]`, 제목, 원본 링크, 원본 버전(앞 7자, 커밋 해시가 아니면 앞 12자), 원본 수정일(한국 시간 날짜, 없으면 "수정 미상"), 수집 시각(한국 시간)(C-02).
  목록 머리에 "자료 기준: 색인된 문서"처럼 색인 시점의 자료임을 알린다. 링크는 미리보기 카드를 만들지 않는 꼴로 보낸다. 원본 링크가 없으면 "링크 없음"을 쓴다.
  길이 규칙: 제목은 80자에서 줄이고 "…"를 붙인다. 원본 링크가 300자를 넘으면 "링크 생략(길이 초과)"으로 바꾼다. 링크는 자르지 않는다. 두 상한은 설정으로 바꿀 수 있고 FR-012의
  설정 검사를 받는다.
- **FR-014**: 어떤 메시지도 사용자·역할·`@everyone`·`@here` 알림을 일으키지 않는다(질문자 알림 포함). 출처 제목과 수정일 같은 자료 유래 글에서 Discord 서식·링크 꼴 글자는 서식으로
  읽히지 않게 바꾼다. 답변 본문의 서식(굵게, 목록, 코드)은 그대로 둔다.

**질의 경로 (US1, US6)**

- **FR-015**: 질의 서비스는 QK-RET-001 검색 경계와 QK-GEN-001 생성 경계를 그대로 부르고, 두 명세의 계약(상태, 출처 목록, 요약, 외부 호출 상한)을 바꾸지 않는다. 생성 모델과 질의용
  임베딩은 기존 Workers AI REST 제공자(QK-GEN-001·QK-EMB-001)로 부른다. Worker의 Workers AI 바인딩은 쓰지 않는다(ADR-022).
- **FR-016**: 질의 하나의 외부 호출(검색 단계 상한 7, 생성 단계 상한 4, 답변 갱신·이어지는 메시지와 재시도)은 질의 경로 상한(초기값 20) 안이고 설정 검사가 확인한다. Worker는 요청 하나에
  질의 서비스 호출을 최대 2회(중계, 시작 확인) 한다(Workers 요청당 외부 호출 한도 50, ADR-008). 운영 로그에 단계별 실제 호출 수를 남긴다.
- **FR-017**: 검색 단계의 일시 실패 재시도 대기 시간(QK-RET-001이 넘긴 초기값 2초)은 질의 마감 안에서만 기다린다. 남은 시간이 모자라면 다시 시도하지 않는다.

**운영 저장소 연결 (US5)**

- **FR-018**: 질의 서비스는 같은 인스턴스의 운영 저장소에 `localhost`로 붙는다. Worker와 질의 서비스 사이는 Workers VPC 바인딩과 Cloudflare Tunnel로 잇고, 인스턴스는 공인 포트를 새로
  열지 않으며 질의 서비스는 `127.0.0.1`에서만 받는다. 연결 방식, 대안, 비용(추가 고정비 월 0원, C-05), 데이터 처리 정책(지나가는 데이터, 보존, 학습 사용), 공유 인스턴스 영향은 결정
  기록(ADR-022)으로 남기고 사람 승인을 받는다. 공유 인스턴스에 구성 요소(질의 서비스, `cloudflared`)를 더하는 일은 팀원(인스턴스 관리자) 동의 뒤에 한다.
- **FR-019**: 질의 경로의 저장소 권한은 검색에 필요한 읽기와 질의응답 사용량 기록 쓰기로 한정한다. 문서·청크·인덱스 버전·동기화 기록을 바꾸거나 지우는 권한, 스키마를 바꾸는 권한은 없다.
  자격 정보는 실행 환경의 비밀값 저장소에만 두고 저장소·문서·로그에 남기지 않는다.
- **FR-020**: 저장소에 닿지 않거나 시간 안에 응답이 없으면 검색 실패(저장소 사용 불가)로 다루고 FR-011 안내로 갱신한다.

**기록 (US3)**

- **FR-021**: 운영 로그의 허용 항목은 아래가 전부다. 이 명세의 다른 절이 "운영 로그에 남긴다"고 할 때도 이 목록 안의 항목만 뜻한다.
  - 질의 실행 식별자(FR-011), 허용 범위 판정 결과, "나만 보기" 여부, 결과 상태와 실패 종류(검색·생성·전송), 단계별 시간, 단계별 외부 호출 수, 답변 전송 다시 시도 횟수와 실패 종류
  - QK-RET-001 검색 요약과 QK-GEN-001 생성 요약의 수치·이름 항목(생략 사유, 뺀 묶음 수와 규칙 이름, 토큰·Neurons, 질의응답 예비분 경고 등). 두 요약은 이미 원문을 담지 않는다
    (QK-GEN-001 FR-026)
  - 질문 원문, 답변 본문, 청크 본문, 출처 제목·링크, Discord 상호작용 식별자·사용자 식별자·이름·채널 식별자, 서명·토큰·자격 정보는 운영 로그와 오류 메시지에 남기지 않는다(AGENTS.md 6절).
    이 운영 로그는 질의 로그가 아니다. 사용자 식별자를 포함한 질의 로그 저장(ADR-016)은 QK-OBS-001 몫이고, 이 명세는 그것을 더하지도 막지도 않는다.

**명령 등록·설정·검증 (US6)**

- **FR-022**: 설정된 서버에 `/ask`를 등록·갱신하는 운영 명령을 둔다. 다시 실행해도 결과가 같고, 등록 내용(이름, 설명, 질문 인자와 길이 상한, "나만 보기" 인자, 서버 안에서만 쓰기)은
  FR-003과 같다.
  실제 등록은 사람이 실행한다.
- **FR-023**: Discord 애플리케이션 식별자·공개 키, 허용 범위, 질의 마감과 안내 전송 여유, 메시지 수 상한, 외부 호출 상한, 저장소 연결 정보는 설정으로 두고 설정 검사가 형식과 범위를 확인한다.
  허용 채널 목록이 비면 설정 검사는 경고한다. 봇 토큰이 필요한지는 계획 단계에서 정하고, 필요 없으면 질의 경로 설정에 두지 않는다.
- **FR-024**: 가짜 Discord 수신부, 가짜 검색·생성 제공자, 시험용 서명 키로 기본 검증이 외부 호출 0건으로 돈다(C-12). 실제 Discord·Workers AI를 부르는 시험은 따로 표시해 기본 실행에서 뺀다.
- **FR-025**: 운영 담당자가 운영 환경에서 질의 하나의 처리 중 응답 시간, 갱신까지 시간, 단계별 시간, 실행 환경이 센 처리 시간, 외부 호출 수, 소비 Neurons(측정·추정 구분)를 재서
  기록할 수 있다. 기록에는 날짜, 질문 세트 이름과 버전, 질문 수, SC-002 판정 기준, 생성 모델과 프롬프트 버전, 질의 임베딩 모델, 인덱스 버전과 색인 시점, 실행 방식(FR-008)을 붙인다
  (AGENTS.md 3.4, C-13). 질문 원문은 기록에 넣지 않고 질문 세트 안의 번호로 가리킨다.

### Key Entities

- **상호작용 요청(Interaction)**: 상호작용 식별자, 종류(연결 확인, 명령), 명령 이름, 질문 인자, "나만 보기" 인자, 서버·채널·스레드 여부, 요청자 역할 목록, 서명·서명 시각.
  원문은 저장하지 않는다.
- **허용 범위(Access Policy)**: 서버, 허용 채널 목록, 허용 역할 목록(선택). 판정 결과는 허용, 서버 밖, 채널 밖, 스레드, DM, 역할 없음.
- **질의 실행(Query Run)**: 질의 실행 식별자(생성 요청에도 넘김), 결과 상태·실패 종류, 단계별 시간, 단계별 외부 호출 수, 질의 마감과 안내 전달 마감. 운영 로그에는 FR-021 항목만 남는다.
- **중복 판정 상태(Dedup Entry)**: 상호작용 식별자, 처리 단계(처리 중, 끝남), 만료 시각(받은 때 + 15분). 질문·사용자 정보 없음. 운영 로그에 남기지 않는다(FR-010).
- **표시 메시지 묶음(Rendered Reply)**: 순서 있는 메시지 목록(첫 메시지는 처리 중 응답을 바꾸는 것), 각 메시지 글, 알림 설정(알림 없음), 생략 여부.
- **안내 문구(Notice)**: 결과·실패 종류 → 문구, 다음 행동 구분(다시 시도, 운영 담당자에게 알림, 내일 다시), 질문자만 보는지 여부.
- **실측 기록(Measurement)**: FR-025의 항목과 조건.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사람 확인 뒤 운영 환경의 허용 채널에서 질문 세트(10개 이상, 자료로 답할 수 있는 질문과 자료에 없는 질문을 섞음)를 실행하면 처리 중 응답이 모두 3초 안에 보이고,
  모두 안내 전달 마감(FR-008) 안에 답변이나 안내로 바뀐다. 처리 중 응답 시간과 갱신까지 시간의 p50·p95를 질문 수·날짜·모델·인덱스 버전과 함께 기록한다(C-13).
- **SC-002**: SC-001에서 자료로 답할 수 있는 질문의 답변에는 모두 출처 목록이 붙고 각 링크가 원본 문서를 연다. 자료에 없는 질문은 모두 "제공된 자료만으로 확인할 수 없습니다."로 답한다
  (로드맵 1.G). 판정은 사람이 화면을 보고 확정하고 화면 기록(값 가림)을 남긴다.
- **SC-003**: 서명 없음·틀림·시각 초과 요청 시험 전부가 거부되고 검색·생성·Discord 호출이 0회다.
- **SC-004**: 허용 밖 서버·채널·DM·스레드·역할 없음·빈 허용 목록 시험 전부가 질문자만 보는 안내로 끝나고 검색·생성 호출이 0회다.
- **SC-005**: 비밀값 규칙에 걸리는 질문 시험 전부에서 채널에 공개되는 메시지가 0건, 임베딩·생성 호출이 0회, 안내·로그 안의 맞은 문자열이 0건이다. 이와 별도로 사람 단계에서 합성
  비밀값(실제 값이 아닌 규칙에 맞춘 가짜 값)으로 `/ask`를 실행해, 다른 구성원 화면에 명령 실행 사실과 질문 인자가 보이지 않는지 질문자 화면과 대조해 기록한다. 이 확인 전에는 FR-006의
  "질문이 채널에 공개되지 않는다"를 응답 메시지 비공개까지만 보장된 것으로 본다(Assumptions).
- **SC-006**: 상태·표시·실패 종류별 시험 전부에서 FR-011 표의 문구가 나오고, 메시지 안에 실패 종류 이름·제공자 오류·예외 메시지·주소·질문 원문이 든 사례가 0건이다.
- **SC-007**: 분할 시험(긴 본문, 긴 코드 블록, 경계에 걸친 링크·인용, 공백 없는 긴 문자열, 한도를 넘는 본문 링크, 설정이 허용하는 최대 수의 출처 항목이 모두 최대 길이 제목·긴 링크를
  가진 경우, 상한 초과 본문) 전부에서 모든 메시지가 한도 안이고, 코드 블록 짝이 맞으며, 링크·`[S번호]` 표기가 나뉜 사례가 0건이고, 출처 항목의 순서·개수가 생성 결과와 같으며, 메시지 수가
  상한 안이다. 출처 목록이 메시지 수 상한 − 1을 넘게 되는 설정은 설정 검사 시험에서 모두 거부된다.
- **SC-008**: 멘션 꼴 글을 심은 시험 전부에서 알림을 일으키는 메시지가 0건이고, 서식 글자를 심은 출처 제목이 링크 꼴을 바꾼 사례가 0건이다.
- **SC-009**: 질의 경로 시험 전부(실패 주입 포함)에서 운영 로그·오류 메시지에 질문 원문, 답변 본문, 청크 본문, 출처 제목, Discord 사용자 식별자, 자격 정보가 든 사례가 0건이다.
- **SC-010**: 운영 환경에서 인스턴스 공인 주소의 데이터베이스 포트와 질의 서비스 포트 접속이 모두 실패하고, 로컬 데이터베이스 시험에서 질의 경로 자격으로 문서·청크·인덱스 버전 표 쓰기·지우기와 스키마 변경이
  모두 거부되며, 검색과 사용량 기록은 성공한다.
- **SC-011**: 같은 상호작용을 처리 중에 다시 보낸 시험과 처리가 끝난 뒤(15분 안) 다시 보낸 시험 모두에서 질의 실행과 갱신이 한 번뿐이고, 중복 판정 상태에 질문·사용자 정보가 없다.
  질의 서비스를 다시 시작한 뒤 같은 상호작용을 보낸 시험은 다시 처리되는 것을 기대 결과로 기록한다(FR-010 예외). 등록 명령을 두 번 실행한 시험에서 등록 결과가 같다.
- **SC-013**: "나만 보기"를 켠 시험 전부(답변, 분할된 답변, 실패 안내 포함)에서 채널에 공개되는 메시지가 0건이다. 처리 중 응답 전 검사(허용 범위, 비밀값, 지원하지 않는 요청)를 통과하고
  질의 서비스가 받아들인(FR-007 예외에 들지 않은)
  "나만 보기"를 끈 시험 전부에서 처리 중 응답과 답변 메시지가 모두 공개다. 검사에 걸린 요청은 인자와 상관없이 질문자만 보는 안내다(SC-004·SC-005).
  SC-001 실측에 "나만 보기" 질문을 1개 이상 넣어 화면에서 확인한다.
- **SC-012**: SC-001 실측에서 질문마다 단계별 시간, 실행 환경이 센 처리 시간, 외부 호출 수(상한 20 이하), 소비 Neurons(측정·추정 구분)를 FR-025의 조건과 함께 기록한다.
  한도를 넘은 단계가 있으면 넘은 한도와 대안을 함께 적는다.

**Discord 플랫폼 동작** (2026-10-25 독립 검토가 공식 문서로 확인. 계획 단계 research에 다시 적는다)

- 상호작용에는 3초 안에 첫 응답을 보내야 하고, 상호작용 토큰은 15분 동안 유효해 그동안 같은 상호작용의 메시지를 고치거나 더할 수 있다
  (https://docs.discord.com/developers/interactions/receiving-and-responding).
- 이미 보낸 응답의 비공개(질문자만 보기) 여부는 바꿀 수 없다(같은 문서, followup message). 그래서 처리 중 응답을 보내기 전에 공개 범위를 정한다(FR-006·FR-007, Edge Cases).
- 메시지 하나의 본문 글자 수 한도는 2,000자이고, 임베드는 별도 한도가 있다(https://docs.discord.com/developers/resources/message). 어느 꼴로 보일지는 계획 단계에서 정하고, FR-012는
  고른 꼴의 한도를 따른다.
- 상호작용 요청은 Ed25519 서명과 서명 시각 헤더를 달고 오고, 서명은 시각과 원본 요청 본문을 이어 붙인 값으로 검사한다(https://docs.discord.com/developers/interactions/overview).
- **미확인**: 질문자만 보는 응답으로 처음 답하면 명령 실행 사실과 질문 인자까지 다른 구성원에게 보이지 않는지는 확인하지 못했다. 공식 자료로 확인된 것은 응답 메시지가 질문자에게만
  보인다는 것까지다(https://support-apps.discord.com/hc/en-us/articles/26501839512855-Ephemeral-Messages-FAQ). FR-006의 종단 간 비공개는 SC-005의 사람 단계 확인 뒤에 확정한다.
  확인 결과 인자가 보인다면, 비밀값이 든 질문은 채널에 이미 노출된 것이므로 안내 문장에 "질문 기록을 지우고 해당 값을 바꾸라"는 권고를 더하는 명세 변경을 따로 올린다.

**실행 환경 한도** (2026-10-25 독립 검토가 공식 문서로 확인)

- Worker(중계)는 Cloudflare Workers Free에서 돈다(ADR-008). 요청당 CPU 10 ms, 외부 호출 50, 동시 외부 연결 6이고, CPU 시간은 외부 호출을 기다리는 시간을 세지 않는다
  (https://developers.cloudflare.com/workers/platform/limits/). Python Worker 기동이 CPU 한도 안인지는 재 보지 않았다(QK-FND-001 research). 계획 단계 실측(M-02)으로 확인한다.
- 응답을 보낸 뒤 계속 처리(`waitUntil`)는 응답 뒤 30초까지 유지되고, 지나면 끝나지 않은 작업이 취소된다(https://developers.cloudflare.com/workers/runtime-apis/context/#waituntil).
  생성 경계는 재시도까지 기본 45초가 걸릴 수 있다. 이 충돌 때문에 검색·생성은 질의 서비스가 실행한다(2026-10-25 결정, ADR-022). Worker의 응답 뒤 처리는 질의 서비스에 시작 확인을 보내는
  짧은 호출 하나뿐이다(plan research R-03).
- 질의별 생성 설정은 기존 생성 함수의 설정 인자로 넘길 수 있다(`generate(request, deps, settings)`, 2026-10-25 독립 검토 확인). 생성 포트(`Generator.generate(request)`)에는 설정 인자가
  없으므로, 포트를 유지하려면 질의별 설정을 가진 어댑터로 조립한다. 어느 쪽으로 할지는 계획 단계에서 정한다. 설정을 넘기는 것만으로 강제 종료가 되지는 않으므로 질의 마감은 질의 경로가
  기다리지 않는 방식으로 지킨다(FR-008).
- Python Worker가 CPU 한도에 걸리면 중계 Worker만 TypeScript로 옮긴다(QK-FND-001 research). 검색·생성은 질의 서비스에서 돌므로 도메인 코드는 옮기지 않는다(C-06).
- 2026-10-25 결정(ADR-022): 위 한도와 동기 코드 문제 때문에 검색·생성은 OCI 인스턴스의 질의 서비스가 실행한다. Worker는 서명 검사와 중계만 하므로 30초 한도와 CPU 위험이 Worker의 첫 응답
  경로로 줄어든다.

**비용**

- 기본 검증은 가짜 제공자로 0 Neurons다.
- 운영 질의 하나는 질의 임베딩과 생성 1회로 약 38~51 Neurons다(QK-GEN-001 Assumptions 비용, 출력 800 기준 38, 1,200 가정 51). 하루 50건이면 약 1,900~2,550으로 질의응답 예비분(3,000) 안이다.
- SC-001·SC-012 실측은 질문 10~12개 × 약 51로 약 500~610 Neurons다. 실행 전 예상량을 보고하고 사람 확인을 받는다(AGENTS.md 3.5).
- 저장소 연결의 추가 고정비는 월 0원이어야 한다(ADR-008, C-05). 무료 범위를 넘는 구성이 필요하면 결정 기록과 사람 승인 전에는 쓰지 않는다.

**범위**

- 질의 로그·피드백 버튼·`/sources`·질의 원문 저장 옵션(QK-OBS-001), 스레드 대화·질의 재작성(QK-BOT-002), `/reindex`(QK-SYN-002), 질문 분류(QK-TRK-001), 요약 게시,
  검색·생성 동작 변경(QK-RET-001·QK-GEN-001)은 이 명세 밖이다.
- Workers 배포, Discord 애플리케이션 서버 설치·명령 등록, 공유 인스턴스 구성 변경은 이 명세의 산출물로 절차를 쓰고, 실제 실행은 명세·결정 승인과 팀원 동의 뒤 사람이 명령마다 승인해서 한다.
- 허용 채널·역할의 실제 값(어느 채널인지)은 운영 설정이며 문서·저장소에 식별자를 기록하지 않는다.
