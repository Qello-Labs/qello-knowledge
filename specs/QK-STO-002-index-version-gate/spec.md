## User Scenarios & Testing *(mandatory)*

이 명세의 사용자는 운영 저장소에서 새 인덱스 버전을 만들고 활성화하는 운영 담당자, QK-EVL-001 실행기로 평가를 돌리는 평가 담당자, 게이트 기준과 활성화를 승인하는 결정자(사람 리뷰어),
PR 리뷰어다. Discord에서 질문하는 팀원은 이 절차를 직접 쓰지 않는다. 다만 새 버전을 만드는 동안에도 검색 결과가 그대로여야 하고, 버전을 바꾸는 순간에도 두 버전이 섞인 결과를 받지 않아야 한다.
뒤따르는 작업(QK-CHK-001 코드 청킹 켜기, QK-ING-003 Confluence 켜기, ADR-010 운영 반영, 임베딩 모델 교체)은 이 절차로 새 인덱스 버전을 활성화한다.

용어:

- **인덱스 버전 재료**: 인덱스 버전 ID를 정하는 값이다. 지금은 임베딩 모델, 차원, 청킹 규칙 버전, 메타데이터 스키마 버전 넷이다(`sync/keys.py`의 `index_version_id`). 재료가 같으면 ID가 같다.
- **활성 버전·준비 버전·보관 버전**: QK-STO-001 FR-005의 상태(`active`·`ready`·`archived`)다. 검색은 활성 버전의 청크만 본다(QK-STO-001 FR-008).
- **현재 설정 버전**: 배포된 코드와 설정으로 계산한 인덱스 버전이다. 동기화는 이 버전에만 쓴다(QK-SYN-001 FR-019).
- **불일치**: 활성 버전이 있고 현재 설정 버전과 다른 상태다. 지금 동기화는 이 상태에서 바뀐 문서 처리와 일반 내림을 보류하고 "인덱스 버전 불일치"로 보고한다
  (QK-SYN-001 FR-020, `domain/sync.py`의 `ALLOWED`). 보안 내림만 한다.
- **재색인**: 불일치 상태에서 활성 버전을 그대로 둔 채 모든 대상 문서를 현재 설정 버전에 처리하는 실행이다. 사람이 명시적으로 시작한다.
- **기준 버전·후보 버전**: 게이트 비교에서 기준은 지금 활성 버전, 후보는 활성화하려는 준비 버전(현재 설정 버전)이다.
- **평가 대상**: QK-EVL-001이 정한 로컬 컨테이너의 `qk_eval_*` 데이터베이스다. 질문 세트의 라벨 기준 커밋으로 만든다.
- **게이트 정책**: 통과 기준(필수 질문 세트, 판정 방식, 주 지표, 허용 하락, 가드레일, 최소 판정 질문 수)을 담은 파일이다. 측정 전에 고정한다.
- **게이트 기록**: 게이트 정책과 QK-EVL-001 실행 기록으로 한 판정 결과 파일이다. 활성화가 이 기록을 확인한다.
- **덮음**: 활성 버전에서 검색되는 문서 가운데 후보 버전 처리를 마친 문서 수다. 처리를 마친 문서는 후보 버전 청크가 있거나, "본문 없음"이거나, 새 설정에서 "대상 아님"인 문서다.
- **본문 삭제 대기**: 보안 내림 뒤 다시 처리된 문서에서, 다른 인덱스 버전에 남은 보안 대상 본문이다(QK-SYN-001 FR-017). 문서마다 남은 버전 목록이 있다.
- **전환 기록**: 인덱스 버전 상태가 바뀔 때마다 남기는 기록이다(첫 활성화, 활성화, 되돌리기, 정리, 재사용).

### User Story 1 - 활성 버전을 그대로 둔 채 새 인덱스 버전을 만든다 (Priority: P1)

운영 담당자가 청킹 규칙이나 임베딩 모델을 바꾼 코드를 배포하면 현재 설정 버전이 활성 버전과 달라진다. 운영 담당자는 재색인 미리 보기로 비용과 예상 일수를 확인하고,
명시적으로 허락한 재색인 실행으로 모든 대상 문서를 새 버전에 처리한다. 그동안 팀원의 검색은 계속 활성 버전을 쓴다.

**Why this priority**: 지금은 불일치가 생기면 동기화가 멈추고 새 버전을 만들 방법이 없다(QK-SYN-001 FR-020). 평가와 활성화도 새 버전이 먼저 있어야 할 수 있다.

**Independent Test**: 로컬 시험 데이터베이스에 활성 버전 하나를 만들고 청킹 설정을 바꿔 재색인한다. 재색인 전후로 같은 질의의 활성 버전 검색 결과와 출처 정보가 같은지,
새 버전에 모든 대상 문서가 처리됐는지, 가짜 임베딩 제공자의 호출 수가 미리 보기 예상과 맞는지 본다.

**Acceptance Scenarios**:

1. **Given** 불일치 상태(활성 V1, 현재 설정 V2), **When** 운영 담당자가 재색인 미리 보기를 실행하면, **Then** 대상 문서 수, 새로 임베딩할 청크 수, 캐시 적중 수, 예상 Neurons와 계산 근거,
   오늘 남은 색인 예산, 예산 안에서 끝내는 데 필요한 예상 실행 일수, 지금 덮음이 나온다. 임베딩 호출과 저장소 쓰기는 0건이다(원본 목록·본문 읽기는 한다).
2. **Given** 같은 상태, **When** 재색인을 명시적으로 허락해 실행하면, **Then** V2가 준비 상태로 생기고(이미 있으면 그대로 쓴다) 대상 문서가 V2에 처리된다.
   V1의 청크는 만들어지거나 바뀌거나 지워지지 않고, 검색은 계속 V1을 쓰며, V1 결과의 출처 정보도 그대로다.
3. **Given** 미리 보기가 예산 초과일 때, **When** 재색인을 실행하면, **Then** 기본은 실행하지 않는다. 사람이 부분 실행을 명시적으로 고르면 예산 안에서 처리할 만큼만 처리하고 멈춘다.
   **When** 다음 날 다시 실행하면, **Then** 처리를 마친 문서는 다시 처리하지 않고 남은 문서만 처리한다.
4. **Given** 재색인 도중 한 문서가 비밀값 규칙에 걸리면, **When** 그 실행이 끝나면, **Then** 그 문서는 V1을 포함한 모든 검색에서 즉시 빠진다(QK-SYN-001 보안 내림 규칙 그대로).
5. **Given** 재색인 도중 원본에서 지워진 문서가 있으면, **When** 재색인 실행이 끝나면, **Then** 그 문서는 지금 일반 내림 규칙(비율 안전장치 포함)대로 V1 검색에서도 빠진다(FR-010).
   새 설정에서만 "대상 아님"인 문서는 내리지 않고 V2 처리 완료로 센다.
6. **Given** 불일치 상태, **When** 예약 동기화가 돌면, **Then** 재색인을 시작하지 않고 지금처럼 불일치로 보고한다. 보고에 V2의 덮음과 남은 문서 수가 더해진다.
7. **Given** 재색인 도중 설정이 다시 바뀌어 현재 설정 버전이 V3가 되면, **When** 재색인을 실행하면, **Then** V3로 처리하고 V2는 정리 대상으로 표시된다. V2에 대한 게이트 기록은 V3 활성화에 쓰이지 않는다.
8. **Given** 현재 설정 버전 ID가 보관 버전(정리 여부와 관계없이)과 같아졌을 때, **When** 재색인을 실행하면, **Then** 그 버전이 준비 상태로 돌아오고(재사용 전환) 활성 이력은 남는다.
9. **Given** 임베딩 모델만 바꾼 설정(차원 1024 유지), **When** 미리 보기를 실행하면, **Then** 캐시를 쓸 수 없는 전체 재임베딩 청크 수와 예상 Neurons, 예상 일수가 나온다.

### User Story 2 - 후보 버전을 평가 게이트로 판정한다 (Priority: P1)

결정자가 측정 전에 게이트 정책을 정하고, 리뷰를 거쳐 `main`에 병합해 고정한다. 평가 담당자는 기준 버전·후보 버전과 인덱스 버전 ID가 같은 평가 대상을 라벨 기준 커밋으로 만들고,
QK-EVL-001 실행기(`qk-dev eval run`)로 정책이 요구하는 질문 세트를 돌린다. 게이트 판정 명령은 실행 기록과 정책만 읽어 통과·실패·판정 불가를 내고 게이트 기록을 남긴다.

**Why this priority**: AGENTS.md 3.3과 C-07은 평가를 통과한 버전만 활성화하게 한다. 판정 규칙이 코드와 고정된 정책으로 정해져야, 작성 세션이나 사람이 수치를 본 뒤 그때그때 통과를 정하지 않는다(AGENTS.md 9절).

**Independent Test**: 손으로 만든 실행 기록 예시(통과, 지표 하락, 후보에서만 실패한 질문, 가드레일마다 하나, 판정 불가 사유마다 하나)와 정책 예시로 판정을 돌려 기대 판정·지표·사유와 같은지 본다.
저장소 데이터베이스와 외부 호출 없이 끝난다.

**Acceptance Scenarios**:

1. **Given** 정책이 요구하는 질문 세트마다 완료된 실행 기록이 있고 기록 안에 기준·후보 평가 대상이 있을 때, **When** 판정하면, **Then** 세트별 주 지표(기준값, 후보값, 차이, 판정 질문 수),
   가드레일 결과, 회귀 질문 ID(기준에서는 상위 5건 안에 근거가 있었지만 후보에서는 없음)와 개선 질문 ID, 판정(통과·실패)이 게이트 기록에 남는다.
2. **Given** 후보의 주 지표 하나가 허용 하락보다 더 떨어졌을 때, **When** 판정하면, **Then** 실패이고 어긴 세트·방식·지표가 기록에 남는다.
3. **Given** 기준에서는 정상 결과였던 질문이 후보에서 근거 미색인·검색 실패·하이브리드 생략이 됐을 때, **When** 판정하면, **Then** 그 질문은 판정에서 빠지지 않고 후보의 놓침으로 계산된다.
4. **Given** 실행 기록이 미완료이거나, 세트가 확정 전이거나, 세트 지문이 정책과 다르거나, 비교 조건이 다르거나, 평가 대상의 인덱스 버전 ID·토크나이저가 요청과 다르거나,
   실행한 코드 커밋이 정책 고정 커밋을 포함하지 않거나 커밋하지 않은 변경이 있었거나, 판정 질문 수가 정책 최소값보다 적을 때, **When** 판정하면, **Then** "판정 불가"와 사유 이름이 나오고 통과·실패를 내지 않는다.
5. **Given** 게이트 기록을 만든 뒤 실행 기록 파일 내용이 바뀌었을 때, **When** 활성화가 그 게이트 기록을 확인하면, **Then** 지문이 맞지 않아 거부된다.
6. **Given** 측정 뒤에 정책의 허용 하락을 바꾸려 할 때, **Then** 새 정책 버전을 리뷰를 거쳐 `main`에 병합해야 하고, 새 정책으로 판정하려면 그 병합 커밋을 포함한 코드로 다시 돌린 실행 기록이 있어야 한다.

### User Story 3 - 게이트를 통과한 버전만 활성화하고 이전 버전은 보관한다 (Priority: P1)

운영 담당자가 게이트 기록을 지정해 활성화 미리 보기를 보고, 확인 옵션을 준 실행에서 후보 버전을 활성으로 바꾼다. 이전 활성 버전은 보관 상태가 된다.

**Why this priority**: 로드맵 2.G 완료 조건 "새 인덱스 버전을 만들고, 평가를 통과한 뒤 활성화하는 절차"의 끝이다. 지금 활성화 명령은 활성 버전이 없을 때만 동작한다(QK-SYN-001 FR-021).

**Independent Test**: 로컬 시험 데이터베이스에서 V1 활성, V2 준비 상태를 만들고, FR-021 조건마다 그 조건 하나만 어긴 상태에서 활성화가 거부되고 아무 상태도 바뀌지 않는지 본다.
모든 조건을 채운 상태에서는 V2 활성, V1 보관으로 한 번에 바뀌는지, 전환 중 동시 검색이 두 버전이 섞인 결과를 받지 않는지 본다.

**Acceptance Scenarios**:

1. **Given** V2가 FR-021 조건을 모두 채울 때, **When** 확인 옵션을 주어 활성화하면, **Then** V2가 활성, V1이 보관 상태로 한 번에 바뀌고 검색이 바로 V2를 쓴다.
   전환 기록에 게이트 기록 ID와 지문, 기준·후보 버전, 문서·청크 수가 남는다.
2. **Given** FR-021 조건 하나를 채우지 못했을 때, **When** 활성화하면, **Then** 거부되고 채우지 못한 조건 이름이 모두 나온다. 상태와 전환 기록은 바뀌지 않는다.
3. **Given** 확인 옵션 없이 활성화를 실행하면, **Then** 기준·후보의 문서 수·청크 수, 덮음, 처리 실패 문서 수, 벡터 없는 청크 수, 본문 삭제 대기 문서 수, 게이트 기록 요약(세트별 지표·판정 질문 수),
   게이트 정책의 요청 단위 검색 설정과 실행 코드의 기본값, 평가가 다루지 않은 자료원 종류를 보이고 아무것도 바꾸지 않는다.
4. **Given** V2 활성화 직후, **When** 예약 동기화가 돌면, **Then** 불일치가 없어 바뀐 문서를 V2에 처리하고 보류했던 일반 내림을 한다.
5. **Given** 활성 버전이 하나도 없을 때(첫 색인), **Then** 첫 버전 활성화는 QK-SYN-001 FR-021 그대로이고 이 명세의 활성화 명령은 쓰지 않는다.

### User Story 4 - 문제가 생기면 보관 버전으로 되돌린다 (Priority: P2)

V2를 활성화한 뒤 답변 품질이 떨어지거나 운영 문제가 생기면, 운영 담당자가 사유를 적고 보관 버전(보통 직전 활성 버전 V1)을 다시 활성으로 바꾼다.

**Why this priority**: 평가 세트가 작아(QK-EVL-001 골든 세트 지표 대상 8문항) 게이트를 통과해도 실제 사용에서 문제가 드러날 수 있다. 되돌릴 길이 있어야 활성화의 위험이 작다. 활성화가 먼저 있어야 해 P2다.

**Independent Test**: V1 보관·V2 활성 상태에서 되돌리고, V1 활성·V2 보관이 되는지, 보안 내림된 문서와 본문 삭제 대기 본문이 V1 검색에 나오지 않는지, 정리된 버전은 거부되는지 본다.

**Acceptance Scenarios**:

1. **Given** V2 활성, V1 보관(청크 정리 전), **When** 사유와 확인 옵션을 주어 V1로 되돌리면, **Then** V1 활성, V2 보관으로 한 번에 바뀌고 전환 기록에 사유가 남는다. 게이트를 다시 거치지 않는다.
2. **Given** 되돌린 뒤 현재 설정 버전이 여전히 V2일 때, **Then** 상태 보기와 동기화 보고가 불일치를 알리고 해소 방법(설정을 V1으로 되돌려 배포, 또는 V2 문제를 고친 새 버전 절차)을 보인다.
3. **Given** V2 활성 기간에 내린 문서, **When** V1로 되돌리면, **Then** 그 문서는 V1 검색에도 나오지 않는다.
4. **Given** 되돌리기 미리 보기, **Then** V1에 청크가 없는 노출 문서 수(V1 보관 뒤에 새로 생긴 문서), V1 청크와 지금 문서 단위 출처 정보가 어긋나는 문서 수, 본문 삭제 대기에 V1이 든 문서 수를 보인다.
5. **Given** 출처 정보가 어긋나는 문서가 1개 이상일 때, **When** 별도 확인 옵션 없이 되돌리면, **Then** 거부된다. 별도 확인 옵션을 주면 되돌리고 그 수를 전환 기록에 남긴다.
6. **Given** 본문 삭제 대기에 V1이 든 문서가 있거나, V1이 정리됐거나 한 번도 활성이었던 적이 없을 때, **When** 되돌리기를 하면, **Then** 거부된다.

### User Story 5 - 버전 상태를 보고, 쓰지 않는 버전을 정리하고, 불일치를 해소한다 (Priority: P2)

운영 담당자는 상태 보기로 활성·현재 설정·준비·보관 버전과 각 버전의 크기, 재색인 덮음, 불일치 해소 방법을 본다. 쓰지 않게 된 준비 버전과 오래된 보관 버전의 청크는
미리 보기와 확인을 거쳐 지운다.

**Why this priority**: QK-SYN-001이 쓰지 않게 된 준비 버전 정리와 불일치 해소 절차를 이 명세로 넘겼다(QK-SYN-001 plan). 버전마다 청크가 따로 쌓이므로 정리하지 않으면 저장소가 커진다.

**Independent Test**: 준비 버전 둘, 보관 버전 둘, 활성 버전 하나를 만든 뒤 상태 보기 값이 데이터베이스와 같은지, 정리 거부 조건마다 거부되는지, 정리한 버전의 청크가 0이고 다른 버전 청크와 임베딩 벡터는 그대로인지,
본문 삭제 대기 목록에서 정리한 버전이 빠지는지 본다.

**Acceptance Scenarios**:

1. **Given** 여러 버전이 있을 때, **When** 상태 보기를 실행하면, **Then** 활성 버전, 현재 설정 버전, 일치 여부, 불일치가 시작된 시각, 버전마다 상태·재료·문서 수·청크 수·정리 여부·마지막 재색인 결과·활성 이력이 나온다.
   불일치면 해소 방법 두 가지(재색인 → 게이트 → 활성화, 또는 설정을 활성 버전으로 되돌려 배포)와 처리 실패가 계속되는 문서 목록(위치와 실패 단계)을 보인다. 저장소에 쓰지 않는다.
2. **Given** 준비 버전 V3를 정리하려 할 때, **When** 확인 옵션 없이 실행하면, **Then** 지울 청크 수만 보이고 아무것도 지우지 않는다. **When** 확인 옵션을 주면, **Then** V3 청크를 지우고 V3를 보관·정리됨으로 표시한다.
3. **Given** 활성 버전이나 재색인 중인 현재 설정 버전을 정리하려 하면, **Then** 거부된다.
4. **Given** 가장 최근 보관 버전(되돌리기 대상)을 정리하려 하면, **Then** 되돌리기 대상임을 알리는 별도 확인 옵션이 있을 때만 지운다.
5. **Given** 정리가 도중에 중단됐을 때, **When** 다시 실행하면, **Then** 남은 청크만 지우고 끝난다. 다른 버전의 청크와 임베딩 벡터는 지우지 않는다.

### User Story 6 - 운영에서 절차를 한 번 끝까지 실행한다 (Priority: P3)

구현이 끝난 뒤 운영 담당자와 결정자가 실제 설정 변경 하나(ADR-010 결정 결과나 Phase 1 평가로 고친 청킹 설정)로 재색인 → 평가 → 게이트 → 활성화를 한 번 끝까지 실행하고 기록을 남긴다.

**Why this priority**: 로드맵 2.G 완료 조건이다. 구현과 사람 승인, 운영 접근이 모두 있어야 해 마지막이다.

**Independent Test**: 시험이 아니라 사람 단계다. 실행 전 예상 Neurons 보고, 게이트 정책 병합 커밋, 게이트 기록, 활성화 전환 기록, 실제 Neurons 사용량이 남았는지 본다.

**Acceptance Scenarios**:

1. **Given** 설정 변경 PR이 병합되고 배포됐을 때, **When** 운영 담당자가 평가 대상 준비·질의 임베딩·재색인의 예상 Neurons를 합쳐 보고하고 승인을 받아 실행하면, **Then** 실제 사용량이 각 장부에 남고 보고와 대조된다.
2. **Given** 게이트가 통과일 때, **When** 활성화하면, **Then** 게이트 기록과 전환 기록이 Jira 이슈 증빙으로 남는다. 실패나 판정 불가면 활성화하지 않고 그 기록을 남긴다(목표 미달도 기록, C-13).

### Edge Cases

- **재색인 동안 활성 버전이 낡음**: 불일치 상태에서는 바뀐 문서가 활성 버전에 반영되지 않는다(QK-SYN-001 FR-020). 재색인부터 활성화까지가 이 기간이다. 미리 보기의 예상 일수로 기간을 미리 보이고,
  상태 보기에 불일치가 시작된 시각을 보인다.
- **불일치 중 일반 내림 보류**: 지금 불일치 보류는 원본에서 사라진 문서와 끈 자료원 문서의 일반 내림도 막는다(`domain/sync.py`의 `ALLOWED`). 그대로 두면 재색인부터 활성화까지 지워진 문서가 활성 버전에서 계속 검색된다.
  FR-010이 재색인 실행에서 설정과 무관한 일반 내림을 하게 한다. 예약 실행의 보류는 바꾸지 않는다(D2).
- **재색인이 문서 단위 값을 바꿈**: 원본 버전은 청크마다 저장되지만(`chunk.source_version`), 원본 링크·제목·원본 수정 시각·수집 시각은 문서 단위로 저장되고 지금 문서 처리가 바뀌지 않은 문서도 덮어쓴다
  (`adapters/postgres/sync_store.py`의 문서 행 갱신). 그러면 재색인만 해도 활성 버전 결과의 출처 정보가 바뀐다. FR-005가 이를 막는다. 방법은 plan에서 정한다.
- **본문 삭제 대기 본문의 재노출**: 보안 내림 뒤 다시 처리된 문서는 그때 쓴 버전만 대기 목록에서 빠진다. 다른 버전에 남은 옛 본문은 그 버전이 활성이 아니어서 검색되지 않는다는 것이 지금의 안전 근거다
  (QK-SYN-001 FR-017). 그 버전을 활성화하거나 되돌리면 옛 본문이 다시 검색된다. FR-021 (10)과 FR-025가 막는다.
- **보류된 예약 실행의 기록**: 불일치 중 예약 실행도 실행 기록에 현재 설정 버전을 적고 보류 때문에 "멈춤"으로 끝난다. 활성화 조건은 재색인 실행만 본다(FR-021 (2)).
- **영구 처리 실패**: 입력 한도 초과처럼 계속 실패하는 문서가 있으면 덮음이 차지 않아 활성화할 수 없다. 실패를 무시하는 옵션은 두지 않는다. 원인을 고치거나 그 문서를 자료원 설정에서 빼는 것은 사람이 정한다(FR-011).
- **같은 재료로 돌아감**: 설정을 옛 값으로 되돌리면 보관(정리 포함) 버전과 같은 ID가 나온다. 재색인이 그 버전을 준비 상태로 되돌린다(FR-001 재사용 전환). 정리 전 보관 버전이면 되돌리기도 고를 수 있다.
- **기준 평가 대상을 만들 수 없음**: 평가 대상은 라벨 기준 커밋과 그때 코드로 만든다. 새 청킹 규칙을 담은 코드는 옛 청킹 규칙 버전을 만들지 못할 수 있다. 그래서 기준 평가 대상은 활성 버전을 만든 코드 커밋으로 만들 수 있어야 한다.
  만든 기준 평가 대상의 인덱스 버전 ID가 운영 활성 버전과 다르면 게이트는 판정 불가다.
- **평가 대상을 만들 수 없는 후보**: 지금 평가 대상 준비 명령과 실행기는 후보 A·B·C(색인 쪽 규칙과 토크나이저의 세 조합)만 다룬다. 평가 대상 이름도 (규칙, 커밋)으로 정해져 규칙이 같은 기준·후보를 함께 만들 수 없다
  (`devtools/eval_index.py`, `evaluation/prechecks.py`). 코드 청킹·Confluence 켜짐·다른 임베딩 모델 후보는 그 확장 뒤에야 게이트를 쓸 수 있다(Assumptions "의존과 넘김").
- **같은 인덱스 버전 ID, 다른 키워드 동작**: 키워드 색인 토크나이저는 인덱스 버전 재료가 아니고 모든 버전의 청크에 걸린 키워드 색인 하나의 설정이다. QK-EVL-001 후보 A와 C는 인덱스 버전 ID가 같다(`iv-4c0bc4fcc642`). FR-033이 다룬다.
- **임베딩 모델이 다른 후보**: QK-EVL-001 실행기는 한 실행의 대상이 모두 같은 임베딩 모델이어야 하고(사유 `model_mismatch`), 비교표는 임베딩 모델이 다른 기록을 비교하지 않는다(QK-EVL-001 research R-11).
  그래서 모델 교체 후보는 기준과 후보를 다른 실행으로 돌려야 하고 질의 벡터도 다시 쓸 수 없다. FR-015 (4)가 이 경우의 비교 조건을 정한다.
- **차원이 다른 임베딩 모델**: 스키마가 차원을 1024로 고정한다(`migrations/0001_initial_schema.sql`). 차원이 다른 모델은 저장이 거부되므로 이 절차로 바꿀 수 없다. 별도 스키마 변경 작업이다.
- **평가가 다루지 않는 자료원**: 질문 세트의 근거 문서가 한 자료원(지금은 `dnd-backend-docs`)에만 있으면 다른 자료원에 생긴 변화는 평가에 드러나지 않는다. 게이트 기록에 평가가 다룬 자료원을 남기고,
  활성화 미리 보기가 운영에는 있지만 평가가 다루지 않은 자료원 종류를 보인다.
- **게이트 통과 뒤 활성화 전 원본이 바뀜**: 게이트는 인덱스 버전 ID로 가리키는 설정을 판정한다. 운영 데이터는 라벨 기준 커밋보다 새롭다. 활성화 전 마지막 재색인 실행이 성공했고 덮음이 채워졌으면 활성화할 수 있다.
- **기준 버전이 바뀜**: 게이트 기록을 만든 뒤 되돌리기 등으로 활성 버전이 바뀌면, 기록의 기준 버전이 지금 활성 버전과 달라 활성화가 거부된다.
- **키워드 규칙 대응표에 없는 후보**: 대응표(`domain/keyword_rules.py`)에 없는 버전을 활성화하면 검색 요약의 색인 쪽 규칙이 `unknown`이 되고, 코드 청킹·Confluence 켜짐 버전은 설정 점검이 막는다(`config/check.py`).
  대응표에 더하는 코드 변경이 재색인보다 먼저다.
- **전환 순간의 검색**: 검색 하나가 벡터·키워드·문맥 확장을 따로 조회하는 사이에 활성 버전이 바뀌면 그 검색은 `index_version_changed`로 실패하고 다시 시도하지 않는다(`retrieval/service.py`).
  결과가 섞이지는 않는다. SC-004가 이 실패를 센다.
- **평가 사용량이 운영 장부에 안 보임**: 평가 대상 준비와 질의 임베딩 사용량은 평가 대상 데이터베이스의 장부에 남는다(QK-EVL-001 Assumptions). 무료 한도는 계정 단위라, 같은 날 운영 재색인까지 하면
  운영 장부의 잔여량이 실제보다 많아 보인다. FR-034가 다룬다.
- **동기화와 동시 실행**: 활성화·되돌리기·정리는 동기화와 같은 잠금을 쓴다. 동기화가 실행 중이면 거부한다.

## Requirements *(mandatory)*

### Functional Requirements

**버전 상태와 전환 기록**

- **FR-001**: 인덱스 버전 상태는 준비·활성·보관 셋이고 활성은 동시에 하나 이하다(QK-STO-001 FR-005). 상태 전환은 다음뿐이다.
  첫 활성화(준비 → 활성), 활성화(준비 → 활성, 이전 활성 → 보관), 되돌리기(보관 → 활성, 이전 활성 → 보관), 정리(준비·보관 → 보관·정리됨),
  재사용(현재 설정 버전 ID가 보관 버전과 같을 때 재색인이 그 버전을 보관·정리됨 → 준비로 되돌림. 활성 이력은 남는다).
- **FR-002**: 전환마다 전환 기록을 남긴다. 전환 종류, 시각, 전환 전후 활성 버전, 대상 버전의 문서·청크 수, 실행 위치(로컬·원격)를 담는다.
  활성화는 게이트 기록 ID와 지문, 되돌리기는 사유와 출처 정보가 어긋난 문서 수, 정리는 지운 청크 수를 더한다. 첫 활성화(QK-SYN-001 FR-021)도 같은 기록을 남긴다. 사람 이름은 담지 않는다.
- **FR-003**: 활성화·되돌리기의 상태 변경은 한 트랜잭션이다. 전환 도중 검색이 활성 버전 둘이나 활성 버전 없음을 보지 않고, 한 검색 결과에 두 버전의 청크가 섞이지 않는다.
  조건 확인과 전환 사이에 동기화·재색인이 끼어들지 않는다.

**재색인 (US1)**

- **FR-004**: 불일치 상태에서 사람이 명시적으로 허락한 재색인 실행만 현재 설정 버전을 준비 상태로 만들고(이미 있으면 그대로 쓰고, 보관 버전이면 재사용 전환) 대상 문서를 그 버전에 처리한다.
  예약 실행은 재색인을 하지 않고 지금처럼 불일치로 보고한다(QK-SYN-001 FR-020).
- **FR-005**: 재색인은 QK-SYN-001과 같은 수집, 보안 필터, 청킹, 임베딩, 문서 단위 원자적 교체, 실행 기록을 쓰고, 실행 기록에 재색인임을 표시한다. 활성 버전의 청크를 만들거나 바꾸거나 지우지 않는다.
  보안 내림은 지금 규칙(QK-SYN-001 FR-015~FR-017)을 그대로 따른다. 재색인 동안 활성 버전의 검색 결과와 출처 정보(원본 링크, 원본 버전, 위치, 제목 경로, 제목, 원본 수정 시각, 수집 시각)는
  재색인 시작 전과 같다. 내린 문서가 빠지는 것만 다르다.
- **FR-006**: 재색인 미리 보기는 임베딩 호출과 저장소 쓰기 없이(원본 읽기는 한다, QK-SYN-001 FR-022) 대상 문서 수, 임베딩할 청크 수, 캐시 적중 수, 예상 Neurons와 계산 근거, 오늘 남은 색인 예산,
  예산 안에서 끝내는 데 필요한 예상 실행 일수, 지금 덮음을 보인다(QK-EMB-001 미리 보기와 같은 계산). 예산 초과면 재색인의 기본 동작은 실행하지 않는 것이고,
  사람이 명시적으로 고른 경우에만 예산 안 부분 실행을 한다(QK-EMB-001 FR-024, AGENTS.md 3.5).
- **FR-007**: 재색인이 중단되거나 부분 실행으로 멈추면 처리를 마친 문서는 그대로 두고, 다음 재색인 실행은 아직 처리하지 않았거나 그 뒤에 바뀐 문서만 처리한다(QK-SYN-001 FR-008 (5)).
  같은 재색인을 다시 실행해도 중복이 생기지 않는다(C-08).
- **FR-008**: 재색인 진행 상태로 덮음, 활성 버전에서 검색되는 문서 수, 남은 문서 수, 처리 실패 문서 수를 보인다. 예약 동기화의 불일치 보고에도 이 값을 더한다.
- **FR-009**: 재색인 도중 현재 설정 버전이 바뀌면 다음 재색인은 새 현재 설정 버전에 처리한다. 이전 준비 버전은 상태 보기에서 정리 대상으로 표시한다. 게이트 기록은 그 기록의 후보 버전에만 쓴다.
- **FR-010**: 재색인 실행은 설정과 무관한 일반 내림(원본에서 사라짐, 자료원 끔, 자료원 설정 제외)을 지금 규칙과 비율 안전장치(QK-SYN-001 FR-016·FR-017)대로 한다. 이 내림은 문서 단위라 활성 버전 검색에서도 빠진다.
  새 설정의 청킹 결과에서만 나오는 "대상 아님"은 내리지 않고 후보 버전 처리 완료로 센다. 그 문서는 활성화 뒤 후보 버전에 청크가 없어 검색되지 않고, 다음 동기화가 일반 내림을 한다.
- **FR-011**: 처리 실패가 계속되는 문서가 있으면 활성화할 수 없다(FR-021 (3)). 상태 보기가 그 문서의 위치와 실패 단계를 보인다. 원인을 고친 코드를 배포하거나(재료가 바뀌면 새 버전) 그 문서를 자료원 설정에서 빼는 것은 사람이 정한다.
  실패를 무시하고 활성화하는 옵션은 두지 않는다.

**평가 게이트 (US2)**

- **FR-012**: 게이트 정책 파일은 정책 ID와 버전, 필수 질문 세트(ID·버전·파일 지문), 판정 방식(기본 하이브리드), 주 지표(Recall@5·MRR), 세트·지표별 허용 하락, 고른 가드레일과 값(FR-017),
  세트별 최소 판정 질문 수, 기준·후보 평가 대상의 토크나이저, 요청 단위 검색 설정(질의 쪽 규칙·후보 수·RRF 상수, 기본은 `RetrievalSettings()` 기본값)을 담는다. 값은 사람이 정한다.
  정책은 측정 전에 리뷰를 거쳐 `main`에 병합해 고정한다. 정책 커밋은 평가 코드·측정 결과·후보 설정 변경과 다른 커밋이다. 고정 뒤에는 바꾸지 않고 새 버전을 더한다(AGENTS.md 3.4, QK-EVL-001 FR-026과 같은 방식).
- **FR-013**: 게이트의 입력은 QK-EVL-001 실행 기록(`qk-evl-001-run/v1`, `contracts/run-record.md`)뿐이다. 이 명세는 그 계약과 질문 세트 형식(`contracts/question-set.md`), 실행 명령(`contracts/cli.md`)을 바꾸지 않는다.
  스키마 이름이 다른 기록은 판정 불가다. 평가 대상은 QK-EVL-001이 정한 로컬 `qk_eval_*` 데이터베이스이고 운영 데이터베이스를 평가 대상으로 쓰지 않는다.
  지금 계약으로 평가할 수 있는 후보는 QK-EVL-001 후보 A·B·C 조합뿐이다. 그 밖의 후보를 위해 계약을 넓히는 일은 QK-EVL-001·QK-RET-001 쪽 변경이고 사람 승인을 받는다(Assumptions "의존과 넘김").
- **FR-014**: 기준 평가 대상의 인덱스 버전 ID는 운영 활성 버전 ID와, 후보 평가 대상의 인덱스 버전 ID는 후보 준비 버전 ID와 같아야 한다. 두 대상은 질문 세트의 라벨 기준 커밋으로 만든다.
  기준 평가 대상은 활성 버전을 만든 코드 커밋으로도 만들 수 있어야 한다(Edge Cases "기준 평가 대상을 만들 수 없음").
- **FR-015**: 판정 전에 다음을 모두 확인한다. 하나라도 어긋나면 판정 불가와 사유 이름을 내고 통과·실패를 내지 않는다.
  (1) 기록이 완료(`complete = true`)다. (2) 정책의 필수 세트마다 기록이 있고, 세트가 확정(`confirmed = true`)됐으며, 세트 ID·버전·지문이 정책과 같다.
  (3) 기준·후보 대상이 기록에 있고 인덱스 버전 ID가 FR-014와 같다. (4) 비교 조건이 같다. 조건은 QK-EVL-001 research R-11의 항목(세트 ID·버전·지문, 자료원별 고정 커밋, 임베딩 모델, 질의 쪽 규칙,
  후보 수, RRF 상수, 검색 필터)이다. 예외로 임베딩 모델은 기준·후보 인덱스 버전의 임베딩 모델이 다를 때만 다를 수 있고, 그때 두 대상은 다른 실행 기록이며 게이트 기록에 "질의 벡터 다름"을 남긴다.
  (5) 요청 단위 검색 설정과 판정 방식이 정책과 같다. (6) 대상의 색인 쪽 규칙이 `unknown`이 아니다. (7) 기준·후보 대상의 토크나이저가 정책에 적은 값과 같다.
  (8) 실행 기록의 코드 커밋(`code_commit.sha`)이 정책을 병합한 커밋을 포함하고 커밋하지 않은 변경이 없었다(`dirty = false`). (9) 세트마다 판정 질문 수(FR-016)가 정책의 최소값 이상이다.
- **FR-016**: 지표 정의(Recall@5, MRR, Precision@5, 상한 도달 비율)는 QK-EVL-001과 같고 실행 기록만으로 다시 계산한다(QK-EVL-001 FR-016~FR-020). 판정 질문 집합은 QK-EVL-001 공통 질문 집합과 다르다.
  지표 대상 질문 가운데 기준 대상에서 정상 결과(`ok`·`no_results`이고 하이브리드 생략 없음)인 질문을 판정 질문으로 둔다. 후보에서 근거 미색인·검색 실패·하이브리드 생략이 된 판정 질문은 빼지 않고
  후보의 놓침(Recall@5 0, 역순위 0)으로 센다. 기준에서 정상이 아닌 질문은 판정에서 빼고 ID와 사유를 게이트 기록에 남긴다.
- **FR-017**: 필수 세트마다 주 지표의 (후보 − 기준)이 허용 하락 이상이고 정책이 고른 가드레일을 모두 채우면 통과, 아니면 실패다. 가드레일은 실행 기록 필드로 계산되는 다음 목록에서만 고른다.
  (G1) 기준에서는 정상이고 후보에서 정상이 아닌 판정 질문 수가 허용 수(기본 0) 이하다. (G2) 식별자 세트의 Precision@5 하락이 허용 하락 이하다. (G3) 키워드 전용 상한 도달 비율 증가가 허용 값 이하다.
  실패면 어긴 세트·방식·지표·가드레일을 남긴다. 회귀 질문 ID와 개선 질문 ID를 판정과 함께 남긴다.
- **FR-018**: 게이트 기록은 스키마 이름에 버전을 둔 JSON 파일 하나다. 정책 ID·버전·파일 지문·병합 커밋, 기준·후보 인덱스 버전 ID·임베딩 모델·토크나이저, 입력 실행 기록의 실행 ID·코드 커밋·파일 지문,
  "질의 벡터 다름" 여부, 세트별 지표(기준값·후보값·차이·판정 질문 수), 판정에서 뺀 질문 ID와 사유, 가드레일 결과, 회귀·개선 질문 ID, 평가가 다룬 자료원, 판정, 판정 불가 사유, 판정한 코드 커밋을 담는다.
  질문 문장, 핵심 사실, 라벨 근거 낱말, 검색어, 청크 본문, 접속 정보는 담지 않는다(QK-EVL-001 `contracts/run-record.md` 6절과 같은 기준). 기록 경로가 이미 있으면 쓰지 않는다.
- **FR-019**: 게이트 판정은 외부 호출과 데이터베이스 접근이 0건이다. 저장소의 git 이력은 FR-015 (8) 확인에 읽는다.

**활성화 (US3)**

- **FR-020**: 활성화는 사람이 게이트 기록을 지정해 실행한다. 확인 옵션이 없으면 미리 보기(US3-3)만 보이고 바꾸지 않는다. 이 활성화는 활성 버전이 있을 때만 쓴다.
  활성 버전이 없을 때는 QK-SYN-001 FR-021의 첫 활성화를 쓴다(평가 통과 조건의 예외, 2026-10-21 사용자 결정).
- **FR-021**: 활성화는 다음을 모두 채울 때만 한다. 채우지 못한 조건은 이름을 모두 보인다.
  (1) 대상이 현재 설정 버전이고 준비 상태다. (2) 그 버전에 쓴 마지막 재색인 실행이 성공으로 끝났고 실행 중인 동기화·재색인이 없다. 불일치로 처리를 보류한 예약 실행은 보지 않는다.
  (3) 활성 버전에서 검색되는 문서가 모두 대상 버전 처리를 마쳤고(덮음 = 노출 문서 수) 처리 실패 문서가 0이다. (4) 대상 버전에 벡터 없는 청크가 0이다. (5) 활성화하면 검색될 문서가 1개 이상이다.
  (6) 게이트 기록이 통과이고, 후보가 대상 버전이며, 기준이 지금 활성 버전이고, 정책이 `main`에 병합된 최신 정책 버전이며, 기록과 입력 실행 기록의 지문이 맞다.
  (7) 대상 버전이 키워드 규칙 대응표에 있다. (8) 활성화 뒤 대상 버전의 키워드 검색에 쓰일 토크나이저가 게이트 기록의 후보 토크나이저와 같다(FR-033).
  (9) 활성화를 실행하는 코드의 `RetrievalSettings()` 기본값이 게이트 정책의 요청 단위 검색 설정과 같다. (10) 본문 삭제 대기 목록에 대상 버전이 든 문서가 0이다. (11) 동기화가 실행 중이 아니다.
- **FR-022**: 활성화는 대상을 활성으로, 이전 활성 버전을 보관으로 바꾸고 전환 기록을 남긴다(FR-002·FR-003).

**되돌리기 (US4)**

- **FR-023**: 되돌리기는 사람이 보관 버전 하나와 사유를 지정해 실행한다. 확인 옵션이 없으면 미리 보기(US4-4)만 보인다. 대상은 청크가 정리되지 않았고 전환 기록에 활성 이력이 있는 보관 버전이다.
  게이트를 다시 거치지 않는다. 그 버전은 이전에 게이트 통과나 첫 활성화로 활성이었기 때문이다.
- **FR-024**: 되돌리기는 본문 삭제 대기 목록에 대상 버전이 든 문서가 0이고 동기화가 실행 중이 아닐 때만 한다. 대상 버전 청크와 지금 문서 단위 출처 정보가 어긋나는 문서가 1개 이상이면
  별도 확인 옵션이 있을 때만 하고 그 수를 전환 기록에 남긴다(D7). 대상을 활성으로, 지금 활성 버전을 보관으로 바꾼다(FR-002·FR-003). 내린 문서는 버전과 관계없이 검색되지 않는다(QK-STO-001 FR-008).
- **FR-025**: 되돌린 뒤 현재 설정 버전이 활성 버전과 다르면 상태 보기와 동기화 보고가 불일치를 알린다. 설정을 되돌린 버전으로 배포하면 동기화가 그 버전에 이어서 처리한다.
  문서 처리 상태는 버전 하나만 저장하므로, 그 사이 다른 버전으로 처리된 문서는 모두 다시 처리된다(QK-SYN-001 FR-008 (5)). 대부분 캐시 적중이고 미리 보기가 그 수와 예상 Neurons를 보인다.

**상태 보기·정리 (US5)**

- **FR-026**: 상태 보기는 저장소에 쓰지 않고 활성 버전, 현재 설정 버전, 일치 여부, 불일치가 시작된 시각, 버전마다 상태·재료·문서 수·청크 수·정리 여부·마지막 재색인 결과·활성 이력·덮음,
  처리 실패가 계속되는 문서(위치·실패 단계)를 보인다. 불일치면 해소 방법 두 가지(재색인 → 게이트 → 활성화, 또는 설정을 활성 버전으로 되돌려 배포)를 보인다.
- **FR-027**: 정리는 사람이 준비·보관 버전을 지정해 그 버전의 청크를 지운다. 확인 옵션이 없으면 지울 청크 수만 보인다. 활성 버전과 현재 설정 버전은 거부한다.
  가장 최근 보관 버전은 되돌리기 대상이라 별도 확인 옵션이 있을 때만 지운다. 버전 행과 전환 기록은 남기고 정리됨으로 표시한다. 그 버전의 본문이 사라졌으므로 문서별 본문 삭제 대기 목록에서 그 버전을 뺀다.
  임베딩 벡터는 지우지 않는다(쓰지 않는 벡터 정리는 QK-SYN-003).
- **FR-028**: 정리가 중단되면 다시 실행해 남은 청크를 지운다. 다른 버전의 청크는 지우지 않는다. 정리는 인덱스 일부 삭제라 사람 확인 없이 실행하지 않는다(AGENTS.md 4절).
- **FR-029**: 예약 실행은 재색인·활성화·되돌리기·정리를 하지 않는다.

**모델 교체, 검색 설정, 키워드 동작**

- **FR-030**: 임베딩 모델 교체(차원 1024 유지)도 같은 절차를 쓴다. 미리 보기는 캐시를 쓸 수 없는 전체 재임베딩 비용과 예상 일수를 보인다(US1-9). 게이트는 FR-015 (4)의 예외로 두 실행 기록을 비교한다.
  평가 대상을 만들려면 FR-013의 계약 확장이 먼저다. 차원이 다른 모델은 이 명세 범위 밖이다.
- **FR-031**: 질의 쪽 검색 설정(`RetrievalSettings`)은 인덱스 버전 재료가 아니라 활성화 대상이 아니다. 기본값 변경은 QK-EVL-001 실행 기록을 근거로 PR 리뷰에서 정한다.
  다만 게이트 정책의 요청 단위 검색 설정과 활성화 코드의 기본값이 다르면 활성화를 거부한다(FR-021 (9)).
- **FR-032**: 게이트 기록과 전환 기록은 임베딩 모델, 인덱스 버전, 질문 세트 버전, 판정 질문 수를 함께 담아 수치를 조건과 함께 남긴다(AGENTS.md 3.4, C-13).
- **FR-033**: 같은 인덱스 버전 ID에서 키워드 검색 동작을 바꾸는 저장소 설정(지금은 키워드 색인 토크나이저)은 게이트 전에 활성 버전의 검색을 바꾸지 않아야 한다(FR-005). 그런 변경은 재색인 → 게이트 → 활성화를 거친다.
  게이트는 평가 대상에서 읽은 토크나이저(실행 기록 `targets[].tokenizer`)를 기록하고, 활성화는 FR-021 (8)을 확인한다. 지금 키워드 색인은 모든 버전의 청크에 걸린 하나이고 토크나이저도 하나라,
  토크나이저를 바꾸는 순간 활성 버전의 키워드 동작이 바뀐다. 그래서 토크나이저를 바꾸는 방법은 ADR-010이 후보 C를 고를 때 사람이 D6의 선택지 가운데 정한다.
  ADR-010이 A나 B를 고르면 토크나이저는 지금 값(기본 토크나이저)으로 고정이고 FR-021 (8)은 그 값인지 확인한다.

**비용 (AGENTS.md 3.5)**

- **FR-034**: 재색인과 게이트 평가를 실행하기 전에 평가 대상 준비의 문서 임베딩, 질의 임베딩(QK-EVL-001 비용 미리 보기), 재색인의 예상 Neurons를 합쳐 보고한다.
  평가 대상의 사용량은 운영 장부에 보이지 않으므로, 같은 날 실행하면 합계를 운영 장부의 일일 무료 한도 잔여량(임베딩·생성 차감)과 대조한다. 넘을 것 같으면 실행하지 않고 날을 나눈다.

**검증 (C-12)**

- **FR-035**: 기본 검증의 시험은 로컬 데이터베이스, 가짜 임베딩 제공자, 손으로 만든 실행 기록·정책 예시만 쓴다. Workers AI·원본 자료원 호출과 운영 데이터베이스 접근은 0건이다.
- **FR-036**: 기존 동작의 시험 기대값(QK-SYN-001 첫 활성화, 예약 실행의 불일치 보류, QK-EVL-001 실행 기록 스키마)을 바꾸지 않는다. 재색인 실행에서 일반 내림을 하는 FR-010은 새 시험으로 확인한다.

### Key Entities

- **인덱스 버전**: ID, 재료 넷, 상태, 만든 시각, 활성화 시각, 정리 여부(QK-STO-001 FR-005에 정리 여부를 더한다).
- **전환 기록**: 전환 종류, 시각, 전후 활성 버전, 대상 버전, 문서·청크 수, 실행 위치, 게이트 기록 ID·지문(활성화), 사유·출처 어긋남 수(되돌리기), 지운 청크 수(정리).
- **재색인 실행**: QK-SYN-001 실행 기록에 재색인 표시를 더한다. 대상 버전, 처리 결과, 사용 Neurons.
- **게이트 정책**: FR-012의 항목. 저장소에 커밋하고 `main` 병합으로 고정한다.
- **게이트 기록**: FR-018의 항목. 판정 하나에 파일 하나.
- **QK-EVL-001 실행 기록·질문 세트·평가 대상**: 그 명세의 계약 그대로 입력으로만 쓴다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 로컬 시험에서 재색인 전후 활성 버전 검색 결과(상위 20건의 순위·자료원·위치·원본 링크·원본 버전·제목 경로·제목·원본 수정 시각·수집 시각)가 내린 문서를 뺀 모든 시험 질의에서 같다.

- **SC-007**: 게이트 기록·전환 기록·명령 출력에 시험 질문 세트의 질문 문장과 청크 본문, 접속 정보가 0번 나온다.

**작성 세션 기본값(사람 확인 대상)**

- **D1 평가 위치**: 후보 버전은 운영 저장소에서 직접 평가하지 않고, 같은 인덱스 버전 ID의 로컬 평가 대상에서 평가한다(FR-013·FR-014). 근거는 셋이다. 검색 함수는 활성 버전만 본다
  (`migrations/0002_search_functions.sql`의 `qk.active_index_version()`). QK-EVL-001 실행기는 로컬 `qk_eval_*`만 대상으로 받는다. 실행 전 검사가 대상의 고정 커밋과 라벨 기준 커밋이 다르면 거부한다(`commit_mismatch`).
  운영 준비 버전을 직접 검색하는 안은 검색 함수와 QK-EVL-001 계약을 바꿔야 하고, 운영 데이터는 라벨 기준 커밋보다 새로워 라벨과 맞지 않아 고르지 않았다.
  그래서 게이트는 인덱스 버전 ID가 가리키는 설정을 판정하고, 운영 데이터 자체를 판정하지 않는다. 리포트와 게이트 기록에 이 한계를 적는다.
- **D2 재색인 시작과 내림**: 재색인은 사람이 시작한다(비용 확인, AGENTS.md 3.5). 재색인부터 활성화까지 활성 버전은 바뀐 문서를 반영하지 않는다(지금 QK-SYN-001 동작). 기간을 줄이려 미리 보기에 예상 일수를 보인다.
  재색인 실행은 설정과 무관한 일반 내림을 한다(FR-010). 지금 불일치 보류가 이 내림까지 막아 지워진 문서가 며칠 동안 검색될 수 있기 때문이다. 예약 실행의 보류는 바꾸지 않는다.
  옛 설정으로 활성 버전을 계속 갱신하는 안은 두 설정을 동시에 돌려야 해 고르지 않았다. 예약 실행에서도 일반 내림을 풀지는 사람이 정한다.
- **D3 통과 기준 구조**: 기본은 하이브리드 방식의 주 지표(Recall@5·MRR)가 기준보다 허용 하락 넘게 떨어지지 않는 비열등 판정이다. 판정 질문은 기준이 정한다(FR-016). 그래서 후보가 근거를 잃은 질문이 비교에서 빠져 통과하는 일이 없다.
  허용 하락, 가드레일, 최소 판정 질문 수 값은 사람이 정책에 정한다. 골든 세트 지표 대상이 8문항이라 1문항이 Recall@5 12.5%p다. 허용 하락 0이면 1문항 회귀로도 실패한다. 표본이 늘면 정책 새 버전으로 바꾼다.
- **D4 정책과 기록 위치**: 게이트 정책과 게이트 기록은 저장소 파일로 두고 PR로 리뷰한다. 정책은 `main`에 병합된 뒤에만 유효하다. 작성자가 자기 브랜치에 느슨한 정책을 더해 바로 판정·활성화하는 일을 막기 위해서다(AGENTS.md 2절·9절).
  활성화 전환 기록에는 게이트 기록 ID와 지문을 남긴다. 파일 경로와 운영 쪽 확인 방법은 plan에서 정한다.
- **D5 보관 정책**: 가장 최근 보관 버전 하나를 되돌리기 대상으로 보호하고(정리에 별도 확인), 나머지 보관·준비 버전은 사람이 정리한다. 정리 전이면 어느 보관 버전이든 되돌리기 대상이 될 수 있다. 자동 정리는 하지 않는다.
- **D6 토크나이저(FR-033)**: 선택지는 셋이다. (a) 토크나이저가 기본값이 아닐 때만 인덱스 버전 재료에 더하고(메타데이터 스키마 버전의 `+cf1` 방식, `sync/keys.py`), 키워드 색인을 버전마다 따로 둔다.
  지금 버전 ID가 바뀌지 않고 게이트·대응표·불일치 검사가 그대로 토크나이저를 가른다. 저장 구조 변경이 가장 크다. (b) 활성화 순간에 키워드 색인을 다시 만든다. 그동안 키워드 검색이 멈춘다.
  (c) 후보 C 운영 반영은 이 절차 밖의 별도 절차로 하고 그 절차가 게이트를 따로 둔다. 작성 세션은 (a)를 권한다. ADR-010이 C를 고르지 않으면 이 결정은 필요 없다.
- **D7 되돌리기의 출처 어긋남**: 문서 단위 출처 정보는 마지막 처리 기준이라, 되돌린 버전의 청크와 어긋날 수 있다(QK-SYN-001 FR-021 (1)이 옛 준비 버전 활성화를 막은 이유와 같다).
  되돌리기는 급할 때 쓰는 동작이라 막지 않고, 어긋나는 문서 수를 미리 보기로 보이고 별도 확인 옵션을 요구한다(FR-024). plan이 버전별 출처 정보를 두어 FR-005를 채우면 이 수는 0이 된다.

**범위**

- 이 명세는 기능 요구만 정한다. 명령 이름, 파일 경로, 저장 스키마 변경, 운영 절차 문서(`docs/ops/oci-production-store.md`) 반영은 plan에서 정한다.
- 첫 실제 사용(US6)은 ADR-010 결정 결과나 Phase 1 평가로 고친 청킹 설정이다. ADR-010이 B(`kw-index-idsplit-v1`)를 고르면 후보 버전은 이미 대응표에 있는 `iv-8b7e93b22051`이고,
  기준(`iv-4c0bc4fcc642`)과 후보 모두 지금 QK-EVL-001 평가 대상(후보 A·B)으로 만들 수 있다.
- 게이트 정책의 필수 세트는 확정(`confirmed = true`)된 세트여야 한다. 2026-11-02 기준 QK-EVL-001 골든 세트 v1은 `confirmed = false`이고(`eval/question_sets/qk-evl-001-golden/v1.toml`)
  식별자 세트는 아직 없다. 그래서 첫 게이트 판정은 QK-EVL-001 측정 단계에서 세트를 확정한 뒤에 할 수 있다.

**범위 밖**

- 운영 키워드 규칙·토크나이저 교체와 ADR-010 결정, 코드 청킹·Confluence 켜기(각 켜는 변경이 이 절차를 쓴다)
- Confluence 등록 이력 때문에 붙는 `+cf1` 없애기의 시작 조건. 켜짐 판정이 저장소 등록 이력을 보므로(QK-ING-003 research R-10) 설정만 바꿔서는 현재 설정 버전이 돌아가지 않는다.
  등록 이력을 해제하는 일은 Confluence 자료원을 영구히 끄는 별도 작업이고, 그 뒤 새 버전을 만드는 일은 이 절차를 쓴다.
- 차원이 다른 임베딩 모델, 답변 평가(QK-EVL-002), 쓰지 않는 벡터와 내린 문서의 물리 정리(QK-SYN-003), 백업·복구(QK-SYN-003)
- 질의 쪽 검색 설정 기본값 변경(FR-031)
