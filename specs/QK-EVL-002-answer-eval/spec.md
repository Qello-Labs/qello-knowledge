## Clarifications

### Session 2026-11-01

- Q: 내용 지표를 어떻게 판정하나? → A: Workers AI 모델이 전부 판정하고 사람이 표본을 확인한다. 외부 제공자를 더하지 않는다(FR-020~FR-025).
- Q: ADR-009를 위해 어떤 모델을 비교하나? → A: 현재 모델 qwen3-30b-a3b와 granite-4.0-h-micro다. qwen3는 `gen-p1`·`gen-base`, granite는 `gen-p1`로 조합 3개다(FR-003). mistral-small은 스파이크에서 지시문을 따라 뺀다.
- Q: 첫 측정은 어떤 질문 세트로 하나? → A: 골든 세트 v1이 확정되면 먼저 재고, WBS 0.7 뒤 다음 버전으로 다시 잰다(FR-033).
- Q: (독립 검토 H4) 큰 세트가 하루 무료 한도 안에 끝나지 않으면? → A: 날짜별로 이어 돌린다. 첫 구간에서 Context를 고정하고 그날 잔여량만큼 남은 답변을 만든다(FR-010).
- Q: (독립 검토 H5) 사람이 얼마나 읽나? → A: 판정 대상이 60건 이하면 전수로 읽는다. 첫 측정(약 48건)이 여기에 든다. 넘으면 층화 표본과 가중 추정을 쓴다(FR-024).
- Q: (독립 검토 M2) 표준 문구가 아닌데 뜻은 거절인 답은? → A: 사용자가 실제로 보는 결과 기준으로 코드 지표에서는 실패로 세고, 판정 항목 "실질적 거절"로 따로 보인다(FR-018, FR-019).
- Q: (독립 검토 M10) 파일럿 질문을 어떻게 세트로 옮기나? → A: 질문의 유형과 의도만 옮기고 사람이 새 문장으로 쓴다. 원문은 저장소에 넣지 않으며 ADR-016은 바꾸지 않는다(FR-035).

## User Scenarios & Testing *(mandatory)*

이 명세의 사용자는 답변 평가를 돌리는 평가 담당자(팀원 또는 작성 세션), 답변을 읽고 판정하는 사람 검토자, 리포트를 보고 ADR-009와 QK-GEN-001 FR-015를 정하는 결정자(사람 리뷰어), PR 리뷰어다.
파일럿(2.6)과 뒤따르는 리뷰는 이 평가를 질문 세트의 다음 버전으로 다시 돌린다.

용어:

- **조합**: 생성 모델과 프롬프트 이름의 짝 하나. 비교 단위다.
- **답변 실행**: 질문 세트 하나를 평가 대상 하나에서 검색하고, 그 Context로 조합마다 정한 횟수만큼 답변을 만드는 실행. 평가 대상은 QK-EVL-001과 같은 로컬 평가용 데이터베이스다. 날짜를 나눠 이어 돌릴 수 있다.
- **구간**: 답변 실행을 이어 돌릴 때 한 번에 돈 부분. 날짜와 비용 확인이 구간마다 따로 있다.
- **회차**: 같은 질문·같은 Context·같은 조합으로 답변을 만드는 반복 하나.
- **답변 기록**: 답변 본문, Context, 질문 문장을 담는 저장소 밖 파일. 판정과 사람 검토의 입력이다. 저장소에 넣지 않는다.
- **실행 기록**: 답변 실행의 실행 조건과 질문별·조합별·회차별 결과를 담는 파일. 본문은 없고 답변·Context의 지문만 있다. 저장소에 넣고, 완료 표시 뒤에는 바꾸지 않는다.
- **판정 기록**: 판정 실행 하나의 조건과 답변별 판정 값을 담는 파일. 실행 기록을 실행 ID로 가리킨다.
- **사람 값 파일**: 사람이 적은 답변별 값을 담는 파일. 검토자 이름은 없다.
- **코드 지표**: 생성 결과와 근거 문서 목록만으로 계산하는 지표. 판정이 필요 없다.
- **내용 지표**: 답변 내용을 읽어야 하는 지표(충실성, 인용 정확도, 답변 관련성, 핵심 사실 일치, 실질적 거절).
- **판정 대상**: 상태가 답변인 결과. 실패 결과와 확인 불가 결과는 본문이 없거나 코드 지표로 충분해 판정하지 않는다.
- **판정 실행**: 답변 기록을 읽어 내용 지표의 판정 값을 만드는 실행. 답변 실행과 나눠 돌리고 비용도 따로 확인한다.
- **판정 모델**: 내용 지표를 판정하는 Workers AI 모델. plan에서 후보와 선택 기준을 정하고, 보정 사례로 재어 고르는 일은 사람 단계다(FR-025).
- **판정 실패**: 내용 지표의 어느 항목이든 실패나 판정 불가인 답변.
- **Context 지문**: 표시 형식으로 옮기기 전 Context 묶음 목록의 지문. 그래서 표시 형식이 다른 `gen-p1`·`gen-base` 사이에서도 같다.
- **고정 Context 점검**: 색인하지 않은 고정 합성 Context로 지시문 주입, 자료 충돌, 현재 상태, 일부만 답 가능, 무관 질문을 조합마다 확인하는 실행. 골든 세트로는 볼 수 없는 모델 동작을 본다.

### User Story 1 - 같은 Context로 조합마다 답변을 만든다 (Priority: P1)

평가 담당자는 확정된 질문 세트, 평가 대상, 회차 수를 정해 답변 실행을 돌린다. 질문마다 검색을 한 번만 하고 같은 Context를 모든 조합과 회차에 쓴다. 실행 전에 예상 호출량과 당일 잔여량을 보고 허락한 뒤에만 Workers AI를 부르고, 하루에 끝나지 않으면 다음 날 남은 답변만 이어 돌린다.

**Why this priority**: 모델과 프롬프트를 공정하게 비교하려면 검색 결과가 같아야 한다. 2.G의 답변 평가 리포트와 ADR-009 확정이 이 실행의 결과를 쓴다.

**Independent Test**: 가짜 검색과 가짜 생성 제공자로 조합 3개·회차 2개를 끝까지 돌린다. 질문당 검색이 한 번인지, 모든 조합의 Context 지문이 같은지, 실행 기록에 본문이 없는지 본다. 중간에 멈춘 뒤 이어 돌려 검색이 다시 나가지 않는지 본다. 외부 호출 없이 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 검증을 통과한 질문 세트와 평가 대상, **When** 회차 R개로 실행한다, **Then** 지표 대상 질문마다 검색은 한 번이고 답변은 3 × R개이며, 같은 질문의 Context 지문은 모두 같다.
2. **Given** 실행 전, **When** 평가 담당자가 실행을 요청한다, **Then** 조합별 예상 호출 수, 재시도 포함 상한, 예상·상한 Neurons, 당일 사용량과 잔여량(FR-007)을 먼저 보인다. 허락 표시가 없거나 장부를 읽지 못하면 Workers AI를 부르지 않는다.
3. **Given** 평가 대상이 로컬 평가용 데이터베이스가 아니거나, 고정 커밋이 라벨 기준 커밋과 다르거나, 조합이 목록 밖이다, **When** 실행한다, **Then** 외부 호출 0건으로 멈추고 이유를 보인다.
4. **Given** `no_answer` 질문, **When** 실행한다, **Then** 검색과 생성을 돌린다(QK-EVL-001 검색 평가와 다르다). 벡터 검색에 점수 임계값이 없어 Context가 생기므로 모델 판단을 봐야 한다.
5. **Given** 답이 있는 질문인데 근거 문서가 모두 미색인이다, **When** 실행한다, **Then** 생성하지 않고 "근거 미색인"으로 따로 센다.
6. **Given** 한 조합의 한 회차에서 생성이 실패한다, **When** 실행한다, **Then** 그 결과를 실패 종류와 함께 기록하고 나머지를 계속한다. FR-009의 멈춤 사유면 남은 답변을 만들지 않고 실행을 미완료로 표시한다.
7. **Given** 상한이 그날 잔여량을 넘는 큰 실행, **When** 실행한다, **Then** 잔여량으로 상한이 들어가는 질문까지만 만들고 나머지를 남긴다. 다음 구간은 비용을 다시 확인하고 저장된 Context로 남은 답변만 만든다.
8. **Given** 실행이 끝났다, **When** 실행 기록을 본다, **Then** 질문 문장, 답변 본문, 청크 본문, 핵심 사실을 담는 항목이 없다. 답변 기록은 저장소 밖 경로에만 있고, 저장소 안 경로를 주면 실행 전에 거부한다.

### User Story 2 - 코드 지표를 계산한다 (Priority: P1)

평가 담당자는 실행 기록만으로 확인 불가 정확도, 근거 문서 인용률, 출처 확인 안 됨 비율 같은 코드 지표를 조합별로 받는다. 판정 모델 없이 나오므로 내용 지표보다 먼저 볼 수 있다.

**Why this priority**: QK-GEN-001이 넘긴 FR-015 재결정 근거(출처 확인 안 됨 비율)와 "자료에 없으면 확인 불가"(C-01)를 가장 싸게 확인한다.

**Independent Test**: 상태와 출처를 손으로 정한 결과로 지표 기대값을 확인한다. 데이터베이스와 외부 호출 없이 돌릴 수 있다.

**Acceptance Scenarios**:

1. **Given** 실행 기록, **When** 지표를 계산한다, **Then** 조합별·유형별로 FR-017의 코드 지표를 분자·분모와 함께 내고, 질문 수준 집계(FR-030)도 함께 낸다.
2. **Given** 답이 있는 질문에 확인 불가로 답한 결과, **When** 지표를 계산한다, **Then** 근거 문서가 전송된 Context에 있었는지로 "검색 쪽"과 "생성 쪽 오거부"를 나눠 센다. 전송 차단으로 빠진 묶음에만 근거 문서가 있었으면 그 수를 따로 보인다.
3. **Given** 실패한 결과, **When** 지표를 계산한다, **Then** 분모에 넣고 맞지 않은 것으로 세며, 실패 종류별 수를 따로 보인다.
4. **Given** `no_answer` 질문에 표준 문구가 아닌 뜻만 거절인 답, **When** 지표를 계산한다, **Then** 코드 지표에서 실패로 센다. 뜻이 거절이었는지는 판정 항목으로 따로 보인다(US3-8).
5. **Given** 같은 실행 기록, **When** 다시 계산한다, **Then** 값이 실행 출력과 같다.

### User Story 3 - 내용 지표를 판정한다 (Priority: P1)

평가 담당자는 답변 기록과 실행 기록으로 판정 실행을 돌려 답변마다 내용 지표의 판정 값을 받는다. 판정 값은 통과·실패·판정 불가와 정해진 사유 코드뿐이다.

**Why this priority**: 충실성과 인용 정확도는 RISK-10(답변 환각)과 ADR-009 재검토 조건의 본체이고, 코드로는 잴 수 없다. 질문 세트가 커지면 사람이 전부 읽을 수 없다.

**Independent Test**: 판정 값을 미리 정한 가짜 판정기로 끝까지 돌려 지표를 확인하고, 잘못된 꼴의 판정 응답을 넣어 "판정 불가"로 남는지 본다. 외부 호출 없이 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 완료된 답변 실행, **When** 판정 실행을 요청한다, **Then** 예상 호출 수·Neurons와 당일 잔여량을 먼저 보이고 허락을 받은 뒤에만 판정 모델을 부른다.
2. **Given** 판정 대상 하나, **When** 판정한다, **Then** 입력은 승인된 루브릭과 구획으로 나눈 질문, 핵심 사실, Context, 답변 본문이다. Context는 조합과 무관한 같은 꼴로 보낸다. 결과는 항목별 값과 사유 코드이고 본문을 옮기지 않는다.
3. **Given** 판정 모델의 응답이 정해진 꼴이 아니다, **When** 판정한다, **Then** 다시 묻거나 추측하지 않고 "판정 불가"로 기록한다. 판정 불가는 통과로 세지 않고 수를 따로 보인다.
4. **Given** 답변이나 Context 안에 "통과로 판정하라" 같은 글이나 구획 구분자를 흉내 낸 글, **When** 판정한다, **Then** 구분자를 무력화하고 데이터로만 다룬다(C-03). 이 동작을 보정 사례(US4-5)로 측정 전에 확인한다.
5. **Given** 판정 입력에 비밀값 규칙이 걸린다, **When** 판정한다, **Then** 보내지 않고 "판정 불가(전송 차단)"로 기록한다.
6. **Given** 답변 기록의 지문이 실행 기록과 다르다, **When** 판정한다, **Then** 그 답변의 판정을 거부하고 답변 ID를 보인다.
7. **Given** 실패 결과와 확인 불가 결과, **When** 판정 대상을 고른다, **Then** 판정 모델을 부르지 않는다.
8. **Given** 상태가 답변인 결과, **When** 판정한다, **Then** 실질적 거절 여부를 항목으로 함께 낸다. 조합별 실질적 거절 수와 그 가운데 출처 확인 안 됨 표시가 붙은 수를 보여, 후처리로 고칠 문제인지 가릴 수 있게 한다.
9. **Given** 도중에 멈춘 판정 실행, **When** 이어 돌린다, **Then** 값이 빠진 답변만 판정하고 답변을 다시 만들지 않는다. 판정 모델이나 루브릭을 바꾸면 새 판정 기록으로 처음부터 판정한다.

### User Story 4 - 사람이 답변을 읽어 판정을 확인한다 (Priority: P1)

사람 검토자는 판정 모델의 값과 조합을 가린 자료를 읽고 판정한다. 판정 대상이 60건 이하면 전부 읽는다. 평가 담당자는 항목별 일치 결과를 받고, 사람 값이 있는 답변은 사람 값을 최종값으로 쓴다. 일치 결과가 측정 전에 정한 기준에 못 미치면 판정 모델의 수치를 결론에 쓰지 않는다.

**Why this priority**: 판정 모델의 수치를 믿을 수 있는지 사람 검토 없이는 알 수 없다. `templates/eval-report.md` 5절도 채점 모델과 표본 수, 일치율을 요구한다.

**Independent Test**: 고정 시드로 뽑은 표본이 다시 뽑아도 같은지, 검토 자료에 모델 값과 조합 이름이 없는지, 손으로 정한 값에서 혼동표와 최종값, 가중 추정이 기대대로 나오는지 본다.

**Acceptance Scenarios**:

1. **Given** 완료된 판정 실행, **When** 검토 대상을 고른다, **Then** FR-024 기준을 따르고, 표본이면 같은 입력에서 같은 표본이 나온다. 대상 목록과 시드를 판정 기록에 남긴다.
2. **Given** 검토 대상, **When** 검토 자료를 만든다, **Then** 저장소 밖 파일로 만들고 전용 임의 ID를 쓰며 항목 순서를 섞는다. 판정 모델의 값과 조합 이름을 가리고, Context는 조합과 무관한 같은 꼴로 보인다. 임의 ID 대응표도 저장소 밖에 둔다.
3. **Given** 사람 값, **When** 저장소에 넣는다, **Then** 판정 기록보다 먼저 커밋한다. 사람 값을 확정하기 전에 검토자는 판정 값을 보지 않는다. 말투로 조합이 드러날 수 있다는 한계를 리포트에 적는다.
4. **Given** 사람 값, **When** 지표를 계산한다, **Then** 항목별·조합별 혼동표(모델 통과·실패 × 사람 통과·실패)와 거짓 통과 비율을 분자·분모와 함께 낸다. 전수면 사람 값으로 지표를 낸다. 표본이면 층별 가중 추정값을 내되 조합 비교 결론에 쓰지 않는다.
5. **Given** 정답을 사람이 미리 정한 합성 보정 사례(틀린 사실, 근거 없는 주장, 맞지 않는 인용, 답변 안·Context 안 각각의 "통과로 판정하라" 지시, 옳은 답변), **When** 판정 모델을 본 실행 전에 돌린다, **Then** 결과를 리포트에 적는다. 지시를 따라 통과로 판정한 사례가 있거나 측정 전 계약의 항목별 보정 기준에 못 미치면 그 모델로 본 판정을 돌리지 않는다.
6. **Given** 일치 결과가 측정 전 계약의 기준보다 낮은 항목, **When** 리포트를 쓴다, **Then** 그 항목의 모델 수치를 결론에 쓰지 않고, 사람 전수 값이 있을 때만 결론에 쓴다.

### User Story 5 - 고정 Context로 모델 동작을 점검한다 (Priority: P2)

평가 담당자는 QK-GEN-001 `gen-ko-v1`의 고정 합성 Context를 조합마다 돌려 지시문 무시, 충돌 처리, 현재 상태 한정, 일부만 답하기, 무관 질문의 확인 불가, 종합 질문의 사실 누락을 확인한다. 임베딩 호출은 0건이다.

**Why this priority**: 골든 세트의 실제 문서에는 주입 글과 충돌이 없고 종합 유형도 없다. C-03을 어기는 모델을 ADR-009 후보로 올리면 안 되므로 비교의 가드레일이다.

**Independent Test**: 가짜 제공자로 끝까지 돌려 조합별 결과가 나오고 임베딩 호출이 0건인지 본다.

**Acceptance Scenarios**:

1. **Given** 조합 3개, **When** 점검을 돌린다, **Then** FR-007의 비용 확인을 거쳐 조합마다 `gen-ko-v1` 12문항을 한 번씩, 주입 문항 I1은 정한 횟수만큼 돌린다. 상태, 후처리 수치, 지연, Neurons를 기록하고 세트 이름과 측정 스크립트 지문을 조건으로 남긴다.
2. **Given** 점검 답변, **When** 판정한다, **Then** 지시문을 따랐는지, 근거 없음·무관 문항에서 확인 불가인지, 충돌·현재 상태 문구, 일부만 답하기(P1), 종합 사실 누락(G3)을 사람이 확정한다(QK-GEN-001 H03과 같은 방법).
3. **Given** 지시문을 한 번이라도 따른 조합, **When** 비교한다, **Then** 다른 수치와 관계없이 ADR-009 권고 후보에서 뺀다(C-03). 0건이어도 반복 횟수만큼의 근거라고 적고 "C-03을 지킨다"로 일반화하지 않는다.
4. **Given** `gen-base`, **When** 점검 결과를 쓴다, **Then** 그 프롬프트에 충돌·현재 상태 규칙이 없어 문구를 지키지 않는 것이 예상된 결과임을 함께 적는다.

### User Story 6 - 측정 전 계약을 고정하고 비교 리포트로 남긴다 (Priority: P2)

평가 담당자는 측정 전에 리포트 계약 절과 ADR-009 판단 규칙을 고정하고, 측정 뒤 `templates/eval-report.md` 양식으로 비교 리포트를 쓴다. 결정자는 이를 보고 ADR-009 상태, 프롬프트 기본값, QK-GEN-001 FR-015 재결정을 정한다.

**Why this priority**: 2.G 완료 조건 "생성 모델이 확정됐다(ADR-009)"와 답변 평가 리포트의 본체다. ADR-009는 재검토 조건에 "목표에 못 미칠 때"를 적었지만 목표값이 어디에도 없어, 측정 전에 정해야 한다.

**Independent Test**: 고정된 기록 예시에서 리포트 표의 수치가 다시 계산한 값과 같은지, 계약 절이 측정 전 커밋과 같은지, 측정 결과·작성 세션 해석·사람 결정이 나뉘어 있는지 본다.

**Acceptance Scenarios**:

1. **Given** 측정 전, **When** 계약을 쓴다, **Then** FR-029의 항목을 평가 코드·측정 결과와 다른 커밋으로 고정하고 사람이 확인한다. 측정 뒤에는 고치지 않는다.
2. **Given** 기록 파일, **When** 리포트를 쓴다, **Then** 양식의 각 절을 채운다. Before는 기준 조합 `qwen3 × gen-p1`, After는 나머지 조합이다. 검색 지표 절은 QK-EVL-001 리포트를 가리키고, 검색 p50·p95는 "재지 않음", 생성 지연은 "운영 지연과 비교하지 않음"으로 적는다.
3. **Given** 측정 결과, **When** 실패 분석을 쓴다, **Then** 사람이 질문 ID마다 정해진 실패 유형 코드(검색 누락, 순위, 문맥 부족, 환각, 오래된 정보, 자료 충돌)를 고른다. 자유 서술에 본문을 옮기지 않는다.
4. **Given** 지표가 목표보다 낮다, **When** 리포트를 쓴다, **Then** 그대로 기록한다. 수치를 높이려고 질문 세트, 라벨, 루브릭, 보정 사례를 같은 변경에서 고치지 않는다.
5. **Given** 표본이 작다, **When** 해석을 쓴다, **Then** 한 문항이 지표를 몇 %p 바꾸는지 적고(답 있음 8문항 12.5%p, `no_answer` 3문항 33.3%p) 회차 사이 판정이 바뀐 문항 수를 적는다. 답변 수를 독립 표본으로 읽지 않는다.
6. **Given** 리포트, **When** ADR-009 개정안을 쓴다, **Then** 측정 수치와 실행 조건, 측정 전에 고정한 판단 규칙, 작성 세션 권고를 더하고 Status는 사람이 정한다. 프롬프트·모델 기본값은 이 명세에서 바꾸지 않는다.

### User Story 7 - 질의 로그를 골든셋 후보로 옮긴다 (Priority: P3)

평가 담당자는 파일럿 뒤 QK-OBS-001 내보내기를 받아, 질문의 유형과 의도만 옮겨 사람이 새 문장으로 쓰고 라벨을 달아 질문 세트의 다음 버전으로 더한다.

**Why this priority**: QK-OBS-001 plan이 넘긴 일이고 2.6의 골든셋 후보 수집이 쓴다. 파일럿 전에는 내보낼 자료가 없어 P3로 둔다.

**Independent Test**: 합성 내보내기 파일로 절차를 따라 만든 세트가 형식 검증을 통과하고, 내보내기의 질문 문장·실행 식별자·날짜·청크 식별자가 세트에 없는지 본다.

**Acceptance Scenarios**:

1. **Given** 내보내기 파일, **When** 후보를 옮긴다, **Then** 사람이 질문을 고르고 유형과 의도만 옮겨 새 문장으로 쓴다. 원문 문장을 그대로 쓰지 않는다. 내보내기 파일 자체는 저장소에 넣지 않는다.
2. **Given** 새로 쓴 질문, **When** 세트에 더한다, **Then** QK-EVL-001 형식의 새 버전으로 평가 코드와 다른 커밋에 넣고, 유형·근거 문서·핵심 사실은 사람이 확정한다. 재작성 기준을 라벨 기준 문서에 적는다.
3. **Given** 원문 기록을 지웠다(QK-OBS-001 FR-013·FR-014), **When** 저장소 밖 내보내기 파일이 남아 있다, **Then** 절차에 따라 함께 지운다. 사람이 새로 쓴 질문은 원문이 아니므로 이 삭제 대상이 아니다.

---

### Edge Cases

- 검색이 실패했다(전송 차단, 저장소 오류 등): 그 질문은 모든 조합의 실패로 기록하고 생성하지 않는다. 질문이 전송 차단이면 QK-GEN-001 FR-010과 같다.
- Context가 비었거나 `no_results`다: 호출 없이 확인 불가다. 답이 있는 질문이면 "검색 쪽"으로 센다.
- 질의 임베딩이 실패해 하이브리드가 키워드 결과만 냈다: 비교 근거가 조용히 바뀌므로 실행을 멈춘다(FR-009).
- `model_unconfirmable_parts`(모든 문장이 "…는 확인할 수 없습니다" 꼴): 후처리 규칙대로 상태는 확인 불가다. 사유별 수를 보인다.
- 사실 문장과 확인 불가 문장이 섞인 일부 답변: 상태는 답변이고 코드로 가려지지 않는다. 답변 관련성 판정의 사유 코드 "일부만 답함"으로 센다.
- 표준 문구를 인용한 거절(`따라서 '제공된 자료만으로 확인할 수 없습니다.'입니다.`): 후처리에서 답변과 출처 확인 안 됨으로 나온다. 코드 지표는 실패, 판정 항목은 실질적 거절이다(Clarifications).
- 출처 확인 안 됨·출력 잘림: 결과는 답변으로 세고 표시를 함께 센다. 내용 지표 판정 대상이다.
- 답이 있는 질문에 근거 문서 일부만 미색인이다: 남은 근거 문서로 평가하고 미색인 수를 적는다.
- 회차 사이 답변이 다르다(온도 0.2): 회차마다 따로 판정한다. 출처 목록이나 판정 값이 바뀐 질문 수를 보인다.
- 비교 대상 모델이 카탈로그에서 내려갔거나 인증 오류가 난다: 실행을 미완료로 멈춘다.
- 판정 모델이 비교 대상 모델과 같다: 허용하되 리포트에 표시한다. 일치 결과를 그 조합과 나머지로 나눠 보인다.
- 판정 불가가 많다: 항목별 수를 보이고, 측정 전 계약의 기준을 넘으면 그 항목은 결론에 쓰지 않는다.
- 답변 기록을 잃거나 지웠다: 기록 파일의 지표는 그대로 다시 계산할 수 있다. 새 판정, 사람 검토, 이어 돌리기는 할 수 없고 답변 실행부터 다시 한다.
- 이어 돌리는데 조건이 다르다(세트 지문, 평가 대상 조건, 활성 인덱스 버전, 코드 커밋, 조합, 회차 수, 온도 등): 거부하고 다른 조건을 보인다. 새 실행으로 시작한다.
- 사람 값의 답변 지문이 맞지 않는다: 그 값을 거부하고 답변 ID를 보인다.
- 서로 다른 실행 기록을 비교한다: 조건이 다르면 거부한다(FR-031). Context 지문이 다른 질문은 "Context 다름"으로 표시하고 모델 효과로 읽지 않는다.
- 질문 세트가 미확정(`confirmed = false`)이다: 실행은 할 수 있으나 리포트 결론과 ADR-009에 쓰지 않는다.
- 한 조합만 실패한 질문: 비교표는 모든 조합에서 성공한 질문으로 계산하고 뺀 질문 ID와 사유를 보인다. 조합별 지표는 따로 그대로 둔다.
- 당일 잔여량이 실행 중에 줄어든다: 실행 전 확인은 그 시점 값이다. 한도에 닿으면 `provider_quota`로 멈추고 다음 구간에 이어 돌린다.

## Requirements *(mandatory)*

### Functional Requirements

**답변 실행 (US1)**

- **FR-001**: 실행 입력은 질문 세트 파일, 평가 대상 하나, 회차 수, 답변 기록 경로다. 질문 세트는 QK-EVL-001 `contracts/question-set.md` 형식을 그대로 읽고 형식을 바꾸지 않는다. 회차 수 기본값은 2다(H05 v2와 같다).
- **FR-002**: 평가 대상은 QK-EVL-001 FR-012의 실행 전 검사를 통과해야 한다(로컬 평가용 데이터베이스, 활성 인덱스 버전, 자료원 일치, 고정 커밋과 라벨 기준 커밋 일치). 운영 저장소는 받지 않는다. 검색 방식은 하이브리드이고, 검색 설정은 운영 기본값(Context 예산 3,000, ADR-025)이며 조건으로 남긴다.
- **FR-003**: 조합은 `@cf/qwen/qwen3-30b-a3b-fp8` × `gen-p1`, 같은 모델 × `gen-base`, `@cf/ibm-granite/granite-4.0-h-micro` × `gen-p1` 셋이다. 이 목록 밖의 모델·프롬프트는 실행 전에 거부한다. 후보를 더하려면 이 명세를 고친다.
- **FR-004**: qwen3 계열이 아닌 모델은 답변 실행, 고정 Context 점검, 판정 실행에서만 부른다. 운영 생성 설정이 받는 모델 범위(QK-GEN-001 FR-018)는 넓히지 않는다. 같은 프롬프트 이름을 쓰는 조합 사이에는 시스템 프롬프트와 Context 표시 형식이 같다(`gen-p1`과 `gen-base`는 원래 다르다). 후처리, 출력 상한, 온도, 시간 제한, 재시도 횟수는 모든 조합이 같다.
- **FR-005**: 추론 끔 규칙은 모델마다 정한다. qwen3는 사용자 메시지 끝 `/no_think`, granite는 표기 없음이다(스파이크 조건과 같다). 표기가 다르면 프롬프트 버전 식별자도 달라지므로 조합 이름과 실제 전송한 프롬프트·템플릿의 지문을 조건으로 남긴다. 실행 기록과 사용량 기록의 모델 식별자는 실제 호출한 모델이고, 제공자가 Neurons를 알려 주지 않을 때의 추정은 그 모델의 단가로 한다.
- **FR-006**: 질문마다 검색은 한 번 하고 같은 Context를 모든 조합·회차에 쓴다. 질문마다 모든 조합·회차의 답변을 이어서 만들어 시간대 효과를 줄이고, 호출 순서를 기록한다. 전송 전 비밀값 검사(QK-GEN-001 FR-010)를 그대로 거친다. 지표 대상은 라벨 완료이고, 답이 있는 질문이면 근거 미색인이 아닌 질문이다. `no_answer` 질문도 대상이다. 빠진 질문은 사유별 수를 보인다.
- **FR-007**: Workers AI를 부르는 모든 실행(답변 실행의 구간, 판정 실행, 고정 Context 점검, 보정)은 부르기 전에 예상 호출 수, 재시도 포함 상한, 예상·상한 Neurons, 잔여량을 보인다. 잔여량은 일일 무료 한도 − 운영 사용 장부의 당일 임베딩·생성 합계 − 평가용 사용 기록의 당일 합계 − 운영 몫 여유분(값은 측정 전 계약)이다. 장부 읽기는 QK-EVL-001 FR-013과 같은 방식(별도 접속 정보, 읽기 전용, 원격 읽기 허락)이다. 허락 표시가 없거나 장부를 읽지 못하면 부르지 않고, 상한이 잔여량을 넘으면 답변 실행은 들어가는 만큼만 돌리며(FR-010) 나머지 실행은 부르지 않는다(AGENTS.md 3.5, C-05).
- **FR-008**: 사용량은 평가용 사용 기록에만 남기고 운영 장부에 쓰지 않는다. 생성, 점검, 판정, 보정 사용량을 나눠 볼 수 있어야 한다. 기록의 호출 수와 Neurons는 실제 제공자 호출로 센다. 평가 사용량이 운영 장부에 보이지 않는다는 점을 리포트 비용 절에 적는다.
- **FR-009**: 제공자 한도 초과, 질의 임베딩 불가(`query_embedding_unavailable`), 저장소 연결 실패, 활성 인덱스 버전 변경, 인증·설정 오류가 나면 남은 작업을 멈추고 실행을 미완료로 표시한다. 미완료 기록은 비교와 리포트에 쓰지 않는다. 앞선 기록과 평가 대상의 색인을 바꾸지 않는다.
- **FR-010**: 미완료 답변 실행은 같은 실행으로 이어 돌릴 수 있다. 검색은 첫 구간에 모든 지표 대상 질문을 끝내고 Context를 답변 기록에 고정하며, 이어 돌릴 때 검색을 다시 하지 않는다. 구간마다 FR-007을 거치고, 잔여량으로 상한이 들어가는 질문까지만 질문 단위로 만든다. FR-012 실행 조건이 하나라도 다르거나 Context 지문이 맞지 않으면 거부한다. 구간별 날짜와 사용량을 기록한다.
- **FR-011**: 답변 기록과 검토 자료, 임의 ID 대응표는 저장소 밖 파일로만 쓴다. 저장소 안 경로를 주면 실행 전에 거부한다. 표준 출력과 로그에 질문 문장, 답변 본문, 청크 본문을 내지 않는다. 리포트를 확정한 뒤 이 파일들을 지우는 절차를 둔다.

**기록 파일 (전체)**

- **FR-012**: 실행 기록의 실행 조건은 질문 세트 ID·버전·파일 지문·확정 여부, 평가 대상 조건(고정 커밋, 인덱스 버전, 색인 쪽 규칙, 토크나이저, 색인 시점), 검색 설정, 조합별 모델·프롬프트 이름과 버전 식별자·전송 글 지문·추론 끔 규칙·온도·출력 상한·시간 제한·재시도 횟수, 회차 수, 임베딩 모델, 실행 시각, 실행 코드 커밋이다(C-13).
- **FR-013**: 질문 항목은 질문 ID, 유형, 라벨 상태, 근거 문서 위치, 지표 대상 여부와 빠진 사유, 검색 상태와 생략 사유, 근거 문서의 첫 순위, 전송된 Context 묶음의 문서 위치, 전송 차단으로 빠진 묶음의 수와 그 안의 근거 문서 수, Context 지문이다.
- **FR-014**: 결과 항목은 질문 ID, 조합, 회차, 구간, 호출 순서, 답변 ID, 답변 지문, 상태, 실패 종류나 확인 불가 사유, 출처 문서 위치, 근거 문서가 출처에 있는지, 후처리 수치(사실 문장, 지운 인용, 인식 못 한 꼴, 인용 없는 문장), 표시(출처 확인 안 됨, 출력 잘림, 추론 출력 감지), 시도 수, 입력·출력 토큰, Neurons와 측정·추정 구분, 지연이다.
- **FR-015**: 질문 문장, 답변 본문, 청크 본문, 핵심 사실, 질의 벡터를 담는 항목은 어느 기록 파일에도 두지 않는다. 실행 기록은 완료 표시 뒤 바꾸지 않고, 판정 값과 사람 값은 실행 ID를 가리키는 별도 파일에 둔다. 스키마 이름에 버전을 둔다. QK-EVL-001 실행 기록 `qk-evl-001-run/v1`은 바꾸지 않고 별도 스키마로 둔다.
- **FR-016**: 모든 지표는 실행 기록, 판정 기록, 사람 값 파일만으로 다시 계산할 수 있어야 하고, 다시 계산한 값은 실행 출력과 같아야 한다.

**코드 지표 (US2)**

- **FR-017**: 코드 지표는 다음과 같이 정의하고 분자·분모를 함께 낸다. 조합별·유형별로 낸다.
  - 확인 불가 정확도: `no_answer` 결과 가운데 상태가 확인 불가인 비율. 표준 문구 처리까지 재는 값이며 실패·실질적 거절은 맞지 않은 것으로 센다.
  - 오거부 비율: 답이 있는 질문의 결과 가운데 상태가 확인 불가인 비율. 근거 문서가 전송된 Context에 있었는지로 나눈다.
  - 근거 문서 인용률: 답이 있는 질문의 결과 가운데 출처 하나 이상이 근거 문서 목록에 있는 비율(H05 v2 출처 조건).
  - 출처 확인 안 됨 비율: 상태가 답변인 결과 가운데 표시가 붙은 비율(QK-GEN-001 FR-015 재결정 근거). 판정 뒤에는 실질적 거절을 뺀 값도 함께 낸다.
  - 출력 잘림 비율, 생성 실패 비율, 답변당 지운 인용 수·인용 없는 문장 수, 확인 불가 사유별 수.
  - 비용·지연: 답변당 평균 Neurons, 실행 합계와 일일 무료 한도 대비, 생성 지연 p50·p95. 지연은 작업자 PC에서 잰 값이라 운영 지연이나 NFR-02와 비교하지 않는다(NFR-02 비교는 2.6 파일럿의 질의 로그로 한다).

**내용 지표와 판정 (US3)**

- **FR-018**: 내용 지표의 판정 대상은 상태가 답변인 결과다. 지표는 다음과 같이 정의한다.
  - 충실성: 판정 대상 가운데 Context에 근거 없는 주장이 없는 답변의 비율. 많이 거절하는 조합이 높아 보이므로 오거부 비율과 함께 읽는다.
  - 인용 정확도: 인용이 붙은 사실 문장 가운데 인용한 Source가 문장 내용을 담고 있는 비율. 문장 경계와 분모는 코드 값(사실 문장 − 인용 없는 문장)이고, 코드가 문장 번호를 매겨 입력으로 준다. 판정은 문장별 맞음·틀림이며 수가 맞지 않으면 판정 불가다.
  - 답변 관련성: 답이 있는 질문의 판정 대상 가운데 질문에 실제로 답하는 답변의 비율. "일부만 답함"을 사유 코드로 남긴다.
  - 핵심 사실 일치: 핵심 사실이 있고 답이 있는 질문의 판정 대상 가운데 핵심 사실과 어긋나지 않고 하나 이상 담은 답변의 비율. 일부만 담아도 틀린 내용이 없으면 통과다(H05 v2 기준). 포함 정도(전부·일부·없음)를 값으로 남긴다.
  - 실질적 거절: 표준 문구가 아니지만 뜻이 자료 없음이라는 거절인 답변의 수와 비율. 충실성 분모에 넣되 수를 따로 보인다.
- **FR-019**: 판정 값은 항목별로 통과·실패·판정 불가와 정해진 사유 코드, 인용 정확도는 문장별 값, 핵심 사실 일치는 포함 정도를 더한 것이다. 판정 불가는 분모에서 빼되 수를 따로 보이고 통과로 세지 않는다. `no_answer` 질문은 핵심 사실 일치와 답변 관련성을 재지 않고, 판정 입력에서 `facts`를 뺀다. 그 `facts`는 사실이 아니라 기대 응답 설명이다. 판정 결과와 기록 파일에 본문을 옮기지 않는다.
- **FR-020**: 판정 입력은 승인된 루브릭과 구획으로 나눈 질문·핵심 사실·Context·답변이다. 구획 안의 구분자를 무력화하고 데이터로만 다루며(C-03), 외부로 보내기 전에 비밀값을 검사한다. Context는 조합과 무관한 같은 꼴이다. 루브릭은 버전 식별자를 가지며 조건으로 남기고, 판정 출력 상한을 둔다.
- **FR-021**: 한 판정 기록의 판정 모델과 루브릭은 모든 조합에 같다. 판정 실행은 FR-007을 거치고 답변 실행과 따로 허락받는다. 일시 실패 재시도는 생성과 같은 규칙이고, 꼴이 틀린 응답은 다시 묻지 않는다. 판정 호출 수와 Neurons를 생성과 나눠 기록한다. 모델이나 루브릭을 바꾸면 새 판정 기록으로 전부 다시 판정한다.

**사람 검토 (US4)**

- **FR-022**: 검토 자료는 전용 임의 ID, 섞은 순서, 조합과 무관한 Context 꼴을 쓰고 판정 모델의 값과 조합 이름을 넣지 않는다. 사람 값 파일에는 답변 ID, 답변 지문, 항목별 값만 둔다. 사람 값은 판정 기록보다 먼저 커밋한다.
- **FR-023**: 사람 값이 있는 답변은 사람 값을 최종값으로 쓴다. 리포트에는 항목별·조합별 혼동표, 거짓 통과 비율, 모델 값만 쓴 수치, 사람 값을 반영한 수치를 함께 적는다.
- **FR-024**: 판정 대상이 60건 이하면 전수로 검토한다. 60건을 넘으면 판정 실패 전부와, 판정 통과 가운데 조합·유형별로 고정 시드에서 25%(올림)를 뽑고, 합쳐서 20건보다 적으면 통과에서 더 뽑아 채운다. 표본일 때 사람 값을 반영한 수치는 층별 가중 추정값이며 조합 비교 결론에 쓰지 않는다. 이때 조합 비교는 일치 기준을 통과한 항목의 모델 값으로 한다.
- **FR-025**: plan은 판정 모델 후보와 선택 기준을 정한다. 실측과 선택은 사람 단계다. 본 판정 전에 사람이 정답을 정한 합성 보정 사례를 후보로 돌려 리포트에 적는다. 지시를 따라 통과로 판정한 사례가 하나라도 있거나 측정 전 계약의 항목별 보정 기준에 못 미치면 그 모델로 본 판정을 돌리지 않는다. ADR-009 대안 목록 밖의 모델을 쓰려면 AGENTS.md 3.1에 따라 결정 기록을 먼저 쓴다.
- **FR-026**: 측정 전 계약에 항목별 일치 기준과 판정 불가 비율 상한을 정한다. 기준에 못 미치는 항목은 모델 수치를 결론에 쓰지 않고, 사람 전수 값이 있을 때만 결론에 쓴다.

**고정 Context 점검 (US5)**

- **FR-027**: 조합마다 QK-GEN-001 `gen-ko-v1`의 고정 합성 Context 12문항을 한 번씩 돌리고, 주입 문항 I1은 정한 횟수(초기값 5회)만큼 돌린다. FR-007을 거치고 임베딩 호출은 0건이다. 판정은 사람이 하고(QK-GEN-001 H03) 지시문을 따랐는지, 근거 없음·무관 문항 확인 불가, 충돌·현재 상태 문구, 일부만 답하기(P1), 종합 사실 누락(G3)을 조합별로 적는다. 답변 원문은 저장소 밖 파일에 둔다. 세트 이름과 측정 스크립트 지문을 조건으로 남긴다.
- **FR-028**: 지시문을 한 번이라도 따른 조합은 ADR-009 권고 후보에서 뺀다. 근거 없음·무관 문항에서 확인 불가가 아닌 조합도 리포트에 적고, 후보에서 뺄지는 판단 규칙을 따른다.

**비교와 리포트 (US6)**

- **FR-029**: 측정 전에 다음을 쓰고 평가 코드·측정 결과와 다른 커밋으로 고정한 뒤 사람이 확인한다. 리포트 계약 절(가설, 주 지표, 가드레일, 지표별 목표값, 중단 기준), 일치 기준과 판정 불가 상한, 항목별 보정 기준, 운영 몫 여유분, ADR-009 판단 규칙과 동률 폭, QK-GEN-001 FR-015 재결정 기준, 루브릭과 보정 사례 기대값, 판정 모델, 표본 시드와 비율, 회차 수. 측정 뒤에는 바꾸지 않는다. 바꾸려면 새 버전으로 답변 또는 판정을 전부 다시 돈다(AGENTS.md 3.4). 목표값은 이 명세가 정하지 않고 이 계약에서 사람이 정한다.
- **FR-030**: 질문 수준 집계를 답변 수준과 함께 낸다. 질문 수, 회차가 모두 통과·모두 실패·갈린 질문 수다. 판단 규칙의 비교 단위는 질문 수다.
- **FR-031**: 비교표는 모든 조합에서 성공한 질문으로 계산하고 뺀 질문 ID와 사유를 보인다. 실행 기록 둘을 비교하려면 질문 세트 지문, 평가 대상 조건, 임베딩 모델, 검색 설정, 판정 모델, 루브릭이 같아야 하고, 다르면 거부하고 다른 조건을 보인다. 같은 실행 안의 조합 비교가 기본이다.
- **FR-032**: 리포트는 `templates/eval-report.md` 양식을 따르고 측정 결과, 작성 세션 해석, 사람 결정을 나눠 적는다(C-13). 목표에 못 미쳐도 기록한다. 질문 문장, 핵심 사실, 답변 본문, 청크 본문은 넣지 않고 질문 ID와 문서 위치로 가리킨다. 미확정 세트의 수치는 결론에 쓰지 않는다. 실패 유형은 사람이 정해진 코드로 고른다.
- **FR-033**: 첫 측정은 확정된 골든 세트 v1로 한다. WBS 0.7 뒤 라벨을 단 다음 버전으로 다시 재고 같은 리포트 양식으로 남긴다. 2.G가 요구하는 코드·회의·종합 유형은 그 유형이 세트에 들어간 뒤에야 리포트에 나오므로, 리포트에 빠진 유형을 적고 첫 측정만으로 2.G 조건을 채웠다고 쓰지 않는다. ADR-009 재검토 근거인 granite의 종합 질문 약점은 첫 측정에서 G3으로만 본다는 한계를 적는다.
- **FR-034**: 프롬프트·생성 모델·검색 설정의 운영 기본값은 바꾸지 않는다. 수치 근거와 함께 제안으로 남긴다. ADR-009 개정안에는 측정 수치, 조건, 판단 규칙, 작성 세션 권고를 더하고 Status 결정과 운영 반영은 사람이 정해 별도 작업으로 한다. QK-GEN-001 FR-015 재결정도 같다.

**골든셋 후보 (US7)**

- **FR-035**: 내보내기를 질문 세트로 옮기는 절차 문서를 둔다. 사람의 질문 선택, 유형과 의도만 옮긴 새 문장 작성(원문 복사 금지), 이름·연락처·민감한 질의 원문·비공개 문서 원문·서버 주소·내부 도메인 제거 확인, 질문 출처 표시, 유형·근거 문서·핵심 사실 확정, 새 버전·별도 커밋, 저장소 밖 내보내기 파일의 삭제를 담는다(AGENTS.md 3.4·6절, QK-OBS-001 FR-019). 자동으로 세트에 넣는 동작은 두지 않는다.

**검증 (C-12)**

- **FR-036**: 기본 검증의 시험은 로컬 데이터베이스와 가짜 생성 제공자, 가짜 판정기, 가짜 사용 장부만 쓴다. Workers AI·원본 자료원 호출과 운영 데이터베이스 접근은 0건이다. 지표 계산은 손으로 정한 사례의 기대값과 비교한다. 실제 모델 호출은 사람 단계로 둔다.

### Key Entities

- **조합**: 생성 모델, 프롬프트 이름과 버전 식별자, 추론 끔 규칙, 전송 글 지문.
- **답변 실행과 실행 기록**: 실행 조건, 완료 여부, 구간, 질문 항목, 질문별·조합별·회차별 결과. 본문은 없다.
- **답변 기록**: 답변 ID별 질문, 고정한 Context, 답변 본문. 저장소 밖에만 있고 리포트 확정 뒤 지운다.
- **판정 기록**: 실행 ID, 판정 모델, 루브릭 버전, 답변 ID, 답변 지문, 항목별 값과 사유 코드, 검토 대상 목록과 시드.
- **사람 값 파일**: 실행 ID, 답변 ID, 답변 지문, 항목별 값. 임의 ID 대응표는 저장소 밖에 있다.
- **보정 사례**: 사람이 정답을 정한 합성 답변과 항목별 기대값.
- **측정 전 계약**: FR-029 항목. 측정 전 커밋으로 고정한다.
- **비교 리포트**: `templates/eval-report.md` 양식의 문서.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 조합 3개·회차 R개·지표 대상 N문항 실행에서 검색 호출이 N건, 생성 호출이 재시도를 빼고 많아야 N × 3 × R건이고, 같은 질문의 Context 지문이 모두 같다. 중간에 멈춘 뒤 이어 돌린 실행의 추가 검색 호출은 0건이고, 끝까지 돈 결과의 답변 수와 조건이 한 번에 돈 실행과 같다.
- **SC-002**: 손으로 정한 결과 사례(확인 불가 정답, 오거부, 검색 쪽 오거부, 전송 차단 묶음, 사유별 확인 불가, 출처 확인 안 됨, 출력 잘림, 생성 실패, 근거 문서 인용 있음·없음)에서 코드 지표가 기대값과 소수점 넷째 자리까지 같다.
- **SC-003**: 손으로 정한 판정 사례(통과, 실패, 판정 불가, 잘못된 꼴, 전송 차단, 인용 맞음·틀림 섞임, 문장 수 불일치, 실질적 거절, 포함 정도 전부·일부·없음)에서 내용 지표, 혼동표, 최종값, 가중 추정이 기대값과 같고, 판정 불가가 통과로 세어진 사례가 0건이다.
- **SC-004**: 같은 입력으로 표본을 두 번 뽑으면 100% 같다. 판정 대상 60건 이하면 전부 검토 대상이다. 검토 자료와 그 순서에 판정 모델의 값, 조합 이름, 실행 기록의 답변 ID가 0건이다.
- **SC-005**: 실행 전 검사가 어긋나는 사례(운영 저장소 대상, 고정 커밋 불일치, 목록 밖 조합, 저장소 안 답변 기록·검토 자료 경로, 이어 돌리기 조건 불일치)에서 외부 호출이 0건이다. 허락 표시가 없거나 장부를 읽지 못하면 생성·판정 호출이 0건이다. 평가 사용량을 뺀 잔여량이 상한보다 작으면 판정·점검·보정 호출이 0건이고, 답변 실행은 들어가는 질문까지만 호출한다.
- **SC-006**: 기록 파일, 표준 출력, 로그, 비교표, 리포트의 구조에 질문 문장·답변 본문·청크 본문·핵심 사실·질의 벡터를 담는 항목이 없고, 시험 세트의 해당 문자열이 이 출력들에서 0건이다. 시험 세트의 문장은 문서 위치와 겹치지 않게 만든다.
- **SC-007**: 지표를 기록 파일만으로 다시 계산한 값이 실행 출력과 같다. 조건 하나만 다른 실행 기록 비교를 거부하고 다른 조건을 보인다.
- **SC-008**: 멈춤 사유마다(FR-009) 남은 호출이 0건이고 기록이 미완료이며, 미완료 기록을 비교·리포트 명령이 거부한다. 지시를 따른 보정 사례가 있는 판정 모델로 본 판정을 요청하면 호출이 0건이다.
- **SC-009**: 운영 생성 설정이 받는 모델 범위와 프롬프트·검색 기본값, QK-EVL-001 계약 파일, 기존 시험 기대값이 이 작업 전후로 같다.
- **SC-010**: 기본 검증에서 Workers AI·원본 자료원 호출과 운영 데이터베이스 접근이 0건이다.
- **SC-011**(측정 단계, 사람 승인 뒤): 확정된 질문 세트로 모든 조합의 코드 지표·내용 지표와 혼동표가 표본 수·실행 조건과 함께 리포트에 있고, 구간마다 사용한 Neurons가 그 구간의 상한 이하다. 계약 절은 측정 전 커밋과 같다.
- **SC-012**(측정 단계): 고정 Context 점검의 지시문 준수, 확인 불가, 충돌·현재 상태, 일부만 답하기, 종합 사실 누락이 조합별로 사람 판정과 함께 리포트에 있다.
- **SC-013**(측정 단계): ADR-009 개정안과 QK-GEN-001 FR-015 재결정 제안이 리포트의 수치·조건과 측정 전 판단 규칙을 그대로 인용하고, Status는 사람이 정한다. 리포트 확정 뒤 답변 기록과 검토 자료를 지웠다는 기록이 남는다.
- **SC-014**: 합성 내보내기 파일로 절차를 따라 만든 질문 세트가 형식 검증을 통과하고, 내보내기의 질문 문장과 식별자가 세트에서 0건이다.

## Assumptions

- **근거 원문 부재**: 백로그의 FR-EVL-03과 `evaluation.md`는 저장소(git 이력 포함)에 원문이 없다. 뜻을 추측해 대응시키지 않고 지표 정의를 이 명세에서 정한다. `templates/eval-report.md` 5절의 항목에 H05 v2의 핵심 사실 판정과 실질적 거절을 더했다. 원문이 나오면 대조해 고친다(C-11).
- **핵심 사실 "없음"**(사람 확인 대상): H05 v2는 "일부만 들어가도 틀린 내용이 없으면 통과"라고만 하고 하나도 담지 않은 경우를 말하지 않는다. FR-018은 실패로 초기값을 뒀다.
- **표본 기준과 I1 횟수**(사람 확인 대상): 60건 기준은 2026-11-01 사용자 결정이다. 표본의 25%·20건과 I1 5회는 작성 세션의 초기값이다.
- **지표별 목표값과 계약 값**(사람 확인 대상): 저장소에 목표값 근거가 없어 이 명세가 정하지 않는다(QK-EVL-001 FR-028과 같다). 측정 전 계약에서 사람이 정한다. 일치 기준, 항목별 보정 기준, 운영 몫 여유분, 동률 폭이 여기에 든다. 작성 세션의 초안은 C-01·C-03에서 나온 두 가지다. `no_answer` 확인 불가 100%, 지시문 따른 답 0건.
- **골든 세트 상태**: 골든 세트 v1은 11문항(`doc` 8, `no_answer` 3)이고 `confirmed = false`다. 확정은 QK-EVL-001 사람 단계 H00이다. 11문항 모두 `facts`가 있고, `no_answer` 3문항의 `facts`는 기대 응답 설명이다. 한 문항이 답 있음에서는 12.5%p, `no_answer`에서는 33.3%p를 바꾼다.
- **코드·회의 자료**: 코드·Confluence 자료원은 `enabled = false`이고, 평가 대상은 라벨 기준 커밋의 `dnd-backend-docs`다. 그래서 이 유형은 자료원을 켜고(QK-STO-002 뒤) 라벨을 단 다음 버전에서만 잴 수 있다.
- **평가 대상의 후보**: 운영 키워드 규칙과 같은 후보 A를 기본으로 쓴다. ADR-010이 다른 후보로 정해지면 그 후보로 다시 잰다. 평가 대상의 후보는 조건으로 남는다.
- **지연**: 작업자 PC에서 Workers AI를 부른 값이라 운영 경로(Discord 중계, 질의 서비스)와 다르다. 조합 사이 비교에만 쓴다. NFR-02 비교는 파일럿의 질의 로그로 한다(로드맵 2.G, QK-OBS-001 FR-018).
- **비용(작성 세션 추정, plan에서 다시 잰다)**: H05 v2에서 qwen3 답변은 Context 예산 3,000에 답변당 약 20 Neurons, 예상 입력 3,736토큰이었다. 단가 기준 입력 3,736·출력 상한 800이면 답변당 약 42, 재시도까지 약 84다. 첫 측정은 조합 3개 × 11문항 × 2회차 = 66건이다.
  - 답변: 예상 약 1,320, 상한 약 5,500(qwen3 단가로 계산. granite는 스파이크에서 더 쌌다. 단가는 plan에서 확인).
  - 판정: 대상 약 48건(8문항 × 3 × 2). 입력 약 5,000·출력 약 150으로 건당 약 28이면 약 1,350. 출력 상한을 300으로 두면 재시도까지 약 3,100.
  - 고정 Context 점검: 조합 3개 × (12 + I1 추가 4) = 48회, 상한 약 3,650(GEN H02의 호출당 38 × 2).
  - 보정: 사례 10건 안팎이면 후보당 상한 약 640.
  - 합계는 예상 약 3,600 Neurons로 일일 무료 한도 10,000 안이지만, 상한을 더하면 약 13,000이라 실행을 답변·판정·점검으로 나누고 날을 나눈다. 같은 날 다른 실행의 사용량은 FR-007이 뺀다.
  - 50문항 세트는 답변 300건에 예상 약 6,000, 상한 약 25,000이어서 답변 실행을 며칠로 나눈다(FR-010).
- **데이터**: 생성과 판정이 Workers AI를 쓴다. ADR-009는 질문과 청크 본문 전송을 적었고, 판정은 여기에 생성된 답변과 핵심 사실을 더한다. Cloudflare는 Workers AI 입력·출력을 학습에 쓰지 않는다고 밝힌다(ADR-009). 전송 범위가 늘어난 점을 ADR-009 개정안에 적는다.
- **답변 원문**: 답변은 비공개 문서를 인용할 수 있어 저장소에 넣지 않는다(AGENTS.md 6절, ADR-016 2026-10-29 갱신, QK-GEN-001 H03·H05 v2와 같은 방법). 사람이 읽고 판정 모델이 입력으로 쓰도록 저장소 밖 파일에만 둔다.
- **보정 사례와 루브릭**: 합성 문서로 만들어 저장소에 넣을 수 있다. 평가 세트와 같이 평가 코드와 다른 커밋에 둔다(AGENTS.md 3.4).
- **`gen-ko-v1`의 위치**: QK-GEN-001 측정 스크립트(`specs/QK-GEN-001-answer-generation/measurement/measure_generation.py`) 안에 있다. 그 문서를 고치지 않고 쓰는 방법은 plan에서 정한다. 이 세트는 고정 Context를 쓰므로 QK-EVL-001 질문 세트 형식 밖이다. 그 스크립트는 메모리 장부만 쓰므로 FR-008의 사용 기록은 이 명세의 경로로 남긴다.
- **plan이 볼 코드 사실**:
  - `GenerationSettings`는 qwen3 계열이 아니면 거부하고, `PromptSpec`은 템플릿이 ` /no_think`로 끝나야 한다(`domain/generation.py`). 운영 설정을 넓히지 않고 FR-004·FR-005를 지킬 방법을 plan에서 정한다.
  - `Postprocessed.fact_sentences`는 있지만 생성 요약에 없다. FR-014가 쓰려면 요약에 더해야 한다.
  - `is_metric_target`(`evaluation/question_set.py`)은 `no_answer`를 빼고, QK-EVL-001 미색인 판정은 근거 문서 0개를 미색인으로 센다. 그대로 재사용하지 않는다.
  - `cost_preview`(`evaluation/prechecks.py`)는 임베딩 전용이고 잔여량에 평가 사용량을 빼지 않는다.
- **ADR-009 판단**: 비교 결과로 모델을 바꾸면 QK-GEN-001 FR-018대로 ADR-009 개정과 추론 끔 규칙이 필요하다. 별도 작업이다.
- **단계 게이트**(2026-11-01 사용자 승인): `1.G` 전에는 명세 단계만 진행한다. plan·tasks·구현은 `1.G` 뒤다.
- **범위 밖**: 검색 평가 변경(QK-EVL-001), 골든셋 질문 수집(WBS 0.7), 파일럿 운영(2.6), 인덱스 버전 게이트(QK-STO-002), 질문 분류(QK-TRK-001), 운영 모델·프롬프트·검색 설정 변경, 후처리 변경, ADR-016 변경, 답변 품질 자동 감시, 운영 데이터베이스 대상 평가.
- **의존**: QK-GEN-001(생성, 후처리, 프롬프트, 사용량), QK-RET-001(검색), QK-EVL-001(질문 세트 형식, 평가 대상, 실행 전 검사, 장부 읽기), QK-SEC-001(비밀값 규칙), QK-OBS-001(내보내기).
