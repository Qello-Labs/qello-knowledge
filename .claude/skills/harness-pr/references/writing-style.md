# PR 본문 문체 규칙

PR 제목과 본문을 쓸 때 적용한다. 리뷰어가 읽는 보고 문서이므로 사실과 근거만 남기고
홍보 문구와 AI 특유의 상투적 표현을 뺀다.

## 1. 종결 어미는 합쇼체

본문의 모든 서술은 `~합니다`, `~했습니다`, `~입니다`로 끝낸다.

근거: `.github/PULL_REQUEST_TEMPLATE.md`가 합쇼체다("확인했습니다", "포함하지 않았습니다").
템플릿을 채우는 글이 템플릿과 다른 말투면 문서가 어긋난다.

| 쓰지 않는다 | 쓴다 |
| --- | --- |
| 로더를 추가한다. | 로더를 추가했습니다. |
| 검증은 통과했다. | 검증은 통과했습니다. |
| 영향은 없다. | 영향은 없습니다. |

예외:

- **PR 제목** — `<type>: <summary>` 형식이며 summary는 명사형으로 끝낸다.
- **인용** — Issue 본문, 로그, 문서를 그대로 인용할 때는 원문 말투를 유지한다.
- **저장소 규범 문서** — `AGENTS.md`, `docs/`, Skill 문서는 평서체(`~한다`)가 기준이다. PR 본문과 혼동하지 않는다.

## 2. 쓰지 않는 표현

| 금지 | 이유 | 대신 |
| --- | --- | --- |
| 이모지 전부 | 리뷰 노이즈이고 검색·diff를 방해한다 | 텍스트로 쓴다 |
| 과장 형용사 — 완벽한, 강력한, 혁신적인, 매끄러운, 손쉽게, 깔끔하게 | 검증할 수 없는 주장이다 | 무엇이 어떻게 달라졌는지 사실로 쓴다 |
| 근거 없는 정도 부사 — 대폭, 크게, 매우, 상당히, 획기적으로 | 측정값이 없으면 뜻이 없다 | 숫자를 쓰거나 뺀다 |
| 자기 평가 — 훨씬 나아졌습니다, 크게 개선했습니다, 최적화했습니다 | 판단은 리뷰어 몫이다 | 변경 내용과 측정 결과만 쓴다 |
| 인사말·맺음말 — 안녕하세요, 리뷰 부탁드립니다, 감사합니다 | PR 본문은 편지가 아니다 | 넣지 않는다 |
| 상투적 도입·마무리 — 이번 PR에서는, 요약하자면, 결론적으로, 앞으로 ~할 것으로 기대됩니다 | 내용 없는 연결어다 | 바로 본론을 쓴다 |
| 번역투 — ~을 통해, ~에 대해서, ~에 있어서, ~하는 것이 가능합니다, ~을 진행하였습니다 | 영어 구문을 직역한 어색한 한국어다 | ~로, ~는, ~할 수 있습니다, ~했습니다 |
| 피동 남용 — 되어집니다, 보여집니다 | 이중 피동이고 주체가 흐려진다 | 능동으로 쓴다 |
| 1인칭·감정 — 제가, 저는, 아쉽게도, 다행히 | PR은 변경 사실을 적는 문서다 | 주어 없이 사실만 쓴다 |
| 기계적 3항 나열 | 항목 수를 맞추려고 없는 내용을 만든다 | 있는 만큼만 쓴다 |
| 굵은 글씨·불릿 남발 | 전부 강조하면 아무것도 강조되지 않는다 | 문단으로 쓰고 목록은 실제 열거일 때만 |
| 같은 내용 반복 요약 | 도입·본문·결론에 같은 말을 세 번 쓴다 | 한 번만 쓴다 |

## 3. 사실과 추측을 구분한다

- 실행한 검증은 명령과 결과를 그대로 적는다.
- 실행하지 않은 검증은 하지 않았다고 적는다. "문제없을 것입니다"로 대신하지 않는다.
- 추측이면 추측이라고 밝힌다. "영향이 없습니다"와 "검색 코드 변경이 없어 영향이 없다고 판단했습니다"는 다른 문장이다.
- 평가 수치는 질문 세트 버전, 표본 수, 모델, 인덱스 버전 없이 쓰지 않는다.
- 리뷰어가 판단해야 할 위험, 미검증 범위, 롤백 절차를 빼지 않는다.

## 4. 초안 제출 전 점검

- [ ] 이모지가 하나도 없는가
- [ ] 모든 서술이 `~습니다`, `~입니다`로 끝나는가
- [ ] 측정값 없이 개선·최적화를 주장하지 않았는가
- [ ] 평가 수치에 조건(질문 세트, n, 모델, 인덱스 버전)이 붙어 있는가
- [ ] 실행하지 않은 검증을 했다고 쓰지 않았는가
- [ ] 인사말과 맺음말이 없는가
- [ ] 표의 금지 표현이 남아 있지 않은가

하나라도 걸리면 고친 뒤에 사용자에게 초안을 보여준다.
