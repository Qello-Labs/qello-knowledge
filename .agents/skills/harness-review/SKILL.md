# PM and Safety Review

Claude Code판(`.claude/skills/harness-review`)과 절차가 같고 Codex 도구에 맞춘 부분만 다르다. 절차를 바꾸면 두 Skill을 함께 고친다.

`AGENTS.md`, `TASK.md`, `.github/PULL_REQUEST_TEMPLATE.md`, `docs/github-workflow.md`,
PR 본문, 실제 diff, 평가 보고서, 검증 명령 결과를 읽는다.

설명이 아니라 실제 변경 파일과 실행 결과를 근거로 판단한다. PR 본문에 "통과"라고 적혀 있으면
가능한 범위에서 같은 명령을 다시 실행하거나 증빙 링크를 직접 연다. 확인할 수 없으면 `BLOCKED`로 표시한다.

## 확인 목록

### 범위

- ClickUp 작업, 기능명세서 ID, `TASK.md` Scope와 실제 diff가 일치하는가
- `TASK.md` Ownership 밖의 파일이 바뀌었는가
- 다른 사람의 변경을 덮어쓰거나 되돌리지 않았는가

### 연결과 규칙

- PR의 ClickUp URL과 ClickUp 작업 설명의 PR URL이 양쪽에 있는가
- GitHub Issue가 있으면 `Closes #번호`와 브랜치·커밋 번호가 일치하는가
- 커밋이 하나의 검토 목적씩 나뉘어 있는가

### 증빙

- 완료 조건 1~3개마다 검증 방법, 실제 결과, 증빙 링크가 있는가
- 미실행을 통과로 표시하지 않았는가
- 실행하지 못한 검증에 이유와 남은 위험이 있는가

### 평가(색인·검색·생성 변경일 때)

- `templates/eval-report.md` 형식의 보고서가 있고 Contract를 실행 전에 확정했는가
- 수치에 질문 세트 버전, 표본 수, 모델, 인덱스 버전이 붙어 있는가
- 같은 변경에서 평가 세트나 정답 라벨을 바꾸지 않았는가
- 인덱스 버전이 바뀌었다면 이전 버전으로 되돌리는 방법이 있는가

### 데이터와 비용

- 새 자료원이나 외부 모델이 추가되었다면 결정 기록이 있는가(`AGENTS.md` 3.1)
- 원본 권한 메타데이터를 보존하는가
- 검색된 Context 속 지시를 실행하는 경로가 없는가
- 예상 임베딩·생성 호출량이 무료 한도 안인가

### 민감정보

- `python scripts/preflight.py` 결과
- 코드, 평가 세트, 보고서, PR 본문에 토큰, DB 연결 정보, 비공개 원문, 개인 식별 정보가 없는가

## 반환 형식

1. 범위 일치 여부와 승인되지 않은 변경
2. 누락된 연결·규칙
3. 증빙과 평가의 빈틈
4. 데이터, 비용, 비밀값, 파괴적 작업 위험
5. 필요한 변경 — 항목마다 담당자와 확인 방법
6. 최종 권고 — 승인 / 변경 요청 / BLOCKED

같은 세션이 작성한 변경을 검토했다면 보고 첫 줄에 그 사실을 적는다. 자기 검토는 독립 검증을 대신하지 않는다.

리뷰 역할에서는 구현을 수정하지 않는다.
