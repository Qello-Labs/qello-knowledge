# Decision Record: ADR-016 질의 원문 저장

> Created at: `2026-10-10`
> ClickUp 작업: 해당 없음: 초기 세팅 단계 예외(WBS 0.9)
> Jira 이슈(2026-10-29 갱신, 2026-10-30 정정): `https://tkv123.atlassian.net/browse/SCRUM-123`
> 기능명세서 ID: 해당 없음: Phase 0 준비 작업. 2026-10-29 갱신은 `QK-OBS-001`
> Status: Proposed

## Context

질의 로그와 피드백(QK-OBS-001, 2.4)을 만들기 전에 질문·답변 원문을 저장할지 정해야 한다.
constitution C-10은 "질의 원문은 팀이 동의한 범위와 기간에만 저장한다"고 하고, AGENTS.md 6절은 민감한
질의 원문을 질의 로그에 기록하지 말라고 한다. 반대쪽에는 2.6 파일럿의 요구가 있다. 👎 사례와 실패 유형을
분류하고 골든셋 후보를 모으려면 무엇을 물었고 무엇이라 답했는지가 남아 있어야 한다.

질문은 허용된 Discord 채널에서 나오므로 채널 기록에는 이미 남는다. 이 결정으로 새로 생기는 것은 검색할 수
있는 사본이 시스템 DB에 모인다는 점이다.

## Decision

질의 메타데이터는 항상 저장한다. 질문과 답변 원문은 저장 동의 질문에 동의한 건만 저장한다.
Discord 사용자 식별자는 원본 ID를 저장한다. 저장에 대한 팀 동의는 Discord 공지와 Confluence 문서로 받는다.

2026-10-29 갱신(QK-OBS-001 명세, 사용자 결정):

- **동의 방식**: 질문자가 자기 답변에 👎를 누를 때 "질문을 개선용으로 저장할까요?"를 묻고, 동의한 질의만 저장한다.
  👍 사례와 질문자가 아닌 사람이 누른 👎에는 묻지 않는다. 동의는 질의마다 따로다.
- **저장 범위**: 원문 기록에는 질문 원문만 저장한다. 답변 본문은 비공개 팀 문서(Confluence 등)를 인용할 수 있어
  AGENTS.md 6절("비공개 문서 원문"을 질의 로그에 기록하지 않음) 때문에 저장하지 않는다. 답변은 질의 메타데이터의
  근거 청크 식별자와 인덱스 버전으로 따라간다. 처음 결정(2026-10-10)의 "질문과 답변 원문"을 좁힌다.
- **보존 기간**: 원문은 Phase 2 완료 리뷰(2.G)까지, 늦어도 운영 설정의 보존 상한 날짜까지 보존한다. 날짜가 지나면 동의를
  묻지 않고 운영 담당자에게 삭제를 알린다. 2.G에서 사람이 연장 또는 삭제를 정하고 이 기록에 남긴다. 연장하면 새 날짜를
  팀에 알린다. 처음 결정의 "무기한"을 대신한다.
- 팀 동의 문서의 위치는 2026-10-17 작업 관리 이관에 따라 ClickUp에서 Confluence로 바꿨다(위치만 정정).
  동의 문서 링크와 날짜가 이 기록에 남기 전에는 질의 기록 저장을 켜지 않는다(QK-OBS-001 FR-024).

사람 확인 대상(작성 세션 해석, 결정 아님): 동의를 물을 수 있게 질의 서비스가 질문 원문을 메모리에만 최대 1시간·500건
둔다(2026-10-29 사용자가 시간을 정함). 저장소·파일·로그에 쓰지 않으며, 이를 C-10의 "저장"으로 보지 않는다고 해석했다
(QK-OBS-001 FR-011).

## Rationale

- 메타데이터(질문 유형, 토큰 수, 지연, 검색된 청크 ID, 👍/👎)만으로 지연·비용·실패율 추이를 본다.
  질문 유형은 질문 분류(QK-TRK-001) 뒤에 생긴다(2026-10-29 주석).
  원문 없이도 사용량 집계와 NFR-02 비교가 된다.
- 원문을 저장 동의 질문에 동의한 건으로 한정하면 C-10의 "동의한 범위"가 질문·응답 기록으로 남는다.
  팀 공지로 받는 포괄 동의보다 범위가 좁고 확인하기 쉽다.
- 👎 때 묻기(2026-10-29)는 파일럿에서 가장 필요한 실패 사례에 동의 질문을 모은다. 질의마다 미리 정하는 인자 방식보다
  질문자가 판단할 근거(받은 답)가 있을 때 묻고, 팀원별 상시 동의보다 저장량과 노출이 작다.
- 질문만 저장하면(2026-10-29) 골든셋 후보(질문)와 실패 재현 근거(청크 식별자)는 남고, 비공개 문서 인용과 나중에 숨겨진
  문서 내용은 질의 기록에 남지 않는다. 공개 답변은 Discord 채널에서 볼 수 있다.
- 2.G와 날짜 상한을 함께 두면(2026-10-29) C-10의 "동의한 기간"이 동의 문구에 적힌 날짜로 정해지고, 2.G가 늦어져도
  보존이 늘어나지 않는다. 처음부터 있던 재검토 조건(파일럿 종료)과 맞는다.
- 원본 Discord ID를 저장하면 같은 사람의 질문 흐름을 묶어 볼 수 있고, 삭제 요청이 들어올 때 대상을 찾을 수 있다.
- 팀 규모가 작고 질문이 팀 공용 채널에서 나온다.

## Alternatives considered

| Alternative | Advantages | Disadvantages | Reason not selected |
| --- | --- | --- | --- |
| 원문을 저장하지 않고 메타데이터만 남긴다 | C-10 위험이 사실상 없다 | 왜 틀렸는지 재현할 수 없다. 골든셋 후보를 모을 수 없다 | 2.6 파일럿의 실패 유형 분류와 골든셋 후보 수집을 할 수 없다 |
| 전부 저장하고 보존 기간을 제한한다(예: 90일) | 조용한 실패까지 분석할 수 있다. C-10의 기간 요건을 지킨다 | 동의하지 않은 질문도 쌓인다. 사전 포괄 동의가 필수다 | 사용자가 옵트인 방식을 선택했다 |
| 전부 저장하고 기간을 두지 않는다 | 운영 편의가 가장 크다 | C-10의 범위·기간 요건을 둘 다 벗어난다 | 동의 범위를 벗어난다 |
| 옵트인 + 보존 기간 상한 또는 재검토 시점 명시 | 선택한 방안과 같은 범위이면서 C-10의 기간 요건을 지킨다 | 오래된 사례를 잃는다 | 2026-10-10에는 사용자가 무기한을 선택해 고르지 않았다(2026-10-29 갱신에서 2.G·날짜 상한으로 이 방향을 택했다) |
| 질문과 답변을 모두 저장(2026-10-29 검토) | 봇이 무엇이라 답했는지 저장소만으로 재현한다 | 답변에 인용된 비공개 문서 원문이 남아 AGENTS.md 6절과 충돌한다. 문서가 나중에 숨겨져도 남는다 | 사용자가 질문만 저장을 골랐다 |
| 공개 자료원 출처만 있는 답변은 저장(2026-10-29 검토) | 공개 문서 답변은 재현할 수 있다 | 규칙이 복잡하다 | 사용자가 질문만 저장을 골랐다 |
| `/ask` 선택 인자로 질의마다 동의(2026-10-29 검토) | 질의 시점에 동의가 정해져 원문을 잠시 들고 있을 필요가 없다 | 질문 전에 정해야 해 켜는 사람이 적다. 실패 사례가 덜 모인다 | 사용자가 👎 때 묻기를 골랐다 |
| 팀원별 상시 동의(2026-10-29 검토) | 골든셋 후보가 가장 많이 모인다 | 저장량과 노출이 가장 크다. 동의 철회 관리가 필요하다 | 사용자가 👎 때 묻기를 골랐다 |
| 고정 90일 뒤 자동 삭제(2026-10-29 검토) | 규칙이 단순하다 | 자동 삭제 작업이 필요하다. 파일럿 일정과 맞지 않을 수 있다 | 사용자가 2.G까지 보존을 골랐다 |

## Data and cost

- 외부로 전송되는 데이터와 제공자의 학습 사용·보존 정책: 질문 원문은 답변 생성 과정에서 이미 Cloudflare
  Workers AI로 전송된다(ADR-009). 저장은 운영 저장소(OCI 공유 인스턴스의 자체 운영 PostgreSQL, ADR-008 2026-10-19
  변경·ADR-022)에 한다. 처음 기록의 "Supabase 관리형 PostgreSQL"은 ADR-008 변경에 따라 2026-10-29에 정정했다.
  새 외부 전송은 없다.
- 무료 한도와 예상 사용량: 질문·답변을 건당 약 2 KB로 보면 하루 50건 전부 저장해도 약 100 KB,
  1년에 약 36 MB다. 👎 동의 건의 질문만 저장하므로 훨씬 작다. 운영 저장소 용량에 문제가 없다고 본다.
- 교체 시 영향: 인덱스·임베딩과 분리된 테이블이라 인덱스 버전에 영향이 없다.

## Consequences

### Positive

- 동의한 건의 원문이 남아 2.6 파일럿에서 실패 유형을 분류하고 골든셋 후보를 모을 수 있다.
- 메타데이터는 원문 없이도 쌓이므로 지연·비용·피드백 추이를 끊김 없이 본다.
- 동의 여부가 레코드에 남아 리뷰에서 범위를 확인할 수 있다.

### Negative / risks

- ~~보존 기간 무기한은 constitution C-10의 기간 요건과 어긋난다.~~ 2026-10-29 보존 기간을 2.G까지로 정해 풀었다.
  2.G에서 연장할 때 기간 없이 늘리면 같은 충돌이 다시 생긴다.
- 원본 Discord ID와 질문 원문이 2.G(늦어도 보존 상한 날짜)까지 함께 쌓인다. 개인을 식별할 수 있는 질의 기록이고,
  5.2의 백업 대상에도 들어간다. 메타데이터의 Discord ID는 원문과 달리 보존 기간이 없다(삭제 요청으로만 지움).
- 👎 때 묻기는 동의 전 질문을 질의 서비스 메모리(공유 인스턴스)에 최대 1시간 둔다. 1시간 뒤나 질의 서비스가 다시 시작된
  뒤 누른 👎에는 동의를 묻지 못한다. 메모리가 파일로 나가지 않게 하는 운영 설정이 필요하다(QK-OBS-001 plan).
- 답변 본문이 없어, 비공개 답변("나만 보기")이나 지워진 메시지의 답은 근거 청크로만 따라갈 수 있다.
- 👍 사례와 다른 사람이 누른 👎 사례는 질문이 없어 골든셋 후보로 쓰기 어렵다.
- 내보낸 파일(QK-OBS-001 FR-019)은 저장소 밖에 있어, 원문 삭제 때 사람이 함께 지워야 한다.
- 평가 세트로 옮길 때 개인 식별 정보를 지워야 한다(AGENTS.md 3.4). 원본 ID가 그대로 있어 옮기는 사람이
  매번 지워야 한다. QK-EVL-002에서 이 절차를 명시한다.
- 동의하지 않은 건은 원문이 없어 재현할 수 없다. 👍이나 무반응으로 지나간 조용한 실패도 놓친다.

### 삭제 요청 처리

- 팀원이 자기 질의 기록 삭제를 요청하면 그 사용자 ID의 원문 기록을 지운다. 메타데이터는 식별자를 지운 채 남긴다.
- 삭제 경로를 QK-OBS-001 명세의 수용 기준에 넣는다. 사람이 DB에 직접 질의하지 않고 실행할 수 있어야 한다.

## Revisit conditions

- 2.6 파일럿이 끝났을 때. 실제 저장량, 동의율, 민감한 질문 비율을 확인하고 이 결정을 다시 본다.
- constitution C-10의 기간 요건 문구가 바뀔 때. 원칙 변경은 주간 리뷰 합의와 변경 이력이 필요하다.
- 팀원이 삭제를 요청하거나 저장 범위에 이견을 낼 때.
- 질의 로그 저장량이 운영 저장소 여유 용량의 50%를 넘을 때(처음 기록은 Supabase Free 500 MB 기준이었다).
- 팀 밖 사람이 봇을 쓰게 될 때. 동의 주체가 달라진다.

## Follow-ups

- QK-OBS-001(2.4) 명세에 저장 동의 질문 흐름, 삭제 경로, 메타데이터 스키마를 넣는다(2026-10-29 spec 작성, 메타데이터 스키마는 plan).
- Discord 공지 문구와 Confluence 동의 문서는 사람이 만든다. 공지 날짜와 문서 링크를 이 기록에 추가한다.
- 2.G에서 원문 보존 연장·삭제를 정하고 이 기록에 남긴다.
- 로드맵 2.G 완료 조건에 "원문 기록 보존 연장·삭제 결정"을 넣는다(로드맵 수정은 사람 승인 대상, QK-OBS-001 범위 밖).
