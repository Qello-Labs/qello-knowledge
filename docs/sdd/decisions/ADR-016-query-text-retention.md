# Decision Record: ADR-016 질의 원문 저장

> Created at: `2026-10-10`
> ClickUp 작업: 해당 없음: 초기 세팅 단계 예외(WBS 0.9)
> 기능명세서 ID: 해당 없음: Phase 0 준비 작업
> Status: Proposed

## Context

질의 로그와 피드백(QK-OBS-001, 2.4)을 만들기 전에 질문·답변 원문을 저장할지 정해야 한다.
constitution C-10은 "질의 원문은 팀이 동의한 범위와 기간에만 저장한다"고 하고, AGENTS.md 6절은 민감한
질의 원문을 질의 로그에 기록하지 말라고 한다. 반대쪽에는 2.6 파일럿의 요구가 있다. 👎 사례와 실패 유형을
분류하고 골든셋 후보를 모으려면 무엇을 물었고 무엇이라 답했는지가 남아 있어야 한다.

질문은 허용된 Discord 채널에서 나오므로 채널 기록에는 이미 남는다. 이 결정으로 새로 생기는 것은 검색할 수
있는 사본이 시스템 DB에 모인다는 점이다.

## Decision

질의 메타데이터는 항상 저장한다. 질문과 답변 원문은 저장 동의 질문에 동의한 건만 저장한다.
Discord 사용자 식별자는 원본 ID를 저장하고, 보존 기간은 무기한이다. 저장에 대한 팀 동의는 Discord 공지와
ClickUp 문서로 받는다.

## Rationale

- 메타데이터(질문 유형, 토큰 수, 지연, 검색된 청크 ID, 👍/👎)만으로 지연·비용·실패율 추이를 본다.
  원문 없이도 사용량 집계와 NFR-02 비교가 된다.
- 원문을 저장 동의 질문에 동의한 건으로 한정하면 C-10의 "동의한 범위"가 질문·응답 기록으로 남는다.
  팀 공지로 받는 포괄 동의보다 범위가 좁고 확인하기 쉽다.
- 원본 Discord ID를 저장하면 같은 사람의 질문 흐름을 묶어 볼 수 있고, 삭제 요청이 들어올 때 대상을 찾을 수 있다.
- 팀 규모가 작고 질문이 팀 공용 채널에서 나온다.

## Alternatives considered

| Alternative | Advantages | Disadvantages | Reason not selected |
| --- | --- | --- | --- |
| 원문을 저장하지 않고 메타데이터만 남긴다 | C-10 위험이 사실상 없다 | 왜 틀렸는지 재현할 수 없다. 골든셋 후보를 모을 수 없다 | 2.6 파일럿의 실패 유형 분류와 골든셋 후보 수집을 할 수 없다 |
| 전부 저장하고 보존 기간을 제한한다(예: 90일) | 조용한 실패까지 분석할 수 있다. C-10의 기간 요건을 지킨다 | 동의하지 않은 질문도 쌓인다. 사전 포괄 동의가 필수다 | 사용자가 옵트인 방식을 선택했다 |
| 전부 저장하고 기간을 두지 않는다 | 운영 편의가 가장 크다 | C-10의 범위·기간 요건을 둘 다 벗어난다 | 동의 범위를 벗어난다 |
| 옵트인 + 보존 기간 상한 또는 재검토 시점 명시 | 선택한 방안과 같은 범위이면서 C-10의 기간 요건을 지킨다 | 오래된 사례를 잃는다 | 에이전트가 2026-10-10에 제안했고 사용자가 무기한을 선택했다 |

## Evidence

- constitution C-10(질의 원문의 범위·기간), AGENTS.md 3.4(평가 세트의 개인 식별 정보 제거), 6절(민감한 질의 원문).
- `docs/sdd/roadmap.md` Phase 2 표의 2.4 QK-OBS-001과 2.6 파일럿, 2.G 완료 조건.
- 2026-10-10 사용자 결정. 저장 범위, 식별자, 보존 기간, 동의 방법을 사용자가 지정했다.
- 측정 근거는 없다. 이 결정은 정책 결정이다.

## Data and cost

- 외부로 전송되는 데이터와 제공자의 학습 사용·보존 정책: 질문 원문은 답변 생성 과정에서 이미 Cloudflare
  Workers AI로 전송된다(ADR-009). 저장은 Supabase 관리형 PostgreSQL에 한다. Supabase의 데이터 처리 정책은
  ADR-008의 후속 확인 항목이다.
- 무료 한도와 예상 사용량: 질문·답변을 건당 약 2 KB로 보면 하루 50건 전부 저장해도 약 100 KB,
  1년에 약 36 MB다. 동의 건만 저장하면 더 작다. Supabase Free 500 MB를 1년 안에 넘지 않는다.
- 교체 시 영향: 인덱스·임베딩과 분리된 테이블이라 인덱스 버전에 영향이 없다.

## Consequences

### Positive

- 동의한 건의 원문이 남아 2.6 파일럿에서 실패 유형을 분류하고 골든셋 후보를 모을 수 있다.
- 메타데이터는 원문 없이도 쌓이므로 지연·비용·피드백 추이를 끊김 없이 본다.
- 동의 여부가 레코드에 남아 리뷰에서 범위를 확인할 수 있다.

### Negative / risks

- **보존 기간 무기한은 constitution C-10의 "동의한 범위와 기간에만 저장한다"에서 기간 요건과 어긋난다.**
  에이전트가 2026-10-10에 이 충돌을 보고했고 사용자가 무기한을 다시 선택했다. 둘 중 하나가 필요하다.
  C-10의 기간 요건 문구를 고치거나, 이 결정을 다시 보는 것이다. 지금은 충돌을 남긴 상태로 둔다.
- 원본 Discord ID와 질문·답변 원문이 기간 제한 없이 함께 쌓인다. 개인을 식별할 수 있는 질의 기록이고,
  5.2의 백업 대상에도 들어간다.
- 평가 세트로 옮길 때 개인 식별 정보를 지워야 한다(AGENTS.md 3.4). 원본 ID가 그대로 있어 옮기는 사람이
  매번 지워야 한다. QK-EVL-002에서 이 절차를 명시한다.
- 동의하지 않은 건은 원문이 없어 재현할 수 없다. 👍이나 무반응으로 지나간 조용한 실패도 놓친다.

### 삭제 요청 처리

- 팀원이 자기 질의 기록 삭제를 요청하면 그 사용자 ID의 원문 기록을 지운다. 메타데이터는 식별자를 지운 채 남긴다.
- 삭제 경로를 QK-OBS-001 명세의 수용 기준에 넣는다. 사람이 DB에 직접 질의하지 않고 실행할 수 있어야 한다.

## Revisit conditions

- 2.6 파일럿이 끝났을 때. 실제 저장량, 동의율, 민감한 질문 비율을 확인하고 이 결정을 다시 본다.
- constitution C-10의 기간 요건 문구가 바뀔 때. 원칙 변경은 주간 리뷰 합의와 변경 이력이 필요하다.
- 팀원이 삭제를 요청하거나 저장 범위에 이견을 낼 때.
- 질의 로그 저장량이 Supabase Free 500 MB의 50%를 넘을 때.
- 팀 밖 사람이 봇을 쓰게 될 때. 동의 주체가 달라진다.

## Follow-ups

- QK-OBS-001(2.4) 명세에 저장 동의 질문 흐름, 삭제 경로, 메타데이터 스키마를 넣는다.
- Discord 공지 문구와 ClickUp 동의 문서는 사람이 만든다. 공지 날짜와 문서 링크를 이 기록에 추가한다.
