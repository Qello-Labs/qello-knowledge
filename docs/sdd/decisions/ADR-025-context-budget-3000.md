# Decision Record: ADR-025 검색 문맥 예산 기본값을 3,000토큰으로 올린다

> Created at: `2026-10-27`
> Jira 이슈: 해당 없음(Jira 없이 진행하는 예외 작업, GitHub Issue #68)
> 기능명세서 ID: `QK-RET-001` (research R-08의 초기값 2,000을 바꾼다)
> Status: Proposed
>
> 문맥을 담는 규칙(중심 먼저, 절 첫 청크·앞뒤 청크 다음, 청크를 자르지 않음)과 예산 범위(1~8000)는 그대로다. 바뀌는 것은 `QK_RETRIEVAL_CONTEXT_BUDGET` 기본값뿐이다.

## Context

- QK-BOT-001 H05 실측에서 Q05(푸시 발송에 외부 큐를 쓰지 않은 이유)가 출처 없이 "명시되지 않음"으로 답했다(#68).
- 운영 재현에서 예산 2,000은 1,980을 썼고, 질문 핵심어(SQS·Kafka)가 있는 유일한 절인 ADR-0008 `고려한 선택지`(통합 6위, 키워드 1위)가 중심 단계에서 `budget_exhausted`로 빠졌다.
  예산은 1·3·4·5위의 다른 문서 청크가 먼저 썼다. 생성은 `선택 이유` 절만 보고 질문과 이유를 잇지 못했다.
- 2,000은 프롬프트 몫 약 1,000과 합쳐 ADR-009의 질의당 입력 3,000에 맞춘 초기값이다(QK-RET-001 spec "초기값", research R-08). R-08은 청크 토큰 분포와 비용 최악값을 쟀고,
  근거가 한 문서의 여러 절에 흩어진 질문의 답 품질은 재지 않았다. 초기값은 평가 결과로 조정하고 결정 기록과 평가 보고서로 남기기로 했다.

## Decision

`QK_RETRIEVAL_CONTEXT_BUDGET`와 `RetrievalSettings.context_budget`의 기본값을 2,000에서 3,000으로 올린다.

## Rationale

- 예산 3,000에서 ADR-0008의 `고려한 선택지`·`선택 이유`가 한 묶음으로 담기고 Q05가 근거 문서를 인용해 답했다(재현 1회, 평가 1회).
- 질문 세트 v1 11문항에서 다른 질문의 답 내용이 나빠지지 않았고, 없음 3문항은 모두 표준 확인 불가 문구를 유지했다.
- 최악 입력(배율 2.0, 질문 상한, 출력 800)이 12,650토큰으로 모델 컨텍스트 32,768 안이다. 설정 검사를 그대로 통과한다.
- 비용 최악값(R-08과 같은 식: p95 비율 1.286, 프롬프트 몫 1,000, 출력 상한 1,200)은 질의당 약 59 Neurons, 하루 50건 약 2,950으로 질의 예비분 3,000 안이다. 실측 평균은 질의당 19.9였다.
- 설정 하나라서 운영에서 `query.env`로 즉시 되돌릴 수 있다.

## Alternatives considered

| Alternative | Advantages | Disadvantages | Reason not selected |
| --- | --- | --- | --- |
| 예산 2,000 유지 | 비용 변화 없음 | Q05처럼 근거가 6위 아래 절에 있는 질문이 계속 실패한다 | #68을 고치지 못한다 |
| 담기 규칙 변경(키워드 상위·같은 문서 절 우선) | 예산을 덜 늘리고 같은 효과를 낼 수 있다 | QK-RET-001 FR-013을 바꾸고 시험·평가 범위가 크다 | 설정 변경으로 먼저 고치고, 비용이 문제가 되면 다시 본다 |
| 예산 4,000 이상 | 더 많은 절을 담는다 | 생성 입력·Neurons가 더 늘고 평가하지 않았다 | 3,000으로 Q05가 해결돼 근거가 없다 |

## Data and cost

- 외부로 전송되는 데이터와 제공자의 학습 사용·보존 정책: 바뀌지 않는다. 생성 입력에 문서 발췌가 더 들어갈 뿐 같은 Workers AI 생성 경로다(ADR-022·ADR-009).
- 무료 한도와 예상 사용량: 질문 세트 v1 기준 질문당 생성이 평균 15.9에서 19.9 Neurons로 약 25% 늘었다(1회 표본). 질의 예비분 3,000으로 하루에 답할 수 있는 수는 실측 평균으로 약 190건에서 약 150건으로 줄어든다(추정).
  최악값은 2,000의 질의당 약 53(하루 50건 약 2,660)에서 약 59(약 2,950)로 늘어 예비분에 가까워진다. 예상 토큰이 실제보다 2.3배 적게 나오는 경우(QK-RET-001 spec)에는 예비분을 넘는다.
  ADR-009의 질의당 입력 3,000 가정도 넘는다(최악 실제 입력 약 4,860).
- 교체 시 영향(재임베딩, 인덱스 버전): 없음. 예산은 인덱스 버전 재료가 아니다(`iv-4c0bc4fcc642` 유지).

## Consequences

### Positive

- 근거가 한 문서의 여러 절에 흩어진 질문에서 근거 절이 문맥에 들어갈 가능성이 커진다.

### Negative / risks

- 답변당 Neurons가 늘어난다.
- 예상 2,001~3,000토큰 청크도 이제 문맥에 들어갈 수 있다(R-08 측정 기준 예상 2,000 초과 청크 3개, 0.23%).
- 문맥에 다른 문서가 더 들어가 인용 문서가 라벨의 근거 문서와 달라질 수 있다. 평가에서 Q02·Q04가 그랬고, 사람이 내용 기준으로 통과로 판정했다.
- 질문마다 1회 표본이라 모델 출력 편차를 분리하지 못했다.
- 현재 기본값을 2,000으로 적은 명세 문장이 남는다: `specs/QK-RET-001-hybrid-retrieval/data-model.md` 1.1 표, 같은 명세 `spec.md`의 "예산 2,000은 청크 상한보다 작아" 문단,
  `specs/QK-CHK-001-code-chunker/spec.md`의 "지금 2,000토큰". 이 결정 범위 밖이라 후속으로 갱신한다. research R-08과 tasks의 기록은 이력이라 그대로 둔다.

## Revisit conditions

- 하루 질의 사용량이 질의 예비분의 80%를 넘을 때
- 근거 절이 예산 부족으로 빠지는 실패가 3,000에서도 다시 나올 때(담기 규칙 변경을 다시 본다)
- 생성 모델이나 청킹 규칙이 바뀌어 청크 크기 분포가 달라질 때
